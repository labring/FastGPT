# 模型管理重构 — 详细设计：数据迁移

> 基于主设计文档第 6 节和项目现有 migration 模式（参考 `projects/app/src/pages/api/admin/initv4151.ts`）展开。定义从旧模型数据结构到新结构的完整迁移流程。

> ⚠️ **实现修订（热升级兼容，2026-08）**：本文所有步骤从「破坏式迁移（rename key / `$unset` 旧字段）」调整为 **additive（只补 canonical 字段、保留 legacy 字段）**，配合 schema 双字段 + 缓存双 map + getters 兼容输入（见[热升级技术分析 §7](./模型管理重构-热升级技术分析.md#7-additive-migration-设计)），使迁移前/中/后及失败回滚四个窗口内新旧镜像均可运行存量数据。通用规则：
> 1. 只补 canonical 字段，不 `$unset` legacy；
> 2. 只写成功解析成真实 ObjectId 的值；unresolved 不写、计入结果；
> 3. 目标 canonical 已有有效值时不覆盖；
> 4. 所有步骤可重复执行，第二次对已完成记录 no-op；
> 5. Step 1 本版本**不删除** `model` unique 索引（推迟到 contract release）。

## 1. 迁移总览

```
initvXXXX handler (authRoot)
├── Step 1: 索引迁移 — 创建新索引（旧 unique 索引本版本保留，不删除）
├── Step 2: system_models 数据迁移 — metadata 扁平化（只补顶层缺失字段）+ isSystem 标记 + 孤儿标记 + 收集 channel 配置（不删 legacy 字段）
├── Step 3: 构建 modelName → modelId 映射表（含 name 别名 map + ambiguous 记录）
├── Step 4: datasets 迁移 — 只补 vectorModelId/agentModelId/vlmModelId（保留 legacy 字段）
├── Step 5: apps + app_versions 迁移 — 保留 legacy input + 补 canonical input + chatConfig 双字段
├── Step 6: eval 迁移 — 只补 evalModelId（保留 evalModel）
├── Step 7: usage_items 迁移 — 补充 modelId（保留 model）+ unresolved 统计
├── Step 8: default_models 初始化 — 从旧 isDefault 标记创建系统默认（$setOnInsert，不删 legacy flags）
├── Step 9: 权限迁移 — 只补 MongoResourcePermission.resourceId（保留 resourceName）
└── Step 10: Channel 迁移 — 旧 requestUrl/requestAuth → aiproxy Channel
```

所有步骤幂等可重入。`modelName → modelId` 的转换规则：同一 model 名有多个文档时，优先选择 `isActive === true` 的文档；`convertModelValue` 解析失败（unresolved）时**不写入** canonical 字段并计数（§4）。

## 2. Step 1: 索引迁移

**文件**: `packages/service/core/ai/config/migration.ts`

> ⚠️ **实现修订（热升级兼容，2026-08）**：`dropModelUniqueIndex` **本版本不调用**。删除旧 `model` 唯一索引意味着旧镜像无法再以 `model` 为唯一键写入（旧写路径依赖该约束），会破坏回滚契约，故推迟到 contract release（此时已确认不再回滚旧镜像）。本步骤只创建新索引。

```typescript
/**
 * 创建重构后的新索引（additive，幂等）。
 * 本兼容版本不删除 system_models 上 model 字段的旧唯一索引——
 * 删除需等待 contract release（届时确认不再回滚旧镜像）。
 */
export async function createNewIndexes(): Promise<string[]> {
  const db = connectionMongo.connection.db;
  if (!db) return [];

  const created: string[] = [];
  const newIndexes: { key: Record<string, number>; name: string }[] = [
    { key: { teamId: 1 }, name: 'teamId_1' },
    { key: { tmbId: 1 }, name: 'tmbId_1' },
    { key: { isActive: 1, provider: 1 }, name: 'isActive_1_provider_1' }
  ];

  for (const { key, name } of newIndexes) {
    const exists = (await db.collection('system_models').listIndexes().toArray())
      .some((idx: { name?: string }) => idx.name === name);
    if (exists) continue;
    await db.collection('system_models').createIndex(key, { name, background: true });
    created.push(name);
  }

  return created;
}

## 3. Step 2: system_models 数据迁移

> ⚠️ **实现修订（热升级兼容，2026-08）**：从「metadata 扁平化 + 删除 legacy 字段」调整为「**只补缺失顶层字段**」：不 `$unset` `metadata`、`isCustom`、`isDefault*`、`tmbId/teamId`、`requestUrl/requestAuth`（新镜像缓存构建兼容两种 schema，旧镜像仍读取 legacy 结构）。`isSystem` 只补不覆盖；`requestUrl/requestAuth` 仍收集给 Step 10，但**不从数据库删除**（旧镜像回滚后继续使用）。

```
旧: { _id, model: "gpt-4o" (unique), metadata: { type, name, provider, isCustom, isDefault,
      requestUrl, requestAuth, isActive, maxContext, ... } }
新（additive 结果）: { _id, model: "gpt-4o" (unique 保留), metadata: { ... }（保留）,
      type: "llm", name: "GPT-4o", provider: "openai", isSystem: true, isActive: true,
      tmbId, teamId（保留）, maxContext, ... }
```

```typescript
export async function migrateModelData(): Promise<{
  total: number;
  flattened: number;        // 仅顶层缺失字段补齐数（不删除 metadata）
  isSystemSet: number;      // 缺失时推导 isSystem 的文档数
  defaultsCleaned: number;  // 补齐必填默认值数（不再清理 isDefault*）
  orphanMarked: number;     // 孤儿模型标记 isSystem 数
  /** 从旧 isDefault* 标记收集的系统默认模型配置（取首次遇到的值），供 Step 8 使用 */
  systemDefaults: Record<string, string>;
  /** 从旧 requestUrl/requestAuth 收集的渠道配置列表，供 Step 10 使用（不删除数据库字段） */
  channelConfigs: { model: string; requestUrl: string; requestAuth: string }[];
}> {
  const db = connectionMongo.connection.db;
  if (!db) return { total: 0, flattened: 0, isSystemSet: 0, defaultsCleaned: 0, orphanMarked: 0, systemDefaults: {}, channelConfigs: [] };

  // 从旧 isDefault* 标记收集的系统默认模型映射（首次遇到即采用，不按 teamId 分组）
  const systemDefaults: Record<string, string> = {};
  // 从旧 metadata 中收集 requestUrl/requestAuth 用于迁移到 Channel 系统（Step 10，不删除原字段）
  const channelConfigs: { model: string; requestUrl: string; requestAuth: string }[] = [];

  // cursor-based 分批处理
  const BATCH_SIZE = 500;
  const cursor = db.collection('system_models').find({}).batchSize(BATCH_SIZE);

  let total = 0, flattened = 0, isSystemSet = 0, defaultsCleaned = 0, orphanMarked = 0;

  while (await cursor.hasNext()) {
    const batch = [];
    for (let i = 0; i < BATCH_SIZE && (await cursor.hasNext()); i++) {
      batch.push(await cursor.next());
    }

    for (const doc of batch as any[]) {
      total++;
      const $set: Record<string, any> = {};

      // 2a. Flatten（additive）：仅补缺失的顶层字段，metadata 整体保留
      if (doc.metadata && typeof doc.metadata === 'object') {
        for (const [key, value] of Object.entries(doc.metadata)) {
          if (value === null || value === undefined || value === '') continue;
          // 顶层已存在则不覆盖；requestUrl/requestAuth 收集给 Step 10，但保留原字段
          if (doc[key] === undefined && !['requestUrl', 'requestAuth'].includes(key)) {
            $set[key] = value;
          }
        }
        flattened++;
      }

      // 2a2. 收集 requestUrl/requestAuth 用于后续 Channel 迁移（Step 10）
      //       仅读取收集，不从数据库删除（旧镜像回滚后仍可读）
      const chanUrl = doc.requestUrl ?? doc.metadata?.requestUrl;
      const chanAuth = doc.requestAuth ?? doc.metadata?.requestAuth;
      if (chanUrl && chanAuth) {
        channelConfigs.push({
          model: ($set.model ?? doc.model) as string,
          requestUrl: chanUrl,
          requestAuth: chanAuth
        });
      }

      // 2b. isSystem 推导（只补缺失，不覆盖已有值；不删除 isCustom）
      const effectiveTmbId = $set.tmbId ?? doc.tmbId;
      const isCustom = doc.isCustom ?? doc.metadata?.isCustom;
      if (doc.isSystem === undefined) {
        if (isCustom !== undefined) {
          $set.isSystem = !isCustom;
          isSystemSet++;
        } else if (effectiveTmbId === undefined || effectiveTmbId === null) {
          $set.isSystem = true;
          isSystemSet++;
        }
      }

      // 2c. 收集 isDefault* 标记到 systemDefaults（保留字段本身，不删除）
      const modelId = String(doc._id);
      const modelType = doc.type ?? doc.metadata?.type;
      const flagValue = (field: string) => doc[field] ?? doc.metadata?.[field];
      if (flagValue('isDefault')) {
        if (modelType === 'llm' && !systemDefaults.llmId) systemDefaults.llmId = modelId;
        if (modelType === 'embedding' && !systemDefaults.embeddingId) systemDefaults.embeddingId = modelId;
        if (modelType === 'tts' && !systemDefaults.ttsId) systemDefaults.ttsId = modelId;
        if (modelType === 'stt' && !systemDefaults.sttId) systemDefaults.sttId = modelId;
        if (modelType === 'rerank' && !systemDefaults.rerankId) systemDefaults.rerankId = modelId;
      }
      if (flagValue('isDefaultDatasetTextModel') && !systemDefaults.datasetTextLLMId) systemDefaults.datasetTextLLMId = modelId;
      if (flagValue('isDefaultDatasetImageModel') && !systemDefaults.datasetImageLLMId) systemDefaults.datasetImageLLMId = modelId;
      if (flagValue('isDefaultChatTitleModel') && !systemDefaults.chatTitleLLMId) systemDefaults.chatTitleLLMId = modelId;
      if (flagValue('isDefaultHelperBotModel') && !systemDefaults.helperBotLLMId) systemDefaults.helperBotLLMId = modelId;

      // 2d. ⚠️ 热升级修订：不再 $unset isDefault / isDefaultXxx / isCustom / metadata——
      //     旧镜像回滚依赖这些 legacy 字段；新镜像缓存按「default_models → isDefault* flags」顺序解析默认模型

      // 2e. ⚠️ 热升级修订：不再 $unset tmbId/teamId（即使 isSystem: true）——
      //     缓存构建时在内存中清理系统模型的 owner 信息，数据库字段保留

      // 2f. 孤儿模型 — 无 tmbId/teamId 的模型标记为 isSystem: true（只补不删）
      const effectiveOrphanTmbId = doc.tmbId ?? doc.metadata?.tmbId;
      if (doc.isSystem === undefined && $set.isSystem === undefined &&
          (effectiveOrphanTmbId === undefined || effectiveOrphanTmbId === null)) {
        $set.isSystem = true;
        orphanMarked++;
      }

      // 2g. 补齐缺失的必填字段默认值（modelType 已在 2c 声明，沿用）
      if (modelType === 'llm') {
        if (doc.maxContext === undefined && $set.maxContext === undefined) { $set.maxContext = 16000; defaultsCleaned++; }
        if (doc.maxResponse === undefined && $set.maxResponse === undefined) { $set.maxResponse = 8000; defaultsCleaned++; }
        if (doc.functionCall === undefined && $set.functionCall === undefined) { $set.functionCall = true; defaultsCleaned++; }
        if (doc.toolChoice === undefined && $set.toolChoice === undefined) { $set.toolChoice = true; defaultsCleaned++; }
        if (doc.quoteMaxToken === undefined && $set.quoteMaxToken === undefined) { $set.quoteMaxToken = 120000; defaultsCleaned++; }
      } else if (modelType === 'embedding') {
        if (doc.defaultToken === undefined && $set.defaultToken === undefined) { $set.defaultToken = 512; defaultsCleaned++; }
        if (doc.maxToken === undefined && $set.maxToken === undefined) { $set.maxToken = 512; defaultsCleaned++; }
        if (doc.weight === undefined && $set.weight === undefined) { $set.weight = 0; defaultsCleaned++; }
      } else if (modelType === 'tts') {
        if (doc.voices === undefined && $set.voices === undefined) { $set.voices = []; defaultsCleaned++; }
      }

      // 写入（仅 $set，无 $unset）
      if (Object.keys($set).length > 0) {
        await db.collection('system_models').updateOne({ _id: doc._id }, { $set });
      }
    }
  }

  logger.info(
    `Model migration (additive): total ${total}, flattened ${flattened}, isSystem ${isSystemSet}, defaults filled ${defaultsCleaned}, orphans marked ${orphanMarked}, channel configs collected ${channelConfigs.length}`
  );
  return { total, flattened, isSystemSet, defaultsCleaned, orphanMarked, systemDefaults, channelConfigs };
}
```

## 4. Step 3: modelName → modelId 映射

```typescript
/**
 * 构建 model 名字符串 → modelId (ObjectId 字符串) 映射。
 * 查询全部模型，优先采用 isActive === true 的文档（同一 model 名有多个时）。
 * 同时构建 name → modelId 辅助映射，用于处理历史 usage_items 中
 * model 字段可能存储的是 name（别名）而非 model（provider 名）的情况。
 * ⚠️ 热升级修订：重名不再静默 first-wins，而是记录 ambiguous，供迁移完成后人工确认。
 */
export async function buildModelNameToIdMap(): Promise<{
  modelMap: Map<string, string>;
  nameMap: Map<string, string>;
  ambiguous: { name: string; ids: string[] }[];
}> {
  const db = connectionMongo.connection.db;
  const modelMap = new Map<string, string>();
  const nameMap = new Map<string, string>();
  const ambiguous: { name: string; ids: string[] }[] = [];
  if (!db) return { modelMap, nameMap, ambiguous };

  const models = (await db
    .collection('system_models')
    .find({ isSystem: true, isActive: true })  // ⚠️ 修订：仅纳入活跃系统模型——若某 model 名仅有停用文档，迁移不得指向停用模型 id
    .sort({ isActive: -1 })  // 活跃模型优先（冗余保险，与 filter 一致）
    .project({ model: 1, name: 1, isActive: 1 })
    .toArray()) as any[];

  const register = (map: Map<string, string>, key: string, id: string) => {
    if (!key) return;
    if (!map.has(key)) {
      map.set(key, id);
    } else if (map.get(key) !== id) {
      // 同 key 不同 id：记录 ambiguous（首条仍占位，保持确定性 first-wins）
      const existing = ambiguous.find((a) => a.name === key);
      if (existing) {
        if (!existing.ids.includes(id)) existing.ids.push(id);
      } else {
        ambiguous.push({ name: key, ids: [map.get(key)!, id] });
      }
    }
  };

  for (const m of models) {
    const id = String(m._id);
    register(modelMap, m.model as string, id);
    register(nameMap, m.name as string, id);
  }

  logger.info(
    `Built model name→id map: ${modelMap.size} model names, ${nameMap.size} alias names, ${ambiguous.length} ambiguous`
  );
  return { modelMap, nameMap, ambiguous };
}
```

> **设计决策**：map 仅纳入 `isActive=true` 且 `isSystem=true` 的模型。迁移后的历史模型均标记为 `isSystem=true`，`isActive` 由原数据决定。同时构建 `nameMap`（name → modelId）作为辅助映射，解决历史 `UsageItem.model` 字段可能存储 `name`（别名）而非 `model`（provider 名）的语义不一致问题——Step 7 迁移时先按 `modelMap` 匹配，未命中再按 `nameMap` 匹配。
>
> ⚠️ **边界说明**：map 只覆盖系统模型——datasets/apps 引用**团队私有模型**（`isSystem: false`）时，转换可能 unresolved。此时 canonical 不写入，运行时靠 getter 按 name 解析；unresolved 记录迁移结果，按业务需要人工修复，不阻断升级期间写入。

export const WORKFLOW_MODEL_KEY_MAP: Record<string, string> = {

export const DATASET_PARAMS_MODEL_FIELDS = [
  'embeddingModel', 'rerankModel', 'datasetSearchExtensionModel',

/**
 * 将 model 名字符串转换为 modelId。
 * 先按 modelMap（provider model 名）匹配，未命中再按 nameMap（别名）匹配。
 * ⚠️ 热升级修订：调用方必须校验返回值是有效 ObjectId 才写入 canonical 字段——
 * 解析失败（仍为 name 字符串）时不得写入，计入 unresolved。
 */
export const convertModelValue = (
  value: unknown,
  modelMap: Map<string, string>,
  nameMap?: Map<string, string>
): { value: unknown; resolved: boolean } => {
  if (typeof value !== 'string' || !value) return { value, resolved: false };
  const hit = modelMap.get(value) ?? nameMap?.get(value);
  return hit ? { value: hit, resolved: true } : { value, resolved: false };
};
```

## 6. Step 4: datasets 迁移

> ⚠️ **实现修订（热升级兼容，2026-08）**：从「`$unset` 旧字段 + `$set` 新字段」调整为「**只 `$set *ModelId`（解析成功时），legacy 字段保留**」。unresolved（解析失败）不写入 canonical 字段并计数，返回 `unresolved` 清单（资源 id + 字段 + 原值）供人工排查。D3（canonical 字段误存 name）与 D0（canonical 缺失）统一处理：canonical 已是有效 ObjectId 不覆盖；否则从 canonical/legacy 解析成功才写入。

```typescript
export async function migrateDatasets(modelMap: Map<string, string>): Promise<{
  total: number; migrated: number; unresolved: { datasetId: string; field: string; value: string }[];
}> {
  const db = connectionMongo.connection.db;
  if (!db) return { total: 0, migrated: 0, unresolved: [] };

  const BATCH_SIZE = 500;
  const cursor = db.collection('datasets').find({
    $or: [
      { vectorModel: { $exists: true } },
      { agentModel: { $exists: true } },
      { vlmModel: { $exists: true } }
    ]
  }).batchSize(BATCH_SIZE);

  let total = 0, migrated = 0;
  const unresolved: { datasetId: string; field: string; value: string }[] = [];

  while (await cursor.hasNext()) {
    const batch = [];
    for (let i = 0; i < BATCH_SIZE && (await cursor.hasNext()); i++) {
      batch.push(await cursor.next());
    }

    const bulkOps: any[] = [];
    for (const doc of batch as any[]) {
      total++;
      const $set: Record<string, any> = {};

      for (const [oldField, newField] of [
        ['vectorModel', 'vectorModelId'],
        ['agentModel', 'agentModelId'],
        ['vlmModel', 'vlmModelId']
      ] as const) {
        // canonical 已有有效 ObjectId → 不覆盖（幂等）
        const existingCanonical = doc[newField];
        if (isValidObjectId(existingCanonical)) continue;

        // D3（canonical 存 name）/ D0（canonical 缺失）→ 从 legacy 解析写入
        //   若 canonical 本身是 name 值（W1 residue 等价形态），先尝试解析 canonical；
        //   失败再回退解析 legacy 值
        const legacyVal = doc[oldField];
        const targetValue = existingCanonical !== undefined ? existingCanonical : legacyVal;
        if (targetValue === undefined || targetValue === null) continue;

        const { value, resolved } = convertModelValue(targetValue, modelMap);
        if (resolved) {
          $set[newField] = value;
        } else {
          // unresolved：不写入 canonical 字段（原 name 不污染 id 字段），记录供人工排查
          unresolved.push({ datasetId: String(doc._id), field: oldField, value: String(targetValue) });
        }
      }

      if (Object.keys($set).length > 0) {
        bulkOps.push({ updateOne: { filter: { _id: doc._id }, update: { $set } } });
        migrated++;
      }
    }

    if (bulkOps.length > 0) {
      await db.collection('datasets').bulkWrite(bulkOps);
    }
  }

  logger.info(`Dataset migration (additive): ${migrated}/${total} datasets, ${unresolved.length} unresolved`);
  return { total, migrated, unresolved };
}
```

> **边界情况**：`convertModelValue` 在 `modelMap` 映射中找不到对应 model 名时，**不写入 canonical 字段**（unresolved）。新系统读取时 canonical 缺失 → getter 按 legacy name 解析 → 仍解析失败则通过 `assertModelUsable` 显式报错。迁移日志记录 unresolved 清单供升级后人工修复。

## 7. Step 5: apps + app_versions 迁移

> ⚠️ **实现修订（热升级兼容，2026-08）**：从「原地 rename key + 删除旧字段」调整为「**保留 legacy input + 新增 canonical input**」，与持久化双 key 方案（[热升级技术分析 §6.4](./模型管理重构-热升级技术分析.md#64-workflow-input-key-兼容持久化双-key--参数传递双字段)）一致——迁移后的数据同时携带 `model` 与 `modelId`，新老镜像各取所需：
> - legacy input 保留原 key/value，不 rename、不删除；
> - 缺少 canonical input 时新增 canonical 副本（复制 legacy value 并转换为 id）；已有有效 canonical input 不覆盖；
> - W1 residue（canonical key + name value）解析成功时更新为 id；
> - chatConfig 保留 `model` 并补 `modelId`；datasetParams 保留旧字段并补新字段；
> - 去除重复 canonical key（迁移前已存在 canonical + 新增的重复时），以有效 canonical 优先；
> - 为防止迁移与在途请求覆盖，apps 更新 filter 带 `updateTime`、autosave version 带 `time` 做 CAS，失败计入 `conflicts` 不覆盖，重跑迁移即可。

```typescript
/**
 * 变更单个 workflow node input 对象（additive：保留 legacy，在 inputs 兄弟数组中新增 canonical input）。
 * 返回 true 表示有任何改动。
 *
 * ⚠️ 说明：canonical input 是 node.inputs（或 mod.inputs）数组中的**兄弟元素**，
 * 不是 input 的内嵌子数组——`FlowNodeInputItemType` 不存在 `appInputs` 字段。
 */
const migrateInput = (
  inputs: Record<string, any>[],   // 当前 node 的 inputs 数组（migrate 时逐元素传入自身引用所在数组）
  input: Record<string, any>,
  appId: string,                   // 调用方传入，用于 unresolved 定位
  modelMap: Map<string, string>,
  unresolved: { appId: string; key: string; value: string }[]
): boolean => {
  let changed = false;

  // 直接模型键迁移（保留 legacy input，新增/修正 canonical input）
  if (input.key && WORKFLOW_MODEL_KEY_MAP[input.key]) {
    const legacyKey = input.key;
    const canonicalKey = WORKFLOW_MODEL_KEY_MAP[legacyKey];

    // 仅转换非引用类型（非 reference）的 value
    const isReference = input.selectedTypeIndex !== undefined && input.selectedTypeIndex !== 0;

    if (legacyKey === canonicalKey) {
      // key 已是 canonical（W1 residue：canonical key + name value）→ 解析 name 为 id
      if (!isReference && typeof input.value === 'string' && input.value) {
        const { value, resolved } = convertModelValue(input.value, modelMap);
        if (resolved && value !== input.value) {
          input.value = value;
          changed = true;
        } else if (!resolved && !isValidObjectId(input.value)) {
          // name 无法解析且不是 ObjectId：不写入，记录 unresolved
          unresolved.push({ appId, key: canonicalKey, value: input.value });
        }
      }
    } else {
      // legacy input 保留；缺少 canonical input 时在 inputs 数组新增兄弟副本
      if (!isReference && typeof input.value === 'string' && input.value) {
        const { value, resolved } = convertModelValue(input.value, modelMap);
        if (resolved) {
          // 已有有效 canonical input 不覆盖；否则追加 canonical input 到 inputs 数组
          const existingCanonical = inputs.find((i) => i.key === canonicalKey);
          if (!existingCanonical) {
            inputs.push({ key: canonicalKey, value });
            changed = true;
          }
        } else {
          unresolved.push({ appId, key: legacyKey, value: input.value });
        }
      }
    }
  }

  // datasetParams 复合对象中的模型字段（保留旧字段并补新字段）
  if (input.key === 'datasetParams' && input.value && typeof input.value === 'object') {
    const val = input.value as Record<string, unknown>;
    for (const field of DATASET_PARAMS_MODEL_FIELDS) {
      if (field in val) {
        const canonicalField = WORKFLOW_MODEL_KEY_MAP[field];
        // 保留旧字段；canonical 缺失时才补充
        if (val[canonicalField] === undefined) {
          const { value, resolved } = convertModelValue(val[field], modelMap);
          if (resolved) {
            val[canonicalField] = value;
            changed = true;
          } else {
            unresolved.push({ appId, key: `datasetParams.${field}`, value: val[field] as string });
          }
        }
      }
    }
  }

  return changed;
};

export async function migrateAppWorkflows(modelMap: Map<string, string>): Promise<{
  appsChecked: number; appsMigrated: number; versionsMigrated: number; conflicts: number;
  unresolved: { appId: string; key: string; value: string }[];
}> {
  const db = connectionMongo.connection.db;
  if (!db) return { appsChecked: 0, appsMigrated: 0, versionsMigrated: 0, conflicts: 0, unresolved: [] };

  let appsChecked = 0, appsMigrated = 0, conflicts = 0;
  const unresolved: { appId: string; key: string; value: string }[] = [];

  // ── apps 集合 ──
  {
    const cursor = db.collection('apps').find({
      $or: [
        { modules: { $exists: true, $not: { $size: 0 } } },
        { chatConfig: { $exists: true } }
      ]
    });
    const docs = (await cursor.toArray()) as any[];
    appsChecked = docs.length;

    for (const app of docs) {
      let changed = false;

      // 迁移 modules（保留 legacy input，在 inputs 数组补 canonical input）
      if (Array.isArray(app.modules)) {
        for (const mod of app.modules as any[]) {
          if (Array.isArray(mod.inputs)) {
            for (const input of mod.inputs as Record<string, any>[]) {
              if (migrateInput(mod.inputs as Record<string, any>[], input, String(app._id), modelMap, unresolved)) changed = true;
            }
          }
        }
      }

      // 迁移 chatConfig（保留 model 并补 modelId）
      if (app.chatConfig) {
        for (const [configKey, modelKey] of [
          ['questionGuide', 'model'],
          ['ttsConfig', 'model']
        ] as const) {
          const cfg = app.chatConfig[configKey];
          if (cfg?.[modelKey] !== undefined && cfg.modelId === undefined) {
            const { value, resolved } = convertModelValue(cfg[modelKey], modelMap);
            if (resolved) {
              cfg.modelId = value;
              changed = true;
            } else {
              unresolved.push({ appId: String(app._id), key: `chatConfig.${configKey}.${modelKey}`, value: cfg[modelKey] as string });
            }
          }
        }
      }

      if (changed) {
        // CAS：带 updateTime 条件更新，防止冻结前在途保存被覆盖；失败计入 conflicts
        const result = await db.collection('apps').updateOne(
          { _id: app._id, updateTime: app.updateTime },
          { $set: { modules: app.modules, chatConfig: app.chatConfig } }
        );
        if (result.modifiedCount === 1) {
          appsMigrated++;
        } else {
          conflicts++;
        }
      }
    }
  }

  // ── app_versions 集合 ──
  let versionsMigrated = 0;
  {
    const cursor = db.collection('app_versions').find({
      $or: [
        { nodes: { $exists: true, $not: { $size: 0 } } },
        { chatConfig: { $exists: true } }
      ]
    });
    const docs = (await cursor.toArray()) as any[];

    for (const version of docs) {
      let changed = false;

      if (Array.isArray(version.nodes)) {
        for (const node of version.nodes as any[]) {
          if (Array.isArray(node.inputs)) {
            for (const input of node.inputs as Record<string, any>[]) {
              if (migrateInput(node.inputs as Record<string, any>[], input, String(version._id), modelMap, unresolved)) changed = true;
            }
          }
        }
      }

      // chatConfig（同 apps，保留 model 并补 modelId）
      if (version.chatConfig) {
        for (const [configKey, modelKey] of [
          ['questionGuide', 'model'],
          ['ttsConfig', 'model']
        ] as const) {
          const cfg = version.chatConfig[configKey];
          if (cfg?.[modelKey] !== undefined && cfg.modelId === undefined) {
            const { value, resolved } = convertModelValue(cfg[modelKey], modelMap);
            if (resolved) {
              cfg.modelId = value;
              changed = true;
            } else {
              unresolved.push({ appId: String(version._id), key: `chatConfig.${configKey}.${modelKey}`, value: cfg[modelKey] as string });
            }
          }
        }
      }

      if (changed) {
        // CAS：autosave version 带 time 条件
        const result = await db.collection('app_versions').updateOne(
          { _id: version._id, time: version.time },
          { $set: { nodes: version.nodes, chatConfig: version.chatConfig } }
        );
        if (result.modifiedCount === 1) {
          versionsMigrated++;
        } else {
          conflicts++;
        }
      }
    }
  }

  logger.info(`App workflow (additive): ${appsMigrated}/${appsChecked} apps, ${versionsMigrated} versions, ${conflicts} conflicts, ${unresolved.length} unresolved`);
  return { appsChecked, appsMigrated, versionsMigrated, conflicts, unresolved };
}

```typescript
export async function migrateModelPermissions(modelMap: Map<string, string>): Promise<{
  total: number; migrated: number; unresolved: number;
}> {
  const db = connectionMongo.connection.db;
  if (!db) return { total: 0, migrated: 0, unresolved: 0 };

  const perms = (await MongoResourcePermission.find({
    resourceType: PerResourceTypeEnum.model
  }).lean()) as any[];

  let migrated = 0, unresolved = 0;
  for (const perm of perms) {
    // resourceId 已有正确值 → 跳过
    if (perm.resourceId && !perm.resourceName) continue;

    if (perm.resourceId) {
      // 已有 resourceId → 无需处理（resourceName 保留）
      continue;
    }

    const modelId = perm.resourceName
      ? (modelMap.get(perm.resourceName) ?? undefined)
      : undefined;

    if (!modelId) {
      unresolved++;
      continue;
    }

    // 只补 resourceId，保留 resourceName
    await MongoResourcePermission.updateOne(
      { _id: perm._id },
      { $set: { resourceId: modelId } }
    );
    migrated++;
  }

  logger.info(`Permission migration (additive): ${migrated}/${perms.length}, ${unresolved} unresolved`);
  return { total: perms.length, migrated, unresolved };
}

## 12. Step 10: requestUrl/requestAuth → Channel 迁移

> ⚠️ **实现修订（经评审确认，2026-08）**：为满足 §14「所有步骤幂等可重入」，实现新增跨 run 守卫 —— 创建前通过 aiproxy 渠道列表 API 拉取现有渠道，`name === "Migrated: <model>"` 的渠道跳过（skipped）。单 run 内仍按 (model, requestUrl, requestAuth) 去重。

```typescript
/**
 * 将旧模型的自定义 requestUrl/requestAuth 迁移到 aiproxy Channel 系统。
 * 按 (model, requestUrl, requestAuth) 去重，避免为同一上游模型创建重复渠道。
 */
export async function migrateChannelsFromLegacyConfigs(
  channelConfigs: { model: string; requestUrl: string; requestAuth: string }[]
): Promise<{ created: number; skipped: number; failed: number }> {
  if (!channelConfigs || channelConfigs.length === 0) {
    logger.info('Channel migration: no legacy channel configs to migrate');
    return { created: 0, skipped: 0, failed: 0 };
  }

  // 按 (model, requestUrl, requestAuth) 去重
  const uniqueMap = new Map<string, { model: string; requestUrl: string; requestAuth: string }>();
  for (const cfg of channelConfigs) {
    const key = `${cfg.model}::${cfg.requestUrl}::${cfg.requestAuth}`;
    if (!uniqueMap.has(key)) {
      uniqueMap.set(key, cfg);
    }
  }

  // 检查 aiproxy API 是否配置
  let baseUrl: string, token: string;
  try {
    const adminConfig = getAIProxyAdminConfig();
    baseUrl = adminConfig.baseUrl;
    token = adminConfig.token;
  } catch {
    logger.warn(
      `Channel migration: aiproxy API not configured, skipping ${uniqueMap.size} channel(s). ` +
      `Manual channel details will be logged without authentication credentials.`
    );
    for (const [, cfg] of uniqueMap) {
      logger.info(`  Manual channel needed: model=${cfg.model}, url=${cfg.requestUrl}`);
    }
    return { created: 0, skipped: uniqueMap.size, failed: 0 };
  }

  let created = 0, skipped = 0, failed = 0;

  for (const [, cfg] of uniqueMap) {
    try {
      // 通过 aiproxy API 创建 Channel（与 createChannel.ts handler 相同的行为）
      await axiosWithoutSSRF.post(
        `${baseUrl}/api/channel/`,
        {
          type: 1,                              // 默认类型
          model_mapping: {},
          key: cfg.requestAuth,
          name: `Migrated: ${cfg.model}`,
          base_url: cfg.requestUrl,
          models: [cfg.model]                   // 上游 provider model 名
        },
        {
          headers: { Authorization: `Bearer ${token}` },
          timeout: 10000
        }
      );
      created++;
      logger.info(`Channel created: model=${cfg.model}, url=${cfg.requestUrl}`);
    } catch (error) {
      failed++;
      logger.error(`Channel creation failed for model=${cfg.model}: ${getErrText(error)}`);
    }
  }

  logger.info(`Channel migration: ${created} created, ${skipped} skipped, ${failed} failed`);
  return { created, skipped, failed };
}
```

> **注意**：
> - 去重粒度：同一 `(model, requestUrl, requestAuth)` 组合只创建一个 Channel
> - 安全边界：迁移日志仅记录 `model` 和 `requestUrl`，不记录 `requestAuth` 全文、前缀或任何可恢复片段
> - aiproxy API 未配置时不阻塞迁移：记录 warning 日志并输出各 channel 配置供手动创建
> - Channel 的 `models` 字段使用旧 model 名（provider model 名），aiproxy 路由层按此字段匹配上游模型

## 14. 幂等性保证

所有步骤均可重复执行，不产生副作用：

| 步骤 | 幂等策略 |
|------|---------|
| Step 1 (索引) | 检查新索引是否已存在，跳过已完成的操作；旧 unique 索引本版本不删除 |
| Step 2 (模型数据) | 只补顶层缺失字段（已存在不覆盖）；不删除 metadata/isCustom/isDefault*/tmbId/teamId |
| Step 3 (映射表) | 纯查询，无副作用；ambiguous 记录确定性 first-wins |
| Step 4 (datasets) | 只补 `*ModelId`（canonical 已有有效值不覆盖）；legacy 字段保留 |
| Step 5 (apps/versions) | 保留 legacy input；canonical input 缺失时才新增，W1 residue 已解析的不再改；CAS（updateTime/time）失败计入 conflicts 不覆盖 |
| Step 6 (eval) | 只补 `evalModelId`（已有值跳过）；`evalModel` 保留 |
| Step 7 (usage_items) | 只补 `modelId`（已有值跳过）；`model` 保留；unresolved 不写 |
| Step 8 (default_models) | `$setOnInsert` 仅在系统默认文档不存在时写入，不覆盖已有配置 |
| Step 9 (权限) | 只补 `resourceId`（已有值跳过）；`resourceName` 保留 |
| Step 10 (Channel) | 去重后通过 aiproxy API 创建；aiproxy 未配置时跳过，记录日志供手动创建 |

## 15. 风险与回滚

| 风险 | 缓解措施 |
|------|---------|
| 同一 model 名对应多个 isActive + isSystem 文档时映射歧义 | 仅纳入同时满足 `isActive === true` 且 `isSystem === true` 的模型，deterministic first-wins；返回 ambiguous 清单，迁移完成后人工确认 |
| 历史 usage_items.model 存储 name 别名导致匹配失败 | Step 7 使用 `modelMap` + `nameMap` 双映射 fallback；均未命中时**不写入 modelId**（unresolved 计数），避免 name 污染 id 字段 |
| legacy model 引用已被删除（unresolved） | 不写入 canonical 字段，保留 legacy 值；运行时 getter 解析失败经 `assertModelUsable` 显式报错；返回资源定位清单供人工修复 |
| 迁移期间服务中断 | 所有步骤幂等可重入；additive 语义下中断重跑只补齐未完成记录；保持 root-only 手动调用，不自动绑定 pod 启动 |
| 存量数据量过大（10M+ 条 usages） | Steps 2/4 使用 cursor-based 分批处理（BATCH_SIZE = 500）+ bulkWrite 批量写入；⚠️ Steps 5/6/7/9 当前伪代码为全量 `toArray()/find().lean()` + 逐条 updateOne——实现时应按需改造为 cursor + bulkWrite（尤其是 Step 7 usages），避免大集合全量加载 |
| Channel 迁移时 aiproxy API 不可用 | Step 10 在 aiproxy 未配置时跳过，日志中输出各 channel 配置供手动创建；去重避免重复 |
| 迁移与在途写请求并发 | app/version 更新带 updateTime/time CAS；datasets/eval/usage_items/resource_permissions 写入时匹配 canonical 字段读取快照。失败计入 conflicts，且不覆盖并发写入，重跑即可 |
| 回滚 | 迁移前全量备份所有受影响集合；回滚 = 停止新镜像 → 恢复备份 → 回滚旧镜像 → 验证。additive 迁移保留 legacy 字段，旧镜像可读取迁移后数据；但失败回滚以备份恢复为准 |
