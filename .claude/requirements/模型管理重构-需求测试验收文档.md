# 模型管理重构 — 需求与测试验收文档

> 基于 `.claude/requirements/模型管理重构需求.md` 拆分，聚焦 Story 验收条件与测试用例。

---

## 1. 概述

### 1.1 重构目标
- 将模型创建能力从 root 下放至授权团队成员
- 建立「系统模型/私有模型」分层共享机制
- 以 MongoDB `_id` (ObjectId) 替代 `model` 字符串作为模型唯一标识
- 将 `metadata: Object` 中的配置字段提升为文档顶层级字段

### 1.2 核心角色
| 角色 | 职责 |
|------|------|
| root 管理员 | 创建/管理系统模型及公共渠道，监测全平台模型 |
| 团队 Owner | 控制团队成员的模型创建权限 |
| 团队成员（授权用户） | 创建/管理自有模型及渠道，控制模型可用范围 |
| API 用户 | 通过 API 调用模型，受模型权限控制 |

## 3. Story 验收条件与测试用例

### F1. 模型创建权限管控

#### Story: 团队 Owner 控制成员创建模型权限

**验收条件：**

##### 正常场景

**场景 1.1 — 无权限查看（默认状态）：**
- Given 团队成员 A 没有创建模型权限（默认状态）
- When 团队成员 A 进入「模型配置」和「模型渠道」页面
- Then 新建模型和新建渠道的按钮都置灰，鼠标悬浮提示「暂无权限，请先联系管理员获取权限」

**场景 1.2 — 授予权限：**
- Given 团队 Owner 进入团队管理-权限设置页面
- When Owner 为某成员开启「创建模型」权限（默认关闭）
- Then 被授权成员登录后可在「模型配置」和「模型渠道」页面看到新建按钮激活，可新建模型和渠道

**场景 1.3 — 收回权限（该成员有自定义模型）：**
- Given 某成员的「创建模型」权限已开启，且该成员已创建了自定义模型
- When Owner 关闭该成员/部门/群组的「创建模型」权限
- Then 该成员已创建的模型和渠道仍然保留，可进行配置，但新建按钮置灰

##### 测试用例

| ID | 测试场景 | 前置条件 | 操作步骤 | 预期结果 |
|----|---------|---------|---------|---------|
| F1-TC01 | 无权限用户查看页面 | 团队成员无创建模型权限（默认） | 成员进入「模型配置」和「模型渠道」页面 | 新建按钮置灰，悬浮提示「暂无权限，请先联系管理员获取权限」 |
| F1-TC02 | 授予成员创建模型权限 | 团队成员无创建模型权限 | Owner 在权限设置中为成员开启「创建模型」 | 成员登录后新建按钮激活，可新建模型和渠道 |
| F1-TC03 | 收回有模型成员的权限（成员级） | 成员有创建权限且已创建模型 | Owner 关闭该成员的创建权限 | 权限收回成功，该成员已创建的模型和渠道保留、可配置，新建按钮置灰 |
| F1-TC04 | 收回有模型部门的权限（部门级） | 部门中某成员已创建模型 | Owner 关闭该部门的创建权限 | 权限收回成功，已创建的模型和渠道保留，新建按钮置灰 |
| F1-TC05 | 收回有模型群组的权限（群组级） | 群组中某成员已创建模型 | Owner 关闭该群组的创建权限 | 权限收回成功，已创建的模型和渠道保留，新建按钮置灰 |
| F1-TC06 | 未授权用户直接 URL 访问 | 用户无创建模型权限 | 用户直接访问新建模型的 URL | 无法访问，提示无权限或跳转 |

### F2. root 创建和管理模型及渠道

#### Story F2-S1：root 创建全平台系统模型

**验收条件：**

##### 正常场景

**场景 2.1.1 — 创建系统模型：**
- Given root 进入「系统模型配置」页面，点击「新建模型」
- When root 填写模型信息（模型名、选择模板渲染默认参数配置，增加系统模型渠道的选择并提供快速创建入口，去掉自定义请求地址和 Key，保留价格配置）
- Then 模型自动标记为「系统模型」
- And 模型创建成功，全平台所有用户均可在可用模型列表中看到该模型，可测试，并能在工作流中选用，但不可启停/编辑/删除

**场景 2.1.2 — 模型别名重复：**
- Given root 新建模型
- When root 填写的模型别名与其他系统模型重复
- Then 弹窗确认后提示「模型别名已存在，请更换其他别名」

#### Story F2-S2：root 创建全平台公共渠道

**验收条件：**

##### 正常场景

**场景 2.2.1 — 创建公共渠道：**
- Given root 进入「系统模型渠道」页面，点击「新建渠道」

- Given root 创建了公共渠道绑定上游模型
- When 团队成员使用 root 创建的系统模型发起调用
- Then 调用可正常走该公共渠道，无需成员自行配置渠道

### 5.4 兼容性
- Open API 存量调用方不受影响：请求可传 model 名字符串或 modelId（入站 schema 保留 legacy `@deprecated` 字段 + handler 读 `*ModelId ?? legacy` + getter 按名解析，不再依赖 HTTP middleware 重写——原"wrap 层"表述已废弃）
- 迁移后**所有可解析的存量引用**均补齐 canonical 字段；unresolved（无法解析的模型名）不写入 canonical、登记后按业务需要修复（与 additive 语义一致，见 MIG-TC04a/08b）
- **升级过程中系统可用（滚动升级）** — 兼容版新镜像通过「schema 双字段 + 缓存双 map + getters 兼容输入」在迁移前/中/后及回滚窗口内运行存量数据；即使存在配置写入也不要求冻结，运行流量（chat、workflow runtime、dataset search）不中断
