## 1. 模型数据获取方式重构（Lazy Load）

### 1.1 现状问题

前端通过 `init` 接口在应用启动时全量拉取模型数据并缓存在 `useSystemStore` 中（`defaultModels`、`getModelProviders` 等），随着模型数量增长，全量加载导致首屏性能下降，且模型变更需要刷新页面才能生效。

### 1.2 重构方案

- **废弃 `init` 接口中的模型缓存**：`clientInitData` 不再包含 `systemModels` 字段
- **按需请求**：各组件（模型选择器、模型配置表等）通过分页接口按需获取模型列表
- **分页加载**：模型列表页面默认每页 20 条，支持翻页、搜索、过滤
- **模型选择器**：通过 `search` + `type` + `isActive='active'` 参数过滤，支持下拉滚动加载更多
- **详情按需获取**：模型详情通过 `GET /api/core/ai/model/detail?id=xxx` 按需加载
- **Provider 列表保留在 init 中**：`ModelProviderListCache` 数据量小且不常变，保留在 store 中

### 1.3 变更对比

| 场景 | 旧方案 | 新方案 |
|------|--------|--------|
| 应用启动 | `init` 接口全量加载模型列表到 store | 仅加载 providers 列表，模型按需请求 |
| 模型选择器 | 从 store 读取全量模型，前端过滤 | 调 `list` 接口（带 type/isActive 过滤），支持搜索 |
| 模型配置表 | 从 store 读取全量模型，前端分页过滤 | 调 `list` 接口（带分页参数 + 搜索过滤） |
| 模型详情 | 从 store 查找 | 调 `detail` 接口按 modelId 获取 |
| 默认模型 | 从 store 的 `defaultModels` 读取 | 调 `GET /api/core/ai/model/getSystemDefault` 获取 |
| 模型模板 | `getDefaultConfig` 接口 | 调 `GET /api/core/ai/model/templates` 获取 |

## 2. 模型选择器（AIModelSelector）重构

### 2.1 基于分页接口的新逻辑

```typescript
// 模型选择器核心逻辑（重构后）
function AIModelSelector({ 
  type,           // 模型类型：'llm' | 'embedding' | 'tts' | 'stt' | 'rerank'
  value,          // modelId: string (ObjectId)
  onChange,       // (modelId: string, modelData: ModelListItem) => void
  disabled,       // 无权限时禁用（需求 F1）
  disabledTip     // 禁用时的 tooltip 文案
}: Props) {
  // 1. 首次加载：请求第一页（仅启用的指定类型模型）
  const { data, isLoading, fetchNextPage, hasMore, refresh } = useRequest({
    api: getSystemModelList,
    params: { type, isActive: 'active', pageSize: 20, pageNum: 1 }
  });

  // 2. 搜索：debounce 300ms 后请求
  const handleSearch = useDebounceCallback((search: string) => {
    refresh({ type, isActive: 'active', search, pageSize: 20, pageNum: 1 });
  }, 300);

  // 3. 滚动加载更多（分页）
  const handleLoadMore = () => {
    if (hasMore) {
      fetchNextPage();  // pageNum + 1
    }
  };

  // 4. 选中项回显处理：如果 value 对应的模型不在当前已加载列表中，需单独 fetch
  const { data: selectedModel } = useRequest({
    api: getSystemModelDetail,
    params: { id: value },
    // 仅当 value 存在且不在已加载列表中时才请求
    ready: !!value && !data?.list.find(m => m.id === value)
  });

  return (
    <Select
      value={value}           // modelId: string
      options={data?.list}    // ModelListItem[]
      optionLabel="name"       // 显示名称
      optionValue="id"         // 值为 modelId
      onSearch={handleSearch}
      onScrollToBottom={handleLoadMore}
      disabled={disabled}
      disabledTip={disabledTip}
    />
  );
}
```

### 2.2 关键变更点

- **value 从 `model` 名字符串改为 `modelId` 字符串**：所有表单提交和工作流参数传递均使用 ObjectId
- **搜索支持按 `modelId` / `model` / `name` 模糊匹配**：后端 `list` 接口统一处理
- **不再从 store 读取**：每次打开下拉框触发分页请求
- **`isActive='active'` 确保仅展示已启用的模型**：模型选择器必须传此参数，否则会展示已停用的系统模型
- **分页下拉滚动加载**：避免一次性加载大量数据，滚动到下拉框底部自动加载下一页
- **选中项回显**：当 value 对应的模型不在已加载列表首页时，通过 `detail` 接口单独获取并展示
- **禁用态**（需求 F1）：无权限时 `disabled=true`，hover 提示「暂无权限，请先联系管理员获取权限」

### 2.3 各场景使用方式

```typescript

  type="llm"
  value={formData.llmModelId}

// 工作流节点 — AI 对话节点的模型选择
```

## 3. 默认模型获取逻辑变更

### 3.1 现状

前端从 `clientInitData.defaultModels` 或 `useSystemStore().defaultModels` 读取默认模型配置。

### 3.2 重构方案

**系统默认模型通过独立 API 获取**：`GET /api/core/ai/model/getSystemDefault`

1. **创建资源时获取默认模型**：
   ```typescript
   const defaults = await fetch('/api/core/ai/model/getSystemDefault').then(r => r.json());
   // 返回：{ llm: { id, model, name }, embedding: { id, model, name }, ... }
   ```

2. **模型选择器中的默认选中**：
   ```typescript
   const [{ list }, defaults] = await Promise.all([
     getSystemModelList({ type: 'llm', isActive: 'active', pageSize: 20 }),
     getSystemDefault()
   ]);
   // 优先使用系统默认，fallback 到首个启用系统模型
   const defaultModelId = defaults.llm?.id ?? list.find(m => m.isSystem)?.id ?? list[0]?.id;
   ```

3. **回退策略**：`getSystemDefault` 返回的默认模型由服务端 `loadDefaultModels()` 解析（显式配置 → 首个启用的同类型系统模型 → null），前端在模型选择器中根据 `defaultValue` 自动选中。

### 3.3 默认模型变更后的联动处理

当 root 在「系统默认模型配置」中修改默认模型后：
- 前端重新调用 `getSystemDefault` 获取最新配置
- 已创建的应用/知识库不受影响（它们存储的是具体 modelId）
- 新建资源时自动使用新的默认模型

## 5. 页面结构与路由设计

### 5.1 工作台端页面结构

> **实现修订（经评审确认）**：五个页面合并为单一路由 `/account/model`，以 Tab 切换（`projects/app/src/pages/account/model/index.tsx`），功能与拆分页面等价。

```
工作台端（普通用户 + root）
│
└── 模型管理
    └── 路径: /account/model（单页面 + 5 个 Tab）
    ├── 可用模型 Tab
    │   └── 功能: 浏览所有可访问的模型（系统 + 自己 + 授权），查看渠道
    │   └── 特征: 只读视角，不可编辑/删除，展示模型名/ID 切换（root 展示全部，成员展示可访问）

    │   └── 特征: 
    │       - root 视角：展示 tab「系统模型」「团队模型」
    │       - 成员视角：仅展示自己的模型 + 授权的模型（只读）
    │       - 排序：启用在前 → provider 字母序

    │   └── 功能: 渠道 CRUD（创建/编辑/删除）
    │   └── 特征:
    │       - root 视角：展示 tab「公共渠道」「团队渠道」，团队渠道仅展示 root 自有渠道
    │       - 成员视角：仅展示自己的渠道
    ├── 调用日志 Tab
    │   └── 功能: 查看可访问模型的调用日志
    │   └── 特征: 模型下拉 lazy load，创建人列，按创建人搜索
    └── 监控 Tab
        └── 功能: 可访问模型的监控数据
```

```typescript
// 通用二次确认弹窗
interface ConfirmInputProps {
  title: string;                    // 弹窗标题
  message: string;                  // 警告文案
  detail?: string;                  // 受影响资源的详细列表
  confirmPlaceholder: string;       // 输入框 placeholder
  confirmValue: string;             // 需要匹配的确认值
  onConfirm: () => void | Promise<void>;
}

function ConfirmInput({ title, message, detail, confirmPlaceholder, confirmValue, onConfirm }: ConfirmInputProps) {
  const [inputValue, setInputValue] = useState('');
  const [loading, setLoading] = useState(false);

  const canConfirm = inputValue === confirmValue;

  const handleConfirm = async () => {
    if (!canConfirm) return;
    setLoading(true);
    try {
      await onConfirm();
    } finally {
      setLoading(false);
    }
  };

  return (
    <Modal
      title={title}
      open={visible}
      onOk={handleConfirm}
      confirmLoading={loading}
      okButtonProps={{ disabled: !canConfirm, danger: true }}
      okText="确认"
      cancelText="取消"
    >
      <Alert type="warning" message={message} />
      {detail && (
        <div className="confirm-detail">
          <p>受影响的资源：</p>
          <div className="detail-list">{detail}</div>
        </div>
      )}
      <div className="confirm-input-area">
        <p>请输入 <strong>{confirmValue}</strong> 确认操作：</p>
        <Input
          value={inputValue}
          onChange={e => setInputValue(e.target.value)}
          placeholder={confirmPlaceholder}
        />
      </div>
    </Modal>
  );
}
```

### 16.3 错误处理

```typescript
// API 错误码映射
const MODEL_ERROR_MAP: Record<string, string> = {
  modelUnExist: '模型不存在，可能已被删除',
  unAuthModel: '无权访问该模型',
  canNotEditAdminPermission: '不能修改管理员的模型权限',
  invalidModelId: '无效的模型 ID',
  invalidModelConfig: '无效的模型配置',
  modelNameConflict: '模型别名已存在，请更换其他别名',   // 需求 F2-S1 异常场景1
  systemModelReadonly: '系统模型仅可读取',
  noFieldsToUpdate: '没有可更新的字段'
};

// 全局请求拦截
function handleModelError(error: ApiError) {
  const msg = MODEL_ERROR_MAP[error.code] || error.message;
  
  switch (error.code) {
    case 'modelNameConflict':
      // 表单字段级错误：在模型名输入框下方显示
      form.setFields([{ name: 'name', errors: [msg] }]);
      break;
    case 'unAuthModel':
      // 权限不足：跳回列表页或展示 403
      message.error(msg);
      router.replace('/account/model');
      break;
    case 'modelUnExist':
      // 模型被删除：刷新列表
      message.warning(msg);
      refreshList();
      break;
    default:
      message.error(msg);
  }
}
```
