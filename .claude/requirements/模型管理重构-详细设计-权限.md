# 模型管理重构 — 详细设计：权限

> 基于主设计文档第 2.6 节展开。遵循项目现有权限规范（`authApp`/`authDataset` 模式），定义模型权限鉴权体系、协作者管理及 API 端点权限要求。

## 1. 权限体系

### 1.1 现有基础设施

`PerResourceTypeEnum.model` 已在 `packages/global/support/permission/constant.ts:52` 定义。`ModelPermission` 已在 `packages/global/support/permission/model/controller.ts` 声明：

```typescript
// packages/global/support/permission/model/controller.ts
import { Permission } from '../controller';
export class ModelPermission extends Permission {}
```

权限数据存储在 `MongoResourcePermission`，通过 `getTmbPermission()` 查询（先查个人权限，再聚合 group/org 权限），位掩码按 `CommonPerList`（read=0b100, write=0b010, manage=0b001）计算。

**重构变更**：现有的 `getMyModels({ teamId, tmbId, isTeamOwner })` 函数（返回 `string[]` — model 名字符串数组）被 `getUserAccessibleModels({ teamId, tmbId, tmbPer })`（返回 `SystemModelItemType[]` — 完整模型对象数组）替代。原因：(1) 模型列表需要返回完整对象而非仅 model 名字符串；(2) 权限判断需要完整的 `tmbPer` 对象而非 `isTeamOwner` boolean；(3) 重构后 model 名不再唯一，无法仅凭名字符串区分模型。

**MongoResourcePermission 文档结构**（重构后）：

```typescript
{
  _id: ObjectId,
  teamId: ObjectId,
  resourceType: 'model',                        // PerResourceTypeEnum.model
  resourceId: '68ad85a7463006c963799a05',       // model._id.toString()
  resourceName: 'gpt-4o',                       // 保留展示用（provider model 名）
  tmbId?: ObjectId,                             // 协作者 tmbId（个人权限）
  groupId?: ObjectId,                           // 协作者 groupId（组权限）
  orgId?: ObjectId,                             // 协作者 orgId（组织权限）
  permission: 0b110                             // Read + Write 位掩码
}
```

### 1.2 `getModelPermission` — 核心权限计算

**文件**: `packages/service/support/permission/model/auth.ts`（新建）

遵循 `authAppByTmbId` 内部权限计算模式，计算用户对单个模型的有效权限：

```typescript
import { ModelPermission } from '@fastgpt/global/support/permission/model/controller';
import {
  PerResourceTypeEnum,
  ReadRoleVal
} from '@fastgpt/global/support/permission/constant';
import { getTmbPermission } from '../controller';
import type { SystemModelItemType } from '../../../core/ai/type';
import type { TeamMemberWithTeamPermission } from '../../user/team/type';

export const getModelPermission = async ({
  model,
  teamId,
  tmbId,
  isRoot,
  tmbPer
}: {
  model: SystemModelItemType;
  teamId: string;
  tmbId: string;
  isRoot?: boolean;
  tmbPer: TeamMemberWithTeamPermission['permission'];
}): Promise<ModelPermission> => {
  // root 拥有全部权限
  if (isRoot) {
    return new ModelPermission({ isOwner: true });
  }

  // 系统模型：全平台可读，不可写/管理
  if (model.isSystem) {
    return new ModelPermission({ role: ReadRoleVal });
  }

  // 仅创建者拥有全部权限（用户裁决 2026-08：团队 owner 对他人私有模型无管理权，
  // root 通过 Pro Admin 查看/管理全平台模型；可见性由 getUserAccessibleModels 控制）
  // 注意：系统模型不维护 tmbId/teamId，因此 model.tmbId 为 undefined 时跳过此检查
  const isOwner = model.tmbId !== undefined && String(model.tmbId) === tmbId;
  if (isOwner) {
    return new ModelPermission({ isOwner: true });
  }

  // 非本团队模型不可访问（系统模型已在上面返回 ReadRoleVal，不会到达此处）
  if (model.teamId !== undefined && String(model.teamId) !== teamId) {
    return new ModelPermission({ role: 0 });
  }

  // 查询协作者权限（MongoResourcePermission）
  const myPer = await getTmbPermission({
    teamId,
    tmbId,
    resourceType: PerResourceTypeEnum.model,
    resourceId: model.id
  });

  // 未配置权限的同团队模型 → 无权限（仅创建者可见）
  return new ModelPermission({ role: myPer ?? 0 });
};
```

### 1.3 权限决策流程

```
getModelPermission(model, teamId, tmbId, isRoot, tmbPer)
├── isRoot?                         → ModelPermission({ isOwner: true })
├── model.isSystem?                 → ModelPermission({ role: ReadRoleVal })
├── tmbPer.isOwner OR model.tmbId === tmbId? → ModelPermission({ isOwner: true })
├── model.teamId !== teamId?        → ModelPermission({ role: 0 })         ← 无权限
└── getTmbPermission(...)           → ModelPermission({ role: myPer ?? 0 })
                                        ↑ 未配置 → 无权限（仅创建者可见）
```

## 1.4 模型创建权限（团队级开关）

### 概述

`TeamModelCreatePermissionVal` 是新增的团队级权限值，对应需求 **F1「允许成员创建模型」** 开关。团队 Owner/Admin 可在团队设置中控制是否允许普通成员创建私有模型。

与 `WritePermissionVal`（对象级写权限）不同，`TeamModelCreatePermissionVal` 是**团队级**权限 — 它不针对任何具体模型资源，而是控制成员在团队内创建新模型的能力。

### 实现方案

**便捷常量**（`packages/global/support/permission/user/constant.ts`，遵循 TeamAppCreatePermissionVal / TeamAppCreateRoleVal 模式）：

```typescript
export const TeamModelCreatePermissionVal = TeamPerList.modelCreate;
export const TeamModelCreateRoleVal = TeamRoleList['modelCreate'].value;
```

> **设计决策**：使用 `0b10000000`（bit 7），避免与现有权限位冲突。现有 `TeamPerList` 已占用 bit 0-6（read=0b100, write=0b010, manage=0b001, appCreate=0b001000, datasetCreate=0b010000, apikeyCreate=0b100000, skillCreate=0b1000000）。

**在 `TeamPerList` 中注册**（`packages/global/support/permission/user/constant.ts`）：

```typescript
// TeamPerKeyEnum 新增：

  // ... existing ...
  modelCreate = 'modelCreate'
}

// TeamPerList 新增（bit 7 = 128，不与现有 bit 0-6 冲突）：
export const TeamPerList: PermissionListType<TeamPerKeyEnum> = {
  ...CommonPerList,
  apikeyCreate: 0b100000,     // 32
  appCreate: 0b001000,         // 8
  datasetCreate: 0b010000,     // 16
  skillCreate: 0b1000000,      // 64
  modelCreate: 0b10000000      // 128  [新增]

// TeamRoleList 新增（TeamModelCreatePermissionVal 引用 TeamPerList.modelCreate）：

    description: '',

// TeamRolePerMap 新增映射（modelCreate 角色含 modelCreate + read + write）：

    TeamRoleList['modelCreate'].value,

  ]

### API 使用场景

> ⚠️ **用户裁决（2026-08）**：系统模型是**全局资源、不从属任何人**——不维护
> tmbId/teamId；**仅 root** 可创建/删除/更新其配置（`create` 内部设 `isSystem: true`、
> `update`/`delete` 经 `authModel` + `systemModelReadonly` 检查保证非 root 不可写；
> root 也无法经 update 变更归属，归属变更走删除重建）。实现与裁决一致，无代码改动。

| 端点 | 鉴权 | 说明 |
|------|------|------|
| `create.ts` | `authUserPer(per=TeamModelCreatePermissionVal)` | 成员需团队开启「允许成员创建模型」；root 可创建系统模型（内部设 `isSystem: true`） |

`update` / `delete` 端点使用 `authModel`（对象级鉴权），不依赖 `TeamModelCreatePermissionVal` — 因为模型已存在，权限由模型创建者和协作者体系控制。

### 与现有权限体系的关系

```
团队级权限（TeamPermission）
├── isOwner                    → 团队 Owner（对团队资源的管理权；模型对象权限见下）
├── hasModelCreatePer          → [新增] 是否允许创建模型（F1 开关）
├── hasWritePer                → 是否有团队写权限
├── ...

对象级权限（ModelPermission）
├── isOwner                    → 仅模型创建者（用户裁决 2026-08：团队 Owner 对他人私有模型
│                                 无 owner 权——列表不可见、凭 modelId 直接操作也被拒绝，
│                                 root 全平台视图走 Pro Admin，见 §9）
├── authModel(per=Read)        → 读某个具体模型
├── authModel(per=Write)       → 写某个具体模型
├── authModel(per=Manage)      → 管理某个具体模型（协作者）
└── ...
```

## 2. 鉴权函数

### 2.1 `authModelByTmbId` — 单模型鉴权

**文件**: `packages/service/support/permission/model/auth.ts`

```typescript
import { ModelErrEnum } from '@fastgpt/global/common/error/code/model';
import { ERROR_ENUM } from '@fastgpt/global/common/error/errorCode';
import { ReadPermissionVal } from '@fastgpt/global/support/permission/constant';
import type { PermissionValueType } from '@fastgpt/global/support/permission/type';
import { getTmbInfoByTmbId } from '../../user/team/controller';
import { getModelById } from '../../../core/ai/model';

export const authModelByTmbId = async ({
  tmbId,
  modelId,
  per,
  isRoot,
  resourceContext
}: {
  tmbId: string;
  modelId: string;
  per: PermissionValueType;
  isRoot?: boolean;
  resourceContext?: { appId: string } | { datasetId: string };
}): Promise<{
  model: SystemModelItemType & {
    permission: ModelPermission;
  };
}> => {
  const tmb = await getTmbInfoByTmbId({ tmbId });
  const model = getModelById(modelId);

  if (!model) {
    return Promise.reject(ModelErrEnum.unExist);
  }

  // 通过资源上下文（app/dataset）绕过直接权限检查
  if (resourceContext) {
    const canBypass = await checkModelAccessThroughResource({
      modelId,
      teamId: tmb.teamId,
      tmbId,
      isRoot,
      resourceContext
    });
    if (canBypass) {
      return {
        model: {
          ...model,
          permission: new ModelPermission({ isOwner: false, role: ReadPermissionVal })
        }
      };
    }
  }

  const permission = await getModelPermission({
    model,
    teamId: tmb.teamId,
    tmbId,
    isRoot,
    tmbPer: tmb.permission
  });

  if (!permission.checkPer(per)) {
    return Promise.reject(ModelErrEnum.unAuthModel);
  }

  return {
    model: {
      ...model,
      permission
    }
  };
};

// 注：authModelByTmbId 中，若 model.isSystem && !isRoot && per > ReadPermissionVal，
// getModelPermission 返回 ReadRoleVal → checkPer(per) 失败 → 抛出 ModelErrEnum.unAuthModel。
// 如需区分「系统模型只读」错误提示，可在 checkPer 前增加显式检查：
//   if (model.isSystem && !isRoot && (per & WritePermissionVal)) {
//     return Promise.reject(ModelErrEnum.systemModelReadonly);
//   }
// 当前版本暂不区分，使用统一的 unAuthModel 错误码。
```

### 2.2 `checkModelAccessThroughResource` — 资源上下文绕过

当模型已在 app/dataset 中被引用且用户有该资源的读权限时，无需直接权限即可使用模型：

```typescript
const checkModelAccessThroughResource = async ({
  modelId,
  teamId,
  tmbId,
  isRoot,
  resourceContext
}: {
  modelId: string;
  teamId: string;
  tmbId: string;
  isRoot?: boolean;
  resourceContext: { appId: string } | { datasetId: string };
}): Promise<boolean> => {
  try {
    if ('appId' in resourceContext) {
      const app = await MongoApp.findById(
        resourceContext.appId,
        'modules chatConfig tmbId teamId'
      ).lean();
      if (!app) return false;

      const existingModelIds = extractWorkflowModelIds({
        modules: app.modules,
        chatConfig: app.chatConfig
      });
      if (!existingModelIds.includes(modelId)) return false;

      await authAppByTmbId({
        tmbId,
        appId: resourceContext.appId,
        per: ReadPermissionVal,
        isRoot
      });
      return true;
    }

    if ('datasetId' in resourceContext) {
      const dataset = await MongoDataset.findById(
        resourceContext.datasetId,
        'vectorModelId agentModelId vlmModelId tmbId teamId'
      ).lean();
      if (!dataset) return false;

      const existingModelIds = [
        dataset.vectorModelId,
        dataset.agentModelId,
        dataset.vlmModelId
      ].filter((id): id is string => typeof id === 'string' && !!id);

      if (!existingModelIds.includes(modelId)) return false;

      await authDatasetByTmbId({
        tmbId,
        datasetId: resourceContext.datasetId,
        per: ReadPermissionVal,
        isRoot
      });
      return true;
    }

    return false;
  } catch {
    return false;
  }
};
```

### 2.3 `authModel` — 带 Header 解析的单模型鉴权

```typescript
export const authModel = async ({
  modelId,
  per,
  resourceContext,
  ...props
}: AuthModeType & {
  modelId: string;
  per: PermissionValueType;
  resourceContext?: { appId: string } | { datasetId: string };
}): Promise<
  AuthResponseType<ModelPermission> & {
    model: SystemModelItemType & {
      permission: ModelPermission;
    };
  }
> => {
  const result = await parseHeaderCert(props);

  if (!modelId) {
    return Promise.reject(ModelErrEnum.invalidModelId);
  }

  const { model } = await authModelByTmbId({
    tmbId: result.tmbId,
    modelId,
    per,
    isRoot: result.isRoot,
    resourceContext
  });

  return {
    ...result,
    permission: model.permission,
    model
  };
};
```

### 2.4 `authModels` — 批量模型鉴权

用于 workflow 节点执行、知识库同步等多模型同时校验场景。

**辅助函数**：

```typescript
/** 展开、去重、过滤空值的 modelId 列表 */
export const normalizeModelIds = (
  modelIds?: string | Array<string | undefined | null>
): string[] => {
  const list = Array.isArray(modelIds) ? modelIds : [modelIds];
  return [...new Set(list.filter((id): id is string => typeof id === 'string' && !!id))];
};
```

```typescript
export const authModels = async ({
  modelIds,
  per = ReadPermissionVal,
  resourceContext,
  ...props
}: AuthModeType & {
  modelIds?: string | Array<string | undefined | null>;
  per?: PermissionValueType;
  resourceContext?: { appId: string } | { datasetId: string };
}): Promise<
  AuthResponseType<ModelPermission> & {
    models: (SystemModelItemType & {
      permission: ModelPermission;
    })[];
  }
> => {
  const result = await parseHeaderCert(props);
  const ids = normalizeModelIds(modelIds);

  if (ids.length === 0) {
    return {
      ...result,
      permission: new ModelPermission(),
      models: []
    };
  }

  const models = ids.map((id) => getModelById(id));

  if (models.some((model) => !model)) {
    return Promise.reject(ModelErrEnum.unExist);
  }

  const tmb = await getTmbInfoByTmbId({ tmbId: result.tmbId });
  const modelsWithPermission = await Promise.all(
    (models as SystemModelItemType[]).map(async (model) => {
      if (resourceContext) {
        const canBypass = await checkModelAccessThroughResource({
          modelId: model.id,
          teamId: tmb.teamId,
          tmbId: result.tmbId,
          isRoot: result.isRoot,
          resourceContext
        });
        if (canBypass) {
          return {
            ...model,
            permission: new ModelPermission({ isOwner: false, role: ReadPermissionVal })
          };
        }
      }

      const permission = await getModelPermission({
        model,
        teamId: tmb.teamId,
        tmbId: result.tmbId,
        isRoot: result.isRoot,
        tmbPer: tmb.permission
      });

      if (!permission.checkPer(per)) {
        return Promise.reject(ModelErrEnum.unAuthModel);
      }

      return {
        ...model,
        permission
      };
    })
  );

  return {
    ...result,
    permission: modelsWithPermission[0]?.permission ?? new ModelPermission(),
    models: modelsWithPermission
  };
};
```

## 3. 协作者管理

### 3.1 现有实现

### 3.2 重构后变更

不移动 API 路径，直接修改 `pro/admin` 下的实现文件。核心变更：

- **以 `modelId` 替代 `model` 名字符串**：`MongoResourcePermission.resourceId` 存储 `modelId`（`_id.toString()`）
- **鉴权从 `authUserPer` 升级为 `authModel`**：通过模型鉴权中间件统一校验
- **审计日志**：添加 `AuditEventEnum.UPDATE_MODEL_COLLABORATOR` / `DELETE_MODEL_COLLABORATOR` 审计事件
- **维持硬编码 `ReadRoleVal`**：现有 `update.ts` 将所有协作者权限硬编码为 `ReadRoleVal`（只读），重构后保持此行为不变。协作者只能被授予只读权限，不可授予 write/manage 等更高权限。

### 3.4 update.ts 实现

**文件**: `pro/admin/src/pages/api/system/model/collaborator/update.ts`

> ⚠️ **实现修订（经评审确认，2026-08）**：以下要点与实现一致——
> - `modelIds` 规范化：`[...new Set((modelIds || []).filter(Boolean))]`，空集时拒绝 `CommonErrEnum.missingParams`（避免唯一索引 `resourceType+teamId+resourceId+tmbId` 重复键 500）
> - **创建者行保留**：deleteMany 清空后，`effectiveClbs` 将创建者（私有模型的 `tmbId` 持有者）以 `OwnerRoleVal` 重新写回；协作者一律 `ReadRoleVal`。与 app/dataset 的协作者管理语义一致
> - **权限归一化防提权**：insertMany 时按行判断——仅创建者本人行保留 `OwnerRoleVal`，其余（即使请求恶意传入 `OwnerRoleVal`）一律压为 `ReadRoleVal`

```typescript
async function handler(req, res) {
  const { collaborators = [], modelIds } = req.body;
  // 规范化 + 去重（design §3.4）：空集拒绝 missingParams
  const ids = [...new Set((modelIds || []).filter((id): id is string => !!id))];
  if (ids.length === 0) {
    return Promise.reject(CommonErrEnum.missingParams);
  }

  // 对每个 modelId 进行 authModel 鉴权
  const authedModels = await Promise.all(
    ids.map((modelId) =>
      authModel({ modelId, per: ManagePermissionVal, req, authToken: true })
    )
  );
  const { teamId } = authedModels[0];

  // 协作者变更：前端做二次确认，后端直接执行
  // （需求 F3-S3 场景3：移除协作者时前端提示影响并填写模型名确认）

  // 创建者行保留：私有模型创建者恒为 OwnerRoleVal；协作者只读
  const effectiveClbs = (modelData: Pick<SystemModelItemType, 'id' | 'tmbId' | 'isSystem'>) => {
    const ownerTmbId = !modelData.isSystem && modelData.tmbId ? String(modelData.tmbId) : undefined;
    const list = collaborators.filter(
      (clb) => !(ownerTmbId && clb.tmbId && String(clb.tmbId) === ownerTmbId)
    );
    if (ownerTmbId) {
      list.push({ tmbId: ownerTmbId, permission: OwnerRoleVal });
    }
    return list;
  };

  await mongoSessionRun(async (session) => {
    await MongoResourcePermission.deleteMany({
      resourceType: PerResourceTypeEnum.model,
      teamId,
      resourceId: { $in: ids }
    }).session(session);

    await MongoResourcePermission.insertMany(
      authedModels
        .map(({ modelData }) => {
          const ownerTmbId =
            !modelData.isSystem && modelData.tmbId ? String(modelData.tmbId) : undefined;
          return effectiveClbs(modelData).map((clb) => ({
            ...clb,
            teamId,
            resourceId: modelData.id,
            resourceType: PerResourceTypeEnum.model,
            // 协作者硬编码只读；仅创建者本人行保留 OwnerRoleVal（防提权）
            permission:
              ownerTmbId && clb.tmbId && String(clb.tmbId) === ownerTmbId
                ? OwnerRoleVal
                : ReadRoleVal
          }));
        })
        .flat(),
      { session }
    );
  });

  // 审计日志
  // ...

  // 刷新权限缓存
  await refreshVersionKey(SystemCacheKeyEnum.modelPermission, teamId);

  return {};
}
```

**核心设计要点**：
- **前端二次确认** — 移除协作者时前端提示影响并填写模型名确认，后端直接执行（需求 F3-S3 场景3）
- **维持 `ReadRoleVal`** — 协作者权限硬编码为只读，与现有行为一致
- **创建者 OwnerRoleVal 保留** — 私有模型创建者权限行恒存在（清空协作者后仅剩创建者行）
- **`replaceResourceClbs`** — 原子替换协作者列表（deleteMany + insertMany in session）
- 权限变更后通过 `refreshVersionKey` 刷新缓存

## 4. 模型列表可见性

**文件**: `packages/service/support/permission/model/controller.ts`

```typescript
export const getUserAccessibleModels = async ({
  teamId, tmbId, tmbPer
}: {
  teamId: string; tmbId: string;
  tmbPer: TeamMemberWithTeamPermission['permission'];
}): Promise<SystemModelItemType[]> => {
  // 1. 自己创建的模型 — 始终可见（无论 isSystem、isActive）
  //    注意：系统模型（isSystem: true）不存储 tmbId，因此仅私有模型通过 tmbId 匹配
  const ownModels = global.systemModelList.filter(m =>
    !m.isSystem && String(m.tmbId) === tmbId
  );

  // 2. 非自己创建的模型 — 需要可见性检查
  const otherModels = global.systemModelList.filter(m =>
    m.isSystem || String(m.tmbId) !== tmbId
  );

  // 查询当前团队下的模型权限配置
  const rps = await MongoResourcePermission.find({
    teamId,
    resourceType: PerResourceTypeEnum.model
  }).lean();

  const myGroups = await getGroupsByTmbId({ teamId, tmbId });
  const myOrgs = await getOrgsByTmbId({ teamId, tmbId });
  const myIdSet = new Set([
    tmbId,
    ...myGroups.map(g => String(g._id)),
    ...myOrgs.map(o => String(o._id))
  ]);

  const permissionConfiguredIds = new Set(rps.map(rp => String(rp.resourceId)));
  const myPermissionIds = new Set(
    rps.filter(rp => myIdSet.has(getCollaboratorId(rp))).map(rp => String(rp.resourceId))
  );

  const accessibleModels = otherModels.filter(m => {
    // 注意：此处不检查 isActive — 系统模型全平台可见包含已停用模型。
    // 模型选择器（picker）应由 list API 通过 isActive='active' 过滤已停用模型。
    if (m.isSystem) return true;                          // 系统模型全平台可见
    if (String(m.teamId) !== String(teamId)) return false; // 非本团队不可见
    // 同团队模型：已配置权限 → 必须在授权列表；未配置 → 不可见（仅创建者可见）
    return myPermissionIds.has(m.id);
  });

  return [...ownModels, ...accessibleModels];
};
```

| 模型来源 | 条件 | 是否可见 |
|---------|------|---------|
| 系统模型 | `isSystem === true`（不存储 tmbId/teamId） | 全平台可见 |
| 自己创建的 | `tmbId === 当前用户`（仅私有模型） | 始终可见（含禁用） |
| 同团队模型 | 已配置 + 用户在授权列表中 | 可见 |
| 同团队模型 | 未配置权限 | 不可见（仅创建者可见） |
| 同团队模型 | 已配置 + 用户不在授权列表中 | 不可见 |
| 其他团队模型 | `teamId` 不匹配 | 不可见 |

## 5. `authModels` 批量鉴权入口

### 5.2 `extractWorkflowModelIds` 工具函数

**文件**: `packages/global/core/workflow/utils.ts`（新建或扩展）

```typescript
/** 从 workflow modules 和 chatConfig 中提取所有 modelId */
export function extractWorkflowModelIds({
  modules = [],
  chatConfig
}: {
  modules?: any[];
  chatConfig?: any;
}): string[] {
  const ids = new Set<string>();

  for (const mod of modules) {
    for (const input of mod.inputs || []) {
      if (input.key === 'modelId' && typeof input.value === 'string') {
        ids.add(input.value);
      }
      if (input.key === 'rerankModelId' && typeof input.value === 'string') {
        ids.add(input.value);
      }
      if (input.key === 'datasetSearchExtensionModelId' && typeof input.value === 'string') {
        ids.add(input.value);
      }
      if (input.key === 'datasetDeepSearchModelId' && typeof input.value === 'string') {
        ids.add(input.value);
      }
      // datasetParams 复合对象中的模型字段
      if (input.key === 'datasetParams' && typeof input.value === 'object') {
        for (const field of ['embeddingModelId', 'rerankModelId', 'datasetSearchExtensionModelId', 'datasetDeepSearchModelId']) {
          if (typeof input.value[field] === 'string') ids.add(input.value[field]);
        }
      }
    }
  }

  if (chatConfig?.questionGuide?.modelId) ids.add(chatConfig.questionGuide.modelId);
  if (chatConfig?.ttsConfig?.modelId) ids.add(chatConfig.ttsConfig.modelId);

  return [...ids];
}
```

## 6. `getUserAccessibleModels` 性能优化

> **待独立设计方案确认。**

当前设计的性能瓶颈：

1. **每次调用都查 DB**：`getUserAccessibleModels` 每次执行都需要查询 `MongoResourcePermission`、`getGroupsByTmbId`、`getOrgsByTmbId`，在高频调用场景（如模型列表分页）下开销大
2. **全量模型遍历**：`global.systemModelList` 全量遍历 + 逐条过滤，模型数量大时 O(n) 开销

优化方向（待确认）：

- **方案 A：内存缓存 + 版本号刷新** — 构建 `Map<teamId, Map<tmbId, Set<modelId>>>` 的权限缓存，通过 `SystemCacheKeyEnum.modelPermission` 版本号触发刷新
- **方案 B：预计算位图** — 在 `loadSystemModels` 时预计算每个团队成员的可见模型集合，写入 `global.teamMemberAccessibleModelIds: Map<teamId, Map<tmbId, Set<modelId>>>`
- **方案 C：仅缓存权限配置** — 缓存 `MongoResourcePermission` 查询结果（按 teamId），用户组/组织成员关系仍实时查询

推荐方案 A，详细设计另文输出。

## 9. Pro Admin 模型管理权限

root 作为系统超管查看全平台所有模型的权限通过 **Pro Admin 端点**实现，与 FastGPT 的 `authModel` 体系分离。

### 9.1 鉴权机制

Pro Admin 端点使用 `adminCert`（`pro/admin/src/service/support/permission/adminCert.ts`），仅 `username === 'root'` 可访问。不经过 `authModel` / `authUserPer` 体系。

```typescript
// adminCert 实现（现有）
export const adminCert = async ({ req, authToken }: AdminCertProps) => {
  const { tmbId, teamId, user } = await parseHeaderCert({ req, authToken });
  if (user.username !== 'root') {
    return Promise.reject(ERROR_ENUM.unAuthorization);
  }
  return { tmbId, teamId, user, isRoot: true };
};
```

### 9.2 Pro Admin 端点权限矩阵

| 端点 | 鉴权 | 权限要求 | 数据范围 |
|------|------|---------|---------|
| `GET /api/admin/routes/models/getModels` | `adminCert` | `username === 'root'` | 全平台所有模型 |
| `GET /api/admin/routes/models/getChannels` | `adminCert` | `username === 'root'` | 全平台所有渠道 |
| `GET /api/admin/routes/models/getUsageLogs` | `adminCert` | `username === 'root'` | 全平台所有调用日志 |

### 9.3 与 FastGPT 模型鉴权的对比

| 维度 | FastGPT `authModel` | Pro Admin `adminCert` |
|------|---------------------|-----------------------|
| **入口** | `/api/core/ai/model/*` | `/api/admin/routes/models/*` |
| **鉴权逻辑** | `getModelPermission()` → 按 isSystem/teamId/tmbId 分级 | 仅检查 `username === 'root'` |
| **团队隔离** | 是（非本团队模型不可见） | 否（全平台可见） |
| **数据查询** | 从内存 Map（`global.llmModelIdMap` 等） | 直接从 MongoDB（`readFromSecondary`） |
| **返回信息** | 模型配置 + 当前用户 permission | 模型配置 + 团队名称 + 创建人名称 |
| **操作权限** | 按角色分 read/write/manage | 只读 |

> Pro Admin 端点的完整实现设计见 [模型管理重构-详细设计-API设计 §10](./模型管理重构-详细设计-API设计.md#10-pro-admin-模型管理-api)。
