private usagePush(usages: ChatNodeUsageType[]) {
  if (this.isRootRuntime) {
    if (this.data.usageId) {
      pushChatItemUsage({
        teamId: this.data.runningUserInfo.teamId,
        usageId: this.data.usageId,
        nodeUsages: usages   // ChatNodeUsageType[] → 每个 item 含 model?: string

}

## 4. 计费价格查询链路

### 4.1 formatModelChars2Points

**文件**: `packages/service/support/wallet/usage/utils.ts:5-35`

```typescript
export const formatModelChars2Points = ({
  model,        // string | SystemModelItemType
  inputTokens, outputTokens, multiple
}) => {
  const modelData = findAIModel(model);     // ← 当前用 findAIModel (遍历 5 个 Map)
  if (!modelData) return { totalPoints: 0, modelName: '' };

  const { totalPoints } = calculateModelPrice({
    config: modelData,
    inputTokens, outputTokens, multiple
  });

  return {
    modelName: modelData.name,   // ← 返回 modelData.name
    totalPoints
  };
};
```

**函数签名变更**:

```typescript
// 旧
formatModelChars2Points({ model: string | SystemModelItemType, ... })

// 新 — 直接接受 modelData 对象，消除二次查找
formatModelChars2Points({ modelData: SystemModelItemType, ... })
// → 返回 { modelName, totalPoints }（modelId 由调用方以 modelData.id 单独落库，见文件头修订说明）
```

> ⚠️ **实现修订（2026-08，见文件头）**：下方「推荐方案」示例为原稿形态；实际实现只返回 `{ modelName, totalPoints }`，`modelId` 由各调用方通过 `modelData.id` 单独写入 UsageItem —— 与上方「各节点示例」一致。

由于所有调用方在重构后都已经通过 `getLLMModel(modelId)` 拿到了完整的 `modelData` 对象，最佳方案是改为直接传入 `modelData` 对象，避免二次查找：

```typescript
// 推荐方案（实现形态）
export const formatModelChars2Points = ({
  modelData,     // SystemModelItemType — 直接传入已查找好的 modelData
  inputTokens, outputTokens, multiple
}) => {
  const { totalPoints } = calculateModelPrice({
    config: modelData,
    inputTokens, outputTokens, multiple
  });
  return {
    modelName: modelData.name,
    totalPoints
  };
};
```

## 9. 迁移风险提示

1. **`ChatNodeUsageType.model`** 在重构前后语义变化：
   - 重构前：存 `modelData.name` 或 `modelData.model`（不一致，有时是 name 有时是 OpenAI model 名）
   - 重构后：`model` 字段保持存 OpenAI model 名（provider 的 model 参数），新增 `modelId` 存 ObjectId
   
2. **`formatModelChars2Points`** 的改造是阻塞点 — 21 个调用点全部依赖它做计费换算，改为传 `modelData` 对象后调用方式变化但不影响计费逻辑。

3. **`createTrainingUsage`** 参数从 `vectorModel: string` 改为 `vectorModelId: string` 需要同步修改所有上游调用方（知识库训练流程）。

4. **用量查询历史数据**：迁移脚本执行前，历史 `UsageItem` 记录的 `model` 字段可能存的是 `name` 而非 `model`（因为不同调用点存的值不一致）。**已通过 `nameMap` fallback 解决**：迁移时先按 `modelMap`（provider model 名）匹配，未命中再按 `nameMap`（别名）匹配。如两个 map 均未命中，保留原值不变，需在迁移日志中记录供人工排查。
