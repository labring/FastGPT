Complete [your first request](/en/openapi/intro). The current interface supports JSON with `stream: false` and an event stream with `stream: true`.

## Conversation identity

Omitting `chatId` or passing an empty value generates a new conversation ID. The response `id` identifies the conversation. Reuse `chatId` with the same application for continued conversations and submit current input according to the message contract. Keep separate conversation identifiers and trusted identity mappings for each business user.

Access to an existing conversation checks team and conversation permissions. [Identity proxy](/en/openapi/identity-proxy) follows the same checks.

## Stream results

Change the first request to `"stream": true` and add curl's `--no-buffer`. After the stream opens, parse SSE frames containing `event:` and `data:`. Retain incomplete frames across network reads. Text fragments typically appear in `choices[0].delta.content`. Finish when `[DONE]` arrives.

Set `detail: true` to receive detailed events. The runtime defines the following 17 event types; the endpoint, runtime version, and application determine which are emitted. With `detail: false`, answer frames use the default SSE message event. Clients should tolerate unknown event types.

| Event Name | `data` Payload | Business Meaning and Processing |
|---|---|---|
| `answer` | `WorkflowAnswerChunk` or text `[DONE]` | Model text delta, thought delta, heartbeat, or stream completion |
| `fastAnswer` | `WorkflowAnswerChunk` | Direct text output from designated fast-answer nodes |
| `chatTitle` | `{ title: string }` | Suggested title generated for this conversation turn |
| `flowNodeStatus` | `{ status: 'running', name: string }` | Node execution started, used to highlight running UI nodes |
| `flowNodeResponse` | `ChatHistoryItemResType` | v2 single-node execution result tree with node latency and debug metadata |
| `flowResponses` | `ChatHistoryItemResType[]` | v1 array of node execution responses emitted before completion |
| `updateVariables` | `Record<string, any>` | Updated persistent workflow variables |
| `interactive` | `{ interactive: { type, params } }` | User-facing interaction configuration; execution state stays on the server |
| `workflowDuration` | `{ durationSeconds: number }` | Overall workflow execution duration in seconds |
| `toolCall` | `{ tool: ToolModuleResponseItemType }` | Agent tool call initialization with tool identity and schema |
| `toolParams` | `{ tool: { id: string, params: string } }` | Streamed parameter fragments for the tool call |
| `toolResponse` | `{ tool: { id: string, response: string } }` | Output string returned by the tool execution |
| `planStatus` | `{ planStatus: { status: 'generating' \| 'updating' } }` | Agent plan generation or status transition |
| `plan` | `{ plan: AgentPlanType }` | Full snapshot of current Agent plan steps and execution progress |
| `error` | `Record<string, any>` | Runtime error; mark the run as failed |
| `skillCall` | `{ skill: SkillModuleResponseItemType }` | Skill invocation notification, when emitted by the runtime |
| `sandboxStatus` | `SandboxStatusItemType` | Agent sandbox lifecycle status (provisioning, mount, upgrading) |

During generation, the server sends an empty answer chunk every 10 seconds as a heartbeat. Configure proxy buffering and idle timeouts accordingly. Errors and network failures may close the stream before `[DONE]`; track completion and failure separately.

### Interactive Node Suspension and Resumption

With `detail: true`, an interactive node returns display configuration containing `type` and `params`. Render the choice or form and retain the conversation's `chatId`.

Continue with a new request to the same application and `chatId`. For user selection, send the selected value as the user message content. For a form, JSON-serialize the input object into the user message content. The server restores the checkpoint from conversation history.

## Errors and retries

Before the event stream opens, inspect HTTP status, Content-Type, and JSON errors. After it opens, continue handling error events, final results, and network disconnections. In JSON mode, inspect `error` as well as the completeness of the business result.

Model calls and tools can incur charges or external effects. Check whether the previous run executed before retrying, particularly for write operations. Record application, conversation, time, and available request identifiers with credential-free error details.

## Verify

Use the same input to verify JSON and streaming outputs satisfy application rules. Test an invalid application ID and confirm the client displays a useful error. Interrupt a connection and confirm that the UI marks the result incomplete. Then connect [log observation](/en/guide/build/logs).

## System OpenAPI Endpoint Reference (Chat, Sessions, Records, and Feedback)

Aside from `/api/v1/chat/completions` and `/api/v2/chat/completions` (which also accept `Bearer <apiKey>-<appId>`), all session, record, and feedback endpoints require **`appId` to be passed explicitly** in the request body or query string.

### 1. Chat Generation and Execution Control (`chatController`)

| Method | Path | Summary | Key Request Fields |
| --- | --- | --- | --- |
| `POST` | `/api/v2/chat/completions` | Create a chat completion v2 (recommended, OpenAI-compatible) | Body: `appId`, `chatId`, `stream`, `detail`, `messages`, `variables`, `responseChatItemId` |
| `POST` | `/api/v1/chat/completions` | Create a chat completion v1 (legacy stream/response format) | Body: `appId`, `chatId`, `stream`, `detail`, `messages`, `variables` |
| `POST` | `/api/v2/chat/stop` | Stop an in-progress conversation run | Body: `appId` (required), `chatId` (required), `outLinkAuthData` (optional); halts workflow scheduling at the next safe checkpoint |

### 2. Session History Management (`chatHistory`)

| Method | Path | Summary | Key Parameters (Query / Body) |
| --- | --- | --- | --- |
| `GET` | `/api/core/chat/init` | Initialize chat session metadata (welcome text, pre-chat variables) | Query: `appId` (required), `chatId` (optional) |
| `POST` | `/api/core/chat/history/getHistories` | List paginated conversation sessions for an application | Body: `appId` (required), `offset`/`pageNum`, `pageSize`, `source` |
| `POST` | `/api/core/chat/history/getHistoryStatus` | Batch-poll session generation and read statuses | Body: `appId` (required), `chatIds` (string array); returns `chatGenerateStatus`, `hasBeenRead`, `updateTime` |
| `POST` | `/api/core/chat/history/markRead` | Mark a conversation session as read | Body: `appId` (required), `chatId` (required) |
| `PUT` | `/api/core/chat/history/updateHistory` | Rename a session or toggle its pinned status | Body: `appId` (required), `chatId` (required), `title`, `customTitle`, `top` (boolean) |
| `DELETE` | `/api/core/chat/history/delHistory` | Soft-delete a single conversation session | Query: `appId` (required), `chatId` (required) |
| `DELETE` | `/api/core/chat/history/clearHistories` | Soft-delete all sessions under an application | Query: `appId` (required) |
| `POST` | `/api/core/chat/history/batchDelete` | Permanently delete multiple sessions in batch | Body: `appId` (required), `chatIds` (non-empty string array) |

### 3. Message Records and Citation Lookup (`chat`)

| Method | Path | Summary | Key Parameters (Query / Body) |
| --- | --- | --- | --- |
| `POST` | `/api/core/chat/record/getPaginationRecords` | List paginated message records in a session | Body: `appId` (required), `chatId` (required), `offset`/`pageNum`, `pageSize`, `loadCustomFeedbacks` |
| `POST` | `/api/core/chat/record/getRecords_v2` | Fetch message records around a cursor anchor | Body: `appId` (required), `chatId` (required), `pageSize`, `initialId`, `prevId`, `nextId` |
| `GET` | `/api/core/chat/record/getResData` | Fetch full node execution details (`responseData`) for a message | Query: `appId` (required), `chatId` (required), `dataId` (message record ID, required) |
| `POST` | `/api/core/chat/record/getQuote` | Fetch cited knowledge chunks by chunk ID list | Body: `appId` (required), `chatId` (required), `chatItemDataId` (required), `datasetDataIdList` |
| `POST` | `/api/core/chat/record/getCollectionQuote` | Fetch paginated collection chunks for the full-text citation reader | Body: `appId` (required), `chatId` (required), `chatItemDataId` (required), `collectionId` (required), `pageSize` |
| `DELETE` | `/api/core/chat/record/delete` | Delete a single message record | Query: `appId` (required), `chatId` (required), `contentId` (required) |

### 4. Message Feedback (`chatFeedback`)

| Method | Path | Summary | Key Request Fields |
| --- | --- | --- | --- |
| `POST` | `/api/core/chat/feedback/updateUserFeedback` | Add, update, or clear thumbs-up / thumbs-down feedback on a message | Body: `appId` (required), `chatId` (required), `dataId` (required), `userGoodFeedback`, `userBadFeedback` |
