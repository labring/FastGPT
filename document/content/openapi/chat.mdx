先完成[首次请求](/zh-CN/openapi/intro)。当前接口支持 `stream: false` 的 JSON 响应及 `stream: true` 的事件流。

## 会话标识

`chatId` 省略或为空时生成新会话 ID。响应 `id` 用于后续会话识别；持续对话时复用同一应用下的 `chatId`，并按接口的消息契约提交当前输入。每位业务用户应使用独立的会话标识和可信身份映射。

访问既有会话时会检查团队和会话权限。身份代理也遵循这些检查，见[身份代理](/zh-CN/openapi/identity-proxy)。

## 流式结果

在首次请求中改为 `"stream": true`，并给 curl 加 `--no-buffer`。成功建立流后，按 SSE 帧处理 `event:` 与 `data:`，跨网络读取保留未完成的帧；文本片段通常位于 `choices[0].delta.content`。遇到 `[DONE]` 完成读取。

设置 `detail: true` 可接收详细事件。运行时定义以下 17 类事件，具体返回内容取决于接口、运行时版本和应用配置。`detail: false` 时，回答帧使用 SSE 默认消息事件。客户端应兼容未知事件类型。

| 事件名称 | `data` 载荷内容 | 业务含义与消费方式 |
|---|---|---|
| `answer` | `WorkflowAnswerChunk` 或纯文本 `[DONE]` | 模型文本片段、思考内容增量、心跳包与流结束信号 |
| `fastAnswer` | `WorkflowAnswerChunk` | 指定快速回答节点的直出文本 |
| `chatTitle` | `{ title: string }` | 本轮对话生成的标题建议（每轮至多发送一次） |
| `flowNodeStatus` | `{ status: 'running', name: string }` | 节点进入执行阶段，驱动前端节点高亮 |
| `flowNodeResponse` | `ChatHistoryItemResType` | v2 节点发布执行结果树，包含各节点执行耗时与调试数据 |
| `flowResponses` | `ChatHistoryItemResType[]` | v1 详细流结束前的节点执行结果数组 |
| `updateVariables` | `Record<string, any>` | 更新变量节点输出的持久化变量键值对 |
| `interactive` | `{ interactive: { type, params } }` | 面向用户的交互展示配置；运行状态保存在服务端 |
| `workflowDuration` | `{ durationSeconds: number }` | 工作流全流程执行耗时（秒） |
| `toolCall` | `{ tool: ToolModuleResponseItemType }` | Agent 触发工具调用，包含工具标识与入参结构 |
| `toolParams` | `{ tool: { id: string, params: string } }` | 工具入参流式片段 |
| `toolResponse` | `{ tool: { id: string, response: string } }` | 工具执行返回结果 |
| `planStatus` | `{ planStatus: { status: 'generating' \| 'updating' } }` | Agent 规划生成或状态变更 |
| `plan` | `{ plan: AgentPlanType }` | Agent 当前步骤规划完整快照 |
| `error` | `Record<string, any>` | 运行错误，客户端标记本次执行失败 |
| `skillCall` | `{ skill: SkillModuleResponseItemType }` | 运行时发送的技能调用通知 |
| `sandboxStatus` | `SandboxStatusItemType` | Agent 虚拟机沙箱生命周期状态（预热、挂载、升级） |

生成期间，服务端每隔 10 秒发送空回答块作为心跳。反向代理仍需配置流式转发和空闲超时。错误或断网可能使流在 `[DONE]` 前关闭，客户端需分别跟踪完成与失败状态。

### 交互节点挂起与恢复运行

使用 `detail: true` 时，交互节点返回包含 `type` 和 `params` 的展示配置。客户端据此渲染选项或表单，并保存当前 `chatId`。

用户完成交互后，向同一应用、同一 `chatId` 发起下一次请求：用户选择节点将选中结果作为 user 消息内容；表单输入节点将输入对象序列化为 JSON 字符串作为 user 消息内容。服务端从会话历史中恢复检查点。

## 错误与重试

建立事件流前，检查 HTTP 状态、Content-Type 和 JSON 错误。建立流后，继续处理错误事件、最终结果及网络断开。JSON 模式也应检查 `error` 字段，核对业务结果是否完整。

模型调用和工具执行可能产生费用或外部副作用。重试前确认前一次运行是否已经执行，尤其是写入工具。记录应用、会话、时间和可用请求标识，保留去除凭证后的错误以便排查。

## 验收

用同一输入验证 JSON 与流式结果均满足应用规则；测试一个无效应用 ID，确认客户端能显示可诊断错误；中断连接后确认界面显示未完成状态。成功后再接入[日志观察](/zh-CN/guide/build/logs)。

## 开放接口端点参考（System OpenAPI—对话、会话、记录与反馈）

除 `/api/v1/chat/completions` 与 `/api/v2/chat/completions` 支持在 `Bearer <apiKey>-<appId>` 中附带应用 ID 外，其余会话、记录与反馈接口均推荐在请求体或查询参数中**显式传入 `appId`**。

### 1. 对话生成与运行控制（`chatController`）

| 方法 | 完整路径 | 摘要与用途 | 核心请求字段 |
| --- | --- | --- | --- |
| `POST` | `/api/v2/chat/completions` | 发起对话 v2（推荐，兼容 OpenAI 格式） | Body: `appId`、`chatId`、`stream`、`detail`、`messages`、`variables`、`responseChatItemId` |
| `POST` | `/api/v1/chat/completions` | 发起对话 v1（兼容旧版流与响应格式） | Body: `appId`、`chatId`、`stream`、`detail`、`messages`、`variables` |
| `POST` | `/api/v2/chat/stop` | 停止正在生成的会话运行 | Body: `appId`（必填）、`chatId`（必填）、`outLinkAuthData`（可选）；在后续安全检查点终止工作流调度 |

### 2. 会话管理（`chatHistory`）

| 方法 | 完整路径 | 摘要与用途 | 核心请求字段（Query / Body） |
| --- | --- | --- | --- |
| `GET` | `/api/core/chat/init` | 获取会话初始化信息（应用信息、开场白、前置变量配置） | Query: `appId`（必填）、`chatId`（可选） |
| `POST` | `/api/core/chat/history/getHistories` | 分页获取应用的会话历史列表 | Body: `appId`（必填）、`offset` / `pageNum`、`pageSize`、`source` |
| `POST` | `/api/core/chat/history/getHistoryStatus` | 批量轮询会话生成状态与已读状态 | Body: `appId`（必填）、`chatIds`（字符串数组）；返回 `chatGenerateStatus`、`hasBeenRead`、`updateTime` |
| `POST` | `/api/core/chat/history/markRead` | 标记指定会话为已读 | Body: `appId`（必填）、`chatId`（必填） |
| `PUT` | `/api/core/chat/history/updateHistory` | 修改会话标题、自定义标题或置顶状态 | Body: `appId`（必填）、`chatId`（必填）、`title`、`customTitle`、`top`（布尔值） |
| `DELETE` | `/api/core/chat/history/delHistory` | 软删除单个会话 | Query: `appId`（必填）、`chatId`（必填） |
| `DELETE` | `/api/core/chat/history/clearHistories` | 清空指定应用下的全部会话（软删除） | Query: `appId`（必填） |
| `POST` | `/api/core/chat/history/batchDelete` | 批量物理删除多个会话（需目标管理权限） | Body: `appId`（必填）、`chatIds`（非空字符串数组） |

### 3. 对话消息记录与知识引用查询（`chat`）

| 方法 | 完整路径 | 摘要与用途 | 核心请求字段（Query / Body） |
| --- | --- | --- | --- |
| `POST` | `/api/core/chat/record/getPaginationRecords` | 分页获取会话内的对话消息列表 | Body: `appId`（必填）、`chatId`（必填）、`offset` / `pageNum`、`pageSize`、`loadCustomFeedbacks` |
| `POST` | `/api/core/chat/record/getRecords_v2` | 按消息锚点游标获取对话消息列表 | Body: `appId`（必填）、`chatId`（必填）、`pageSize`、`initialId`、`prevId`、`nextId` |
| `GET` | `/api/core/chat/record/getResData` | 获取单条 AI 回复的完整节点执行详情（`responseData`） | Query: `appId`（必填）、`chatId`（必填）、`dataId`（消息记录 ID，必填） |
| `POST` | `/api/core/chat/record/getQuote` | 根据数据块 ID 列表获取对话引用的知识分块详情 | Body: `appId`（必填）、`chatId`（必填）、`chatItemDataId`（必填）、`datasetDataIdList` |
| `POST` | `/api/core/chat/record/getCollectionQuote` | 分页获取引用来源集合的全文数据块（用于分块阅读器） | Body: `appId`（必填）、`chatId`（必填）、`chatItemDataId`（必填）、`collectionId`（必填）、`pageSize` |
| `DELETE` | `/api/core/chat/record/delete` | 删除单条对话消息记录 | Query: `appId`（必填）、`chatId`（必填）、`contentId`（必填） |

### 4. 消息反馈管理（`chatFeedback`）

| 方法 | 完整路径 | 摘要与用途 | 核心请求字段 |
| --- | --- | --- | --- |
| `POST` | `/api/core/chat/feedback/updateUserFeedback` | 添加、更新或取消用户对单条回复的好评/差评反馈 | Body: `appId`（必填）、`chatId`（必填）、`dataId`（必填）、`userGoodFeedback`（好评说明）、`userBadFeedback`（差评说明；均不传表示取消反馈） |
