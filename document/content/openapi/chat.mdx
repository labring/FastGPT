---
title: 会话、流式响应与错误处理
description: 管理 chatId，消费 SSE 内容，并区分请求错误和运行失败。
---

先完成[首次请求](/zh-CN/openapi/intro)。当前接口支持 `stream: false` 的 JSON 响应及 `stream: true` 的事件流。

## 会话标识

`chatId` 省略或为空时生成新会话 ID。响应 `id` 用于后续会话识别；持续对话时复用同一应用下的 `chatId`，并按接口的消息契约提交当前输入。每位业务用户应使用独立的会话标识和可信身份映射。

访问既有会话时会检查团队和会话权限。身份代理也遵循这些检查，见[身份代理](/zh-CN/openapi/identity-proxy)。

## 流式结果

在首次请求中改为 `"stream": true`，并给 curl 加 `--no-buffer`。成功建立流后，按 SSE 帧处理 `event:` 与 `data:`，跨网络读取保留未完成的帧；文本片段通常位于 `choices[0].delta.content`。遇到 `[DONE]` 完成读取。

详细模式可能包含命名事件、运行状态与 `flowResponses`。客户端按事件类型分派，分别处理文本、状态和结构化数据。仅消费文本的客户端也应处理错误和连接中断。

## 错误与重试

建立事件流前，检查 HTTP 状态、Content-Type 和 JSON 错误。建立流后，继续处理错误事件、最终结果及网络断开。JSON 模式也应检查 `error` 字段，核对业务结果是否完整。

模型调用和工具执行可能产生费用或外部副作用。重试前确认前一次运行是否已经执行，尤其是写入工具。记录应用、会话、时间和可用请求标识，保留去除凭证后的错误以便排查。

## 验收

用同一输入验证 JSON 与流式结果均满足应用规则；测试一个无效应用 ID，确认客户端能显示可诊断错误；中断连接后确认界面显示未完成状态。成功后再接入[日志观察](/zh-CN/guide/build/logs)。
