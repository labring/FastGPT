## Before calling

Complete [your first request](/en/openapi/intro) and confirm that the current member can read the target application. Editing and publishing have their own permissions. Actual calls use published runtime configuration; see [published versions](/en/guide/build/publish/versions).

## Conversational applications

Call `/api/v1/chat/completions` with `appId` and a user question in `messages`. The interface supports Chat Agent, Chat Agent V2, and Workflow applications as implemented by your version. Product application types and API resource scope have separate purposes: this endpoint also recognizes workflow-tool resources.

Supply declared global variables through `variables` using matching keys and values. Compare API results with a fixed input tested in the application before adding business data.

```json
{
  "appId": "YOUR_APP_ID",
  "messages": [
    { "role": "user", "content": "Analyze expense reports for this quarter" }
  ],
  "variables": {
    "department": "Engineering",
    "fiscalYear": 2026
  },
  "stream": false
}
```

## Workflow tools

Workflow tools declare input and output contracts and can execute independently. Debug and publish the tool in the interface, then supply its `appId` and input variables according to the current generated reference. Inspect tool output in the detailed response; use your deployment's System OpenAPI for exact fields.

For conversation reuse and streamed content, read [conversation integration](/en/openapi/chat); for interactive node suspension and file inputs, read [Interactive Suspension Resume and File Input API Flow](/en/openapi/interactive-and-variables).

## System OpenAPI Endpoint Reference (Application Logs and Analytics)

The endpoints below accept team-level `Authorization: Bearer <apiKey>` authentication (commercial analytics endpoints use the `/api/proApi/` prefix):

| Method | Path | Summary | Key Parameters (Query / Body) |
| --- | --- | --- | --- |
| `POST` | `/api/core/app/logs/list` | List paginated application conversation logs | Body: `appId` (required), `dateStart`, `dateEnd`, `sources`, `logUser`, `errorFilter`, `unreadOnly`, `offset`/`pageNum`, `pageSize` |
| `POST` | `/api/core/app/logs/getUsers` | List users recorded in application logs | Body: `appId` (required), `dateStart`, `dateEnd`, `searchKey` |
| `GET` | `/api/proApi/core/app/logs/getTotalData` | Get cumulative application totals (users, chats, consumed points) | Query: `appId` (required) |
| `POST` | `/api/proApi/core/app/logs/getChartData` | Get time-series chart metrics (users, turns, feedback, token usage) | Body: `appId` (required), `dateStart`, `dateEnd`, `source` |

[Historical application parameters](/en/openapi/legacy/app) preserve earlier log-interface documentation for maintaining existing integrations.
