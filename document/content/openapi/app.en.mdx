## Before calling

Complete [your first request](/en/openapi/intro) and confirm that the current member can read the target application. Editing and publishing have their own permissions. Actual calls use published runtime configuration; see [published versions](/en/guide/build/publish/versions).

## Conversational applications

Call `/api/v1/chat/completions` with `appId` and a user question in `messages`. The interface supports Chat Agent, Chat Agent V2, and Workflow applications as implemented by your version. Product application types and API resource scope have separate purposes: this endpoint also recognizes workflow-tool resources.

Supply declared global variables through `variables` using matching keys and values. Compare API results with a fixed input tested in the application before adding business data.

## Workflow tools

Workflow tools declare input and output contracts and can execute independently. Debug and publish the tool in the interface, then supply its `appId` and input variables according to the current generated reference. Inspect tool output in the detailed response; use your deployment's System OpenAPI for exact fields.

## Runtime and management

For conversation reuse and streamed content, read [conversation integration](/en/openapi/chat). For statistics and log management, verify each generated operation's availability, version, and licensing requirements before calling it.

[Historical application parameters](/en/openapi/legacy/app) preserve earlier log-interface documentation for maintaining existing integrations.
