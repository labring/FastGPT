## Endpoint Overview

- **Method** : `POST`
- **Path** : `/api/v2/chat/completions`
- **Module** : Chat / Chat Completions & Control
- **Authentication** : `Authorization: Bearer <apiKey>`—Supports **App API Key** ( `appId` optional) and **Personal API Key** ( `appId` required); also supports `authProxy` team member proxy and `outLinkAuthData` share link (see [API Getting Started](/en/openapi/intro) )
- **Interactive Try-It-Out** : [Open in Scalar API Explorer](https://cloud.fastgpt.io/apidoc/systemopenapi#tag/%E4%BC%9A%E8%AF%9D%E6%93%8D%E4%BD%9C/POST/v2/chat/completions) (self-hosted instances: replace the origin with `<instance>/apidoc/systemopenapi#tag/%E4%BC%9A%E8%AF%9D%E6%93%8D%E4%BD%9C/POST/v2/chat/completions` )

## Description & Notes

The v2 chat completions endpoint follows the OpenAI Chat Completions schema.

**API Key Usage**

- Authenticate with an API Key. When calling `chat/completions` with a personal key, passing `body.appId` in the request body is recommended.
- For OpenAI SDK compatibility, `Authorization: Bearer <apiKey>-<appId>` is also supported without passing `body.appId` .
- Some SDKs append `/v1` to `baseURL` while others do not; if you receive a 404, try adjusting `/v1` in `baseURL` .
- `appId` resolution precedence: `body.appId` > `<apiKey>-<appId>` header suffix \> legacy key-bound `appId` .

**Important Notes**

- Backend callers can pass `customUid` to identify their end users (passed to workflow `userId` ). It does not change the authenticating member and is mutually exclusive with `authProxy` (max 1024 chars; empty string uses the default member; supported in FastGPT \>= 4.18.0).
- To impersonate a team member via `authProxy` , a team owner must enable `authProxy` on the personal API key; the proxied member must still have access to the target app and chat session (FastGPT \>= v4.15.0).
- Request fields such as `model` and `temperature` are ignored because model and inference parameters are controlled by the published app workflow.
- Standard `usage` tokens are placeholder values; set `detail=true` and sum `tokens` in `responseData` if you need per-node token usage.

**`chatId` Behavior**

- Omitted or empty: FastGPT server-side history is disabled; context is constructed solely from the request `messages` array.
- Non-empty string: FastGPT loads existing conversation history for `chatId` from storage and uses only the last message in `messages` as the user prompt (earlier entries are ignored). Ensure `chatId` is unique (max 1024 chars).

**`stream` / `detail` Combinations**

- `detail=false, stream=false` : Returns compact OpenAI-compatible JSON ( `choices` , `usage` , `id` ).
- `detail=false, stream=true` : Returns an OpenAI-compatible SSE stream with answer deltas and `[DONE]` .
- `detail=true, stream=false` : Includes `responseData` (per-node execution details) and `newVariables` in the JSON response.
- `detail=true, stream=true` : Returns a multi-event SSE stream ( `answer` , `flowNodeStatus` , `flowNodeResponse` , `workflowDuration` , etc.).

Share-link calls use the same per-node SSE protocol with public fields filtered by share settings ( `showCite` , `showRunningStatus` , `showSkillReferences` , and download permissions).

**Interactive Nodes**

If the workflow includes interactive nodes, set `detail=true` :

- `stream=true` : Read interactive payloads from `event: interactive` .
- `stream=false` : Read the `interactive` entry from `choices[].message.content` .

Non-streaming `interactive` payloads unwrap nested `children` / `loop` / `tool` wrappers down to the innermost prompt and strip internal runtime fields ( `entryNodeIds` , `memoryEdges` , `nodeOutputs` ). SSE frames may preserve wrapper envelopes whose inner payload sits under `params.childrenResponse` .

To resume execution after rendering the interactive prompt to the user, call this endpoint again with the same `chatId` :

- User selection: Send the selected option value directly as the user message `content` .
- Form input: Serialize the form key-value map as a JSON string in the user message `content` .

**Mutually Exclusive Branches ( `anyOf` )**

- **App Chat**

Identify the application via `appId` and authenticate with an API Key or login session. Personal API Key requests may omit `body.appId` when using an `apiKey-appId` header suffix or legacy bound key; login sessions must provide `appId` . App API Keys do not support `authProxy` .

| Field   | Type     | Required | Default | Constraints & Description                                                                                                                                                                                                                  |
| ------- | -------- | -------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `appId` | `string` | Yes      | -       | Application ID. App API Keys ignore this field and SDK suffixes in favor of the bound app; personal keys resolve in order: `body.appId` \> `Authorization` `key-appId` suffix. The suffix is never persisted. pattern: `^[0-9a-fA-F]{24}$` |

**Default Identity** : Omit `customUid` and `authProxy` to execute using the team member identity associated with the credential.

**Custom end user ( `customUid` )**: Tag end users from your own system via `customUid` without changing the authenticating member or permissions. Passed as workflow `userId` and used to scope chat management.

| Field       | Type     | Required | Default | Constraints & Description                                                                                                                                                                                                                                                                                                                                                                  |
| ----------- | -------- | -------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `customUid` | `string` | Yes      | -       | End user ID supplied by your backend during API Key calls (FastGPT \>= 4.18.0, max 1024 chars); does not alter member permissions and is mutually exclusive with `authProxy` . New chats treat empty string as default user; existing chats bound to a `customUid` reject missing, empty, or mismatched values. Share-link calls use `outLinkAuthData.outLinkUid` instead. maxLength: 1024 |

**Proxy Team Member ( `authProxy` )**: Act on behalf of another member in the same team via `authProxy` . Available only on personal API keys with `authProxy` enabled; mutually exclusive with `customUid` .

| Field                | Type     | Required | Default | Constraints & Description                                                                                                                                                                                                                       |
| -------------------- | -------- | -------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `authProxy`          | `object` | Yes      | -       | Team member identity to proxy via API Key (mutually exclusive with `customUid` ; unsupported on share-link chats). Specify `tmbId` or `username` ; if both are sent, `tmbId` takes precedence without falling back to `username` on invalid ID. |
| `authProxy.tmbId`    | `string` | Yes      | -       | **Branch: By Team Member ID** . Proxied team member ID ( `tmbId` ), takes precedence over `username` . pattern: `^[0-9a-fA-F]{24}$`                                                                                                             |
| `authProxy.username` | `string` | Yes      | -       | **Branch: By Username** . Proxied team member username. minLength: 1; maxLength: 128                                                                                                                                                            |

- **App API Key (no appId required)**

When using an app-bound App API Key, `appId` is omitted and resolved from the key binding; supports default identity or `customUid` (not `authProxy` ). Compatible with personal key `key-appId` SDK suffixes (which follow App Chat proxy rules); regular personal keys and login sessions require `appId` .

**Default Identity** : Omit `customUid` and `authProxy` to execute using the team member identity associated with the credential.

**Custom end user ( `customUid` )**: Tag end users from your own system via `customUid` without changing the authenticating member or permissions. Passed as workflow `userId` and used to scope chat management.

| Field       | Type     | Required | Default | Constraints & Description                                                                                                                                                                                                                                                                                                                                                                  |
| ----------- | -------- | -------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `customUid` | `string` | Yes      | -       | End user ID supplied by your backend during API Key calls (FastGPT \>= 4.18.0, max 1024 chars); does not alter member permissions and is mutually exclusive with `authProxy` . New chats treat empty string as default user; existing chats bound to a `customUid` reject missing, empty, or mismatched values. Share-link calls use `outLinkAuthData.outLinkUid` instead. maxLength: 1024 |

- **Share-Link Chat**

Resolves the app via `outLinkAuthData` , scoping the end user by `outLinkUid` . Takes precedence over `appId` and header auth without fallback on failure; protected share links still require login token/cookie and do not support `authProxy` .

| Field                        | Type     | Required | Default | Constraints & Description                                                                                                                      |
| ---------------------------- | -------- | -------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `outLinkAuthData`            | `object` | Yes      | -       | Share-link auth payload containing `shareId` and `outLinkUid` . Overrides `appId` ; protected links still verify login session cookies/tokens. |
| `outLinkAuthData.shareId`    | `string` | Yes      | -       | Share link ID. minLength: 1                                                                                                                    |
| `outLinkAuthData.outLinkUid` | `string` | Yes      | -       | External share user ID. minLength: 1                                                                                                           |

#### Polymorphic Field: `messages`

- **Variant 1** ( `role="system"` ): `role` , `content` , `name` , `reasoning_content` , `dataId` , `hideInUI`
- **Variant 2** ( `role="developer"` ): `role` , `content` , `name` , `reasoning_content` , `dataId` , `hideInUI`
- **Variant 3** ( `role="user"` ): `role` , `content` , `name` , `reasoning_content` , `dataId` , `hideInUI`
- **Variant 4** ( `role="assistant"` ): `role` , `content` , `tool_calls` , `interactive` , `audio` , `function_call` , `refusal` , `name`
- **Variant 5** ( `role="tool"` ): `role` , `content` , `tool_call_id` , `name` , `reasoning_content` , `dataId` , `hideInUI`
- **Variant 6** ( `role="function"` ): `role` , `content` , `name` , `reasoning_content` , `dataId` , `hideInUI`

### HTTP 409

Rejects the request when the conversation already has an active generation without persisting the rejected message. Non-streaming calls return HTTP 409; streaming calls emit the same payload on `event: error` . Use `data.responseChatItemId` to resume the active assistant message (or reuse the latest AI message when `data.reusePreviousAi=true` ).

**Content-Type** : `application/json`

| Field                     | Type                 | Required | Default | Constraints & Description                                                                                                                    |
| ------------------------- | -------------------- | -------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `code`                    | `504001`             | Yes      | -       | Fixed: `504001`                                                                                                                              |
| `statusText`              | `"chatIsGenerating"` | Yes      | -       | Fixed: `"chatIsGenerating"`                                                                                                                  |
| `message`                 | `string`             | Yes      | -       | Localized display error message; use `code` or `statusText` for programmatic handling. Defaults to English when no translation is available. |
| `data`                    | `object`             | Yes      | -       | -                                                                                                                                            |
| `data.responseChatItemId` | `string`             | No       | -       | Active assistant message ID currently generating on the server; clients should resume tracking this ID. minLength: 1                         |
| `data.reusePreviousAi`    | `true`               | No       | -       | Indicates an interactive resume reusing the latest assistant message; refresh records before resuming. Fixed: `true`                         |

### SSE `event` Types Reference (v2)

#### `answer` · Answer Delta

Includes empty heartbeat deltas, answer text, `reasoning_content` deltas, `stop` finish chunks, and `[DONE]` markers.

```text
: 1. Empty heartbeat
event: answer
data: {"choices":[{"delta":{"role":"assistant","content":""},"index":0,"finish_reason":null}]}

: 2. Answer text
event: answer
data: {"choices":[{"delta":{"role":"assistant","content":"Makoto Shinkai directed the film Suzume."},"index":0,"finish_reason":null}]}

: 3. Reasoning delta
event: answer
data: {"choices":[{"delta":{"role":"assistant","reasoning_content":"Verify the director of Suzume first."},"index":0,"finish_reason":null}]}

: 4. Stop finish chunk
event: answer
data: {"choices":[{"delta":{"role":"assistant","content":null},"index":0,"finish_reason":"stop"}]}

: 5. End of stream
event: answer
data: [DONE]
```

#### `fastAnswer` · Specified Reply

Emitted for immediate outputs such as Specified Reply nodes; includes text deltas and a stop chunk.

```text
: 1. Specified reply text

: 2. Specified reply stop chunk
```

Emitted when a workflow Node.js starts running; governed by `showRunningStatus` on share links.

```text

```

#### `toolCall` · Tool Call

Initializes a tool call card; shows both standard calls and `hideDetails` calls with hidden parameters.


#### `toolParams` · Tool Params Delta

Appends or merges tool arguments keyed by `tool.id` ; does not indicate execution completion.

```text
event: toolParams
data: {"tool":{"id":"call-search-1","params":"{\"query\":\"Suzume director\"}"},"responseValueId":"call-search-1"}
```

#### `toolResponse` · Tool Response

Delivers the tool execution result keyed by `tool.id` ; `response` can be a string or `null` .

```text
: 1. String response
event: toolResponse
data: {"tool":{"id":"call-search-1","response":"Director: Makoto Shinkai"},"responseValueId":"call-search-1"}

: 2. Empty response
event: toolResponse
data: {"tool":{"id":"call-search-1","response":null},"responseValueId":"call-search-1"}
```

#### `updateVariables` · Variable Updates

Updates workflow variables for the current turn; values may be strings, numbers, booleans, arrays, objects, or `null` .

```text
event: updateVariables
data: {"lastQuestion":"Who is the director?","searchCount":1,"found":true,"movieNames":["Suzume"],"director":{"name":"Makoto Shinkai"},"nextPage":null}
```

#### `workflowDuration` · Workflow Duration

Total elapsed execution time for the turn, with `durationSeconds` measured in seconds.

```text
event: workflowDuration
data: {"durationSeconds":2.41}
```

#### `chatTitle` · Chat Title

Emitted only when `detail=true` and an untitled conversation receives an auto-generated title; never overwrites manual titles.

```text
event: chatTitle
data: {"title":"Suzume Director"}
```

#### `planStatus` · Plan Generation Status

Emitted only when planning is enabled; shows `generating` and `updating` statuses.


#### `plan` · Agent Plan

Identifies the plan with `plan.planId` and each step with `steps[].id` ; step statuses update during execution.

```text
event: plan
data: {"plan":{"planId":"plan-1","name":"Look up director info","steps":[{"id":"step-1","name":"Confirm film title","status":"done"},{"id":"step-2","name":"Search film references","status":"in_progress"},{"id":"step-3","name":"Compile director details","status":"pending"},{"id":"step-4","name":"Verify paid sources","status":"blocked","note":"Waiting for user authorization"},{"id":"step-5","name":"Add unrelated works","status":"skipped","note":"Out of scope"}]}}
```

#### `error` · Stream Error

Error emitted after the SSE stream opens, including plain `message` errors or structured business errors with `code` , `statusText` , and `data` . Do not rely on HTTP 200 alone.

```text
: 1. Generic error
event: error
data: {"message":"Model request failed. Please retry shortly."}

: 2. Business error
event: error
data: {"code":510003,"statusText":"runtimeUpgradeInProgress","message":"Sandbox upgrade in progress. Please retry shortly.","data":null,"httpStatus":409}
```
