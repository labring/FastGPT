## Overview

Currently supported team modes:

1. Single-team mode (default, one global team)
2. Multi-team mode
3. Member sync mode (all members synced from external systems)

### Multi-team Mode

In multi-team mode, a default team owned by the user is automatically created when each user is created.

### Single-team Mode

Single-team mode is a new feature introduced in v4.9. To simplify personnel and resource management for enterprises, when single-team mode is enabled, new users no longer get their own default team — instead, they are added to the root user's team.

### Sync Mode

When system configuration is complete and sync mode is enabled, members from external member systems are automatically synced to FastGPT.

For specific sync methods and rules, see [SSO & External Member Sync](./sso.en.mdx).

## Configuration

The team mode is configured via the `TEAM_MODE` environment variable of the `fastgpt-pro` (admin) service. Valid values are `multi` (multi-team), `single` (single-team), and `sync` (member sync). The team mode shown in the admin console's System Configuration - Member Configuration is read-only — change it through the environment variable instead.

```bash
# fastgpt-pro (admin service) environment variable; optional, defaults to single when unset
TEAM_MODE=multi
```

> **Upgrade notice**: existing deployments whose team mode was saved to the database through the old admin console must explicitly set `TEAM_MODE` (e.g. `TEAM_MODE=multi`, `TEAM_MODE=sync`) after upgrading if they do not run in single-team mode.
>
> - `TEAM_MODE` is authoritative and overrides the team mode stored in the database on service startup.
> - When unset or empty, the value is treated as `single`.
