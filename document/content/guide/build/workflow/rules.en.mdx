When you build a workflow, FastGPT checks whether nodes can connect. This page explains the connection rules so you can tell which nodes can connect and why a connection point may be hidden.

## Connection rules

### Connection types

The canvas supports two types of connections. Connection points are also called handles.

| Type               | Connection                                                                                         | Purpose                                          |
| ------------------ | -------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| Regular connection | A node's regular, branch, or error-catching output → another node's regular input                  | Connect steps in a workflow                      |
| Tool connection    | The diamond output at the bottom of a Tool Call node → the diamond input at the top of a tool node | Attach a node as the entry point for a tool call |

Regular outputs are usually on the right side of a node, and regular inputs are usually on the left. The two connection types cannot be mixed: a regular output cannot connect to a tool input, and a tool output cannot connect to a regular input.

Only nodes that support being used as tools have a tool input. See [Tool calling and termination](/en/guide/build/workflow/nodes/tool) for usage details.

### Basic restrictions

- A node cannot connect to itself.
- You cannot create duplicate connections with the same source node, source handle, target node, and target handle.
- Both nodes and both handles must exist and support the connection type. A node without a regular input or output cannot connect in that direction.
- Branch connections must use branches or options that exist in the current configuration. Error-catching connections require error catching to be enabled on the node.

Subject to the other rules, one output can connect to multiple different nodes, and multiple nodes can connect to the same regular input. Different branch outputs on one node can also connect to the same next node.

### Main and tool workflow boundaries

A Tool Call node belongs to the outer workflow that contains it. A node attached through a diamond tool connection is a **tool entry node**. That entry node and the nodes reachable from it through regular connections form its **tool workflow**.

Each tool entry node defines a separate tool workflow. Even when two tool entry nodes belong to the same Tool Call node, their workflows cannot connect to each other through regular connections.

| Source and target of a regular connection                             | Allowed?                                                            |
| --------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Main workflow node → node in the same main workflow                   | Yes                                                                 |
| Tool workflow node → a subsequent node in the same tool workflow      | Yes, except for connections back to the tool entry node             |
| Main workflow node → tool workflow node                               | No                                                                  |
| Tool workflow node → main workflow node                               | No                                                                  |
| Node in one tool workflow → node in another tool workflow             | No, including separate tool workflows under the same Tool Call node |
| Tool workflow node → its calling Tool Call node or an ancestor caller | No                                                                  |

For example, if a Tool Call node in the main workflow has “AI Chat #2” attached as a tool, “AI Chat #2” and its subsequent nodes belong to that tool workflow. They cannot connect to “AI Chat #3” in the main workflow, and “AI Chat #3” cannot connect into the tool workflow either.

You can extend a tool workflow from an internal node to an unassigned node or disconnected group of nodes, making them part of that tool workflow. An external node cannot join an existing tool workflow by connecting into it. Intermediate nodes cannot be used to bypass workflow boundaries.

Workflow membership depends on tool attachments and existing connections. A node's position on the canvas does not affect its membership.

### Tool entry attachment rules

- One Tool Call node can have multiple different tool entry nodes.
- **A tool entry node can belong to only one Tool Call node.** Multiple Tool Call nodes cannot share the same entry node.
- A node with an existing regular incoming connection cannot be attached as a tool entry node. First, manually delete its regular incoming connections.
- An attached tool entry node cannot receive regular incoming connections, including connections from inside its own tool workflow.
- A tool workflow can contain another Tool Call node with its own child tool workflows, but tool calls cannot form a cycle back to the current workflow or an ancestor workflow.

To move a tool entry node to a different Tool Call node, first manually delete the original tool connection, then connect it to the new caller. FastGPT does not automatically change ownership or delete the old connection. If multiple Tool Call nodes need similar tool workflows, add separate tool nodes for each caller.

### Containers and special nodes

Nodes inside [Loop nodes](/en/guide/build/workflow/nodes/loop_run) and [Parallel Run nodes](/en/guide/build/workflow/nodes/parallel_run) must also follow container boundaries:

- Nodes in the same container can connect according to the rules above.
- Internal nodes cannot connect directly to nodes outside the container or inside another container.
- The outer workflow connects to the container node's own external handles. The container runs its internal workflow.

Some nodes have additional restrictions: tool parameter configuration nodes can only be attached through tool connections; Tool Calling Termination nodes must be connected within a tool workflow; loop termination nodes are only available inside Loop nodes; Parallel Run nodes do not support connections to interactive nodes such as User Selection and Form Input.

### Handle visibility and validation

While you drag a connection, the canvas only shows target handles that the current source can connect to. Ineligible target handles are hidden. For example, when you drag a regular connection from inside a tool workflow, inputs in the main workflow and other tool workflows are hidden as connection targets.

Target handle visibility, connection creation, and whole-workflow connection validation use the same rules. If connection conditions change while you drag, FastGPT checks them again when creating the connection.

When you are not dragging a connection, some unconnected inputs are hidden. Collapsing a node can also change where its handles appear. **These display changes do not delete existing connections.**

### When connections are deleted

The following actions delete the corresponding connections:

- Manually deleting a connection.
- Deleting a node at either end of a connection.
- Deleting a branch, option, or output field with a connection handle, which removes that handle.
- Disabling error catching, which removes the error-catching output handle.

Display changes such as temporarily hiding handles or collapsing nodes do not delete connections. If an existing connection fails validation, follow the validation message to adjust it manually. FastGPT does not automatically delete connections because they fail validation.
