## 特点

- 可重复添加
- 有外部输入
- 需要手动配置
- 触发执行
- 通过提示词约束模型输出分类 id

![特点：界面示例](/imgs/optimized/current/node-question-classify.png.webp)

## 功能

可以将用户的问题进行分类，分类后执行不同操作。在语义较为重叠的场景中，建议配合具体上下文示例进行调优。

## 参数说明

### 背景知识

被放置在对话最前面，可用于补充说明分类内容的定义。例如问题会被分为：

1. 打招呼
2. 计费常见问题
3. 其他问题

由于“计费”范围比较宽，需要给它一个定义，此时提示词里可以填入计费问题的定义：

```
计费常见问题包括套餐价格、余额、积分消耗、续费、发票、退款等问题
当用户询问为什么扣费、如何充值、如何查看账单时，应归类为计费常见问题
当用户只是在询问产品功能或打招呼时，不应归类为计费常见问题
```

### 聊天记录

适当增加一些聊天记录，可以联系上下文进行分类。

### 用户问题

用户输入的内容。

### 分类内容

依然以这 3 个分类为例。运行时，系统把分类列表整理为 `[{ id, description }]` 写入系统提示词的“分类清单”，`id` 是系统随机生成的分类 key，`description` 是你填写的分类内容，并要求模型只输出分类 id。

1. 打招呼
2. 计费常见问题
3. 其他问题

```json
[
  { "id": "abc", "description": "打招呼" },
  { "id": "vvv", "description": "计费常见问题" },
  { "id": "aaa", "description": "其他问题" }
]
```

模型返回普通文本。系统先查找文本中包含的分类 key，找不到时再查找分类内容；两者都匹配不到时进入最后一个分类。模型实际结果和最终分支应通过运行详情验证。

## 连接、输出与验证

选择可用模型，设置分类背景、历史记录和用户问题，并为每个类别填写清晰且互有区别的说明。每个类别连接对应的下游分支。成功分类后，字符串输出“分类结果”保存所选类别的显示文本，对应分支继续执行。当前实现对无法匹配类别 key 的模型结果使用列表最后一个类别兜底，因此建议把“其他问题”放在最后。

示例：设置“打招呼”“计费常见问题”“其他问题”，分别连接回复 `Hello`、`Billing help`、`Please clarify` 的指定回复节点。调试输入“你好”“如何查看账单？”和“明天天气怎样？”，核对分类结果和实际执行分支。模型分类有不确定性；保留兜底类别，并检查模糊问题和连续对话。空问题或模型调用失败时查看运行错误。

需要按确定值分支时，使用[判断器](/zh-CN/guide/build/workflow/nodes/tfswitch)。
