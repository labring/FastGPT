## 特点

- 可重复添加
- 需要手动配置
- 触发执行
- 通过提示词约束模型输出 JSON
- 核心模块

![特点：界面示例](/imgs/optimized/current/node-content-extract.png.webp)

## 功能

从文本中提取结构化数据，通常是配合 HTTP 模块实现扩展。也可以做一些直接提取操作，例如：翻译。

## 参数说明

### 提取要求描述

顾名思义，给模型设置一个目标，需要提取哪些内容。

**示例 1**

> 你是实验室预约助手，从对话中提取出姓名，预约时间，实验室号。当前时间 `{{cTime}}`

**示例 2**

> 你是谷歌搜索助手，从对话中提取出搜索关键词

**示例 3**

> 将我的问题直接翻译成英文，不要回答问题

### 聊天记录（`history`）

配置携带的历史对话轮数或引用上游上下文数组，辅助多轮对话场景下的信息补全提取。例如需要提供姓名、时间和实验室名时，结合上一轮聊天记录即可在用户补齐姓名后一次性提取出完整字段。

### 需要提取的文本（`content`）

必填输入，通常引用流程开始节点的**用户问题**（`userChatInput`）或上游节点的文本输出。

### 目标字段（`extractKeys`）

目标字段与提取结果一一对应，每新增一个目标字段，节点输出区都会增加一个输出端口，其 key 等于字段名，界面标签为 `提取结果-{字段名}`：

- **必须返回**：标记该字段是否为必需提取项；开启后还可配置未提取到时的**默认值**。
- **数据类型**：支持 `string`、`number`、`boolean`、`array<string>`、`array<number>`、`array<boolean>`、`object` 共 7 种类型。
- **字段名（Key）**：字段的唯一英文/标识符 key，对应输出端口标识。
- **字段描述**：说明该字段的语义与格式要求（如姓名、预约时间、搜索关键词）。
- **枚举值（可选）**：仅当数据类型为 `string` 或 `number` 时显示，可按行填写允许的候选值列表。

## 输出介绍

| 输出端口 | 内部 Key | 数据类型 | 说明 |
| --- | --- | --- | --- |
| **完整提取结果** | `fields` | `String` | 包含全部提取字段键值对的 JSON 字符串 |
| **字段完全提取** | `success` | `Boolean` | 所有标记为“必填”的目标字段均成功提取（或填充默认值）时为 `true` |
| **提取结果-`{字段名}`** | 字段名 `key` | 对应配置的**数据类型** | 按目标字段声明的数据类型单独输出对应值 |
| **错误信息** | `system_error_text` | `String` | 开启**报错捕获**后显示，模型调用失败时输出错误原因并触发异常分支 |
