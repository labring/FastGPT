## 介绍

HTTP 模块会向对应的地址发送一个 `HTTP` 请求，实际操作与 Postman、Apifox 等主流接口调试工具的用法一致。

- Params 为 URL 查询参数（Query），GET 请求中较为常用；路径参数直接写在请求 URL 中。
- Body 为请求体，POST/PUT 请求中用的居多。
- Headers 为请求头，用于传递一些特殊的信息。
- 在 URL、Params、Body 与 Headers 输入框中输入 `/` 或 `{` 即可唤起变量选择器（插入 `{{变量}}`），直接引用**全局变量**、**系统变量**与**上游节点输出**。

## 参数结构

### 系统变量说明

可在请求地址、请求头、Params 与 Body 中引用以下运行时系统变量：

- userId: 当前触发会话的使用者 ID
- appId: 应用的 ID
- chatId: 当前对话的 ID（正式会话与调试预览均会生成）
- responseChatItemId: 当前对话中 AI 回复的消息 ID（正式会话与调试预览均会生成）
- variables: 当前对话的全局变量。
- cTime: 当前时间。
- histories: 历史记录（默认最多取 10 条，无法修改长度）

### Params, Headers

使用方法与 Postman、Apifox 一致。

可通过 `{{key}}` 来引入变量。例如：

| key           | value              |
| ------------- | ------------------ |
| appId         | `{{appId}}`        |
| Authorization | Bearer `{{token}}` |

### HTTP 代理

在 **HTTP 代理** 中填写 HTTP 或 HTTPS 正向代理地址，例如 `http://user:password@proxy.example.com:8080`。用户名和密码中的特殊字符需使用百分号编码。完整地址使用密码输入控件，保存工作流时会加密。

代理仅用于当前节点及其重定向，并覆盖环境代理设置（包括 `NO_PROXY`）。留空时沿用现有网络配置。导出工作流会移除此配置，导入后需重新填写。

目标地址、重定向目标和代理端点均须通过部署环境的出站地址策略校验。代理侧的 DNS 解析遵循代理服务器自身的网络策略。

你可以配置对应的 `key` 来从 `FastGPT 转化后的格式` 获取需要的值，该规则遵守 JS 的对象取值规则。例如：

1. 获取 `message` 的内容，那么你可以配置 `message` 的 `key` 为 `message`，这样就可以获取到 `message` 的内容。
2. 获取 `user的name`，则 `key` 可以为：`data.user.name`。
3. 获取 list 中第二个元素，则 `key` 可以为：`data.list[1]`，然后输出类型选择字符串，则会自动获取到 `[ { "test": 22 } ]` 的 `json` 字符串。

### 节点输出端口

- **原始响应**（`httpRawResponse`，`Any`）：接口返回的完整原始响应体，默认自带且无需手动添加。
- **自定义提取字段**：按上方 JSONPath 规则添加的自定义输出端口。
- **错误信息**（`error`，`String`）：开启**报错捕获**后显示，输出请求失败原因。
- **完整错误**（`system_httpRawError`，`Object`）：开启**报错捕获**后显示，输出结构化的错误详情对象。

### 错误响应与排查

当 HTTP 请求节点收到非 2xx 响应时，若响应体未包含 `message` 或 `msg` 字段，节点错误文本中会附加该响应体的截断片段（最多 2000 个字符），便于排查接口失败原因。

### 自动格式化输出

FastGPT v4.6.8 后，加入了出参格式化功能，主要以 `json` 格式化成 `字符串` 为主。如果你的输出类型选择了 `字符串`，则会将 `HTTP` 对应 `key` 的值，转成 `json` 字符串进行输出。因此，未来你可以直接从 `HTTP` 接口输出内容至 `文本拼接` 中，然后拼接适当的提示词，最终输入给 `AI对话`。

## HTTP 对接业务服务示例

下面是一个 POST 请求服务示例：

```ts
type RequestType = {
  appId: string;
  appointment: string;
  action: 'post' | 'delete' | 'put' | 'get';
};

export async function handleAppointmentRequest(body: RequestType) {
  try {
    const { appId, appointment, action } = body;

    const parseBody = JSON.parse(appointment);
    if (action === 'get') {
      return await getRecord(appId, parseBody);
    }
    if (action === 'post') {
      return await createRecord(appId, parseBody);
    }
    if (action === 'put') {
      return await putRecord(appId, parseBody);
    }
    if (action === 'delete') {
      return await removeRecord(appId, parseBody);
    }

    return {
      response: '异常'
    };
  } catch (err) {
    return {
      response: '异常'
    };
  }
}
```
