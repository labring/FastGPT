## 特点 

- 用户交互
- 可重复添加
- 触发执行

![特点 ：界面示例](/imgs/optimized/current/node-user-selection.png.webp)

## 功能 

「用户选择」节点属于用户交互节点，当触发这个节点时，对话会进入“交互”状态，会记录工作流的状态，等用户完成交互后，继续向下执行工作流

![功能 ：界面示例](/imgs/optimized/current/selection-await-input.png.webp)

比如上图中的例子，当触发用户选择节点时，对话框隐藏，对话进入“交互状态”

![功能 ：界面示例](/imgs/optimized/current/selection-complete.png.webp)

当用户做出选择时，节点会判断用户的选择，执行所选选项对应的分支

## 作用

基础的用法为提出需要用户做抉择的问题，然后根据用户的反馈设计不同的工作流流程

## 选项配置与输出

填写展示给用户的说明，添加选项文本，并把各选项的执行连接点接到对应分支。选项由各自的 key 区分，用户选择的文本作为字符串“选择结果”输出；工作流恢复时只沿所选项分支继续执行。

除手动配置固定选项外，节点还支持通过变量引用动态生成选项列表（例如引用上游代码运行或 HTTP 节点的数组输出）。动态选项共用一个动态选项出口；若解析后的动态选项列表为空，节点会返回明确错误，避免出现没有可选选项的无效等待。

## 示例：确认或取消

1. 连接开始节点与用户选择，说明填写 `Continue this task?`。
2. 保留两个选项 `Confirm` 和 `Cancel`，分别连接回复 `Confirmed` 与 `Cancelled` 的指定回复节点。
3. 调试并选择 `Confirm`，核对选择结果为 `Confirm`，回复为 `Confirmed`。
4. 重新开始对话并选择 `Cancel`，核对只执行取消分支。

访问渠道需要支持交互；并行执行容器限制放入此节点。选择后未继续时，检查选项连线和恢复时使用的会话。需要多个结构化字段时使用[表单输入](/zh-CN/guide/build/workflow/nodes/form_input)。
