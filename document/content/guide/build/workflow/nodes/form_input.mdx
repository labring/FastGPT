## 特点 

- 用户交互
- 可重复添加
- 触发执行

![特点 ：界面示例](/imgs/optimized/current/node-form-input.png.webp)

## 功能 

「表单输入」节点属于用户交互节点。当触发该节点时，对话进入“交互”状态并隐藏底部常规输入框，系统保存当前工作流状态，等待用户填写表单并提交后继续向下执行。

![功能 ：界面示例](/imgs/optimized/current/form-await-input.png.webp)

如上图所示，当必填字段“测试名称”未填写时，表单会显示必填校验提示。

![功能 ：界面示例](/imgs/optimized/current/form-submit-result.png.webp)

当用户填完必填信息并点击提交后，节点会收集用户填写的表单数据，并传递到后续节点中使用。

## 作用

能够精准收集需要的用户信息，再根据用户信息进行后续操作。

## 配置与输出

在节点中填写说明文字，再在“表单配置”右侧点击“新增输入”添加输入项。每项设置名称、唯一变量 key、类型及必填状态；按类型配置默认值、长度、数值范围或选项。字段名称用于表单展示，也是变量选择器中该字段输出的显示名；key 是输出数据中的字段名。单选（下拉单选）和多选字段除了手动配置固定选项外，也支持通过变量引用动态生成选项列表。与用户选择节点一致，若引用的动态选项列表为空，节点会返回明确错误，避免展示无法选择的表单项。

提交后，节点输出 **用户完整输入结果** 对象，按 key 保存各字段值；每个字段也有对应的独立输出，在变量选择器中按字段名称显示。下游节点通过变量选择器引用字段输出或完整对象。文件字段输出可供后续节点使用的链接列表，受部署的文件类型和数量限制约束。

## 示例：收集联系人姓名

1. 将开始节点连接到表单输入，再连接到指定回复。
2. 说明文字填写 `请填写联系人姓名。`。添加一个文本输入项，名称为 `联系人姓名`，key 为 `contactName`，设为必填。
3. 在指定回复中通过变量选择器引用表单节点的 `联系人姓名` 输出（key 为 `contactName`）。
4. 开始调试，确认表单出现且下游等待；填写 `张伟` 并提交。
5. 预期回复为 `张伟`，运行详情的用户完整输入结果包含 `{"contactName":"张伟"}`。

表单需要支持交互的访问渠道。并行执行容器会限制交互节点；循环中的交互会暂停并等待恢复。表单未出现时检查执行连线；提交后值为空时检查 key、必填设置及下游引用。通过 API 接入时按当前生成接口的交互契约处理提交，保留同一会话。
