## 特点 

- 用户交互
- 可重复添加
- 触发执行

![特点 ：界面示例](/imgs/form_input1.png)

## 功能 

「表单输入」节点属于用户交互节点，当触发这个节点时，对话会进入“交互”状态，会记录工作流的状态，等用户完成交互后，继续向下执行工作流

![功能 ：界面示例](/imgs/form_input2.png)

比如上图中的例子，当触发表单输入节点时，对话框隐藏，对话进入“交互状态”

![功能 ：界面示例](/imgs/form_input3.png)

当用户填完必填的信息并点击提交后，节点能够收集用户填写的表单信息，传递到后续的节点中使用

## 作用

能够精准收集需要的用户信息，再根据用户信息进行后续操作

## 配置与输出

在节点中填写表单说明，再添加输入项。每项设置名称、唯一变量 key、类型及必填状态；按类型配置默认值、长度、数值范围或选项。字段名称用于展示，key 用于输出引用。

提交后，节点输出 **表单输入结果** 对象，按 key 保存各字段值；每个字段也有对应的独立输出。下游节点通过变量选择器引用字段输出或完整对象。文件字段输出可供后续节点使用的链接列表，受部署的文件类型和数量限制约束。

## 示例：收集联系人姓名

1. 将开始节点连接到表单输入，再连接到指定回复。
2. 表单说明填写 `Enter the contact name.`。添加一个文本输入项，名称为 `Contact name`，key 为 `contactName`，设为必填。
3. 在指定回复中通过变量选择器引用表单节点的 `contactName` 输出。
4. 开始调试，确认表单出现且下游等待；填写 `Alex` 并提交。
5. 预期回复为 `Alex`，运行详情的表单输入结果包含 `{"contactName":"Alex"}`。

表单需要支持交互的访问渠道。并行执行容器会限制交互节点；循环中的交互会暂停并等待恢复。表单未出现时检查执行连线；提交后值为空时检查 key、必填设置及下游引用。通过 API 接入时按当前生成接口的交互契约处理提交，保留同一会话。
