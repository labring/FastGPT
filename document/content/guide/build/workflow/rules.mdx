编排工作流时，系统会检查节点之间能否连接。本页介绍连线规则，帮助您判断哪些节点可以连接，以及连接点为什么会隐藏。

## 连线规则

### 连线类型

画布中有两类连线，连接点也称为 Handle。

| 类型     | 连接方式                                                      | 用途                       |
| -------- | ------------------------------------------------------------- | -------------------------- |
| 普通连线 | 节点的普通出口、分支出口或报错捕获出口 → 另一个节点的普通入口 | 连接工作流的执行步骤       |
| 工具连线 | 工具调用节点底部的菱形出口 → 工具节点顶部的菱形入口           | 将节点挂载为工具调用的入口 |

普通出口通常位于节点右侧，普通入口通常位于节点左侧。两类连接点不能混用：普通出口不能连接工具入口，工具出口也不能连接普通入口。

只有支持作为工具使用的节点，才具有工具入口。工具调用的使用方式见[工具调用与终止](/guide/build/workflow/nodes/tool)。

### 基本限制

- 节点不能连接自身。
- 不能重复创建起点节点、起点连接点、终点节点和终点连接点均相同的连线。
- 连线两端的节点和连接点必须存在，并支持对应的连线类型。没有普通入口或出口的节点，不能从对应方向连接。
- 分支连线必须使用当前配置中存在的分支或选项；报错捕获连线要求节点已开启报错捕获。

在满足其他规则的前提下，一个出口可以连接多个不同节点，多个节点也可以连接同一个普通入口。同一节点的不同分支出口可以连接同一个后续节点。

### 主流程与工具流程的边界

工具调用节点本身属于它所在的外层流程。通过菱形工具连线挂载的节点是**工具入口**；从该入口沿普通连线向后延伸的节点，属于这个入口对应的**工具流程**。

每个工具入口对应独立的工具流程。即使两个工具入口挂载在同一个工具调用节点下，它们的工具流程也不能通过普通连线互相连接。

| 普通连线的起点与终点                                      | 是否允许                                 |
| --------------------------------------------------------- | ---------------------------------------- |
| 主流程节点 → 同一主流程节点                               | 允许                                     |
| 工具流程内节点 → 同一工具流程内的后续节点                 | 允许，但不能连回工具入口                 |
| 主流程节点 → 工具流程内节点                               | 不允许                                   |
| 工具流程内节点 → 主流程节点                               | 不允许                                   |
| 一个工具流程内节点 → 另一个工具流程内节点                 | 不允许，包括同一工具调用下的不同工具流程 |
| 工具流程内节点 → 调用它的工具调用节点，或更外层的调用节点 | 不允许                                   |

例如，主流程中的工具调用节点挂载了“AI 对话 #2”，则“AI 对话 #2”及其后续节点属于工具流程。它们不能连接到主流程中的“AI 对话 #3”，“AI 对话 #3”也不能反向连接到该工具流程内。

工具流程可以从内部节点向尚未归属任何流程的节点或独立片段延伸，使其成为该工具流程的一部分。外部节点不能通过反向接入已有工具流程来取得归属，也不能用中间节点绕过流程边界。

流程归属由工具挂载关系和已有连线决定，节点在画布上的位置不影响归属。

### 工具入口的挂载规则

- 一个工具调用节点可以挂载多个不同的工具入口。
- **一个工具入口只能挂载在一个工具调用节点下**，不能同时被多个工具调用节点共用。
- 已有普通入线的节点不能直接挂载为工具入口，需要先手动删除普通入线。
- 已经挂载为工具入口的节点不能再接收普通入线，包括来自同一工具流程内部的普通入线。
- 工具流程内可以继续使用工具调用节点挂载子工具流程，但不能形成返回当前流程或祖先流程的循环调用关系。

需要更换工具入口所属的工具调用节点时，先手动删除原有工具连线，再连接新的工具调用节点。系统不会自动替换归属或删除旧连线。多个工具调用节点需要类似工具流程时，应分别添加独立的工具节点。

### 容器与特殊节点

[循环节点](/guide/build/workflow/nodes/loop_run)和[并行执行节点](/guide/build/workflow/nodes/parallel_run)内部的节点，还需要遵守容器边界：

- 同一容器内的节点可以按照上述规则连接。
- 容器内部节点不能直接连接容器外的节点，也不能连接另一个容器内部的节点。
- 外部流程应连接容器节点自身的外部连接点，由容器执行内部流程。

部分节点还有额外限制：工具参数配置节点只能通过工具连线挂载；工具调用终止节点只能接在工具流程内；循环终止节点只能用于循环节点内部；并行执行节点内部不支持连接用户选择、表单输入等交互节点。

### 连接点的显示与校验

拖动连线时，画布只显示当前起点可以连接的目标连接点；不符合规则的目标连接点会隐藏。例如，从工具流程内部拖出普通连线时，主流程和其他工具流程的入口不会显示为可连接目标。

候选连接点的显示、创建连线时的校验，以及工作流整体的连线校验使用同一套规则。若连接条件在拖动期间发生变化，创建连线时仍会重新检查。

未拖动连线时，部分未连接的入口会隐藏；节点折叠也会改变连接点的显示位置。**这些显示变化不会删除已有连线**。

### 连线何时会被删除

以下操作会删除对应连线：

- 手动删除连线。
- 删除连线所连接的节点。
- 删除分支、选项或带有连线出口的输出字段，使对应连接点被删除。
- 关闭报错捕获，使报错捕获出口被删除。

连接点暂时隐藏、节点折叠等显示变化不会触发连线删除。已有连线如果不符合校验规则，需要根据提示手动调整，系统不会因校验失败而自动删除它们。
