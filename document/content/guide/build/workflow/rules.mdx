编排工作流时，系统会检查节点之间能否连接。本页介绍连线规则，帮助您判断哪些节点可以连接，以及连接点为什么会隐藏。

## 连线规则

### 连线类型

画布中有两类连线，连接点也称为 Handle。

| 类型     | 连接方式                                                      | 用途                       |
| -------- | ------------------------------------------------------------- | -------------------------- |
| 普通连线 | 节点的普通出口、分支出口或报错捕获出口 → 另一个节点的普通入口 | 连接工作流的执行步骤       |
| 工具连线 | 工具调用节点底部的菱形出口 → 工具节点顶部的菱形入口           | 将节点挂载为工具调用的入口 |

普通出口通常位于节点右侧，普通入口通常位于节点左侧。两类连接点不能混用：普通出口不能连接工具入口，工具出口也不能连接普通入口。

只有支持作为工具使用的节点，才具有工具入口。工具调用的使用方式见[工具调用与终止](/guide/build/workflow/nodes/tool)。

### 基本限制

- 节点不能连接自身。
- 不能重复创建起点节点、起点连接点、终点节点和终点连接点均相同的连线。
- 连线两端的节点和连接点必须存在，并支持对应的连线类型。没有普通入口或出口的节点，不能从对应方向连接。
- 分支连线必须使用当前配置中存在的分支或选项；输出字段的连线必须使用当前存在且有效的出口；报错捕获连线要求节点已开启报错捕获。

在满足其他规则的前提下，一个出口可以连接多个不同节点，多个节点也可以连接同一个普通入口。同一节点的不同分支出口可以连接同一个后续节点。

### 主流程与工具流程的边界

工具调用节点本身属于它所在的外层流程。通过菱形工具连线挂载的节点是**工具入口**；从该入口沿普通连线向后延伸的节点，属于这个入口对应的**工具流程**。

每个工具入口对应独立的工具流程。即使两个工具入口挂载在同一个工具调用节点下，它们的工具流程也不能通过普通连线互相连接。

| 普通连线的起点与终点                                      | 是否允许                                   |
| --------------------------------------------------------- | ------------------------------------------ |
| 主流程节点 → 同一主流程节点                               | 允许                                       |
| 工具流程内节点 → 同一工具流程内的其他节点                 | 允许，仍需满足回环规则，且不能连回工具入口 |
| 主流程节点 → 工具流程内节点                               | 不允许                                     |
| 工具流程内节点 → 主流程节点                               | 不允许                                     |
| 一个工具流程内节点 → 另一个工具流程内节点                 | 不允许，包括同一工具调用下的不同工具流程   |
| 工具流程内节点 → 调用它的工具调用节点，或更外层的调用节点 | 不允许                                     |

例如，主流程中的工具调用节点挂载了“AI 对话 #2”，则“AI 对话 #2”及其后续节点属于工具流程。它们不能连接到主流程中的“AI 对话 #3”，“AI 对话 #3”也不能反向连接到该工具流程内。

工具流程可以从内部节点向尚未归属任何流程的节点或独立片段延伸，使其成为该工具流程的一部分。外部节点不能通过反向接入已有工具流程来取得归属，也不能用中间节点绕过流程边界。

流程归属由工具挂载关系和已有连线决定，节点在画布上的位置不影响归属。

### 工具入口的挂载规则

- 一个工具调用节点可以挂载多个不同的工具入口。
- **一个工具入口只能挂载在一个工具调用节点下**，不能同时被多个工具调用节点共用。
- 已有普通入线的节点不能直接挂载为工具入口，需要先手动删除普通入线。
- 已经挂载为工具入口的节点不能再接收普通入线，包括来自同一工具流程内部的普通入线。
- 工具流程内可以继续使用工具调用节点挂载子工具流程，但不能形成返回当前流程或祖先流程的循环调用关系。

需要更换工具入口所属的工具调用节点时，先手动删除原有工具连线，再连接新的工具调用节点。系统不会自动替换归属或删除旧连线。多个工具调用节点需要类似工具流程时，应分别添加独立的工具节点。

### 容器与特殊节点

[循环节点](/guide/build/workflow/nodes/loop_run)和[并行执行节点](/guide/build/workflow/nodes/parallel_run)内部的节点，还需要遵守容器边界：

- 同一容器内的节点可以按照上述规则连接。
- 容器内部节点不能直接连接容器外的节点，也不能连接另一个容器内部的节点。
- 外部流程应连接容器节点自身的外部连接点，由容器执行内部流程。

部分节点还有额外限制：工具参数配置节点只能通过工具连线挂载；工具调用终止节点只能接在工具流程内；循环终止节点只能用于循环节点内部；并行执行节点内部不支持连接用户选择、表单输入等交互节点。

### 回环与分支汇合

**禁止纯串行回环，允许经过条件出口控制的回流。** 系统检查的是连线实际使用的出口，以及加入该连线后形成的每一条回路，不是简单地禁止连接所有上游节点。

以下出口可以控制回流：

| 出口                            | 规则                                                             |
| ------------------------------- | ---------------------------------------------------------------- |
| 判断器的 IF、ELSE IF、ELSE 分支 | 当前配置中存在的分支可以控制回流                                 |
| 问题分类的分类出口              | 当前配置中存在的分类可以控制回流                                 |
| 用户选择的手动选项出口          | 当前配置中存在的选项可以控制回流                                 |
| 用户选择的动态选项出口          | 动态选项共用的出口可以控制回流                                   |
| 已开启报错捕获的节点            | 成功出口和报错捕获出口都可以控制回流；成功与失败会选择不同的出口 |

报错捕获的成功出口包括节点的普通出口，以及有效输出字段对应的出口。关闭报错捕获后，成功出口恢复为普通串行出口。工具挂载的菱形出口不属于这里的条件出口。

以下示例均假设节点位于同一流程，并且连接点满足其他规则：

| 已有结构与候选连线                                               | 是否允许 | 原因                                  |
| ---------------------------------------------------------------- | -------- | ------------------------------------- |
| 普通节点 `A → B`，再连接 `B → A`                                 | 不允许   | 形成纯串行回环                        |
| 普通节点 `A → B → C`，再连接 `C → A`                             | 不允许   | 回路中没有条件出口                    |
| `A → B → D`，同时有 `A → C`，再连接 `D → C`                      | 允许     | 这是分支汇合，没有形成回环            |
| `A → 判断器 B → C`，再连接 `C → A`                               | 允许     | 回路经过 B 的有效分支出口             |
| `A → 问题分类 B → C`，再连接 `C → A`                             | 允许     | 回路经过 B 的有效分类出口             |
| `A → B → C`，B 已开启报错捕获，再连接 `C → A`                    | 允许     | 回路经过 B 受成功或失败结果控制的出口 |
| `A → B → C` 是普通串行路径，A 的另一路经过判断器，再连接 `C → A` | 不允许   | 环外的条件分支不能控制这条纯串行回路  |

条件出口可以位于回路的任意位置，新增的连线本身也可以来自条件出口。但如果另有一条绕过条件出口的串行路径，仍会拒绝形成该回环的连接。节点拥有判断分支，不代表它的其他普通出口也获得回环许可。

回环许可不会放宽其他限制：节点仍不能连接自身，工具流程仍不能跨边界连接，工具入口仍不能接收普通入线。变量引用不是执行连线，不参与这项回环判断。

这项检查只识别回路是否经过受控出口，不会计算条件表达式、预测分类结果，也不保证流程一定退出。搭建回流时需要保留合理的退出条件；持续回流的流程仍受运行时的执行次数上限约束。[循环节点](/guide/build/workflow/nodes/loop_run)内部的循环配置和终止规则仍需单独遵守。

### 连接点的显示与校验

拖动连线时，画布只显示当前起点可以连接的目标连接点；不符合规则的目标连接点会隐藏。例如，从工具流程内部拖出普通连线时，主流程和其他工具流程的入口不会显示为可连接目标。

候选连接点的显示、创建连线时的校验，以及工作流整体的连线校验使用同一套规则。若连接条件在拖动期间发生变化，创建连线时仍会重新检查。

重复连线、回连自身、跨流程连接，以及不满足上述回环规则的目标入口，也会在拖线时隐藏。不能连接的目标不会通过“先连上、再报错”的方式提示。

未拖动连线时，部分未连接的入口会隐藏；节点折叠也会改变连接点的显示位置。**这些显示变化不会删除已有连线**。

### 连线何时会被删除

以下操作会删除对应连线：

- 手动删除连线。
- 删除连线所连接的节点。
- 删除分支、选项或带有连线出口的输出字段，使对应连接点被删除。
- 关闭报错捕获，使报错捕获出口被删除。

连接点暂时隐藏、节点折叠等显示变化不会触发连线删除。已有连线如果不符合校验规则，需要根据提示手动调整，系统不会因校验失败而自动删除它们。

排序或拖动分支、展开或折叠节点、取消拖线、拒绝一次连接，都不会删除已有连线。关闭报错捕获只删除对应报错捕获出口的连线，不会删除成功出口的连线；如果保留的连线因此形成纯串行回环，系统会提示调整。

### 旧流程与校验时机

打开旧流程时，系统会保留已有连线，并显示不符合当前规则的问题。旧版连接点格式和判断器分支格式继续兼容，但旧流程不会豁免当前的流程边界、工具归属和回环规则。

| 操作                         | 连线校验的影响                                   |
| ---------------------------- | ------------------------------------------------ |
| 打开、编辑流程               | 显示已有问题；新建连线时只显示可连接的目标入口   |
| 保存草稿                     | 可以保留尚未修复的连线问题，不因这些问题阻止保存 |
| 在编辑页运行、调试或测试对话 | 检查当前工作流，存在连线错误时需要先修复         |
| 保存并发布                   | 检查当前工作流，存在连线错误时需要先修复         |

例如，旧流程如果存在跨工具流程连接、多个工具调用节点共用一个工具入口，或者纯串行回环，重新调试或发布时需要调整。已发布版本通过正式聊天、分享链接或 API 运行时，仍由后端按其执行逻辑运行；上述客户端编排校验不会修改已发布版本的执行图。
