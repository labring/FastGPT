FastGPT 工作流基于图调度引擎构建。通过可视化的节点连线，开发者能够将复杂的多步骤业务拆解为确定性、可追踪、易调试的处理管线。

## 图调度引擎核心运行机制

工作流从“流程开始”节点启动，调度器按照入边依赖关系驱动整个图谱的推进：

```
[流程开始] ──(active)──► [意图识别] ──(active)──► [知识库检索] ──(active)──► [AI 对话生成]
                             │
                             └──(skipped)────► [工单填报] ──(级联 skipped)──► [工单确认回复]
```

### 1. 入边分组就绪判定（In-Edge Groupings）
调度器按节点的前置入边依赖进行执行条件评估：
- **执行就绪**：当某节点的某一组前置入边全部结束等待，且至少有一条边处于 `active` 激活状态时，该节点立即进入就绪队列开始执行。
- **并发调度**：多个同时处于就绪状态的无依赖节点将并发启动执行，充分利用系统 I/O 资源。

### 2. 连线的三态模型
画布上的每条连线在执行周期中具有三种确定状态：

| 连线状态 | 状态含义与系统行为 |
| --- | --- |
| `waiting` | 初始等待状态。前置上游节点尚未执行完毕，下游节点保持等待。 |
| `active` | 激活就绪状态。上游节点执行成功且满足连线条件，下游节点被唤醒并准备运行。 |
| `skipped` | 跳过传播状态。上游条件分支未选中该路径，触发下游跳过级联传播。 |

### 3. 跳过传播机制（Skip Propagation）
当上游节点（如条件分支或问题分类）仅激活了特定分支时，未选中的分支输出边被标记为 `skipped`。调度引擎将 `skipped` 状态沿连线方向向下游依次广播，所有前置入边均被标记为 `skipped` 的下游节点将安全跳过自身执行，避免出现未完成的挂起死锁。

## 异常分支与熔断机制

为保证工作流在面对外部服务抖动时的健壮性，系统建立了异常分支处理逻辑：

1. **显式异常出口**：对于配置了“异常出口”的节点（如 HTTP 请求、代码沙箱），一旦执行发生超时或接口报错，系统立即激活异常连线分支，并跳过正常业务出口，将错误详情安全交由下游补偿节点处理。
2. **默认错误拦截**：未配置异常出口的节点若运行失败，系统自动跳过该节点自身的所有下游连线，并在会话详情中记录错误堆栈，保障其他并发分支平稳收尾。
3. **运行步数预算（Step Quota）**：为防止循环结构引发死循环，系统对单次请求设置了最大节点执行步数上限。达到预算上限时，调度器主动终止后续调度并在运行结果中记录终止情况。

## 交互检查点机制（Interactive Checkpoints）

FastGPT 支持在工作流执行中途进行人机交互与状态暂留：

```
[执行上游节点] ──► [用户选择/表单输入] ──► (工作流挂起保存 Checkpoint)
                                                  │
                                                  ▼ (等待用户端提交输入)
[下一次请求恢复] ◄── [装载 Checkpoint] ◄───────────────┘
```

1. **执行挂起**：当流程流转至“用户选择”或“表单输入”节点时，系统生成交互内容并随当前轮次响应返回给客户端，同时将工作流上下文、待激活连线与变量快照持久化至数据库检查点。
2. **状态恢复**：用户在聊天界面提交选项或表单后，下一轮请求自动装载该检查点，精准恢复中断现场，继续驱动下游节点执行。
3. **协作式取消**：用户在流式生成期间点击“停止”时，服务端写入停止标记。调度器在下一个节点调度周期协作式退出，并完整持久化当前已产生的执行记录。

## 节点编排最佳实践

1. **从左至右布局**：保持流程从左侧的“流程开始”向右侧的回复节点自然延伸。
2. **单一出口聚合**：通过“指定回复”节点统一控制最终文本渲染，减少多个分散节点的直接回复。
3. **变量规范命名**：在开始节点与全局配置中为业务变量定义清晰的标识符，方便下游节点稳定引用。
