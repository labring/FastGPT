发布版本确定实际访问使用的运行配置，发布渠道提供分享链接、API、MCP 等访问方式。需要应用编辑及对应发布管理权限。

![保存并发布差旅制度 v1 配置](/imgs/optimized/current/app-publish.png.webp)

## 草稿与初始版本

创建应用时系统建立初始发布版本。编辑器保存当前草稿；调试使用编辑中的配置。后续修改需要发布，才能进入分享链接或 API 等实际访问使用的配置。

发布快照包含工作流节点、连线和对话配置。应用名称、头像等当前元数据独立更新；已有会话还具有历史消息、变量及执行状态。验证发布效果时开启新会话，可以清楚观察本次配置的行为。

## 发布一次修改

1. 在编辑器调试一个已知输入，核对输出及引用。
2. 点击编辑器右上角 **保存 → 保存并发布**，填写便于识别的版本名称并确认。看到“发布成功”后继续。
3. 进入发布渠道，选择[分享链接](/zh-CN/guide/build/publish/link)、[API](/zh-CN/guide/build/publish/openapi)或[MCP 服务](/zh-CN/guide/build/publish/mcp_server)。
4. 在该渠道开启新对话，重复测试；查看日志核对运行结果。差旅示例应回答 15 个自然日、发票和已批准差旅申请，引用片段应支持这些事实；住宿补贴问题应说明资料缺失。

## 知识资料更新与配置发布

编辑资料后，按[更新资料](/zh-CN/guide/dataset/update-data)等待索引完成，并在检索与渠道的新会话中检查新条款。更换知识库、修改检索参数或提示词时，需要发布应用配置。分享渠道的引用展示与访问限制还应在渠道设置中单独核对。

## 排查版本差异

调试与实际访问结果不同，依次检查最后发布的版本、访问渠道关联的应用、会话历史、模型设置和知识库处理状态。模型生成可能变化，验收以事实、格式和业务规则为准。找到差异后修正对应配置、完成所需发布，再从同一渠道新建对话复测答案与引用。

使用版本历史恢复配置时，查看界面的恢复与发布提示，并重新验证实际访问。Skill 的独立版本操作见[Skill 版本与发布](/zh-CN/guide/build/skill/version)。
