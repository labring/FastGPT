In FastGPT, the API entry under Publish Channels shows **API Keys** available to the current signed-in member. API Keys are member credentials for OpenAPI calls and are no longer created as app-scoped keys.

When calling this app through `chat/completions`, passing `appId` in the request body is recommended. If a third-party app only supports OpenAI SDK-style key configuration, you can use the `apiKey-appId` compatibility format. For details, [see the OpenAPI Introduction](/en/openapi/intro).

![API channel: APIKey list and New action](/imgs/optimized/current/publish-api.png.webp)

The APIKey list is empty in this example. The displayed service root ends in `/api`; an OpenAI-compatible SDK uses `/api/v1` as described below.

## Get an API Key

Go to App -> "Publish Channels" -> "API", then click "New" to create a key.

<Alert context="warning">
  An API Key represents the current signed-in member's OpenAPI credential. Keep your key safe. To
  copy it again later, use the copy button in the API list.
</Alert>

<Alert icon="🍅" context="success">
  Quota and expiration controls depend on commercial capability configuration; see [API getting started](/en/openapi/intro). Store keys on a trusted server and revoke exposed credentials promptly.
</Alert>

## Replace Variables in Third-Party Apps

OpenAI-compatible clients use your instance URL plus `/api/v1` as the SDK base URL, and `/chat/completions` as the request path. For example:

```text
Base URL: https://YOUR_FASTGPT_HOST/api/v1
API key: YOUR_API_KEY-YOUR_APP_ID
```

Some clients expect a service origin and append `/api/v1` themselves. Follow that client’s version-specific configuration and inspect the final request URL. Test a short message and confirm the published application answers; credentials stay in a trusted server-side configuration.

For [ChatGPT Next Web](https://github.com/Yidadaa/ChatGPT-Next-Web) and [ChatGPT Web](https://github.com/Chanzhaoyu/chatgpt-web), consult the client’s current configuration guide.
