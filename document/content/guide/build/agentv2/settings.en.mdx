The Configuration Panel is used to configure and bind all the core capabilities and execution environments required by your Agent.

---

## AI Configuration & Virtual Machine

- **AI Model**: Choose the chat model and configure its parameters. For general LLM parameters, see [AI Settings](/en/guide/build/general/ai_settings).
- **Prompt**: Define the core persona, objectives, and specific rules for the Agent. The editor supports rich text, and you can type `@` to quickly reference and bind tools, etc.
- **Virtual Machine**: The virtual machine supports code execution, file operations, and startup scripts. The runtime instance is scoped by source, application, and user; conversations use separate session work directories. Lifecycle and persistence depend on the execution service and storage configuration. For architecture and debugging details, refer to [Virtual Machine](/en/guide/build/agentv2/vm). For startup script details and execution limits, see [Virtual Machine Lifecycle](/en/guide/build/agentv2/vm#virtual-machine-lifecycle).

## Associate SKILL & Tools

- **Associated SKILLs**: Select and bind published SKILL packages from the skill library. The runtime prepares the selected published version and records successful initialization; see [Skill initialization](/en/guide/build/skill/initialization) for execution and retry behavior. Associating a Skill automatically enables the virtual machine and shows a notification. Confirm that the execution service is available. To learn how to write and package custom SKILLs, please refer to [Development & Debugging](/en/guide/build/skill/development).

- **Tools**: You can choose to bind system built-in tools (e.g., search engines, charts), custom tools created by yourself or the team (including HTTP/MCP tools), or created apps.

---

## Dataset & File Uploads

- **Dataset**: Associate specific corporate documents and adjust search settings (Hybrid search, Reranking, etc.). It also supports configuring team member permissions.
- **File Uploads**: Toggle file uploads for end-users, permitting images, audio, video, or custom file extensions. File upload capabilities automatically adapt based on the multimodal features of the selected LLM. For detailed configurations, see [File Input](/en/guide/build/general/fileInput).
