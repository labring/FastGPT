## What is Virtual Machine

An Agent uses a virtual machine to execute code, read and write files, and use Skills. Your deployment needs an appropriate sandbox service, and your account needs access and quota. Language runtimes, network access, and resource limits depend on the selected service and image.

## Virtual Machine Design

The current implementation locates a runtime instance by source, application, and user identity. Application conversations use session work directories shaped as `sessions/<chatId>`; shared Skills live under the workspace's `projects/<versionId>`. Older versions may use different instance scoping. Check the deployment version and actual file-manager paths when troubleshooting.

Runtime instances, session directories, and persistent storage have different lifecycles. Restarting a conversation creates new conversation context. File and dependency retention, archiving, and restoration depend on the execution service and storage configuration. Save required artifacts before cleanup or reset operations.

## Using the virtual machine

Enable the virtual machine in Agent V2 settings or associate a Skill requiring execution with a workflow Agent node. Debug a small file and a simple task, observe initialization status, and inspect input files, generated files, and execution logs in the virtual-machine file manager.

Example task: upload a small CSV, ask for a column total, and save the result. Verify column names, row count, a manually calculated total, and file download. Analysis depends on the image's languages and libraries; prepare missing dependencies with a startup script.

## Virtual Machine Lifecycle

The application startup script runs while preparing the environment. Successful execution is recorded by script content. The same successful script reuses that record within an instance; changing the script causes another execution. Skill initialization records published version IDs; see [initialization scripts](/en/guide/build/skill/initialization).

### Execution Constraints & Fault Tolerance

`AGENT_SANDBOX_ENTRYPOINT_TIMEOUT_SECONDS` configures initialization timeout; the current implementation clamps it to 1–600 seconds. Execution output has size limits, and service logs further truncate long text. Initialization errors and timeouts are logged while later task processing may continue. Verify dependencies and results even when task execution starts successfully.

## Virtual Machine Debugging

1. Inspect preparation status and the specific error. Verify service, image, quota, and storage availability.
2. Confirm actual work directories and input files in the file manager.
3. Inspect script exit status, network, dependencies, and permissions. Runtime state is under the virtual-machine user's HOME at `~/.fastgpt/runtime/state.json`.
4. Repeat the small input before increasing task size.

The execution provider supplies isolation, egress controls, and quotas; verify deployment settings. Code, dependencies, and tools affect the runtime environment, so configure the minimum access needed.
