---
title: 创建和调试 HTTP 工具
description: 将 HTTP 服务配置成可调用工具，验证认证、输入和响应。
---

需要工具创建或编辑权限，以及 FastGPT 服务端可以访问的目标 API。准备服务提供方的接口契约和凭证，优先使用只读接口完成初次测试。

## 配置

1. 在工作台创建 HTTP 工具集，选择手动添加工具，或使用界面提供的 API Schema 配置方式。
2. 填写服务地址、工具名称和描述。手动模式配置请求方法与路径；Schema 模式检查解析出的工具列表。
3. 配置认证请求头，将固定凭证放在认证配置中；定义调用者可提供的参数、类型、说明与必填项。
4. 检查请求参数、请求体和输出结构，保存配置。
5. 选中一个工具，在调试区输入已知参数运行，检查响应结构及错误。

例如，把自有测试服务的只读 `GET /status` 配置为工具。预期返回由该服务契约定义的状态字段；先用同一凭证确认服务端能够访问，再验证 FastGPT 的调试结果。

## 接入应用

在应用的工具选择中添加该工具，明确描述适用场景。用一个需要调用它的问题测试，检查模型传参和返回内容。工作流中的单次 HTTP 请求配置见[HTTP 请求节点](/zh-CN/guide/build/workflow/nodes/http)。

## 排障

| 错误 | 检查 |
| --- | --- |
| 401 / 403 | 认证值、目标服务授权范围与过期时间 |
| 404 | 服务地址、路径及请求方法 |
| 超时或网络错误 | FastGPT 服务端的 DNS、出口、TLS 和目标服务状态 |
| 参数或结构错误 | 输入类型、必填值、请求体格式与服务返回的实际结构 |

调试可能真实调用外部服务，操作效果由目标接口决定。正式使用写操作前，验证目标权限和业务确认流程。排障材料中隐藏认证头与个人数据。
