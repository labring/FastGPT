## Why do you need to "Publish"?

Edits in the editor only take effect in the "Debug Chat" panel. To formally apply your changes to your workflows or agents, you must click "Publish" to deploy a formal version.

<Alert icon="💡" context="warning">
  **Note:** The debugging environment is isolated from the production deployment environment. This
  ensures that when you edit or debug skill code, it will not affect the online agents and workflows
  currently running.
</Alert>

---

## Saving Version Snapshots

1. Once testing is successful, click the **"Publish"** button in the top right corner of the editor.
2. In the modal, enter the **Version Name** (by default, the current time is prefilled, but you can customize it, e.g., `v1.0.0`).
3. Confirm, and the system saves a snapshot of the current code and publishes that version.

<Alert icon="💡" context="warning">
  **Note:** During publishing, the system combines default system ignore rules with exclusions in the project root `.gitignore` (default exclusions include `node_modules`, `.venv`, `dist`, `__pycache__`, etc.). Workspace credential files such as `.env` and `.env.*` remain outside system defaults; authors must explicitly add `.env` entries to root `.gitignore` to keep sensitive credentials out of packaged releases. Only files outside ignore rules are packaged; export the ZIP archive to inspect contents and file size before publishing.
</Alert>

## Version Rollback

To restore a previous version:

1. Click the **"Version History"** (clock) icon in the top right corner of the editor to view all published snapshots.
2. Hover over the version you want to restore, and click the **"Switch"** (return arrow) icon.
3. The system updates the Skill active version pointer first, then reinitializes the editing sandbox and restores files to that snapshot.

<Alert icon="💡" context="warning">
  **Note:**
  - Version switching replaces unexported workspace edits; export configurations beforehand to preserve current progress.
  - When sandbox reinitialization encounters unexpected states after version pointer update, refresh the page and reload the workspace.
  - Applications referencing this Skill adopt the switched active version in subsequent executions.
  - Ignored files (such as `node_modules` or `.venv`) remain excluded following a version rollback.
</Alert>
