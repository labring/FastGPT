## Prerequisites

Prepare a published Skill, resource access permissions, a model supporting tool calls, and an available virtual-machine service. Self-hosted installations need a configured execution environment. SaaS license, plan, and quota availability follow the current account interface.

## Bind a Skill to an application

### Chat Agent V2

Open the application editor and select published resources under Associated Skills. Confirm the virtual-machine settings. Associating Skills enables the required virtual machine and keeps that capability enabled while Skills remain associated. Set clear task instructions, save, and debug.

Associate Extract Emails from the [development tutorial](/en/guide/build/skill/development). Instruct the Agent to run the Skill's Python script, then enter `Contact alice@example.com and bob@example.org; CC alice@example.com`. Expect two unique addresses: `alice@example.com` and `bob@example.org`. Expand Processed, then Virtual machine / Execute command to inspect the script input and result.

![Agent with the published Extract Emails Skill returns two unique addresses](/imgs/optimized/current/skill-agent-result.png.webp)

### Workflow Agent node

Open the workflow canvas, add or select an Agent node, and choose published Skills in its Skill configuration. Confirm the model, user question, and virtual-machine settings. Reference the upstream task in the node input and inspect its output. See [Agent node](/en/guide/build/workflow/nodes/agent).

| Host Carrier | Configuration Entry | Sandbox and Execution Scope | Typical Use Case |
| --- | --- | --- | --- |
| **Chat Agent V2** | "Associated Skills" section in the left panel of the application editor | Session-scoped sandbox (`sessions/<chatId>`), preserving workspace files and initialized Skill environments across multi-turn chats | Open-ended multi-turn spreadsheet analysis, interactive report generation, and iterative file processing |
| **Workflow Agent Node** | Workflow canvas → select Agent node → "Skills" selector | Provisions the sandbox for the workflow session, accepts upstream variables and file URLs, and passes its output to downstream nodes | Embedding an autonomous script-execution or Skill-driven step inside a deterministic business pipeline |

## How Agents use Skills

At runtime, selected Skill versions are prepared in the execution environment. The Agent chooses relevant instructions and tools according to the task and model planning. One Skill resource can include multiple instruction sets and supporting files, and an Agent can use multiple resources.

Debug with an input explicitly supported by the Skill. Inspect execution details, virtual-machine files, and the final result. Once the result satisfies the Skill's instructions, [publish application changes](/en/guide/build/publish/versions) and verify in a new conversation.

For missing Skills, inspect published versions and permissions. For environment startup or dependency failures, inspect [initialization scripts](/en/guide/build/skill/initialization) and virtual-machine logs. Skill publishing and application publishing apply to their respective resources; publish the resource you changed.
