Open Account → Model Providers to inspect the model catalog offered by your environment. Filter by name, provider, or type and check context size, capabilities, access scope, and pricing.

## Choose for the task

- Use language models for conversations and summaries. Verify tool calling, vision, and reasoning against model labels and configuration.
- Use embedding models for knowledge indexing. Retrieval reranking requires a configured reranker.
- Confirm member access and quota before selecting a model in an application, then run a small sample.

Display names, model instance identifiers, and provider model names serve different purposes. Use the exact identifier required by an API or configuration contract. Pricing and provider support follow the current environment.

## Team and platform configuration

Members with model-installation permission can configure team models through the templates and channels offered by the interface. Root administrators manage system models. SaaS accounts may expose only the available catalog. See [model configuration](/en/self-host/config/model/intro) for self-hosted administration.

If a listed model fails during execution, inspect the selected instance, member permissions, channel credentials, provider status, and quota. Test configuration updates before verifying dependent applications.
