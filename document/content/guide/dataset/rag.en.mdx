Retrieval-augmented generation (RAG) places relevant material into a language model's context to help it answer using that material. It suits policy lookup, product support, and frequently updated internal knowledge. Start practicing with [your first knowledge-backed Q&A](/en/guide/getting-started/knowledge-qa).

## How material becomes searchable

A Knowledge base organizes material for Applications. An imported file becomes a content Collection holding Data chunks; folder Collections organize other Collections. Parsing determines which text can be read, chunking determines which conditions stay together, and indexing creates searchable representations.

A Data chunk can have several indexes, such as different questions that lead to the same clause. Its text holds the complete facts; indexes locate that text. Assess chunking by whether the deadline, conditions, and exceptions can be retrieved together.

An embedding model represents queries and content numerically for semantic matching; full-text search matches terms. The embedding model and storage backend both affect retrieval. See [search parameters](/en/guide/dataset/dataset_engine) for choices and [Import material](/en/guide/dataset/import-data) for steps.

## The stages behind an answer

1. **Select readable scope.** Knowledge bases, enabled Collections, tags, and applicable permissions constrain candidate material.
2. **Form the query and retrieve.** Query rewriting can use history to resolve references. Semantic, full-text, or hybrid search returns candidate chunks.
3. **Prepare context.** An available rerank model scores text candidates. Results are fused, deduplicated, filtered by applicable scores, and trimmed to a citation budget.
4. **Generate an answer.** The chat model combines the question, prompt, history, and retrieved passages.
5. **Check the evidence.** Read cited passages to confirm facts, conditions, and dates in the answer.

A vision model can describe images for text retrieval. Embedding models that support images can also retrieve image vectors. Both paths require corresponding indexes from ingestion and available model capabilities.

## Retrieval, ranking, and answer correctness

“How long after returning must I submit travel expenses?” needs the clause containing `15 calendar days`. Retrieval scores describe matching for a model or search path; ordering places material in context. The final deadline and citation establish whether the question was answered correctly.

“What is the hotel accommodation allowance?” may retrieve the same travel policy, while that example source lacks an allowance standard. The prompt should require the model to explain the gap, and maintainers must check compliance. A citation provides an inspection point; reading the passage establishes whether it supports the answer.

Assess scores separately across models and search paths. A reranking failure can change order and threshold conditions; see [minimum relevance](/en/guide/dataset/dataset_engine#minimum-relevance).

## Content updates and published configuration

Source text, indexes, Application configuration, and existing conversations each hold different information. Editing a chunk requires updating its indexes; uploading a local file again creates a new Collection; reprocessing rebuilds chunks from the original file stored on the server. See the three paths in [Update material](/en/guide/dataset/update-data).

Editing and debugging use the draft configuration, while published versions serve actual channels. Content updates affect subsequent retrieval; changes to Knowledge base selection, parameters, and prompts take effect through publishing. A new conversation helps separate historical messages from verification of a new clause. See [published versions](/en/guide/build/publish/versions).

## Quality, latency, and maintenance ownership

| Observation | Maintenance focus |
| --- | --- |
| Missing, conflicting, or outdated clauses | Assign source owners, update dates, and retained versions |
| Existing clauses are missed | Check scope, chunks, indexes, and query method |
| Complete material produces inaccurate answers | Inspect the prompt, context budget, and model interpretation |
| Follow-ups are slow or drift | Inspect content and latency for rewriting, reranking, and generation |

Query rewriting, reranking, and generation add model calls. Citation content and history share the context budget. Compare retrieval, answers, citations, and latency with the same questions after each change. Use feedback to revise material, configuration, and prompts; model training or fine-tuning requires a separate process.

## Application scope

Help centers and policy Q&A can be evaluated against fixed clauses. Cross-document summaries also require source-coverage and conflict checks. Image tasks require corresponding models and indexes. Qualified professionals should review medical, legal, and similar specialist conclusions.
