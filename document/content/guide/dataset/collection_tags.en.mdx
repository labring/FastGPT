In complex knowledge bases containing documentation from different departments, product lines, or sensitivity levels, collection tags enable pre-retrieval filtering, isolating distinct business domains cleanly.

## Tag Architecture Planning

Organize orthogonal tag dimensions around organizational governance:
- **Organizational Structure**: `Finance`, `HR`, `Legal`, `Engineering`.
- **Product Lines**: `Product-A`, `Product-B`, `Enterprise-Cloud`.
- **Confidentiality Tiers**: `Public`, `Internal`, `Confidential`.

![Assign department tags to processed collections](/imgs/current/tags-collections.png)

## Step 1: Create and Manage Tag Definitions

1. Open your target knowledge base and click "Tag Management" in the top navigation.
2. Create a tag such as `Department` and choose its type: number, date, or option.
3. For an option tag, create values such as `Finance` and `Support` when assigning the tag to collections.

## Step 2: Assign Tags to Collections

1. In the knowledge base collection list, select the target file or folder collection.
2. Click "Edit Tags" from the collection action menu.
3. Check the tags applicable to this collection, such as tagging `travel-policy.txt` with `Department: Finance`.
4. Click "Save". Retrieval uses collection metadata to select eligible chunks.

![Assign Finance tag to travel policy collection](/imgs/current/tags-finance.png)

## Step 3: Configure Tag Filtering in Applications

By scoping searches with tags, applications isolate domain-specific queries accurately:

### 1. Tag Filtering in Chat Agents
In the application editor, find **Tag Filter** below the attached knowledge base cards. Add a condition row and select the tag, operator, value source, and comparison value. For example, use `Department → contains → Finance`. Combine conditions with AND or OR, and provide variable values matching the tag type.

![Finance filter admits only travel policy citations](/imgs/current/tags-finance-result.png)

### 2. Dynamic Tag Routing in Workflows
Pass a business category from a question classifier into the search node's filter to route topic-specific queries. User identity must come from a trusted backend authentication flow. Enforce sensitive-document access through member authentication and collection permissions; tags describe the retrieval scope.

![Support filter admits only customer support material](/imgs/current/tags-support-result.png)
