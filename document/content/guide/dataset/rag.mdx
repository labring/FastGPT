检索增强生成（Retrieval-Augmented Generation，RAG）是将静态知识库与大语言模型结合的关键架构模式。FastGPT 结合检索、引用提示词与来源展示降低无依据回答的风险，事实准确性需通过代表性测试集验证。

## RAG 完整运行闭环

RAG 管线可包含以下环节；问题改写、混合检索与重排按应用配置启用：

```
[用户提问]
    │
    ▼
[1. 提问分析与改写] ──► 结合历史上下文消解代词，提取核心检索关键词
    │
    ▼
[2. 双引擎混合检索] ──► 执行向量与全文检索，按配置启用重排
    │
    ▼
[3. 上下文筛选截断] ──► 根据最低相似度阈值过滤无效分块，按引用上限控制 Token 预算
    │
    ▼
[4. 提示词动态装配] ──► 将事实分块注入预设模板，加入严格的事实约束指令
    │
    ▼
[5. 带依据流式生成] ──► 大语言模型输出结构化答案，同时向客户端返回关联引用片段
```

## 核心评估指标体系

评估知识库 RAG 系统的性能表现主要依赖以下维度：

| 评估指标 | 定义与关注点 | 调优杠杆 |
| --- | --- | --- |
| **召回率 (Recall)** | 正确答案所在的数据块是否被成功检索出来 | 调整分块边界、开启混合检索、优化 Embedding 模型 |
| **精确率 (Precision)** | 召回的数据块中真正包含核心事实的比例 | 接入 Rerank 模型进行二次重排、合理提高最低相似度阈值 |
| **上下文冗余度** | 上下文中无关干扰信息的密集程度 | 精细化调整分块上限（Token）、降低引用 Token 预算、避免重复分块导入 |
| **事实忠实度** | 最终模型回答与引用材料的一致性程度 | 强化提示词中的事实边界约束、选用推理遵循能力更强的模型 |

## 上下文装配与 Token 预算控制

大语言模型的上下文窗口具有最大长度限制，且模型在长文本环境下的注意力容易衰减。FastGPT 实行精细的上下文装配机制：

1. **Token 预算预留**：系统将上下文空间划分为四部分：全局系统提示词、多轮历史对话、知识库检索内容、模型输出预算。
2. **相关性倒序排列**：候选顺序取决于实际检索和重排配置，应检查最终引用是否保留关键依据。
3. **安全边界截断**：检索阶段保留完整分块，最后一块可能使累计内容越过 Token 预算。AI 对话阶段另有引用限制，应核对最终装配的上下文。

## 防幻觉工程三大支柱

可结合以下措施提升问答可靠性，并在发布后的应用中验证效果：

### 1. 上下文事实强约束指令
在系统提示词中建立明确的事实边界规则：
```text
你是一个专业的制度解答助手。
请仅根据下方检索到的参考文档回答用户提问。
对于参考文档中未记录的信息，直接回复“当前参考资料中未收录相关规定”，说明具体缺失的事实，提示用户向相关责任部门核实。
严禁依据外部常识推断未在文中明确记载的数值、时限或承诺。
```

### 2. 相似度得分硬性截断（Min Score）
使用标注问题校准相似度阈值，核对实际得分过滤模式。在应用中配置空结果分支或依据不足提示，并验证范围外问题的处理。

### 3. 全链路引用溯源透明化
系统在生成回答的同时，记录并输出每个候选块的原始文本、来源文件名与对应集合 ID。前端聊天窗口呈现可点击展开的引用标签，让业务用户能够随时穿透核对原始依据。
