# 1. 引言

当问题依赖企业资料、产品手册或持续更新的信息时，可以把相关资料先检索出来，再交给语言模型回答。本文介绍这一过程及其在 FastGPT 中的边界。

## 1.1 RAG 的定义

检索增强生成（Retrieval-Augmented Generation，RAG）把检索结果作为生成模型的上下文。回答质量取决于资料质量、检索覆盖、提示词和模型能力；生成结果仍需核验。

# 2. RAG 模型的核心机制

一条基础 RAG 链路包含检索器与生成器。资料解析、权限过滤和结果评估同样影响最终效果。

## 2.1 检索器（Retriever）

检索器根据问题返回候选片段。向量检索使用 Embedding 模型编码问题与内容，再比较向量；全文检索利用词项匹配。混合检索融合两类结果。FastGPT 的具体选项见[知识库检索](/zh-CN/guide/dataset/dataset_engine)。

## 2.2 生成器（Generator）

生成器接收用户问题、系统提示词、历史消息和检索片段，生成回答。模型的上下文窗口限制了这些输入与输出预算；应为实际回答保留空间。

## 2.3 RAG 的工作流程

1. 导入资料并完成解析、分块和索引。
2. 根据用户问题与检索配置召回片段。
3. 将筛选后的片段传入 AI 对话。
4. 检查回答、引用和运行详情。

# 3. RAG 模型的工作原理

以下说明当前 FastGPT 默认知识库检索链路。具体行为取决于检索模式、模型能力和节点配置。

## 3.1 检索阶段

FastGPT 按配置进行问题扩展，执行向量或全文召回，融合候选结果，并可对用户文本召回进行重排。随后进行去重、分数过滤和 token 上限裁剪。集合范围、标签条件和可读集合权限共同约束候选数据。图片可通过视觉模型生成描述；支持图片输入的 Embedding 模型还可执行图片向量检索。

## 3.2 生成阶段

在工作流中将知识库搜索结果连接到 AI 对话的知识库引用输入，并说明回答规则。资料缺失时应明确说明证据范围，给出澄清问题或转人工路径。检索分数反映匹配程度，回答准确性需要独立评估。

## 3.3 多轮交互与反馈机制

历史消息可以帮助问题扩展理解指代和上下文。用户反馈需要由维护者用于修订资料、检索配置或提示词，并通过回归问题集验收；模型训练和微调属于单独配置的流程。

# 4. RAG 的优势与局限

评估 RAG 时，同时观察检索结果和最终回答。

## 4.1 优势

RAG 让维护者通过更新资料补充模型可用信息，并能展示被引用的来源。它适合需要查询企业专有资料、核对出处和持续维护知识的场景。

## 4.2 局限

资料错误、检索遗漏、权限配置、上下文截断及模型误读都会影响回答。应为这些情况准备测试问题和处理路径。

#### 4.2.1 检索器的依赖性与质量问题

先检查目标资料是否成功导入，再检查查询范围和召回结果。Embedding 模型负责生成向量，向量索引负责保存与检索向量；二者的配置与兼容性都需要验证。

#### 4.2.2 生成器的计算复杂度与性能瓶颈

问题扩展、重排和回答生成都可能增加延迟与调用费用。通过运行详情定位耗时阶段，再调整片段数量、引用预算、并发与模型选择。

#### 4.2.3 知识库的更新与维护

资料更新后，需要确认解析和索引完成，再用相关问题验证。导入与更新流程见[知识库生命周期](/zh-CN/guide/dataset/lifecycle)。知识的新鲜度受数据来源与同步频率影响。

#### 4.2.4 生成内容的可控性与透明度

引用来源有助于核对证据。应检查引用片段是否真的支持回答，并保留适用的版本、日期和来源信息。敏感业务还需要人工审核和访问权限控制。

# 5. RAG 整体改进方向

使用一组稳定的真实问题逐项比较修改效果，每次记录预期资料、实际召回、最终回答和耗时。

## 5.1 数据采集与知识库构建

选择有授权、可靠且可维护的数据源；清理重复、失效和冲突内容，并记录资料的责任人与更新时间。

## 5.2 数据分块与内容管理

按内容结构分块，保留标题、条件和必要上下文。用代表性问题验证块大小，检查答案所需的信息是否被拆散。

## 5.3 检索优化

先验证权限与检索范围，再比较向量、全文、混合及重排的效果。分数阈值与模型、检索模式有关，应以测试结果调整。

## 5.4 回答生成与优化

在提示词中明确使用资料的规则、引用方式和证据不足时的处理。分别检查检索遗漏和生成误读，按原因修改配置。

## 5.5 RAG 流程

在 FastGPT 中，推荐先完成[首个知识库问答](/zh-CN/guide/getting-started/knowledge-qa)，再用[检索测试](/zh-CN/guide/dataset/dataset_engine)检查命中内容。发布后持续检查日志和反馈，资料变更后重复验收。

# 6. RAG 相关案例整合

示例：导入一份包含产品退款条件的文档，准备“退款期限”“特殊商品是否适用”“资料中缺少的政策”三个问题，分别检查正常命中、条件约束和证据不足的回答。

# 7. RAG 模型的应用

适用范围由资料覆盖、权限和验收结果决定。

## 7.1 智能问答系统中的应用

企业帮助中心、内部制度查询和产品支持可通过 RAG 检索相关条款，并提供来源供用户核对。

## 7.2 信息检索与文本生成

可先检索与任务相关的片段，再生成摘要或报告草稿。跨文档任务需要检查覆盖范围、冲突信息和引用关系。

## 7.3 其它应用场景

图片资料可结合视觉模型和支持图片的 Embedding 模型使用；实际能力以所选模型和导入方式为准。医疗、法律等专业场景需要相应专业人员审核。

## 8 总结

从一份可信资料和一组可验收的问题开始，完成导入、检索、回答与引用核对，再扩大知识库范围。
