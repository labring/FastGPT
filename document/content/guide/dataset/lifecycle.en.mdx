A knowledge base stores material for application retrieval. Verify the complete path with one short document before expanding the dataset; follow [your first knowledge-base Q&A](/en/guide/getting-started/knowledge-qa).

## Create and choose an import method

You need creation or write permission and an available embedding model. Create a knowledge base from the list and choose a model appropriate for the language and material. Team or deployment administrators manage model configuration and quota.

| Source | Method |
| --- | --- |
| Local material | Upload a supported file and inspect parsing and chunk previews |
| Small amounts of curated knowledge | Add chunks or Q&A pairs manually, keeping each independently understandable |
| Web pages | Import accessible pages; see [web synchronization](/en/guide/dataset/websync) for recurring updates |
| Enterprise content systems | Choose a [third-party knowledge source](/en/guide/dataset/third-party/third_dataset) and its connection guide; verify authorization and network access |
| Programmatic ingestion | Follow [knowledge-base API integration](/en/openapi/dataset) and the generated request contract |

## Segmentation and processing

An imported file or page becomes a content collection containing data chunks. Folder collections organize other collections. Retrieval indexes provide searchable representations of chunks.

Preview segmentation before submitting: headings should supply context, conditions should stay with their conclusions, and tables or scans should contain readable text. After submitting, inspect processing status and failures. Wait for indexing before testing retrieval. Parsing and indexing can call separate models or services and consume quota according to your configuration.

## Retrieval and application association

First test retrieval in the knowledge base using a question with a known answer. Inspect matched text, similarity, scope, and ranking. Associate the knowledge base with an application and repeat the question, checking retrieved material, generated answer, and citations. This separates source, retrieval, and generation problems.

References: [retrieval engine](/en/guide/dataset/dataset_engine) and [RAG concepts](/en/guide/dataset/rag).

## Maintenance

- After updating files or synchronizing a source, inspect processing and rerun a fixed set of questions.
- Use [collection tags](/en/guide/dataset/collection_tags) to narrow retrieval and [collection permissions](/en/guide/dataset/collection_permission) to control access.
- Deleting collections or chunks changes material available to associated applications; inspect dependent applications first.
- For empty results, parsing failures, or quota errors, record the collection, processing stage, and error, then follow [troubleshooting](/en/guide/dataset/faq).

Material updates affect later retrieval. Apply application configuration changes to actual access through [published versions](/en/guide/build/publish/versions).
