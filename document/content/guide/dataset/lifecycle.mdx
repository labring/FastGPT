知识库保存供应用检索的资料。先用一份短文验证完整路径，再扩展数据量；示例见[首个知识库问答](/zh-CN/guide/getting-started/knowledge-qa)。

## 创建与选择导入方式

需要知识库创建或写入权限，以及可用的向量模型。进入知识库列表创建知识库，选择适合语言和资料的向量模型。模型配置及额度由团队或部署管理员管理。

| 来源 | 使用方式 |
| --- | --- |
| 本地资料 | 上传受支持的文件，检查解析结果与分段预览 |
| 少量人工知识 | 手动添加数据块或问答对，保持内容可独立理解 |
| 网页 | 导入可访问的页面；周期更新见[网页同步](/zh-CN/guide/dataset/websync) |
| 企业资料系统 | 选择[第三方知识库](/zh-CN/guide/dataset/third-party/third_dataset)及对应连接指南，核对授权和网络条件 |
| 程序写入 | 使用[知识库 API 集成](/zh-CN/openapi/dataset)，核对生成参考的请求契约 |

## 分段与处理

文件或网页导入后形成内容集合，集合中保存数据块。文件夹集合用于组织其他集合。检索索引是数据块的可搜索表示。

提交前预览分段：标题应能说明上下文，关键条件应与对应结论保持在一起，表格和扫描文件应能读出有效文字。提交后检查处理状态与失败原因，等待索引准备完成再测试检索。解析与索引可能分别调用模型或其他服务，按实际配置消耗额度。

## 检索与应用关联

先在知识库内用一个答案已知的问题测试检索，检查命中文本、相似度、范围及排序。再在应用中关联知识库，使用同一问题检查检索内容、模型回答和引用。这样能分别定位资料、检索参数和回答生成的问题。

参数参考：[检索引擎](/zh-CN/guide/dataset/dataset_engine)、[RAG 原理](/zh-CN/guide/dataset/rag)。

## 日常维护

- 更新源文件或同步来源后，核对处理状态，再重复固定问题测试。
- 通过[集合标签](/zh-CN/guide/dataset/collection_tags)限制检索范围，并使用[集合权限](/zh-CN/guide/dataset/collection_permission)控制访问。
- 删除集合或数据块会影响关联应用可检索的资料；操作前检查使用该知识库的应用。
- 遇到空结果、解析失败或额度问题，记录集合、处理阶段与错误信息，按[知识库排障](/zh-CN/guide/dataset/faq)处理。

资料更新影响后续检索；应用配置改动通过[发布版本](/zh-CN/guide/build/publish/versions)应用到实际访问。
