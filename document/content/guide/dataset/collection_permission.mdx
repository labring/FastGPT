集合权限属于商业能力，用于控制知识库内单个文件与文件夹的访问。访问资料需要同时具备知识库读权限和相应集合权限。

## 术语对照

| 概念 | 界面与文档用词 | 说明 |
| --- | --- | --- |
| `dataset` | 知识库 | 权限体系中的资源类型为 `dataset`；知识库读权限是访问内部集合的前置门槛 |
| `collection` | 文件 / 文件夹 / 集合 | 知识库内的单个文件或文件夹，权限体系中的资源类型为 `collection` |
| 集合权限 | 数据集权限配置 / 文件级权限 | 针对知识库内单个文件或文件夹的细粒度协作者权限控制 |

## 权限继承树模型

关闭集合权限时，文件和文件夹使用知识库权限。开启功能后，系统为已有集合物化权限快照；继承态集合跟随父级变化，独立态集合保留自身配置。

![开启集合独立权限](/imgs/optimized/current/collection-permission-enable.png.webp)

## 步骤一：开启集合权限

1. 由知识库管理员打开目标集合的操作菜单，选择“权限”。
2. 确认对当前知识库开启集合权限。资料较多时，权限快照初始化需要一定时间。
3. 初始化成功后，进入目标集合的协作者配置。

知识库信息栏提供关闭入口。关闭会删除该知识库下全部集合协作者配置，恢复知识库权限继承。确认前记录需要保留的授权；再次开启时会重新生成继承态快照。

## 步骤二：配置协作者与角色权限

可通过以下三个入口打开单个文件或文件夹的协作者弹窗（效果一致）：
1. 知识库文件列表 → 目标文件/文件夹行的 `···` 菜单 → **权限**；
2. 打开目标文件详情后的右侧信息栏 → **协作者**；
3. 进入目标文件夹后的右侧信息栏 → **协作者**。

选择成员、成员组或组织，按职责分配角色：

| 角色 | 权限范围 |
|---|---|
| 读权限 | 查看集合内容 |
| 写权限 | 可变更数据集内容（同步/调整训练参数） |
| 管理员 | 可管理整个数据集的信息与权限 |
| 创建者 | 持有集合所有权；删除与所有权转移要求此角色 |

重命名、禁用或变更知识库与集合自身信息需要管理员（Manage）权限；写权限仅用于变更数据集内容（同步/调整训练参数）。协作者提交采用全量覆盖语义，应保留当前创建者记录。修改继承的授权可能需要确认转为独立态；恢复继承时保留当前集合独有的授权，并同步子树。

![配置单个文件或文件夹的协作者权限](/imgs/optimized/current/collection-collaborators.png.webp)

### 继承态与独立态

- **继承态（默认）**：文件或文件夹的权限由父级（上级文件夹，或位于根目录时的知识库）派生，并自动跟随父级协作者变化。
- **独立态**：单独修改或移除继承自父级的协作者时，系统会弹出冲突确认提示；确认后该节点转为独立态，固定保留自身及子树的权限配置。
- **恢复继承**：独立态节点可在权限弹窗中点击恢复继承，恢复时保留该节点相对父级独有的授权，并同步更新其下属子树（若子树中包含另一个独立态分支，该独立分支继续保留自身授权）。

### 各类操作的权限要求矩阵

| 操作类型 | 所需权限与规则 |
| --- | --- |
| **查看文件列表 / 详情** | 知识库 `读权限` + 该文件 `读权限`；列表仅展示当前成员可读的文件并据此计算分页，仅持有子文件权限时父文件夹作为只读导航入口展示 |
| **修改集合内容（同步 / 训练参数 / 分块）** | 该文件 `写权限` |
| **修改集合自身属性（重命名 / 标签 / 禁用状态）** | 该文件 `管理员`（Manage）权限 |
| **移动文件 / 文件夹** | 源位置与目标位置均需 `管理员` 权限；根目录与文件夹之间移动还需团队知识库创建权限；移动请求同时修改属性时需具备该文件的 `管理员` 权限 |
| **配置协作者 / 恢复继承** | 该文件 `管理员` 权限，且知识库已开启集合权限 |
| **删除文件 / 文件夹** | 仅限该集合 `创建者`；批量删除时自动跳过非本人创建的集合并给出提示 |
| **集合所有权转移** | 仅限该集合 `创建者`，可转移给同团队成员，并同步转移下属子文件夹所有权 |
| **知识库所有权转移** | 级联转移该知识库下原创建者持有的全部文件与文件夹所有权 |

## 步骤三：核对检索身份与文件访问

1. **成员身份检索**：搜索测试及配置了当前成员鉴权的应用检索，会计算可读集合，并与元数据过滤条件取交集。
2. **应用预选知识库**：工作流预选知识库且 `authTmbId: false` 时，按应用访问设置运行，跳过成员级集合过滤。需要按用户隔离资料时，应开启成员鉴权并建立可信身份映射。
3. **特殊身份**：团队所有者及授权的系统 Root 操作具有提升权限；团队管理员仍按资源协作者配置鉴权。
4. **原文件链接**：下载和预览遵循存储服务的授权及签名规则。签名链接的持有人可能在有效期内访问文件，应将链接作为敏感凭证管理。

## 常见问题

### 1. 文件行菜单里没有「权限」入口？

该入口仅对具备该文件 `管理员`（Manage）权限的成员展示。请由文件创建者或知识库管理员为你授予管理权限。

### 2. 提示「该知识库尚未开启数据集权限，请先开启」？

说明当前知识库仍处于默认关闭态。请由知识库管理员按“步骤一”从任意集合行的 `··· → 权限` 入口完成首次开启与快照物化。

### 3. 关闭集合权限开关后原有的配置还能找回吗？

关闭开关会清空该知识库下所有集合的独立协作者记录并恢复为继承知识库权限。重新开启时会按当前知识库协作者重新生成继承态快照，因此关闭前请先记录关键集合的授权名单。
