FastGPT 知识库采用双引擎检索架构，将基于语义理解的高维向量检索与基于词频统计的全文检索结合，兼顾泛化理解能力与专业术语的精确命中率。

## 底层存储分工体系

系统将知识数据在物理基础设施中进行分层解耦存储：

| 存储组件 | 技术实现 | 核心存储内容 |
| --- | --- | --- |
| **业务与原文库** | MongoDB | 知识库元数据、集合目录树、数据块原始文本、训练记录、租约状态与 ACL 权限 |
| **向量数据库** | PGVector / Milvus / Zilliz / OceanBase 等 | 由 Embedding 模型生成的稠密向量（Dense Vectors）与分块标识映射 |
| **全文索引引擎** | MongoDB Text / Milvus BM25 | 中英文分词词典、倒排索引表与词频统计权重 |

## 检索双引擎工作机制

### 1. 向量检索引擎（Vector Search）
- **核心原理**：通过 Embedding 模型将文本映射至高维向量空间（如 1536 或 3072 维），由向量后端支持的距离度量计算语义匹配程度。维度与得分分布取决于模型和向量后端。
- **核心优势**：擅长理解同义替换、近义改写、意图泛化与跨语言表达。即使提问中包含不同的词汇，只要语义贴近即可准确命中。

### 2. 全文检索引擎（Full-Text Search）
- **核心原理**：对文本分词后按关键词相关度排序。实现取决于后端：MongoDB 使用文本索引，支持的 Milvus 路径使用 BM25。
- **核心优势**：在型号代码、法律法条条号、专业术语、人名专名与特定错误码查询中表现优异。

## 混合检索与两阶段 Rerank 机制

在复杂的企业知识问答场景中，系统采用两阶段混合检索管道（Two-Stage Retrieval Pipeline）：

```
[用户提问]
    │
    ├──► 阶段一：向量检索 ──► 提取 Top-N 语义候选分块 ──┐
    │                                                   ├──► 候选集归并与去重 ──► 阶段二：Rerank 重排 ──► 按 Token 预算输出上下文
    └──► 阶段一：全文检索 ──► 提取 Top-N 关键词候选分块 ──┘
```

1. **第一阶段：多路召回（Recall）**：
   系统并行向向量库与全文库发起检索，各自召回得分排名前列的候选分块（如各召回 20 条），并在内存中完成合并去重。
2. **第二阶段：重排计算（Reranking）**：
   将用户提问与候选分块文本直接输入 Rerank 模型。重排按配置启用，得分含义取决于所选模型与服务商，应使用已标注样本校准阈值。
3. **截断输出（Selection）**：
   系统按当前模式支持的得分类型过滤候选，再按 Token 预算选取排序后的分块。保留完整数据块时，累计内容可能越过预算边界。

## 核心搜索参数解析

在知识库搜索测试与应用挂载面板中，以下关键参数直接影响检索质量：

| 参数项 | 取值范围 | 配置建议与生效机理 |
| --- | --- | --- |
| **检索模式** | 向量检索 / 全文检索 / 混合检索 | 混合检索为首选项。它兼顾语义拓展与关键词精确命中。 |
| **引用上限（`limit`）** | Token 预算 | 控制检索上下文的体积，结合分块大小与应用上下文窗口调节。 |
| **最低相似度** | 以当前界面或契约为准 | 重排成功时使用重排得分；纯向量模式使用向量得分。其他模式可能跳过得分过滤，可通过返回的 `usingReRank` 和 `usingSimilarityFilter` 核对实际行为。 |
