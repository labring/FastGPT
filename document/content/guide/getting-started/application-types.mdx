FastGPT 提供三种主要应用形态：对话 Agent、对话 Agent V2 与工作流。选择合适的形态能够平衡系统的确定性、开发效率与复杂推理能力。

![在工作台创建应用时选择应用类型](/imgs/current/app-types.png)

## 三种应用形态运行机制

### 1. 对话 Agent（Chat Agent）

对话 Agent 采用单次推理执行模型。当用户发送消息时，系统按固定顺序装配提示词：
- 注入预设的系统提示词（System Prompt）。
- 根据滑动窗口规则载入历史对话轮次。
- 根据用户问题检索关联知识库，并将相关分块拼接为上下文事实。
- 调用大语言模型，直接流式生成最终回复。

该形态逻辑透明，调用链路短，适合规章制度问答、产品手册查阅与固定格式写作助手。

### 2. 对话 Agent V2（Chat Agent V2）

对话 Agent V2 采用 ReAct（Reasoning + Acting）自主推理循环。模型在此形态下充当逻辑规划中枢：
- **目标拆解**：评估复杂指令，推演执行下一步所需的数据与工具。
- **工具调用**：生成结构化参数，调用绑定的知识检索、网络搜索、计算沙箱或企业 API。
- **状态观察**：接收工具的执行返回值，结合上下文更新思维链。
- **循环迭代**：持续执行思考与行动，直至达成终态目标并向用户返回结论。

该形态具备自主环境交互能力，适合多源信息聚合、实时数据查询、计算分析与开放式任务处理。

### 3. 工作流（Workflow）

工作流基于有向无环图（DAG）调度引擎运行。开发者在画布上明确配置节点与连线：
- **显式控制流**：连线严格定义节点的执行依赖与并发顺序。
- **精准数据流**：上游节点的输出参数通过变量引用直接传递给下游输入端口。
- **丰富逻辑组件**：支持条件分支（If-Else）、循环遍历（Loop）、问题意图分类、表单输入等待与多分支并行处理。

该形态具备百分之百的执行确定性与严格的状态审查能力，适合业务审批审批链、多模型交叉核验、结构化数据提取与标准业务系统集成。

## 选型决策矩阵

围绕系统确定性、开发成本、推理能力与响应延迟展开对比：

| 评估维度 | 对话 Agent | 对话 Agent V2 | 工作流 |
| --- | --- | --- | --- |
| **执行确定性** | 适中（依赖提示词约束） | 动态（由模型自主规划） | 严格（由预设画布逻辑掌控） |
| **构建复杂度** | 极低（仅需提示词与知识库） | 中等（需配置工具集与沙箱） | 高度灵活（需设计连线与数据流） |
| **工具扩展能力** | 静态知识关联 | 动态自主工具选择 | 节点级精细化工具集成 |
| **多步骤推理** | 单轮生成 | 循环多步自主推演 | 多节点顺序与条件调度 |
| **首字响应延迟** | 极低（单一模型往返） | 动态（取决于工具调用轮数） | 阶段性（取决于前置节点耗时） |
| **典型应用场景** | 客服知识库、政策咨询 | 智能分析助手、开放任务助理 | 复杂审批流、数据管道、多模型质检 |

## 混合架构模式

在复杂的企业级生产方案中，三种形态可以相互组合编排：

### 工作流中嵌入 Agent 节点

在工作流中添加 [Agent 节点](/zh-CN/guide/build/workflow/nodes/agent)。在整体保持严格流程控制的同时，将局部开放性任务（如用户意图发散推理、开放式内容归纳）委托给 Agent 动态求解。

### 将工作流发布为工具

将特定工作流配置为 [工作流工具](/zh-CN/guide/build/tools/overview)。工作流对外声明标准入参和出参，随后作为工具直接挂载到对话 Agent V2 中供模型自主调度。这兼顾了局部逻辑的确定性与顶层任务的自主性。
