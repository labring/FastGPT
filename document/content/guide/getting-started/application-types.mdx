FastGPT 提供三种主要应用形态：对话 Agent、对话 Agent V2 与工作流。选择合适的形态能够平衡系统的确定性、开发效率与复杂推理能力。

![在工作台创建应用时选择应用类型](/imgs/optimized/current/app-types.png.webp)

## 三种应用形态运行机制

### 1. 对话 Agent（Chat Agent）

对话 Agent（简易版）采用表单化编排模式，支持配置系统提示词、关联知识库与挂载外部工具（插件、工作流工具、HTTP/MCP 工具）。当用户发送消息时，系统按预设流程执行：
- 注入预设的系统提示词（System Prompt）。
- 根据滑动窗口规则载入历史对话轮次。
- 根据用户问题检索关联知识库，并将相关分块拼接为上下文事实。
- 根据挂载的外部工具执行工具调用，并由大语言模型流式生成最终回复。

该形态配置直观、启动迅速，适合规章制度问答、产品手册查阅、固定格式写作助手及轻量工具调用场景。

### 2. 对话 Agent V2（Chat Agent V2）

对话 Agent V2 采用 ReAct（Reasoning + Acting）自主推理循环。模型在此形态下充当逻辑规划中枢：
- **目标拆解**：评估复杂指令，推演执行下一步所需的数据与工具。
- **工具调用**：自主调度内置能力（知识库检索、虚拟机、文件解析）、我的 agents、关联技能与自定义工具。
- **状态观察**：接收工具的执行返回值，结合上下文更新思维链。
- **循环迭代**：持续执行思考与行动，直至达成终态目标并向用户返回结论。

该形态具备 ReAct 动态规划、内置系统工具与独立虚拟机沙箱能力，适合多源信息聚合、实时数据查询、计算分析与开放式任务处理。

### 3. 工作流（Workflow）

工作流基于有向图调度引擎（支持受条件出口控制的回流）运行。开发者在画布上明确配置节点与连线：
- **显式控制流**：连线严格定义节点的执行依赖与并发顺序。
- **精准数据流**：上游节点的输出参数通过变量引用直接传递给下游输入端口。
- **丰富逻辑组件**：支持条件分支（If-Else）、循环遍历（Loop）、问题意图分类、表单输入等待与多分支并行处理。

该形态的执行路径由画布连线确定，可追溯每个节点状态，适合业务审批链、多模型交叉核验、结构化数据提取与标准业务系统集成。

## 选型决策矩阵

围绕系统确定性、开发成本、推理能力与响应延迟展开对比：

| 评估维度 | 对话 Agent | 对话 Agent V2 | 工作流 |
| --- | --- | --- | --- |
| **执行确定性** | 适中（依赖提示词约束） | 动态（由模型自主规划） | 路径确定（由画布连线与条件分支掌控） |
| **构建复杂度** | 极低（表单化配置提示词、知识库与工具） | 中等（配置系统工具、技能与虚拟机沙箱） | 高度灵活（需设计连线与数据流） |
| **工具扩展能力** | 支持挂载外部工具与关联知识库 | 内置系统工具、自定义工具与技能动态调度 | 节点级精细化工具集成 |
| **多步骤推理** | 知识检索与工具调用 | ReAct 动态规划与沙箱循环推演 | 多节点顺序与条件调度 |
| **首字响应延迟** | 极低（单一模型往返） | 动态（取决于工具调用轮数） | 阶段性（取决于前置节点耗时） |
| **典型应用场景** | 客服知识库、政策咨询 | 智能分析助手、开放任务助理 | 复杂审批流、数据管道、多模型质检 |

## 混合架构模式

在复杂的企业级生产方案中，三种形态可以相互组合编排：

### 工作流中调用 Agent

在新建工作流中，可通过节点面板的“Agent”标签页添加已创建的对话 Agent V2（即[应用调用](/zh-CN/guide/build/workflow/nodes/run_app)节点）；历史工作流中已有的独立 [Agent 节点](/zh-CN/guide/build/workflow/nodes/agent) 仍可继续维护运行。在保持主流程连线可控的同时，可将局部开放性任务委托给 Agent 动态求解。

### 将工作流发布为工具

在工作台“我的工具”中新建 [工作流工具](/zh-CN/guide/build/tools/workflow-tools)。工作流工具对外声明标准入参和出参，随后作为工具挂载到对话 Agent 或对话 Agent V2 中供模型自主调度，兼顾局部逻辑的可控性与顶层任务的自主性。
