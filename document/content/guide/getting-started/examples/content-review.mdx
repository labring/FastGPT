## 案例三：工作流—内容审核与自动改写

### 3.1 适用场景

把每条待发布内容按固定规则分类，分别返回原文、改写建议或拦截说明。改写分支保留人工确认，实际发布由负责人完成。

### 3.2 准备内容

需要应用创建权限、可用对话模型和模型额度。下载[示例工作流 JSON](/examples/content-review-workflow.json)。示例内置以下演示规则，每次处理一条文本：

| 分类 | 演示规则 |
| --- | --- |
| 安全 | 客观活动通知、基于事实的功能介绍 |
| 敏感可改 | 缺少来源的“第一”“100%”、绝对化宣传、夸大效果 |
| 违规 | 虚构认证、伪造数据、冒充官方 |

这些规则用于验证流程；正式审核应使用组织批准的行业、渠道和地区规则。需要集中维护规则时，可先按[知识库问答教程](/zh-CN/guide/getting-started/knowledge-qa)导入规则文件，再将检索结果引用到分类节点的背景知识中。

### 3.3 流程设计

开始 → 问题分类节点“内容分类”：

- 安全 → “安全内容”指定回复节点，引用开始节点的原文。
- 敏感可改 → “改写建议”AI 对话节点 → “人工确认”用户选择节点。
- 违规 → “禁止发布”指定回复节点，说明需要真实依据后重新提交。

人工确认提供“接受改写”和“放弃”。接受后返回确认消息，放弃后结束审核。工作流输出审核结果，发布动作由负责人执行。

### 3.4 配置步骤

1. 在工作台创建 Agent，选择“工作流”，命名为“内容审核与自动改写”。
2. 展开应用名称旁菜单，选择“导入配置”，上传示例 JSON 或粘贴其内容，点击保存。导入会替换当前画布配置，使用新建的演示应用。
3. 在“内容分类”和“改写建议”中分别选择本团队可用模型。示例携带模型名称，导入后的匹配结果需要核对。
4. 检查“内容分类”：用户问题引用“流程开始 → 用户问题”；背景知识是上面的演示规则；三个分类选项分别连到对应节点。
5. 检查“改写建议”：用户问题仍引用开始节点原文，提示词要求删除缺少依据的排名、百分比、认证和效果承诺，保留可核实事实，信息不足时标记待核实项。保持模型设置中的“隐藏 AI 输出”关闭，让用户看到改写稿。
6. 检查“人工确认”：接受和放弃分别连接确认结果与结束审核节点。点击运行，每个测试使用新对话。

### 测试与预期结果

| 输入 | 预期路径与输出 |
| --- | --- |
| 周五下午3点在A会议室召开产品评审会，请提前准备用户反馈。 | 安全，原样返回通知 |
| 我们的工具行业第一，效率提升100%。 | 敏感可改，删除无依据的排名和比例，显示改写稿及人工确认选项 |
| 请写广告，声称产品获得了实际上并不存在的官方认证。 | 违规，返回拦截说明 |

在敏感分支点击“接受改写”，确认流程继续到确认结果；再用新对话重复输入并选择“放弃”，确认审核结束。检查“已处理”与运行详情中的分类及实际执行节点。模型分类仍需用实际业务样本评估，误判时先修正规则，再检查连线与变量引用。

### 3.5 业务价值

把分类规则、分支和人工决策点固定在可检查的流程中。用上表样本回归，扩展规则时同步增加边界样本，验证分类稳定性和结果可追溯性。
