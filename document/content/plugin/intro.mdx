> 本文档适用于 FastGPT Plugin v1.0.0 及以上版本的插件系统。

插件开发是 FastGPT 开发者文档中的扩展开发专题。根据要交付的能力选择指南：

| 开发目标 | 开始阅读 | 交付方式 |
| --- | --- | --- |
| 创建第一个工具插件 | [快速开始](/zh-CN/plugin/quick-start) | 本地验证后生成 `.pkg` 工具包 |
| 实现单工具或工具集 | [工具开发指南](/zh-CN/plugin/system-tool-development) | SDK 定义、调试、构建与打包 |
| 增加模型或供应商预设 | [模型预设指南](/zh-CN/plugin/model-presets) | 修改插件仓库中的静态配置并提交变更 |
| 开发智能体技能 (Skill) | [技能开发教程](/zh-CN/guide/build/skill/development) | 在沙盒中编写并在应用中绑定执行 |

安装现成插件请阅读[团队安装与管理](/zh-CN/plugin/team-installation)。系统管理员可进入[系统工具管理](/zh-CN/guide/build/tools/system-plugins/upload_system_tool)和[插件运行时配置](/zh-CN/plugin/runtime)。

推荐开发基线环境：FastGPT v4.15.0+，FastGPT Plugin v1.0.0+，Node.js >= 20.x（推荐 LTS 20 或 22），pnpm >= 9.x。

## 背景

FastGPT Plugin 将插件服务、SDK 和 CLI 集中在[独立仓库](https://github.com/labring/fastgpt-plugin)中维护，使插件可以按各自的版本迭代。工具作者通过 CLI 创建项目，使用 SDK 实现功能，并把构建后的插件包交付给 FastGPT。

## 设计目标

- 独立迭代：插件源码、版本和分发渠道可以独立维护。
- 开发路径清晰：工具作者从创建、调试到打包使用同一套 CLI 与 SDK。
- 运行隔离：插件服务负责执行环境、进程池和请求调度。
- 按资源扩展：每类资源有自己的声明、验证与交付流程。

## 核心概念

| 名称 | 说明 |
| --- | --- |
| 插件 | 为 FastGPT 扩展能力的独立资源；开发步骤取决于资源类型。 |
| 工具 | 封装接口或计算逻辑，供工作流和 Agent 调用。 |
| 工具集 | 在一个插件中提供多个子工具，共享元信息与密钥配置。 |
| 插件包 | 当前工具插件的 `.pkg` 交付文件，用于安装与版本管理。 |
| 模型预设 | 插件服务提供的模型供应商、模型能力和默认参数等静态配置。 |
| 插件市场 | 发现和分发官方及社区插件的 Marketplace。 |
| 运行时 | 执行插件代码并管理资源的后端实现，当前默认采用 `local-pool`。 |
| Pod | `local-pool` 中的插件工作进程。 |

## 仓库结构

插件作者主要接触以下入口：

| 路径 | 职责 |
| --- | --- |
| `apps/cli/` | 创建、调试、构建、检查与打包命令 |
| `sdk/factory/` | 作者侧 SDK，定义工具、工具集、Schema 与 handler |
| `sdk/client/` | FastGPT 主服务调用插件服务的客户端 SDK |
| `apps/server/` | 插件服务的启动与 HTTP 接口 |
| `packages/infrastructure/src/static-data/models/` | 模型与供应商预设 |

服务内部的分层与依赖关系见 [FastGPT Plugin 架构文档](https://github.com/labring/fastgpt-plugin/blob/main/docs/dev/architecture.zh.md)。

## 仓库分工

| 仓库 | 维护内容 |
| --- | --- |
| `labring/fastgpt-plugin` | 插件服务、CLI、SDK、运行时与模型预设 |
| `fastgpt-official-plugins` | 官方维护或审核通过的工具插件 |
| `fastgpt-community-plugins` | 社区贡献的工具插件 |
| `fastgpt-business-plugins` | 私有插件、客户定制与商业交付插件 |

### 插件元数据的多语言展示

FastGPT 保留插件元数据中的多语言对象，在 UI 展示时按当前语言选择，并按当前语言、简体中文、英文顺序回退。普通字符串继续兼容旧插件及缓存。

- 插件名、简介、工具集子工具文案，以及输入、输出和密钥 Schema 的 `x-i18n` 文案用于 UI；旧 Schema 文案字段继续作为回退。
- 工具的模型 function description 由名称和按 UI/metadata locale 解析后的简介组成；不会再按调度请求语言重新选择独立描述。
- README 优先使用 `readmeUrls` 当前语言，再回退简体中文、英文和旧 `readmeUrl`。
- 工作流节点及 Agent 中固定的插件工具会保存添加时的文案语言快照；修改 UI 语言不会改写既有快照。内置 Workflow 模板保持原样。

## `.pkg` 插件包协议

工具插件以 `.pkg` 文件交付。作者需要维护入口、元信息和 Schema；产物结构与 SDK 入口见[插件包与 SDK 参考](/zh-CN/plugin/package-reference)。

## local-pool 运行时

插件服务按工具插件管理工作进程与请求队列。进程数量、并发容量及运行配置由部署环境管理，详细说明见[插件运行时配置](/zh-CN/plugin/runtime#local-pool-运行时)。

## 开发与分发

工具开发从[首个工具教程](/zh-CN/plugin/quick-start)开始，完成实现后进入[调试、打包与发布](/zh-CN/plugin/debugging-and-publishing)。模型预设通过仓库中的静态配置提交变更，按[模型预设指南](/zh-CN/plugin/model-presets)完成验证。
