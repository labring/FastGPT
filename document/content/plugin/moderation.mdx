> 本文档适用于 FastGPT v4.18.0 及以上版本。从旧版商业版内置审查升级的部署，请同步参阅[内容审核升级与迁移指南](/zh-CN/self-host/migration/content-moderation)。

FastGPT 将内容审核（Content Moderation）抽象为独立插件类型 `moderation`，由 `fastgpt-plugin` 插件服务统一托管运行。平台管理员可在后台一站式配置审核服务、生效环节、疑似风险与异常降级策略；开发者也可基于 `@fastgpt-plugin/sdk-factory` 编写适配器插件，接入内部安全网关或第三方内容审核服务。

## 整体架构与职责分工

内容审核采用「平台统一调度 + 插件厂商适配」的分离架构：

| 组件                    | 核心职责                                                                                                                                             |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| **FastGPT 主服务**      | 管理后台策略配置、插件凭据加密存储（AES-256-GCM）、三大运行时审核锚点拦截、流式输出缓冲截断、审核记录（`system_moderation_records`）与管理员操作审计 |
| **FastGPT Plugin 服务** | 托管 `moderation` 插件包安装与版本管理，在隔离进程池（`local-pool`）中提供 `GET /moderation` 与 `POST /moderation/check` 同步文本审查接口            |
| **Moderation 插件**     | 通过 `defineModeration()` 封装外部或本地审核规则，将各厂商响应归一化为标准的四档裁决（`verdict`）与风险命中明细（`hits`）                            |

核心运行边界：

- **单插件互斥启用**：平台可安装并保留多个审核插件的配置，但同一时间仅允许启用一个**当前生效服务**，避免多厂商标准冲突导致裁决语义模糊。
- **同步文本审查**：当前版本聚焦同步文本合规审查（`input.content`），支持在流式输出场景携带分段追踪上下文；暂不涵盖图像、音视频异步回调审查。
- **入口权限范围**：管理后台的 **内容审核 → 审核策略配置**（`/admin/moderation/policy`）面向已激活商业版 License 的 `root` 系统管理员开放。

## 一、使用与管理配置

### 1. 安装并配置审核服务

使用 `root` 管理员登录后台，进入 **内容审核 → 审核策略配置**（`/admin/moderation/policy`）：

1. 打开 **是否开启内容审核** 开关（默认关闭）。
2. 在插件列表区域安装审核插件：
   - **从插件市场添加**：跳转到插件市场审核分类（`/config/tool/marketplace?type=moderation`），可直接安装官方提供的 **百度内容安全**（`baidu`）、**阿里云内容安全**（`aliyun`）、**腾讯云内容安全**（`tencent`）、**关键词审核**（`keyword`）或 **旧版自定义审核兼容**（`legacy-custom-censor`）插件。
   - **从本地安装**：上传自行打包或离线分发的 `.pkg` / `.zip` 插件包。
3. 点击目标插件右侧的 **配置参数**，按插件声明的表单填写厂商凭据或策略 ID：
   - 标记为敏感字段的密钥在服务端采用 AES-256-GCM 加密存储，接口和界面均做脱敏展示，修改时需填写新值，留空则保留已有密钥或按插件校验规则清理。
   - 点击保存时，服务端会使用当前配置向插件发送一条固定非敏感文本执行连通性检测；若返回 `verdict: 'error'` 或调用失败，则拒绝保存，避免把错误凭据写入线上配置。
4. 启用与切换规则：
   - 系统尚无已启用插件时，**首个配置完成的插件会自动启用**。
   - 存在多个已配置插件时，点击目标插件的 **启用** 即可互斥切换到该插件。
   - 卸载采用软卸载（保留已保存凭据，重新从市场或本地安装同插件即可恢复配置）；若存在多个已安装插件，需先切换到其他插件再卸载当前使用中的插件；若卸载最后一个审核插件，系统会自动关闭内容审核总开关。

### 2. 审核生效环节（Hooks）

开启内容审核后，三个审核环节默认全部启用，可按业务需要独立勾选：

| 生效环节                      | 触发时机                                                 | 审查范围                                                                                                                          | 命中拦截后的行为                                                               |
| ----------------------------- | -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| **用户输入**（`userInput`）   | 进入工作流调度与任何节点之前                             | 本轮用户输入文本（`query` / `userChatInput`）、自定义全局变量与动态表单输入中的文本                                               | 立即抛出错误阻断请求，应用不开始执行、不消耗模型额度，客户端可回滚本轮临时消息 |
| **模型输入**（`modelInput`）  | AI 对话、工具调用（`toolCall`）及 Agent 节点请求大模型前 | 组装后发往本轮模型的系统提示词、本轮用户消息、知识库引用与当前轮次解析的文档文本；**历史对话消息（Histories）及历史轮次文件免审** | 模型节点直接报错终止，不向大模型发起请求、不计费                               |
| **最终输出**（`finalOutput`） | 平台准备向用户交付文本输出或工具参数时                   | AI 对话文本、指定回复节点、用户选择提示、表单输入提示以及模型生成的工具调用参数                                                   | 非流式整段阻断；流式输出按间隔累计审查并在违规时立即截断中止生成               |

补充说明：

- **Agent / 工具调用内部响应保护**：在 Agent Loop 或 ToolCall 工具循环中，工具执行返回的响应结果（包含普通工具、子工作流、内置检索或文件读取结果）在启用 `modelInput` 或 `finalOutput` 时也会接受审查；若响应违规，平台会将该工具结果替换为统一脱敏提示（`该信息因内容审核不通过，无法返回`），让 Agent 感知结果受限并继续后续规划，而不是直接中断整条推理链。
- **流式输出缓冲机制**：流式生成不会逐字孤立送审（避免敏感词跨 chunk 切分漏检），而是按 **流式审核间隔** 累计新文本并连同前序上下文送审；一旦命中拦截，平台立即停止向下游推送未审核分块、中止上游模型流式请求并丢弃未展示内容。

### 3. 处理策略（Strategy）

在 **处理策略** 板块可配置以下三项全局规则：

| 配置项           | 默认值           | 可选值与影响                                                                                                                                                                                                                               |
| ---------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **流式审核间隔** | `100` 字符/次    | 大于等于 `1` 的整数。数值越小，首字与分块等待越短，但审核 API 调用频次和费用越高；数值越大，调用更省，但单次等待输出略长                                                                                                                   |
| **疑似风险**     | `拦截并记录`     | 针对插件返回 `verdict: 'suspected'` 的处置方式：可选 **拦截并记录**（`blockAndLog`）或 **放行并记录**（`passAndLog`）                                                                                                                      |
| **服务异常**     | `放行未审核内容` | 针对插件返回 `verdict: 'error'`、插件不可用或调用异常的降级策略：可选 **放行未审核内容**（`pass`，fail-open）或 **拦截未审核内容**（`block`，fail-closed）。选择拦截时，一旦审核服务故障将导致应用无法正常对话，请结合业务合规等级谨慎选择 |

所有策略修改需点击右上角 **保存** 后生效（其中通过插件市场安装或点击「启用」切换插件时，系统会保留当前页已编辑的草稿状态并按需同步激活状态）。

### 4. 在线测试与审计查看

- **审核效果测试**：开启内容审核并选中生效服务后，策略页底部会展示测试面板。输入测试文本并点击 **开始测试**，可直接查看插件返回的原始四档裁决、命中标准标签及置信度、敏感词高亮与异常信息，且测试调用不会受 `疑似风险` / `服务异常` 策略改写。
- **对话运行详情**：在应用对话记录或调试运行详情中，拥有对应应用写权限的成员可查看节点执行明细里的审核记录（展示触发环节、裁决结果、命中标签、关键词与送审原文）。
- **平台审计与持久化记录**：管理员对审核插件的安装、参数保存、启用/切换、卸载以及策略更新操作均会记录到平台审计日志；运行时所有审查调用与裁决异步落库至 `system_moderation_records` 集合，可通过 `/api/core/plugin/admin/moderation/records` 或 `/admin/moderation/records` 页面按审核环节与裁决结果筛选调阅。

## 二、自定义 Moderation 插件开发

如需接入自建安全网关或未内置的第三方审核服务，可基于 FastGPT 插件体系扩展 `moderation` 类型插件：

- **环境准备与打包发布**：Node.js/pnpm 环境、目录约定、本地调试与 `.pkg` 打包上架流程与工具插件一致，请参见[系统工具开发指南](/zh-CN/plugin/system-tool-development)与[调试、打包与发布](/zh-CN/plugin/debugging-and-publishing)。
- **脚手架与核心契约**：执行 `npx @fastgpt-plugin/cli create my-moderation --type moderation` 生成模板；入口使用 `defineModeration()` 与 `defineModerationManifest()`，通过 `secretSchema` 声明凭据与厂商策略 ID，接收同步文本 `input.content` 并返回标准 `verdict`（`pass` / `block` / `suspected` / `error`）与 `hits`。上游请求异常应捕获后返回 `ctx.moderationError('...')`，避免直接抛出。

使用 Claude Code、Codex 或其他 Coding Agent 开发时，可直接复制以下提示词：

```plaintext
请参考 FastGPT 官方插件开发 Skill（https://raw.githubusercontent.com/labring/fastgpt-official-plugins/refs/heads/main/.agents/skills/develop-fastgpt-plugin/SKILL.md）与插件开发文档，使用 `npx @fastgpt-plugin/cli create <plugin-name> --type moderation` 为我开发一个对接【填写审核服务名称与接口文档】的 FastGPT 内容审核插件，完成 `defineModeration()` 实现、`secretSchema` 配置、单元测试、本地 debug 验证与 `.pkg` 打包。
```
