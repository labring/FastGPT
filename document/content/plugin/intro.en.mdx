## Background

[FastGPT Plugin](https://github.com/labring/fastgpt-plugin) maintains the plugin service, SDKs, and CLI in a dedicated repository so plugins can evolve with their own versions. Tool authors create projects with the CLI, implement capabilities with the SDK, and deliver built packages to FastGPT.

## Design Goals

- Independent iteration: maintain plugin source, versions, and publishing channels separately.
- Clear development paths: use the CLI and SDK from project creation through debugging and packaging.
- Runtime isolation: let the plugin service manage execution environments, process pools, and request scheduling.
- Resource-specific development: give each resource its own declarations, validation, and delivery workflow.

## Core Concepts

| Term | Meaning |
| --- | --- |
| Plugin | A resource that extends FastGPT; its development steps depend on the resource type. |
| Tool | An API or computation exposed for Workflows and Agents to call. |
| Toolkit | Multiple child tools in one plugin with shared metadata and secret configuration. |
| Plugin package | The `.pkg` delivery file used to install and version tool plugins. |
| Model preset | Static provider, capability, and default-parameter configuration supplied by the plugin service. |
| Marketplace | A discovery and publishing channel for official and community plugins. |
| Runtime | The backend that runs plugin code and manages resources; the default is `local-pool`. |
| Pod | A plugin worker process in `local-pool`. |

## Repository Structure

Plugin authors primarily use these entry points:

| Path | Responsibility |
| --- | --- |
| `apps/cli/` | Create, debug, build, check, and pack commands |
| `sdk/factory/` | Author SDK for tools, Toolkits, schemas, and handlers |
| `sdk/client/` | Client SDK used by the FastGPT main service to call the plugin service |
| `apps/server/` | Plugin server startup and HTTP interfaces |
| `packages/infrastructure/src/static-data/models/` | Model and provider presets |

For internal layers and dependencies, see the [FastGPT Plugin architecture](https://github.com/labring/fastgpt-plugin/blob/main/docs/dev/architecture.md).

## Repository Responsibilities

| Repository | Maintained content |
| --- | --- |
| `labring/fastgpt-plugin` | Plugin service, CLI, SDKs, runtime, and model presets |

### Localized Plugin Metadata

FastGPT preserves localized plugin metadata and selects text at the UI presentation boundary, falling back from the active locale to Simplified Chinese and then English. Legacy string values remain supported for older plugins and cached responses.

- Plugin names, introductions, toolkit child metadata, and `x-i18n` text in input, output, and secret schemas are used in the UI; ordinary schema text remains the fallback for older plugins.
- A tool's model function description combines its name with the introduction resolved for the UI/metadata locale; FastGPT no longer selects a separate description by dispatch request language.
- README selection prefers the active locale in `readmeUrls`, then Simplified Chinese, English, and the legacy `readmeUrl`.
- Workflow nodes and Agent tool selections retain the metadata locale snapshot from when the plugin tool was added; changing the UI locale does not rewrite existing snapshots. Built-in Workflow templates remain unchanged.

## `.pkg` Plugin Package Protocol

Tool plugins are delivered as `.pkg` files. Authors maintain the entry point, metadata, and schemas. See [package and SDK reference](/en/plugin/package-reference) for artifacts and SDK entry points.

## local-pool Runtime

The plugin service manages worker processes and request queues for tool plugins. Process counts, concurrency, and runtime settings belong to the deployment environment. See [plugin runtime configuration](/en/plugin/runtime#local-pool-runtime).
