## 升级指南

### 配置变更

- `HNSW_EF_SEARCH` / `systemEnv.hnswEfSearch` 的默认值从 `100` 调整为 `200`，适用于 PostgreSQL、Milvus、OceanBase、SeekDB 和 openGauss；显式配置的值继续生效，可按召回率与查询耗时调整。
- `HNSW_MAX_SCAN_TUPLES` / `systemEnv.hnswMaxScanTuples` 不再生效，管理台移除对应设置；PostgreSQL 的扫描上限改按本次索引检索涉及的最大知识库向量行数自动设置，上限为 `2147483647`，已有部署可移除旧配置。
- 默认部署的对象存储改为 RustFS，已有部署可继续使用原存储，如需切换请参考 [MinIO 迁移到 RustFS](/self-host/docker_minio_to_rustfs)。

- **内容审核（Moderation）插件化迁移**：旧版商业版内置的百度文本审核（`censor.BAIDU_TEXT_CENSOR_CLIENTID` / `censor.BAIDU_TEXT_CENSOR_CLIENTSECRET`）、自定义审核地址（`censor.customCensorURL`）以及单模型配置中的 `censor` 开关已废弃，统一升级为由 `fastgpt-plugin` 托管的 `moderation` 插件体系。
  - 原百度审核用户请前往 **管理后台 > 内容审核 > 审核策略配置**，配置并启用官方「百度内容安全（`baidu`）」插件。
  - 原自定义审核 URL（`customCensorURL`）用户可直接安装官方「旧版自定义审核兼容（`legacy-custom-censor`）」插件零代码迁移现有 HTTP 服务，或基于 `@fastgpt-plugin/sdk-factory` 开发原生 `moderation` 插件。
  - 详细的新旧版本对比、配置映射与开发步骤见 [内容审核升级与迁移指南](/self-host/migration/content-moderation)。

### 镜像更新

### 升级脚本

新增 **初始化知识库向量索引**（`20261022_initialize_dataset_vector_indexes`），仅 PostgreSQL 在启动后于后台自动执行，不阻塞业务：先核验并在线删除旧全局 `vector_index`，再分批统计有效知识库并投递索引维护任务。任务成功表示统计与投递完成，实际建图由全局串行队列继续执行；清理或扫描失败时，可在升级管理页修复问题后重试，沿已保存的断点继续，同名但定义不匹配的自建索引会保留并报错。

PG 局部索引要求支持 `halfvec`、固定向量维度在 `1–4000` 范围内，并具备在线创建、删除索引的权限及足够的内存、共享内存和磁盘资源。索引未就绪或失败期间继续精确检索，可能增加查询耗时；建图失败不会自动降低资源预算重试，排除故障后由下一次真实向量计数重新投递，缓存命中不会触发重试。

### 兼容说明

- **工作流历史记忆**：内容提取、问题分类与 Pi Agent 的记忆键改按来源和调用路径隔离，直接读写 `ChatItem.memories` 的自定义集成需适配新键，不再依赖 `agentLoopMemory-${nodeId}` 或不含调用路径的子流程键。
- **API 身份参数**：`chat/completions` 不再接受同时传入 `customUid` 和 `authProxy`，即使 `customUid` 为空字符串也会报参数错误；已有同时传参的调用需按使用者标记或成员代理场景保留其中一个。
- **日志 CSV**：基于「使用者」列解析团队成员的脚本需适配 `ID:name` 格式（旧版为成员名），成员缺少姓名时仅输出 ID。

## 🚀 新增内容

1. **[模型与计费]** 模型管理新增拖拽自定义排序，支持保存前取消；root 可调整系统模型，商业版启用团队模型后，具有「安装模型」权限的成员可调整自己的模型顺序。「可用模型」按本人、共享团队、系统模型分组并在组内应用自定义顺序，JSON 配置更新保留排序，客户端的最终系统模型兜底也使用该顺序。
2. **[系统与运维]** 对话日志新增默认隐藏的「鉴权者」列，与「使用者」分开展示，便于区分接入方用户和实际鉴权成员；API 传入的 `customUid` 按原值显示为使用者，CSV 按所选列导出。

## ⚙️ 优化

1. **[知识库与文件]** PostgreSQL 按知识库维护 FP16 局部 HNSW 索引，向量行数超过 `10000` 时按需建图，低于 `5000` 时移除，中间区间保留已有状态；未就绪或无索引的知识库走精确检索，各组候选统一以 FP32 距离排序，原向量存储精度不变。
2. **[知识库与文件]** 商业版简易应用与 ChatAgent 的标签过滤移入搜索参数的「搜索过滤」页签，并补充独立开关；手动输入模式关闭时保留条件，重新开启可继续编辑，参数提示按开关状态显示是否启用。
3. **[知识库与文件]** 将文件上传按身份累计的每分钟限流额度提高至原来的 3 倍，减少连续或批量上传时触发「请求过于频繁」的情况。
4. **[模型与计费]** 统一移动端模型选择、语音播放、渠道绑定、模型日志与仪表盘筛选中的测试模式模型排序，将测试模式模型置后，同组内保留目录顺序。
5. **[模型与计费]** 模型管理表格统一表头与表体列宽，按行维护编辑弹窗状态，减少大列表打开弹窗时的整表重渲染。
6. **[对话体验]** 优化列表滚动分页，减少滚动触发的重复渲染；内容收缩至不足一屏时，滚动仍可触发继续加载。
7. **[团队与权限]** 统一联系方式及通知接收账号弹窗的关闭按钮位置与样式。
8. **[系统与运维]** 补充 OpenSandbox 启动排障说明，帮助排查卷权限正常但 `/workspace` 仍不可写时的宿主机 seccomp 限制。

## 🐛 修复

1. **[工作流与 Agent]** 修复多个子应用或工作流工具调用同一目标时，内部节点记忆互相覆盖的问题。按完整调用路径隔离内容提取、问题分类与 Pi Agent 状态，覆盖克隆应用共享后代工具、递归进入根应用等场景。
2. **[工作流与 Agent]** 修复 Agent、工具调用及嵌套子流程的记忆未完整回传、未执行分支的历史记忆丢失，以及并发子流程用旧状态覆盖其他节点新状态的问题；仅合并子流程本次更新，保留其他有效记忆。
3. **[工作流与 Agent]** 修复循环、并行运行中的记忆传递与失败隔离问题。循环在成功迭代间传递记忆，交互暂停保留检查点，失败迭代不提交；并行任务仅合并成功结果，失败尝试不影响重试，并按输入顺序合并，同一记忆键以靠后的成功任务为准。
4. **[工作流与 Agent]** 修复嵌套 Pi Agent 在历史为 0 或空自定义历史时无法继续提问交互的问题，续跑时恢复父流程保存的状态。
5. **[工作流与 Agent]** 修复旧 Agent 的知识库引用回退为手动选择后，残留引用值导致保存失败的问题；Agent 与知识库搜索节点的手动选择会过滤格式异常项，并保留其余知识库选择。
6. **[工作流与 Agent]** 修复技能编辑沙盒未运行时导出失败的问题，服务端在可初始化状态下先启动或恢复沙盒，等待就绪后再打包；可编辑成员需等待沙盒就绪，只读协作者的导出入口不再受本地编辑沙盒状态限制。
7. **[工作流与 Agent]** 修复多行文本框在输入法组合输入及确认候选词时重置光标、干扰输入的问题。
8. **[工作流与 Agent]** 修复工具及表单参数配置弹窗内容较多时无法正常滚动的问题。
9. **[对话体验]** 修复免登录分享对话顶部变量面板按普通对话规则展示变量的问题，外部变量不再向分享用户显示。
10. **[对话体验]** 修复免登录分享对话中的全局变量、交互表单使用模型选择器时，未携带分享鉴权信息，导致模型列表或已选模型名称加载失败的问题。
11. **[对话体验]** 修复 Markdown 图片描述包含成对方括号（如 `![Image [1]](...)`）时漏识别图片的问题，图片提取与替换现可正常处理这类描述。
12. **[对话体验]** 补齐沙盒连接及文件错误提示、技能生成状态和工具版本标签的简体中文、繁体中文、英文及韩文文案，修复部分界面显示内部键名或缺少翻译的问题。
13. **[团队与权限]** 修复新建、导入 JSON、复制应用及转为工作流副本时，因引用不可读或已不存在的资源而整体失败的问题。初始版本只记录可读资源的授权快照，节点中仍不可用的引用在详情页标记异常，供后续调整。
14. **[团队与权限]** 修复登录及成员名表单在输入法组合输入期间按回车确认候选词时误提交的问题，确认后再次按回车才提交。
15. **[团队与权限]** 修复账号注销确认弹窗的「取消」按钮未正确使用当前界面语言的问题。
16. **[系统与运维]** 修复对话日志同时按使用者、反馈和会话搜索筛选时，条件相互覆盖的问题，列表与 CSV 导出现在组合应用全部筛选条件。
17. **[工具与渠道]** 修复繁体中文界面中部分工具名称、简介和标签的繁体翻译为空时显示空白的问题，优先回退简体中文，仍无有效文案时回退英文。

## 🛠️ 代码优化

1. **[系统与运维]** 新增手动触发的 GitHub Actions 已合并 PR 回移流程，默认目标分支为 `v4.17.x`，可按需修改，完成后生成草稿 PR。仓库维护技能 `fastgpt-backport-pr` 支持向显式指定的维护分支批量回补，机械冲突自动处理、逻辑冲突需人工确认；局部验证后直接推送代码，回补 `v4.17.x` 时对齐 Pro 同名维护分支，对应进行中版本的中英文文档则基于 `upstream/main` 单独提交 PR。
2. **[系统与运维]** 完善仓库 `pr-review` 技能的审查规范，纳入 PR 评论、Review 正文和行内讨论；复查时结合历史报告与当前完整差异，逐项核对旧问题的修复状态及新增风险，并保留判断依据。
