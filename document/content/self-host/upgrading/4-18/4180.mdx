## 升级指南

**升级前提**：先在 4.17.x 完成所需历史迁移，再升级到本版本；4.18.x 已移除旧任务的注册与实现，不会继续执行，数据库中的历史状态和错误明细保留。

### 配置变更

- 新增 `SERVICE_AXIOS_MAX_CONTENT_LENGTH`，默认 `20` MiB，限制服务端共享 HTTP 客户端缓冲型响应的解压后大小，超限中止请求；依赖更大响应的自定义接入需调大此值。调用方显式设置的响应上限优先，流式下载仍按调用方或业务配额限制。
- `HNSW_EF_SEARCH` / `systemEnv.hnswEfSearch` 的默认值从 `100` 调整为 `200`，适用于 PostgreSQL、Milvus、OceanBase、SeekDB 和 openGauss；显式配置的值继续生效，可按召回率与查询耗时调整。
- `HNSW_MAX_SCAN_TUPLES` / `systemEnv.hnswMaxScanTuples` 不再生效，管理台移除对应设置；PostgreSQL 的扫描上限改按本次索引检索涉及的最大知识库向量行数自动设置，上限为 `2147483647`，已有部署可移除旧配置。
- 新增 `SHOW_OUTLINK_BRAND`：未配置 `PRO_URL` 时固定为 `true`；接入 Pro 后默认 `false`，可设为 `true` 启用品牌展示。前端 `show_outlink_brand` 由服务端环境派生，覆盖 `config.json` 中的同名配置。
- 商业版新增模型下架提醒短信模板 `auth.sms.MODEL_DEPRECATION`；当前短信统一使用该中文模板，不按用户语言选择，`auth.sms.MODEL_DEPRECATION_EN` 配置暂不生效。启用短信提醒前需在管理台配置中文模板 ID。
- **插件服务部署**：Docker Compose 模板补齐 `fastgpt-plugin` 的 `FASTGPT_BASE_URL=http://fastgpt-app:3000`，将 `MONGODB_URI` 指向独立的 `fastgpt-plugin` 数据库，并显式设置 `DB_MAX_LINK=100`，避免与主库集合混用；自定义部署应填写插件容器可访问的主服务地址；若插件容器日志出现反向上传文件 `401`，优先核对该地址，修正后重建插件容器并重试工具。已有部署替换模板前应核对原插件库，保留已使用的独立库连接；若需切换数据库，先备份并迁移既有插件数据。
- 默认部署的对象存储改为 RustFS，已有部署可继续使用原存储，如需切换请参考 [MinIO 迁移到 RustFS](/self-host/docker_minio_to_rustfs)。

- **内容审核（Moderation）插件化迁移**：旧版商业版内置的百度文本审核（`censor.BAIDU_TEXT_CENSOR_CLIENTID` / `censor.BAIDU_TEXT_CENSOR_CLIENTSECRET`）、自定义审核地址（`censor.customCensorURL`）以及单模型配置中的 `censor` 开关已废弃，统一升级为由 `fastgpt-plugin` 托管的 `moderation` 插件体系。
  - 原百度审核用户请前往 **管理后台 > 内容审核 > 审核策略配置**，配置并启用官方「百度内容安全（`baidu`）」插件。
  - 原自定义审核 URL（`customCensorURL`）用户可直接安装官方「旧版自定义审核兼容（`legacy-custom-censor`）」插件零代码迁移现有 HTTP 服务，或基于 `@fastgpt-plugin/sdk-factory` 开发原生 `moderation` 插件。
  - 详细的新旧版本对比、配置映射与开发步骤见 [内容审核升级与迁移指南](/self-host/migration/content-moderation)。

- **全新部署**：`main` Compose 模板默认 MongoDB 更新为 `8.0.34`，初始化和健康检查统一使用 `mongosh`，副本集主节点就绪后再放行依赖服务。

### 升级脚本

本次脚本均为自动执行，无需手动执行。

1. 新增 **初始化知识库向量索引**（`20261022_initialize_dataset_vector_indexes`），仅 PostgreSQL 在启动后于后台自动执行，不阻塞业务：先核验并在线删除旧全局 `vector_index`，再分批统计有效知识库并投递索引维护任务。任务成功表示统计与投递完成，实际建图由全局串行队列继续执行；清理或扫描失败时，可在升级管理页修复问题后重试，沿已保存的断点继续，同名但定义不匹配的自建索引会保留并报错。
2. PG 局部索引要求支持 `halfvec`、固定向量维度在 `1–4000` 范围内，并具备在线创建、删除索引的权限及足够的内存、共享内存和磁盘资源。索引未就绪或失败期间继续精确检索，可能增加查询耗时；建图失败不会自动降低资源预算重试，排除故障后由下一次真实向量计数重新投递，缓存命中不会触发重试。
3. 新增 **回填历史对话调用渠道**（`20261104_backfill_chat_publish_source`），启动后独立在后台批量读写，不阻塞业务，也不等待普通后台长任务；分别为对话与统计记录补齐 `publishSource`，不修改旧字段、身份、消息或统计计数。历史 API、MCP 及已删除渠道可能只能恢复类型，无法补齐渠道 ID；无法识别的旧来源统一归为 `unknown`，不猜测渠道归属。此前因来源枚举失败的记录可在升级管理页直接重试，无需修改旧数据或重置进度；其他引用冲突或数据异常仍会记录失败，修复后沿断点续跑。完成校验改为分批扫描并保存断点，中断或修复校验异常后从对应批次继续；旧断点仅重新校验，保留已完成的回填。
4. 新增 **回填 API Key 类型**（`20261104_backfill_openapi_key_type`），自动分批遍历全部密钥，将缺失的 `type` 补为 `personal`，有效 `appId` 统一保存为 BSON ObjectId；保留凭证、归属、额度及默认应用或绑定语义。运行期管理查询只支持已规范化的数据格式；迁移期间或旧实例继续写入的旧格式数据不在查询兼容范围内。首次扫描上界之后的旧格式记录不会自动补迁，需另行规范化。异常数据可在升级管理页修复后重试。
5. 新增 **回填 STT 计价类型**（`20261112_backfill_stt_pricing_type`），启动后在后台分批执行，不阻塞业务；为缺少计价类型的旧语音识别模型补齐 `duration`，保留原单价、已配置类型及其他字段。异常价格会记录失败，修复后可在升级管理页重试，优先处理失败记录并沿断点继续。

### 兼容说明

- **历史 API 密钥**：无需重新生成。缺少 `type` 的旧 Key 自动归为个人密钥，原 `appId` 仍作为默认对话目标，访问权限和个人管理方式不变；新建的应用 Key 则仅用于绑定应用，由应用管理员共同管理。
- **API Key 健康检查**：由于安全问题，`GET /api/support/openapi/health` 改用 `Authorization: Bearer <apiKey>` 请求头，不再从 URL 的 `apiKey` 参数读取凭证；已有健康探针需调整传参并移除 URL 中的密钥。
- **系统模型直连鉴权**：已有系统模型若设置了 `requestUrl` 却依赖默认 `AIPROXY_API_TOKEN` 鉴权，升级前需显式填写该端点的 `requestAuth`；未配置时，OpenAI SDK 与 Pi Agent 的直连请求不再回退默认凭证。
- **动态选择选项**：用户选择节点及表单单选、多选的变量引用选项，运行时仅保留前 `200` 个有效项，单项文本最长 `100` 个 UTF-16 码元，超出部分截断；依赖超长选项值或后续候选项的流程需调整候选数据，并核对下游匹配逻辑。
- **API 身份参数**：API 会话不再允许更换使用者，已有会话以保存的身份为准，续聊需保持相同 `customUid`；已绑定后漏传、清空或更换，以及从默认身份改为自定义身份都会被拒绝，混用使用者的接入需改用独立 `chatId`。非空 `customUid` 仅允许 API Key 调用；它与 `authProxy` 互斥，即使为空字符串也不能同时传入，已有同时传参的接入需保留一种身份。
- **会话 ID 长度**：会话管理、文件、引用和沙盒等入口统一将 `chatId` 限制为最多 `1024` 个字符；使用超长自定义 ID 的接入需调整生成规则，并核查已有超长会话及相关引用。
- **重复生成响应**：非流式 `chat/completions` 在同会话已有生成时返回 HTTP `409`，依赖原错误状态码的自定义客户端需适配冲突响应。
- **日志 CSV**：基于「使用者」列解析团队成员的脚本需适配 `ID:name` 格式（旧版为成员名），成员缺少姓名时仅输出 ID；渠道列拆分为「调用渠道」与「渠道名」，按列名解析的脚本也需适配。
- **集合删除接口**：定位参数统一为请求体中的 `id`、`collectionIds` 或 `datasetId + apiFileIds`，三种方式不可混用。旧版 `query.id` 继续兼容但已弃用，新接入应使用请求体。
- **语音识别用量**：已有自建语音识别接入需核对上游用量返回；按时长计费读取 `usage.seconds`，按 Tokens 计费读取 `usage.total_tokens`，缺失或无效值记为 `0`，不再用客户端录音时长或识别文本估算用量。

- **API 错误文案**：`message` 现随请求语言变化，未提供语言偏好时默认英文；依赖固定文字或翻译键判断错误的接入需调整为使用 `code`、`statusText` 等机器标识。

## 🚀 新增内容

1. **[工具与渠道]** 新增绑定单个应用的应用 API Key，在应用发布页与个人密钥分开管理，由应用管理员共同维护，专用于该应用的对话及对话管理，不依赖归属成员的应用权限。商业版按资源交接流程转交密钥归属，删除应用时同步清理绑定密钥。
2. **[工具与渠道]** 对话及配套管理统一支持外部使用者标识与成员代理，可通过 `customUid` 进一步限定历史、消息、文件、引用和沙盒等操作的使用者范围；开启代理权限的个人密钥可通过 `authProxy` 按被代理成员的权限执行。
3. **[工具与渠道]** 对话日志新增默认隐藏的「鉴权者」列，与「使用者」分开展示，便于区分接入方用户和实际鉴权成员；API 传入的 `customUid` 按原值显示为使用者，CSV 按所选列导出。日志表格按内容分配列宽，避免长 UID 挤压成员姓名。
4. **[工具与渠道]** 免登录分享页新增适配桌面、移动和嵌入式页面的 FastGPT 标识，启用后新建链接默认展示，桌面访客可在本次访问临时关闭。团队持久隐藏需有效套餐权益，商业版支持按套餐及单条订阅控制；未保存品牌偏好的历史链接继续豁免，已关闭链接在权益失效时恢复展示，保留偏好供权益恢复后生效。
5. **[工具与渠道]** 新增默认关闭的插件化内容审核，启用后可分别审核用户输入、模型上下文与最终输出（含流式输出），并配置疑似风险和审核服务异常时的处理方式。管理台支持插件配置、审核效果测试及全局审核记录查看，对话详情可查看本次审核记录。
6. **[工具与渠道]** 新增官方 CLI 测试版 `@fastgpt/cli`，提供登录、多配置切换、身份与环境诊断、知识库管理及联合检索、应用对话与历史管理命令，支持 JSON 输出和命令元数据发现，便于脚本或 Agent 调用。同时支持文件与链接导入、集合及数据块管理、可用模型查询、输出字段裁剪、路径取值和精简命令发现。
7. **[工作流与 Agent]** 工作流 Agent 节点可从模板面板添加并作为工具节点供其他 Agent 调用，知识库输入支持变量引用；独立 ChatAgent 应用也可作为工作流子应用或 Agent 工具引用，支持传入文件与交互续跑，便于组合多 Agent 流程。
8. **[工作流与 Agent]** 新增可在工作流内直接配置的 MCP 与 HTTP 工具集节点，无需先创建独立工具应用；支持自定义子工具描述、鉴权和逐个调试，运行时读取远端最新工具定义供工具调用节点使用。
9. **[工作流与 Agent]** 商业版工作流 Builder 支持按明确的新建或修改请求直接搭建、校验和修复工作流，用户要求先看方案时仍等待预览确认；候选交付前增加同一 Agent 上下文中的需求覆盖自检，仍由用户手动应用到画布。
10. **[工作流与 Agent]** 商业版工作流 Builder 支持在同一会话内切换并继续独立任务，分别保存需求、方案和草稿，上下文压缩或运行中断后可按已保存资料继续任务。恢复时仍核对任务状态与画布基线，沙盒丢失时不能保证找回未保存草稿。
11. **[工作流与 Agent]** 应用模板支持配置体验链接，商业版可管理自建及插件系统模板的链接，供模板接入方在复制前提供预览入口。
12. **[模型与计费]** 系统模型新增「即将下架」标记，模型管理、模型及语音选择器同步展示预警；商业版管理员可创建多轮通知，按当前已发布应用与知识库的静态模型引用筛选团队，发送站内信并可选短信或邮件。支持查看失败、恢复轮次、重发和终止，截止后停止新投递，实际下架模型仍需另行操作。
13. **[模型与计费]** 商业版团队模型可通过配置接口或模板接入自定义请求地址与鉴权，作为过渡能力支持对话、Agent、向量、重排及语音直连，编辑后保留端点配置。端点在保存和请求时执行安全校验，重定向也受限制；列表隐藏端点与鉴权信息。
14. **[模型与计费]** OpenAI、Azure 模型渠道支持选择自动、Responses 或 Chat Completions 聊天上游协议，新建渠道默认按模型自动选择；仅影响聊天模型，上游需支持所选协议。
15. **[模型与计费]** 模型管理新增拖拽自定义排序，支持保存前取消；root 可调整系统模型，商业版启用团队模型后，具有「安装模型」权限的成员可调整自己的模型顺序。「可用模型」按本人、共享团队、系统模型分组并在组内应用自定义顺序，JSON 配置更新保留排序，客户端的最终系统模型兜底也使用该顺序；新建或新导入的模型默认位于所属分组顶部，保留已有模型的相对顺序。
16. **[模型与计费]** 启用权限配置的模型表格新增创建人展示，系统模型单独标识来源；成员展示页可获取最新创建人资料，外链目录不暴露成员信息。
17. **[模型与计费]** 语音识别模型支持按每 `60` 秒或每百万总 Tokens 配置单价，用量明细按所选计价类型展示；API、飞书及公众号入口均按本次实际调用的模型记录用量。
18. **[模型与计费]** 商业版用量支持按成员、部门（包含下级部门）或群组筛选，三种方式互斥，明细、统计图表与 CSV 导出使用相同范围。所选范围按当前组织及群组成员关系解析，具备团队管理权限的成员可查看对应成员用量，普通成员仅查看本人。
19. **[知识库与文件]** 商业版启用知识库增强时，模板 FAQ 导入接口支持按需生成自动索引，以问题和答案共同作为输入。自动索引任务中超出处理长度上限的条目改走普通向量索引，保留条目及其输入顺序。
20. **[知识库与文件]** 知识库搜索新增「重排候选数」，可设置为 `10–100` 条，默认 `100` 条；按融合、去重后的文本召回顺序选取候选送入重排模型，便于平衡搜索效果、响应耗时和模型负载。重排成功时，超出候选数的文本分块也不会进入权重融合，避免绕过相似度过滤。
21. **[知识库与文件]** 新增统一知识库检索接口，支持多库联合检索、文本或图片查询，以及按条数或 Tokens 预算返回结果；可组合重排、查询扩展和商业版元数据筛选，联合向量检索要求使用相同索引模型。
22. **[知识库与文件]** API 文件库支持通过 `datasetId + apiFileIds` 按外部文件或目录 ID 批量删除，自动清理对应派生目录及子文档，无需提前查询内部集合 ID；操作仍校验删除根的所有权。
23. **[团队与权限]** root 支持搜索并切换到全站可用团队，进入目标团队管理资源和成员，切换操作写入审计日志；跨团队代管成员不占用租户席位，也不会因切换而改变团队真实所有者。
24. **[团队与权限]** 商业版团队审计日志支持按日期、成员和事件组合筛选，默认展示含今天的近 `7` 个本地自然日，可选择更早日期及停用成员。具备团队管理权限的登录成员可导出全部匹配记录的多语言 CSV，单次最多 `50000` 条，超量需缩小范围；CSV 中的日志时间按查询起点偏移展示，发起导出会写入审计记录。
25. **[团队与权限]** 商业版用户管理接口补充所属团队、成员名和部门路径，团队成员列表补充登录用户名，便于管理端区分账号与成员身份。
26. **[系统与运维]** 对话记录最近一次运行的调用渠道，日志区分展示渠道类型和渠道名称，支持查看渠道 ID；相关筛选、CSV 导出与商业版统计同步采用新渠道分类。

## ⚙️ 优化

1. **[工作流与 Agent]** 修复多个子应用或工作流工具调用同一目标时，内部节点记忆互相覆盖的问题。按完整调用路径隔离内容提取、问题分类与 Pi Agent 状态，覆盖克隆应用共享后代工具、递归进入根应用等场景。
