## 重要说明

### 下线配置/功能

- `SYNC_INDEX` 不再生效，系统自动维护。
- 流式恢复的生成中相关参数不再生效，系统固定。
- 沙盒仅支持 `OpenSandbox`，其余沙盒不再支持。
- 下线 `piAgent` 引擎、`AGENT_ENGINE` 环境变量及管理后台 Agent 执行引擎切换项，统一使用内置 `fastAgent` 引擎。

### 兼容说明

- **API Key 健康检查**：由于安全问题，`GET /api/support/openapi/health` 改用 `Authorization: Bearer <apiKey>` 请求头，不再从 URL 的 `apiKey` 参数读取凭证；已有健康探针需调整传参并移除 URL 中的密钥。
- **工作流运行时引用**。工作流运行时按节点的可达范围、输出可用状态和类型解析引用。如已有流程依赖不可达节点、已禁用输出或类型不匹配的引用，请改用可达且类型匹配的有效输出，否则对应输入会按空值处理。
- **动态选择选项**：用户选择节点及表单单选、多选的变量引用选项，运行时仅保留前 `200` 个有效项，单项文本最长 `100` 个 UTF-16 码元，超出部分截断；依赖超长选项值或后续候选项的流程需调整候选数据，并核对下游匹配逻辑。
- **API 身份参数**：API 会话不再允许更换使用者，已有会话以保存的身份为准，续聊需保持相同 `customUid`；已绑定后漏传、清空或更换，以及从默认身份改为自定义身份都会被拒绝，混用使用者的接入需改用独立 `chatId`。非空 `customUid` 仅允许 API Key 调用；它与 `authProxy` 互斥，即使为空字符串也不能同时传入，已有同时传参的接入需保留一种身份。
- **会话 ID 长度**：会话管理、文件、引用和沙盒等入口统一将 `chatId` 限制为最多 `1024` 个字符；使用超长自定义 ID 的接入需调整生成规则，并核查已有超长会话及相关引用。
- **文件预览与下载**：嵌入 HTML、SVG 或 XML 文件预览的集成需改为在独立页面打开。使用短链重定向模式时，这类文件由 FastGPT 代理返回，下载客户端应直接处理文件响应。在短链重定向模式下，`HEAD` 由 FastGPT 直接返回文件元数据，依赖 `Location` 获取跳转地址的客户端需改用 `GET`。曾通过 `STORAGE_EXTERNAL_ENDPOINT` 覆盖 R2 签名端点的部署，升级后需确认 R2 服务端点可从客户端访问。
- **文件下载短链**。使用自定义 Nginx 根路径正则转发 `FILE_DOWNLOAD_PUBLIC_URL_PREFIX` 的部署需在升级前更新正则，同时匹配 `v1` 和带或不带扩展名的 `v2` 格式。多实例部署请协调切换 App 与 Pro，确保新版开始签发后，下载请求只进入支持 `v2` 的 App 实例。若回滚到仅支持 `v1` 的版本，已签发的 `v2` 链接将无法使用。
- **日志 CSV**：基于「使用者」列解析团队成员的脚本需适配 `ID:name` 格式（旧版为成员名），成员缺少姓名时仅输出 ID；渠道列拆分为「调用渠道」与「渠道名」，按列名解析的脚本也需适配。
- **集合删除接口**：定位参数统一为请求体中的 `id`、`collectionIds` 或 `datasetId + apiFileIds`，三种方式不可混用。旧版 `query.id` 继续兼容但已弃用，新接入应使用请求体。
- **语音识别用量**：已有自建语音识别接入需核对上游用量返回；按时长计费读取 `usage.seconds`，缺失或无效值记为 `0`，不再用客户端录音时长或识别文本估算用量。
- **Sealos Devbox 下线与沙盒路径变更**：4.18.0 起不再支持 `sealosdevbox` 运行时并移除对应管理台配置，存量部署需先通过升级脚本第 8 项完成迁移、切换至 OpenSandbox 并验证冷恢复稳定，确认无需回滚后再手动执行第 9 项不可逆清理。沙盒工作区路径统一由 `/workspace` 调整为 `/home/sandbox/workspace`，初始化去重状态路径调整为 `/var/lib/fastgpt-runtime/state.json`，依赖旧路径的自定义启动脚本或派生镜像需同步适配。

## 升级指南

**升级前提**：先在 4.17.x 完成所需历史迁移，再升级到本版本；4.18.x 已移除旧任务的注册与实现，不会继续执行，数据库中的历史状态和错误明细保留。

### 部署模板变更

- **Compose 停机宽限期**：`fastgpt-app` 的默认模板设置 `stop_grace_period: 30s`，给在途 HTTP 请求和 Redis、数据库连接清理留出时间。已有或自定义 Compose 部署请在 `fastgpt-app` 以及单独部署的商业版 Admin 服务下设置同一字段。30 秒是强制终止前的最长等待时间，不保证更长的请求能完成。
- **国内镜像源**：FastGPT 停止向阿里云发布镜像，国内 Docker Compose 模板改用 `ghcr.dockerproxy.net/labring/` 获取 FastGPT、Plugin、Code Sandbox 与 Agent Sandbox 系列服务镜像；`install.sh` 同步调整为「国内镜像源 / 全球镜像源」。
- **默认对象存储改为 RustFS**：默认 Docker Compose 模板改用 `fastgpt-rustfs`（`rustfs:1.0.4`，单盘 `/data` 拓扑，命名卷 `fastgpt-rustfs`）替换 `fastgpt-minio`，`STORAGE_S3_ENDPOINT` 与 `NO_PROXY` 同步指向 `fastgpt-rustfs`；已有部署可继续使用原存储，如需切换请参考 [MinIO 迁移到 RustFS](/self-host/docker_minio_to_rustfs)。
- **MongoDB 默认版本与初始化升级**：`main` Compose 模板默认 MongoDB 升级为 `8.3.17`（`x86_64` CPU 需满足 MongoDB 8.x 指令集要求），初始化与健康检查统一改用 `mongosh` 检查副本集可写主节点就绪后再放行依赖服务，并完善停机信号转发。
- **PostgreSQL 默认版本与持久化路径升级**：`main` Compose 模板默认 PG 向量库升级为 `pgvector/pgvector:0.8.7-pg18`，`fastgpt-aiproxy-pg` 改为标准 `postgres:18.7`（国内源统一切换至 `docker.m.daocloud.io`），两者的数据卷挂载路径同步调整为 `/var/lib/postgresql` 以适配 PostgreSQL 18 布局；该调整仅面向全新部署，已有 PG 15 数据卷不可直接挂载。
- **插件服务独立数据库与回调地址**：Docker Compose 模板为 `fastgpt-plugin` 将 `MONGODB_URI` 指向独立的 `fastgpt-plugin` 数据库、显式设置 `DB_MAX_LINK=100`（避免与主库集合混用），补齐 `FASTGPT_BASE_URL=http://fastgpt-app:3000` 并增加对 `fastgpt-mongo` 健康检查的依赖。自定义部署应填写插件容器可访问的主服务地址；若插件容器日志出现反向上传文件 `401`，优先核对该地址，修正后重建插件容器并重试工具。已有部署替换模板前应核对原插件库，保留已使用的独立库连接；若需切换数据库，先备份并迁移既有插件数据。
- **Agent Sandbox 服务与健康检查调整**：Compose 模板中的 OpenSandbox Server 升级至 `release-1.2.1`，并预置 `host.docker.internal:host-gateway` 映射使服务可访问沙盒对宿主机发布的端口（使用该主机名的自定义 Compose 部署需将此映射加入 `fastgpt-opensandbox-server` 的 `extra_hosts`）；`fastgpt-agent-sandbox-proxy` 新增 `FASTGPT_APP_REQUEST_TIMEOUT_SECS=60`。`fastgpt-code-sandbox`、`fastgpt-opensandbox-server` 与 `fastgpt-volume-manager` 健康检查改用内置 `node` / `python` 执行，并移除仓库静态清单 `deploy/k8s/volume-manager.yaml`（K8s 卷管理配置参见 [OpenSandbox 配置](/self-host/config/sandbox/opensandbox)）。

### 配置变更

<Alert icon="💡" context="info">
  自 V4.18.0
  起，大部分业务与系统配置已迁移至管理后台页面表单统一维护，仅保留少量基础设施及启动必需环境变量，可参考
  [V4.18.0 环境变量说明](/self-host/config/env4180)。
</Alert>

- 新版支持挂载 `/app/defaultConfig.json`，仅在全部业务配置域为空时参与首次初始化，后续修改文件不会覆盖数据库配置。原 `config.json` 已完全移除，不再作为运行期来源。
- 商业版用户必须显式配置 `TEAM_MODE` 控制团队模式，可选 `single`（单团队）、`multi`（多团队）或 `sync`（同步模式），修改后重启 Pro；旧数据库中的团队模式不再生效。`sync` 还需配置 `EXTERNAL_USER_SYSTEM_BASE_URL`，缺失时报错。
- Code Sandbox 和 MCP SSE 改由后台「子服务配置」管理。部署模板需调整，可在 `/app/defaultConfig.json` 中配置默认值，环境变量不生效。
- **内容审核（Moderation）插件化迁移**：旧版商业版内置的百度文本审核（`censor.BAIDU_TEXT_CENSOR_CLIENTID` / `censor.BAIDU_TEXT_CENSOR_CLIENTSECRET`）、自定义审核地址（`censor.customCensorURL`）以及单模型配置中的 `censor` 开关已废弃，统一升级为由 `fastgpt-plugin` 托管的 `moderation` 插件体系。
  - 原百度审核用户请前往 **管理后台 > 内容审核 > 审核策略配置**，配置并启用官方「百度内容安全（`baidu`）」插件。
  - 原自定义审核 URL（`customCensorURL`）用户可直接安装官方「旧版自定义审核兼容（`legacy-custom-censor`）」插件零代码迁移现有 HTTP 服务，或基于 `@fastgpt-plugin/sdk-factory` 开发原生 `moderation` 插件。
  - 新旧版本对比与配置映射见 [内容审核升级与迁移指南](/self-host/migration/content-moderation)，日常配置、测试与自定义插件开发见 [内容审核指南](/plugin/moderation)。

### 镜像更新

### 升级脚本

以下第 1–7 项、第 11 项及第 12 项为自动执行脚本；第 8–10 项及第 13 项为手动执行任务（`manual: true`），需管理员确认前提后在管理后台「版本升级」页面手动触发。

1. 新增 **迁移系统配置**（`20261116_migrate_system_configs`），在启动时自动执行，成功前阻塞 App 业务启动；导入旧配置、补齐缺失字段并加密受管密钥，保留已有管理员值、显式清空、授权与实例身份，原始旧配置数据保留。不符合新保存规则的历史值会保留，日志记录对应字段，升级后可在管理台修正。安全配置损坏时，外链和跨域访问仍受限制。任务采用幂等全量重跑，失败后根据日志修正问题并重启持有租约的节点，待租约过期后自动重试。
2. 新增 **初始化知识库向量索引**（`20261022_initialize_dataset_vector_indexes`），仅 PostgreSQL 在启动后于后台自动执行，不阻塞业务：先核验并在线删除旧全局 `vector_index`，再分批统计有效知识库并投递索引维护任务。任务成功表示统计与投递完成，实际建图由全局串行队列继续执行；清理或扫描失败时，可在升级管理页修复问题后重试，沿已保存的断点继续，同名但定义不匹配的自建索引会保留并报错。
3. PG 局部索引要求支持 `halfvec`（PG vector 需确保在 0.8.0 以上）、并具备在线创建、删除索引的权限及足够的内存、共享内存和磁盘资源。索引未就绪或失败期间继续精确检索，可能增加查询耗时；建图失败不会自动降低资源预算重试，排除故障后由下一次真实向量计数重新投递，缓存命中不会触发重试。
4. 新增 **回填历史对话调用渠道**（`20261104_backfill_chat_publish_source`），启动后独立在后台批量读写，不阻塞业务，也不等待普通后台长任务；分别为对话与统计记录补齐 `publishSource`，不修改旧字段、身份、消息或统计计数。历史 API、MCP 及已删除渠道可能只能恢复类型，无法补齐渠道 ID；无法识别的旧来源统一归为 `unknown`，不猜测渠道归属。此前因来源枚举失败的记录可在升级管理页直接重试，无需修改旧数据或重置进度；其他引用冲突或数据异常仍会记录失败，修复后沿断点续跑。完成校验改为分批扫描并保存断点，中断或修复校验异常后从对应批次继续；旧断点仅重新校验，保留已完成的回填。
5. 新增 **回填 API Key 类型**（`20261104_backfill_openapi_key_type`），自动分批遍历全部密钥，将缺失的 `type` 补为 `personal`，有效 `appId` 统一保存为 BSON ObjectId；保留凭证、归属、额度及默认应用或绑定语义。运行期管理查询只支持已规范化的数据格式；迁移期间或旧实例继续写入的旧格式数据不在查询兼容范围内。首次扫描上界之后的旧格式记录不会自动补迁，需另行规范化。异常数据可在升级管理页修复后重试。
6. 新增 **模型价格迁移**（`20261120_migrate_model_pricing`），系统配置迁移完成后在后台独立执行。先给旧 STT 模型补齐缺失的 `duration` 计价类型，保留原单价和已配置的 `tokens` 类型。随后在单事务内回填系统 LLM 的 `maxInputTokensK`，最后联合校验。同一模型只要有一个旧上限小于 `1`，缺少新字段的有限上限就按百万 Tokens 换算为千 Tokens，四舍五入且最小取 `1`。若该模型的有限旧上限均不小于 `1`，任务按千 Tokens 复制这些值，并校验是否为正整数。回填前，首档仍缺少新上限的旧模型按首档计费。旧 `maxInputTokens` 原值保留供回退读取，回退兼容范围为未被新版改写的阶梯。异常可在升级管理页查看，修复后重试。
7. 新增 **清理废弃 MongoDB 索引**（`20261123_cleanup_mongo_indexes`），启动后独立在后台执行。任务只删除清单中名称、键和选项均匹配的旧索引，保留定义不同的自建索引。若替代索引在默认 30 分钟内仍未就绪，任务保留对应旧索引并记录失败，可在修复后从升级管理页重试。`MONGO_DEPRECATE_INDEX` 默认开启，设为 `false` 或 `0` 时只检查并记录尚待清理的条目。
8. 新增 **迁移存量沙盒到 OpenSandbox (.tar.zst)**（`20261117_migrate_sandbox_to_opensandbox`，**手动执行**）：4.18.0 改用 MongoDB `agent_sandbox_instances_v3` 与 S3 `sandbox/archive-v2/`（`.tar.zst`）。仅重启不会自动执行该任务；凡存在未迁入 `v3` 的活跃 `agent_sandbox_instances_v2` 记录（`sealosdevbox`、旧 `sandbox/archive/*/package.zip` 或旧 `/workspace` 持久卷），运行期访问将返回 `agentSandboxMigrationInProgress`（`409`）；无存量或仅剩软删除源孤儿记录时触发即快速跳过。**切换顺序（不支持 4.17.x 与 4.18.0 混跑）**：
   1. **先下线全部 4.17.x App 与 Pro 节点**。
   2. **升级沙盒配套组件至 `v0.5.0+`**：同步升级 `AGENT_SANDBOX_OPENSANDBOX_IMAGE`（含自定义派生镜像）、`fastgpt-agent-volume-manager`、`fastgpt-agent-sandbox-proxy` 至 `v0.5.0+`，OpenSandbox 升至 `release-1.2.1`。存在活跃 `sealosdevbox` 时，保留 `AGENT_SANDBOX_SEALOS_BASEURL`、`AGENT_SANDBOX_SEALOS_TOKEN`（及自定义 `AGENT_SANDBOX_SEALOS_WORK_DIRECTORY`）直至迁移和清理完成；
   3. **启动 4.18.0 服务**并等待第 1 项启动迁移放行；
   4. **在管理后台「版本升级」手动执行本任务**：只读读取 `v2`，依次完成 `runningDevbox` → `stoppedDevbox` → `legacyArchives` → `validation` 并写入 `v3` 与 `sandbox/archive-v2/`，全程不修改或删除 `v2` 记录、远端 Devbox（保持 `pause`）、旧 `/workspace` 卷及旧 `package.zip`；失败可修复后沿断点重试。

   **迁移后验证**：确认任务「已完成」且无未解决失败记录后，抽检已有 Agent 会话与 Skill 编辑页的冷恢复、文件读写、终端/预览连接及 Skill 发布。

9. 新增 **清理历史沙盒遗留资源**（`20261117_cleanup_legacy_sandbox_resources`，**手动执行，依赖第 8 项**）：前置校验 `v2` 无活跃未迁移记录后才放行；须在 4.18.0 验证稳定后手动触发（回收 Devbox 前保留 Sealos ENV，完成后可移除）。任务会在逐一核验活跃沙盒在 `sandbox/archive-v2/` 的目标 `.tar.zst` 真实存在后，幂等删除远端历史 Devbox、旧容器与旧 `/workspace` 持久卷，以及旧 `sandbox/archive/*/package.zip`，并保持旧 MongoDB 集合 `agent_sandbox_instances_v2` 只读不删除。**回滚边界**：
   - **沙盒层回滚**：执行第 9 项前，旧 `v2` 记录、Devbox、旧 `/workspace` 卷与旧 `package.zip` 均原样保留，**无需恢复 PVC 快照或沙盒 S3 归档**。共用 OpenSandbox 控制面时，4.17.5 会按 `sessionId` 查找并直接连接或唤醒（`resume`）`Running` / `Paused` 实例，因此**停用 4.18.0 App/Pro 后、恢复 4.17.x 流量前**，必须按 `agent_sandbox_instances_v3` 中的远端实例 ID **终止/删除**对应 4.18.0 试运行沙盒（**不可仅 Pause**；新版外置 PVC 已设 `deleteOnSandboxTermination: false`，终止不会删卷与归档），并确认按该 `sessionId` 已查不到可恢复实例（或使用隔离的 OpenSandbox 控制面试运行）；随后将沙盒组件切回 `v0.4.x` 并启动 4.17.x，抽检升级前曾运行且在 4.18.0 验证过冷恢复的沙盒，确认回连原 `/workspace` 卷与 Devbox（试运行新建的带随机后缀 `v3` PVC 与旧卷隔离，放弃升级后可按需清理）。
   - **整站回滚边界**：因 4.18.0 含模型计价、API Key 规范化等非向后兼容迁移，且新发布的 `.tar.zst` Skill 无法被 4.17.x 读取，整站回滚至 4.17.x 仍需恢复升级前数据库备份（若删除过非沙盒 S3 资产或发布了 `.tar.zst` Skill，另需恢复升级前 S3 备份）。
