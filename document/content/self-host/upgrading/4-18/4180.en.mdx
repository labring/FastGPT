## Upgrade guide

**Prerequisite**: Complete the required historical migrations on 4.17.x before upgrading. Version 4.18.x removes the old task registrations and implementations, so they will no longer run; historical status and error records remain in the database.

### Configuration changes

- Added `SERVICE_AXIOS_MAX_CONTENT_LENGTH` (default: `20` MiB) to cap decompressed bodies of buffered responses from the shared server-side HTTP client; requests exceeding the limit are aborted, so custom integrations that need larger responses must raise it. Explicit caller limits take precedence, and streamed downloads remain subject to caller or business quotas.
- The default for `HNSW_EF_SEARCH` / `systemEnv.hnswEfSearch` changes from `100` to `200` for PostgreSQL, Milvus, OceanBase, SeekDB, and openGauss; explicit settings still apply and can be tuned to balance recall and query time.
- `HNSW_MAX_SCAN_TUPLES` / `systemEnv.hnswMaxScanTuples` no longer takes effect, and its admin setting has been removed. PostgreSQL now sets the scan limit automatically from the largest Dataset vector row count involved in the current indexed search, capped at `2147483647`; existing deployments can remove the old setting.
- Added `SHOW_OUTLINK_BRAND`: without `PRO_URL`, it is always `true`; with Pro connected, it defaults to `false` and can be set to `true` to enable branding. The frontend `show_outlink_brand` value comes from the server environment and overrides the same setting in `config.json`.
- The Commercial edition adds `auth.sms.MODEL_DEPRECATION` for the model deprecation SMS template. SMS reminders currently use this Chinese template regardless of the user's language; `auth.sms.MODEL_DEPRECATION_EN` has no effect on SMS delivery. Configure the Chinese template ID in the admin console before enabling SMS reminders.
- **Plugin service deployment**: Docker Compose templates now set `fastgpt-plugin`’s `FASTGPT_BASE_URL=http://fastgpt-app:3000`, point `MONGODB_URI` to a separate `fastgpt-plugin` database, and explicitly set `DB_MAX_LINK=100` to avoid sharing collections with the main database. Custom deployments should use an address for the main service that the Plugin container can reach. If the Plugin container logs `401` during a file upload callback, check this address first, correct it, recreate the Plugin container, and run the Tool again. Before replacing an existing deployment’s template, check which database the Plugin service currently uses and keep its existing dedicated connection; if a database change is needed, back up and migrate the existing Plugin data first.
- Default deployments now use RustFS for object storage; existing deployments can keep their current storage, and switching is covered in [MinIO to RustFS migration](/en/self-host/docker_minio_to_rustfs).

- **Content moderation Plugin migration**: The legacy built-in Baidu text moderation (`censor.BAIDU_TEXT_CENSOR_CLIENTID` / `censor.BAIDU_TEXT_CENSOR_CLIENTSECRET`), custom censor URL (`censor.customCensorURL`), and per-model `censor` flag in the commercial edition are deprecated and replaced by the `moderation` Plugin system managed by `fastgpt-plugin`.
  - If you used legacy Baidu moderation, go to **Admin Console > Content Moderation > Moderation Policy** to configure and enable the official **Baidu Content Security (`baidu`)** Plugin.
  - If you used a custom moderation URL (`customCensorURL`), install the official **Legacy Custom Moderation (`legacy-custom-censor`)** Plugin to connect your existing HTTP service without code changes, or build a native `moderation` Plugin with `@fastgpt-plugin/sdk-factory`.
  - For a full comparison of legacy and new behavior, field mappings, and Plugin development steps, see the [Content moderation upgrade and migration guide](/en/self-host/migration/content-moderation).
- **Agent Sandbox architecture upgrade (OpenSandbox + JuiceFS)**: Sandbox execution now standardizes on OpenSandbox (SDK `1.2.0`) with `fastgpt-volume-manager` and JuiceFS shared storage, retiring the `sealosdevbox` runtime and scheduled S3 zip archiving in the main bucket, and replacing `fastgpt-agent-sandbox-proxy` with the lightweight `fastgpt-opensandbox-proxy` edge gateway (listening on container port `1006`, mapped to host port `3006` by default in Docker Compose). See [OpenSandbox Configuration](/en/self-host/config/sandbox/opensandbox) for full deployment details:
  - `AGENT_SANDBOX_PROVIDER` has been removed—configuring `AGENT_SANDBOX_OPENSANDBOX_BASEURL` enables OpenSandbox directly. Deploy `fastgpt-volume-manager` and provision a dedicated metadata database (such as PostgreSQL) and a dedicated object-storage bucket for JuiceFS (do not share FastGPT's primary database or primary bucket). Docker mode requires `/dev/fuse` and `:rshared` mount propagation on `volume-manager`; Kubernetes mode requires a JuiceFS CSI StorageClass.
  - Deploy `fastgpt-opensandbox-proxy` to serve both interactive terminal WebSockets (`/terminal`) and static file previews (`/preview/*`): configure a matching `AGENT_SANDBOX_PROXY_SECRET` on both `fastgpt-app` and `fastgpt-opensandbox-proxy`, and point `AGENT_SANDBOX_PROXY_URL` to the browser-accessible `fastgpt-opensandbox-proxy` URL (we recommend a dedicated subdomain or domain separate from `FE_DOMAIN` in production for origin isolation; `AGENT_SANDBOX_PREVIEW_PROXY_URL` can stay empty in single-port mode and is needed only when `PREVIEW_PORT` dual-port isolation is enabled).
- **Optional environment variables for legacy Sandbox migration** (needed only when migrating existing Sandbox workspaces and cleaning up legacy resources):
  - `SYSTEM_MIGRATION_SANDBOX_CONCURRENCY` (on `fastgpt-app`, defaults to `5`, range `1`–`20`): Sets per-batch concurrency for the Sandbox migration and legacy cleanup tasks.
  - `AGENT_SANDBOX_SEALOS_BASEURL`, `AGENT_SANDBOX_SEALOS_TOKEN`, and `AGENT_SANDBOX_SEALOS_WORK_DIRECTORY` (on `fastgpt-app`, working directory defaults to `/home/devbox/workspace`): Keep these temporarily only if `v2` still contains unarchived or uncleaned `sealosdevbox` instances so the tasks can export remote workspaces and delete remote instances; remove them after Task 2 finishes.
  - `AGENT_SANDBOX_LEGACY_OPENSANDBOX_BASEURL` and `AGENT_SANDBOX_LEGACY_VOLUME_MANAGER_URL` (plus optional `AGENT_SANDBOX_LEGACY_OPENSANDBOX_API_KEY`, `AGENT_SANDBOX_LEGACY_OPENSANDBOX_IMAGE`, `AGENT_SANDBOX_LEGACY_OPENSANDBOX_RUNTIME`, and `AGENT_SANDBOX_LEGACY_VOLUME_MANAGER_TOKEN`, on `fastgpt-app`): Set as a pair only when migrating across OpenSandbox runtimes or clusters (for example, migrating from legacy Docker OpenSandbox to a new Kubernetes OpenSandbox cluster) so Task 1 can stream workspaces out of the legacy host read-only and Task 2 can reclaim legacy containers and volumes; omit for in-place same-cluster upgrades and remove after Task 2 finishes.
  - `VM_LEGACY_VOLUME_PREFIXES` (on `fastgpt-volume-manager`, comma-separated prefixes): Set only if you previously customized `AGENT_SANDBOX_OPENSANDBOX_VOLUME_NAME_PREFIX` to a different value from the current prefix so `volume-manager` permits probing and deleting those legacy volumes.

- **New deployments**: The default MongoDB version in the `main` Compose templates is now `8.0.34`. Startup and health checks use `mongosh`, and dependent services wait for the replica set primary to become ready.

### Upgrade scripts

Automatic migrations (run in the background after startup):

1. Added **Initialize Dataset vector indexes** (`20261022_initialize_dataset_vector_indexes`), which runs automatically in the background after startup for PostgreSQL without blocking the App: it first verifies and drops the legacy global `vector_index` online, then counts vectors in active Datasets in batches and queues index maintenance jobs. A successful migration means counting and queueing are complete; index builds continue in a globally serial queue. If cleanup or scanning fails, resolve the issue and retry from the upgrade management page to resume from the saved checkpoint. A custom index with the same name but a different definition is preserved and causes an error.
2. PG partial indexes require `halfvec` support, a fixed vector dimension in the `1–4000` range, permission to create and drop indexes online, and sufficient memory, shared memory, and disk space. Datasets whose indexes are not ready or have failed continue to use exact search, which may increase query time. Failed builds do not automatically retry with a lower resource budget; after the issue is resolved, the next actual vector count queues another attempt. A cache hit does not trigger a retry.
3. Added **Backfill historical chat channels** (`20261104_backfill_chat_publish_source`), which runs independently with batched reads and writes in the background after startup without blocking the App or waiting for long-running tasks in the regular background queue. It fills `publishSource` separately for chats and statistics records without changing legacy fields, identities, messages, or counters. Historical API, MCP, and deleted channels may retain only a type without a recoverable channel ID; unrecognized legacy sources are classified as `unknown` without guessing their channel. Records that previously failed source enum validation can be retried directly from the upgrade management page without modifying legacy data or resetting progress; other conflicting references or invalid data remain recorded as failures and can resume from the checkpoint after repair.
4. Added **Backfill API Key types** (`20261104_backfill_openapi_key_type`), which scans all keys in batches, fills missing `type` values as `personal`, and stores valid `appId` values as BSON ObjectId values. Credentials, ownership, quotas, and default target or binding semantics remain unchanged. Repair invalid records and retry from the upgrade management page. Management queries support only normalized data. Legacy-format data present during migration or written by old instances is outside query compatibility support. Legacy records written after the initial scan boundary are not automatically backfilled and require separate normalization.

Manual system upgrade tasks (when historical Sandboxes exist, run in order from the admin upgrade page after upgrading; deployments without Sandboxes or historical `v2` records finish immediately):

- **Migrate sandbox workspaces to JuiceFS** (`20261111_migrate_sandbox_to_juicefs`, manual): Copies active App and Skill workspaces from `agent_sandbox_instances_v2` (legacy OpenSandbox Kubernetes PVCs or Docker named volumes, S3 `package.zip` archives, and remote Sealos Devbox working directories) into JuiceFS, writes `stopped` records to `agent_sandbox_instances_v3`, stops legacy runtime containers, and pauses remote Devbox instances. Original `v2` records and legacy storage remain intact so you can roll back without data loss before running cleanup.
- **Clean up legacy sandbox storage and instances** (`20261111_cleanup_legacy_sandbox_resources`, manual, depends on `20261111_migrate_sandbox_to_juicefs`): Run manually after verifying migrated Sandboxes in production and confirming rollback is no longer needed. Idempotently deletes legacy containers, legacy PVCs or Docker named volumes, S3 archives, and remote Sealos Devbox instances, then removes each `v2` record once external cleanup succeeds.

### Compatibility notes

- **Agent Sandbox storage switch and unmigrated guard**: Sandbox instance records move from `agent_sandbox_instances_v2` to `agent_sandbox_instances_v3`. If an App session or Skill still has an unmigrated record in `v2`, Sandbox requests return HTTP 409 indicating that workspace migration is in progress instead of creating an empty volume over historical files. Normal on-demand wakeups resume once `20261111_migrate_sandbox_to_juicefs` completes.
- **Legacy API keys**: Keep your existing keys. Keys without a `type` are automatically classified as personal keys, with the stored `appId` retained as the default chat target. Their access permissions and personal management remain unchanged. New App keys are limited to their bound App and managed jointly by its administrators.
- **API Key health checks**: `GET /api/support/openapi/health` now reads credentials from the `Authorization: Bearer <apiKey>` header instead of the URL’s `apiKey` parameter. Update existing health probes to send the key in this header and remove it from the URL.
- **System model endpoint authentication**: If an existing system model sets `requestUrl` but relies on the default `AIPROXY_API_TOKEN` for authentication, explicitly configure that endpoint’s `requestAuth` before upgrading. Without it, direct requests through the OpenAI SDK and Pi Agent no longer fall back to default credentials.
- **Dynamic selection options**: User selection Nodes and single- or multi-select form fields now keep only the first `200` valid variable-bound options at runtime, with each option truncated to at most `100` UTF-16 code units. Workflows that depend on longer option values or later candidates must adjust their candidate data and review downstream matching logic.
- **API identity parameters**: API sessions no longer allow switching user identity; existing sessions use their saved identity. Continue with the same `customUid`; omitting, clearing, or changing a bound value, or switching from the default to a custom identity, is rejected. Integrations that reuse a session across users must allocate separate `chatId` values for different users. A nonempty `customUid` requires an API Key. It is mutually exclusive with `authProxy`, even when empty; integrations that send both must choose one identity.
- **Session ID length**: Session management, file, citation, and Sandbox APIs now limit `chatId` to `1024` characters. Integrations that use longer custom IDs must adjust their generation rules and review existing oversized session IDs and their linked records.
- **Concurrent generation responses**: Non-streaming `chat/completions` requests now return HTTP `409` when the same session already has a generation in progress. Custom clients that depend on the previous error status code must handle this conflict response.
- **Log CSV exports**: Scripts that parse Team members from the “User” column must support `ID:name` instead of the previous member name; when a member has no name, the column contains only the ID. Channel columns are now split into “Call channel” and “Channel name,” so scripts that parse column names must also be updated.
- **Collection deletion API**: Select exactly one request-body form: `id`, `collectionIds`, or `datasetId + apiFileIds`. Legacy `query.id` remains supported but is deprecated; new integrations should use the request body.

## 🚀 New features

1. **[Tools and channels]** Added App API Keys bound to a single App, managed separately from personal keys on the App publishing page. App managers share control of these keys for that App’s chats and chat management, independently of the owning member’s App permissions; the Commercial edition transfers key ownership through resource handover, and deleting an App also removes its bound keys.
2. **[Tools and channels]** Chat and related management APIs now share support for external user IDs and Team member proxies. Use `customUid` to narrow access to a user’s history, messages, files, citations, and Sandbox resources; personal keys with proxy permission can use `authProxy` to act with the represented member’s permissions.
3. **[Tools and channels]** Chat logs now include an “Authorizer” column, hidden by default, separate from “User” to distinguish your users from the authenticated Team member. API `customUid` values appear unchanged as the user, and CSV exports follow the selected columns. Log columns now size to their contents so long UIDs do not squeeze member names.
4. **[Tools and channels]** Added FastGPT branding to public share pages across desktop, mobile, and embedded layouts; when enabled, new links show it by default, and desktop visitors can dismiss it for the current visit. Persistent hiding requires a valid plan entitlement, configurable per plan or individual subscription in the Commercial edition; legacy links without a saved preference remain exempt, while links with a saved hiding preference show branding again if the entitlement becomes invalid and hide it again when the entitlement is restored.
5. **[Tools and channels]** Added Plugin-based content moderation, disabled by default. When enabled, policies can independently check user input, model context, and final output, including streamed output, with configurable actions for suspected risks and moderation service errors. Admins can configure Plugins, test moderation results, and view global moderation records; chat details also show the records for that chat.
6. **[Workflows and Agents]** Workflow Agent Nodes can now be added from the template panel and used as Tool Nodes by other Agents. Dataset inputs support variable bindings; standalone ChatAgent Apps can also be referenced as Workflow child Apps or Agent Tools, with file inputs and resumable interactions for composing multi-Agent Workflows.
7. **[Workflows and Agents]** Added MCP and HTTP Toolkit Nodes that you can configure directly in a Workflow without first creating a standalone Tool App. Customize child Tool descriptions and authentication, debug each Tool, and let Tool call Nodes use the latest remote Tool definitions at runtime.
8. **[Workflows and Agents]** Commercial edition Workflow Builder can build, validate, and repair Workflows directly from clear creation or modification requests, while still waiting for preview confirmation when you ask to review a proposal first. Before delivering a candidate, the same Agent checks requirement coverage in its existing context; you still apply the candidate to the canvas manually.
9. **[Workflows and Agents]** Commercial edition Workflow Builder supports switching between independent tasks within a session, saving each task’s requirements, proposals, and draft separately so work can continue from saved data after context compression or an interrupted run. Recovery still checks task status and the canvas baseline; unsaved drafts may be lost if the sandbox is lost.
10. **[Workflows and Agents]** App templates now support experience links, with Commercial edition management for links on custom and Plugin system templates, so template integrations can offer a preview before copying.
11. **[Models and billing]** System models now support an “Upcoming deprecation” flag in model management and model and speech selectors; Commercial edition admins can create notification plans with multiple rounds for Teams whose currently published Apps or Datasets statically use these models, sending in-app messages with optional SMS or email. Plans support failure inspection, run recovery, retries, and termination, and stop new deliveries at the deadline; model removal remains a separate action.
12. **[Models and billing]** Commercial edition Team models can now use custom request URLs and authentication through configuration APIs or templates as a transitional option for direct chat, Agent, embedding, reranking, and speech requests, retaining endpoint settings after edits. Endpoints undergo safety checks when saved and requested, including redirect restrictions; model lists hide endpoint and authentication details.
13. **[Models and billing]** OpenAI and Azure Model providers now offer Auto, Responses, and Chat Completions as upstream chat protocols, with new providers defaulting to automatic selection based on the model. This affects only chat models, and the upstream must support the selected protocol.
14. **[Models and billing]** Model management now supports dragging models into a custom order and canceling before saving; the root account can reorder system models, and with team models enabled in the Commercial edition, members with the “Install model” permission can reorder their own models. “Available models” groups your own team models, shared team models, and system models in that order and applies the custom order within each group; JSON configuration updates preserve this order, which the client also uses for its final system-model fallback. Newly created or newly imported models appear at the top of their group without changing the relative order of existing models.
15. **[Models and billing]** Model tables with permission configuration now show creators and identify system models separately. Member display pages can load current creator details, while shared-link catalogs do not expose member information.
16. **[Models and billing]** Usage in the Commercial edition now supports mutually exclusive member, department (including subdepartments), or group filters, with the same scope applied to details, charts, and CSV exports. Selections use current organization and group memberships; members with Team management permission can view usage for the selected members, while other members can view only their own usage.
17. **[Datasets and files]** With Dataset enhancement enabled in the Commercial edition, the template FAQ import API now supports optional automatic index generation using both questions and answers as input. Automatic indexing tasks that exceed the processing length limit fall back to standard vector indexing, retaining each entry and its input order.
18. **[Datasets and files]** Dataset search adds a rerank candidate limit of `10–100` chunks, with a default of `100`. Candidates are sent to the rerank model in text recall order after fusion and deduplication, helping balance search quality, latency, and model load; after successful reranking, text chunks beyond the candidate limit are excluded from weighted fusion so they cannot bypass the similarity filter.
19. **[Datasets and files]** API file Datasets now support batch deletion by external file or directory IDs through `datasetId + apiFileIds`, including the corresponding derived folders and child documents, without first looking up internal Collection IDs. Deletion still requires ownership of each deletion root.
20. **[Teams and permissions]** Commercial edition Team audit logs now combine date, member, and event filters, defaulting to the latest `7` local calendar days including today, with older dates and inactive members available. Logged-in members with Team management permission can export all matching records as localized CSV, up to `50000` records per export; narrow the filters above that limit. Log timestamps in the CSV use the query start offset, and each export request creates an audit record.
21. **[Teams and permissions]** Commercial edition user management APIs now include Team memberships, member names, and department paths. Team member lists also return login usernames to distinguish accounts from member identities.
22. **[System and operations]** Chats now record the channel used by the latest run. Logs show channel types and names separately, with channel IDs available for inspection; filters, CSV exports, and Commercial edition statistics also use the new channel classification.

## ⚙️ Improvements

1. **[Workflows and Agents]** Fixed internal Node memory being overwritten when multiple child Apps or Workflow Tools call the same target. Content extraction, question classification, and Pi Agent state are isolated by the full call path, including cloned Apps that share descendant Tools and recursive calls back into the root App.
2. **[Workflows and Agents]** Fixed missing memory updates from Agents, Tool calls, and nested Workflows, loss of memory from branches that did not run, and concurrent child Workflows overwriting other Nodes' new state with stale state. Only each child Workflow's updates are merged, preserving other valid memory.
3. **[Workflows and Agents]** Fixed memory propagation and failure isolation in loops and parallel runs. Loops pass memory between successful iterations and preserve checkpoints when paused for interaction; failed iterations do not commit updates. Parallel runs merge only successful task results, keep failed attempts from affecting retries, and merge in input order, with later successful tasks taking precedence for the same memory key.
4. **[Workflows and Agents]** Unified Tool, Skill, and Dataset cards and status checks across Agent forms and Workflow Nodes. Running, publishing, and single-Node Debug use the same rules, report invalid, offline, or unconfigured resources, and preserve existing configuration during asynchronous selection and saves.
5. **[Workflows and Agents]** Commercial edition Workflow Builder previews now show a title, a short summary, and a pending-confirmation status. Restored proposals awaiting confirmation open at the top of the card and preserve the reading position during subsequent rendering; confirmation, revision, and cancellation use the shared interaction controls.
6. **[Workflows and Agents]** Raised the option limit for single- and multi-select configuration from `50` to `200`. Manual options in User selection Nodes are capped at `200`, and each option text input accepts up to `100` UTF-16 code units.
7. **[Workflows and Agents]** Standardized button and model selector sizes across App, Workflow, and Tool editors, and aligned help icons with text for a more consistent layout.
8. **[Datasets and files]** PostgreSQL now maintains FP16 partial HNSW indexes per Dataset, building them on demand above `10000` vector rows and removing them below `5000`; the existing state is retained between these thresholds. Datasets without a ready index use exact search, and candidates from all groups are ranked by FP32 distance without changing the precision of stored vectors. This substantially reduces compute and storage overhead.
9. **[Datasets and files]** In the Commercial edition, moved tag filtering for simple Apps, ChatAgents, and Workflow Agents to the “Search filter” tab in Dataset search settings and added a dedicated toggle. Turning it off in manual input mode preserves conditions for later editing, and the summary reflects its state; variable-bound Datasets or filters preserve their configuration so tags that cannot be resolved while editing are not removed.
10. **[Datasets and files]** Tripled the per-minute file upload rate limit for each upload identity, reducing “Too many requests” errors during repeated or batch uploads.
11. **[Datasets and files]** Fixed website sync in the Commercial edition missing child links on directory pages without valid content and incorrectly deleting existing Collections after invalid content, write failures, or page-limit truncation; link deduplication and relative resource resolution after redirects are improved, and incomplete syncs preserve existing data. Early stops and timeouts now clean up in order with bounded waits, preventing subsequent writes and retries after cancellation while database operations already in progress finish through their normal mechanisms.
12. **[Models and billing]** Consistently place models in test mode last in the mobile model selector, speech playback, channel bindings, and model log and dashboard filters, preserving catalog order within each group.
13. **[Models and billing]** Aligned header and body column widths in the model management table and isolated edit dialog state by row, reducing full-table rerenders when opening a dialog in a large list.
14. **[Models and billing]** Improved truncation and hover text for long names in model and speech selectors, keeping names from stretching controls or crowding the voice column.
15. **[Chat experience]** Improved chat history sidebar refreshes with batched queries for long lists and retries while a chat is running or a request has failed. Hidden tabs pause periodic refreshes, resource switches discard late responses, and failed refreshes preserve the previous status and read flags.
16. **[Chat experience]** Fixed inaccurate generation status and resume connections waiting indefinitely after long periods without output or client disconnects. Persisted chats now use independently renewed Redis leases, which expire within 60 seconds of the last renewal if the process exits; acquisition or read errors trigger fallback behavior, so mutual exclusion and accurate status cannot be guaranteed during Redis failures.
17. **[Teams and permissions]** Fixed App creation, JSON imports, copies, and conversions to new Workflow copies failing when they include unreadable or missing resources. The initial version snapshots only readable resources; any remaining unusable Node references are marked as errors in the detail view for later correction.
18. **[Tools and channels]** API documentation now groups parameters by resource, identity, and pagination mode, highlights fields for the selected branch, and corrects required-field markers and request examples to clarify each integration option.

## 🐛 Fixes

1. **[Workflows and Agents]** Fixed canvas errors or stale parent output types when a Loop end Node has an empty or incomplete reference, or its source Node has been deleted; loop and parallel containers now fall back to a generic array type.
2. **[Workflows and Agents]** Fixed context, plans, or answers being lost when Agents resume questions as child Tools or Apps, and unfinished interaction history affecting downstream Nodes or the next loop iteration. Pause state is saved per Node, and resumes produce the complete answer.
3. **[Workflows and Agents]** Fixed root sessions being unable to browse or download files after a nested Agent successfully prepared a sandbox. Readiness now records actual sandbox use for the session; later rounds without sandbox use or errors after readiness do not clear this state, and system and Team permissions still apply.
4. **[Workflows and Agents]** Fixed parent, child, or sibling Agent and Tool call Nodes overwriting same-named files from different sources in a shared sandbox during the same run. Unique names and model-visible paths are assigned consistently; cross-Node uploads with the same name and source reuse the name allocated in that run.
5. **[Workflows and Agents]** Fixed Nodes selecting different Skills clearing one another’s deployed versions and initialization state. Published Skill versions and successful initialization state remain cached in the sandbox; redeploying a missing directory clears its old marker so initialization runs again.
6. **[Workflows and Agents]** Fixed concurrent child Apps failing immediately when competing for a shared sandbox’s initialization lock. A busy lock now triggers bounded retries; timeouts and lease errors still return an initialization error.
7. **[Workflows and Agents]** Fixed initialization clearing stop requests received during preparation for Workflows and Commercial edition auxiliary generation. Workflow runs without SSE, including MCP calls and scheduled triggers, now also respond to explicit stop signals.
8. **[Workflows and Agents]** Fixed saves failing when legacy Agents fall back to manual Dataset selection but retain old variable references. Manual Dataset selections in Agents and Dataset search Nodes now filter malformed entries while preserving the remaining selections.
9. **[Workflows and Agents]** Fixed Skill exports failing when the edit sandbox was not running: when initialization is allowed, the server starts or resumes the sandbox and waits until it is ready before packaging. Members with write permission must wait for the sandbox to be ready; read-only collaborators can access export regardless of their local edit sandbox state.
10. **[Workflows and Agents]** Fixed Agents dropping the configured time granularity and start/end limits when passing interactive form fields for a date/time or time range. The original field settings are now preserved.
11. **[Workflows and Agents]** Fixed cursor resets in multiline text fields that disrupted input method composition and candidate confirmation.
12. **[Workflows and Agents]** Fixed scrolling in Tool and form parameter configuration dialogs when their content exceeds the available space. Menus in dialogs such as Collaborator permissions and HTTP authentication settings no longer get clipped by the dialog body or expand its scroll area; long menus scroll internally so you can reach the bottom options.
13. **[Workflows and Agents]** Fixed Agent maximum output tokens and answer visibility settings not taking full effect. Hiding the answer preserves required interactions and Node results; with error capture enabled, errors go to the error branch instead of being appended to the visible answer.
14. **[Workflows and Agents]** Fixed Pi Agent requests being rejected by model providers when Tool parameter schemas contained legacy required flags or internal extension fields. Tools, Sandbox Tools, and built-in Tools now normalize schemas before model calls.
15. **[Workflows and Agents]** Fixed untranslated field hints for text editing, Dataset citations, and custom feedback during assisted Workflow generation across Simplified Chinese, Traditional Chinese, English, and Korean. Text editing hints now include the complete reference syntax for upstream outputs and global variables.
16. **[Datasets and files]** Fixed incomplete scope constraints in Collection subtree queries and permission synchronization. Traversal and updates now stay within the current Team and Dataset, preventing invalid parent-child links from affecting other Datasets.
17. **[Datasets and files]** Fixed Alibaba Cloud OSS rejecting stream uploads when a known length was supplied but chunked encoding was also added, conflicting with `Content-Length`.
18. **[Datasets and files]** Fixed filenames containing escaped quotes being truncated when parsing `Content-Disposition`. Quotes and backslashes in the filename are now restored correctly.
19. **[Chat experience]** Fixed input suggestions stopping during continuous typing or after moving the cursor, and replacing the wrong text. Use the up and down keys to select a suggestion and Enter or Tab to fill it while preserving surrounding text; stale suggestions and input method confirmation keys no longer trigger unintended completion.
20. **[Chat experience]** Fixed concurrent sends being rejected and then waiting for a new reply instead of recovering the original round. The rejected text and attachments are restored to the input, and the existing reply is refreshed and recovered, including interactive resumes and replies that have already finished.
21. **[Chat experience]** Fixed members with read-only App access being unable to mark their own sessions as read; session access restrictions still apply.
22. **[Chat experience]** Fixed admin feedback and closing custom feedback updating the user message when it shares a `dataId` with the AI reply in the same round. These operations now update only the corresponding AI reply.
23. **[Chat experience]** Fixed images being missed when their Markdown descriptions contain paired square brackets, such as `![Image [1]](...)`; image extraction and replacement now handle these descriptions correctly.
24. **[Chat experience]** Added missing Simplified Chinese, Traditional Chinese, English, and Korean translations for sandbox connection and file errors, Skill generation status, and Tool version labels, fixing untranslated text or internal keys appearing in some screens. Also added Korean text for account deletion, password setup, related audit events, Dataset tag errors, and rate-limit messages; Question classification Nodes now use Korean default options.
