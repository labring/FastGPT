### Compatibility notes

- **Model ordering and configuration imports**: `PUT /api/core/ai/model/updateOrder` requires an explicit `channelType` (`system` or `team`) and the complete, unique list of `modelIds` in the current management scope, including disabled models. Filtered subsets, duplicate IDs, and models outside that scope are rejected. Model creation, editing, and JSON imports ignore `sortOrder`, and exports omit it. Configuration updates preserve the order of existing models that can be matched; new models and those without a saved order appear after ranked models. Historical records do not require an offline migration.
- **Model catalog and default selection**: `GET /api/core/ai/model/catalog` returns the grouped custom order when `orderBy=custom` is supplied; omitting it preserves runtime order. Display ordering does not overwrite configured defaults or change server-side fallback order. If neither the business default nor the system default meets the requested type and capabilities, the client uses the new catalog order for its final system-model fallback. Dedicated defaults for Dataset images and chat titles still have no automatic final fallback.
- **Workflow memory**: Memory keys for content extraction, question classification, and Pi Agents now include the source and call path. The runtime can read legacy Agent keys and legacy child Workflow keys whose ownership can be determined, then removes the corresponding legacy keys when writing new ones. Historical sessions do not require a bulk migration. Custom integrations that read or write `ChatItem.memories` directly must support the new keys instead of relying on `agentLoopMemory-${nodeId}` or child Workflow keys without a call path.
- **History settings and interaction resumes**: For ordinary new requests, `history=0` disables reading previous memory. Custom history supplies memory only from its final AI message. Explicit interaction resumes prioritize the parent Workflow's checkpoint so history settings do not discard the state needed to continue the current interaction.

## 🚀 New features

1. **[Models and billing]** Model management now supports dragging models into a custom display order, with options to save or cancel before saving. The root account can reorder system models; with team models enabled in the Commercial edition, members with the “Install model” permission can reorder their own models. The “Available models” page lists your team models, shared team models, and system models in that order, applying the custom order within each group.

## ⚙️ Improvements

1. **[Models and billing]** Consistently place models in test mode last in the mobile model selector, speech playback, channel bindings, and model log and dashboard filters, preserving catalog order within each group.
2. **[Models and billing]** Aligned header and body column widths in the model management table and isolated edit dialog state by row, reducing full-table rerenders when opening a dialog in a large list.
3. **[Datasets and files]** In the Commercial edition, moved tag filtering for simple Apps and ChatAgents to the “Search filter” tab in Dataset search settings and added a dedicated toggle. Turning it off in manual input mode preserves conditions for later editing; the settings summary now reflects whether the toggle is on.

## 🐛 Fixes

1. **[Workflows and Agents]** Fixed internal Node memory being overwritten when multiple child Apps or Workflow Tools call the same target. Content extraction, question classification, and Pi Agent state are isolated by the full call path, including cloned Apps that share descendant Tools and recursive calls back into the root App.
2. **[Workflows and Agents]** Fixed missing memory updates from Agents, Tool calls, and nested Workflows, loss of memory from branches that did not run, and concurrent child Workflows overwriting other Nodes' new state with stale state. Only each child Workflow's updates are merged, preserving other valid memory.
3. **[Workflows and Agents]** Fixed memory propagation and failure isolation in loops and parallel runs. Loops pass memory between successful iterations and preserve checkpoints when paused for interaction; failed iterations do not commit updates. Parallel runs merge only successful task results, keep failed attempts from affecting retries, and merge in input order, with later successful tasks taking precedence for the same memory key.
4. **[Workflows and Agents]** Fixed nested Pi Agents failing to resume question interactions when history is set to 0 or an empty custom history array. Resumes restore the state saved by the parent Workflow.
5. **[Chat experience]** Fixed the header variable panel in shared chats without login using regular chat visibility rules. External variables are now hidden from share visitors.
6. **[Chat experience]** Fixed model selectors in global variables and interaction forms in shared chats without login failing to load the model list or selected model name because share authentication was missing.
7. **[Tools and channels]** Fixed blank text in some Tool names, descriptions, and tags when their Traditional Chinese translation is empty. These values fall back to Simplified Chinese, then English if no usable text is available.

## 🛠️ Code improvements

1. **[System and operations]** Added a manually triggered GitHub Actions workflow for backporting merged PRs; its target branch defaults to `v4.17.x` and can be changed, and it creates a draft PR when complete. The repository also provides the `fastgpt-backport-pr` skill for batch backports of merged PRs to an explicitly specified historical branch. It resolves mechanical conflicts automatically, requires confirmation for semantic conflicts, and pushes directly to the target branch on `upstream` after targeted checks pass.
