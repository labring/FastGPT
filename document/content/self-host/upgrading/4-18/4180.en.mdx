## Upgrade guide

### Configuration changes

- The default for `HNSW_EF_SEARCH` / `systemEnv.hnswEfSearch` changes from `100` to `200` for PostgreSQL, Milvus, OceanBase, SeekDB, and openGauss; explicit settings still apply and can be tuned to balance recall and query time.
- `HNSW_MAX_SCAN_TUPLES` / `systemEnv.hnswMaxScanTuples` no longer takes effect, and its admin setting has been removed. PostgreSQL now sets the scan limit automatically from the largest Dataset vector row count involved in the current indexed search, capped at `2147483647`; existing deployments can remove the old setting.
- Default deployments now use RustFS for object storage; existing deployments can keep their current storage, and switching is covered in [MinIO to RustFS migration](/en/self-host/docker_minio_to_rustfs).

### Upgrade scripts

Added **Initialize Dataset vector indexes** (`20261022_initialize_dataset_vector_indexes`), which runs automatically in the background after startup for PostgreSQL without blocking the App: it first verifies and drops the legacy global `vector_index` online, then counts vectors in active Datasets in batches and queues index maintenance jobs. A successful migration means counting and queueing are complete; index builds continue in a globally serial queue. If cleanup or scanning fails, resolve the issue and retry from the upgrade management page to resume from the saved checkpoint. A custom index with the same name but a different definition is preserved and causes an error.

PG partial indexes require `halfvec` support, a fixed vector dimension in the `1–4000` range, permission to create and drop indexes online, and sufficient memory, shared memory, and disk space. Datasets whose indexes are not ready or have failed continue to use exact search, which may increase query time. Failed builds do not automatically retry with a lower resource budget; after the issue is resolved, the next actual vector count queues another attempt. A cache hit does not trigger a retry.

### Compatibility notes

- **Chat running status**: `chatGenerateStatus` is now derived from Redis leases and returns only `0` (generating) or `1` (idle). It is no longer persisted in Mongo and no longer returns `2` (error); integrations that read the database field directly or depend on the error enum must use API status and message errors instead. During upgrade, stop old instances from accepting new requests and let ongoing runs finish, then switch all generation and status-query instances together to avoid mixing the two concurrency controls.
- **Workflow memory**: Memory keys for content extraction, question classification, and Pi Agents now include the source and call path. Custom integrations that read or write `ChatItem.memories` directly must support the new keys instead of relying on `agentLoopMemory-${nodeId}` or child Workflow keys without a call path.
- **API identity parameters**: Existing calls to `chat/completions` that send both `customUid` and `authProxy` must keep only one, depending on whether they identify a user or run as a Team member. Sending both now returns a parameter error, even when `customUid` is an empty string.
- **Concurrent generation responses**: Non-streaming `chat/completions` requests now return HTTP `409` when the same session already has a generation in progress. Custom clients that depend on the previous error status code must handle this conflict response.
- **Message deletion API**: `DELETE /api/core/chat/record/delete` no longer reads URL query parameters. Existing integrations must send parameters in a JSON request body and replace comma-separated `contentIds` strings with arrays.
- **Log CSV exports**: Scripts that parse Team members from the “User” column must support `ID:name` instead of the previous member name; when a member has no name, the column contains only the ID.

## 🚀 New features

1. **[Models and billing]** Model management now supports dragging models into a custom order and canceling before saving; the root account can reorder system models, and with team models enabled in the Commercial edition, members with the “Install model” permission can reorder their own models. “Available models” groups your own team models, shared team models, and system models in that order and applies the custom order within each group; JSON configuration updates preserve this order, which the client also uses for its final system-model fallback.
2. **[System and operations]** Chat logs now include an “Authorizer” column, hidden by default, separate from “User” to distinguish your users from the authenticated Team member. API `customUid` values appear unchanged as the user, and CSV exports follow the selected columns.

## ⚙️ Improvements

1. **[Datasets and files]** PostgreSQL now maintains FP16 partial HNSW indexes per Dataset, building them on demand above `10000` vector rows and removing them below `5000`; the existing state is retained between these thresholds. Datasets without a ready index use exact search, and candidates from all groups are ranked by FP32 distance without changing the precision of stored vectors.
2. **[Datasets and files]** In the Commercial edition, moved tag filtering for simple Apps and ChatAgents to the “Search filter” tab in Dataset search settings and added a dedicated toggle. Turning it off in manual input mode preserves conditions for later editing; the settings summary now reflects whether the toggle is on.
3. **[Datasets and files]** Tripled the per-minute file upload rate limit for each upload identity, reducing “Too many requests” errors during repeated or batch uploads.
4. **[Models and billing]** Consistently place models in test mode last in the mobile model selector, speech playback, channel bindings, and model log and dashboard filters, preserving catalog order within each group.
5. **[Models and billing]** Aligned header and body column widths in the model management table and isolated edit dialog state by row, reducing full-table rerenders when opening a dialog in a large list.
6. **[Chat experience]** Improved chat history sidebar refreshes with batched queries for long lists and retries while a chat is running or a request has failed. Hidden tabs pause periodic refreshes, resource switches discard late responses, and failed refreshes preserve the previous status and read flags.
7. **[Chat experience]** Optimized scroll pagination to reduce rerenders caused by scrolling; scrolling can still load more items after content shrinks to less than one screen.
8. **[Teams and permissions]** Aligned the close button position and style in the contact information and notification account dialogs.
9. **[System and operations]** Added OpenSandbox startup troubleshooting guidance for host seccomp restrictions that can leave `/workspace` unwritable even when volume permissions are correct.

## 🐛 Fixes

1. **[Workflows and Agents]** Fixed internal Node memory being overwritten when multiple child Apps or Workflow Tools call the same target. Content extraction, question classification, and Pi Agent state are isolated by the full call path, including cloned Apps that share descendant Tools and recursive calls back into the root App.
2. **[Workflows and Agents]** Fixed missing memory updates from Agents, Tool calls, and nested Workflows, loss of memory from branches that did not run, and concurrent child Workflows overwriting other Nodes' new state with stale state. Only each child Workflow's updates are merged, preserving other valid memory.
3. **[Workflows and Agents]** Fixed memory propagation and failure isolation in loops and parallel runs. Loops pass memory between successful iterations and preserve checkpoints when paused for interaction; failed iterations do not commit updates. Parallel runs merge only successful task results, keep failed attempts from affecting retries, and merge in input order, with later successful tasks taking precedence for the same memory key.
4. **[Workflows and Agents]** Fixed nested Pi Agents failing to resume question interactions when history is set to 0 or an empty custom history array. Resumes restore the state saved by the parent Workflow.
5. **[Workflows and Agents]** Fixed Agents incorrectly skipping Workflow Tools whose inputs should be generated by the Agent. Input types are now normalized before validation against the saved input modes.
6. **[Workflows and Agents]** Fixed initialization clearing stop requests received during preparation for Workflows and Commercial edition auxiliary generation. Workflow runs without SSE, including MCP calls and scheduled triggers, now also respond to explicit stop signals.
7. **[Workflows and Agents]** Fixed saves failing when legacy Agents fall back to manual Dataset selection but retain old variable references. Manual Dataset selections in Agents and Dataset search Nodes now filter malformed entries while preserving the remaining selections.
8. **[Workflows and Agents]** Fixed Skill exports failing when the edit sandbox was not running: when initialization is allowed, the server starts or resumes the sandbox and waits until it is ready before packaging. Members with write permission must wait for the sandbox to be ready; read-only collaborators can access export regardless of their local edit sandbox state.
9. **[Workflows and Agents]** Fixed cursor resets in multiline text fields that disrupted input method composition and candidate confirmation.
10. **[Workflows and Agents]** Fixed scrolling in Tool and form parameter configuration dialogs when their content exceeds the available space.
11. **[Chat experience]** Fixed inaccurate generation status and resume connections waiting indefinitely after long periods without output or client disconnects. Persisted chats now use independently renewed Redis leases, which expire within 60 seconds of the last renewal if the process exits; acquisition or read errors trigger fallback behavior, so mutual exclusion and accurate status cannot be guaranteed during Redis failures.
12. **[Chat experience]** Fixed concurrent sends being rejected and then waiting for a new reply instead of recovering the original round. The rejected text and attachments are restored to the input, and the existing reply is refreshed and recovered, including interactive resumes and replies that have already finished.
13. **[Chat experience]** Fixed an authentication data format error in shared chats that prevented message deletion and caused retries and sending edited messages to fail.
14. **[Chat experience]** Fixed the header variable panel in shared chats without login using regular chat visibility rules. External variables are now hidden from share visitors.
15. **[Chat experience]** Fixed model selectors in global variables and interaction forms in shared chats without login failing to load the model list or selected model name because share authentication was missing.
16. **[Chat experience]** Fixed images being missed when their Markdown descriptions contain paired square brackets, such as `![Image [1]](...)`; image extraction and replacement now handle these descriptions correctly.
17. **[Chat experience]** Added missing Simplified Chinese, Traditional Chinese, English, and Korean translations for sandbox connection and file errors, Skill generation status, and Tool version labels, fixing untranslated text or internal keys appearing in some screens.
18. **[Teams and permissions]** Fixed App creation, JSON imports, copies, and conversions to new Workflow copies failing when they include unreadable or missing resources. The initial version snapshots only readable resources; any remaining unusable Node references are marked as errors in the detail view for later correction.
19. **[Teams and permissions]** Fixed the login and member name forms submitting when Enter was used to confirm an input method candidate during composition. Pressing Enter again after confirmation submits the form.
20. **[Teams and permissions]** Fixed the “Cancel” button in the account deletion confirmation dialog not following the current interface language.
21. **[System and operations]** Fixed the Commercial edition's admin configuration page showing values that differ from the running configuration when the database has no system configuration or an older record lacks `systemEnv`. Valid `config.json` settings now initialize the running configuration, and the page fills only missing sections while preserving existing site and plan settings, preventing defaults from overwriting them on save.
22. **[System and operations]** Fixed user, feedback, and session search filters overwriting one another in chat logs; the list and CSV export now apply all selected conditions together.
23. **[Tools and channels]** Fixed blank text in some Tool names, descriptions, and tags when their Traditional Chinese translation is empty. These values fall back to Simplified Chinese, then English if no usable text is available.

## 🛠️ Code improvements

1. **[System and operations]** Added skills for authoring and running integration test cases organized by business area. Workflow editor regression cases use scenario matrices with single-page browsing and filtering, while temporary HTML reports record results, evidence, and retest history for each item.
2. **[System and operations]** Added a manually triggered GitHub Actions workflow for backporting merged PRs; its target branch defaults to `v4.17.x` and can be changed, and it creates a draft PR when complete. The repository's `fastgpt-backport-pr` skill supports batch backports to an explicitly specified maintenance branch, resolving mechanical conflicts automatically and requiring confirmation for semantic conflicts. After targeted checks, it pushes code directly, aligns Pro with the matching maintenance branch for `v4.17.x`, and submits Chinese and English release notes for the corresponding unreleased version in a separate PR based on `upstream/main`.
3. **[System and operations]** Updated the repository's `pr-review` skill guidelines to include PR comments, review summaries, and inline discussions. Re-reviews use previous reports and the full current diff to check the status of earlier findings and identify new risks, retaining the evidence for each assessment.
4. **[System and operations]** Removed standalone evaluation workspace configuration and related Pro scripts, commands, and historical assets to simplify development tooling.
