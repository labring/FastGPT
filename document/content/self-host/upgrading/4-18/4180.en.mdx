## Upgrade guide

### Configuration changes

- The default for `HNSW_EF_SEARCH` / `systemEnv.hnswEfSearch` changes from `100` to `200` for PostgreSQL, Milvus, OceanBase, SeekDB, and openGauss; explicit settings still apply and can be tuned to balance recall and query time.
- `HNSW_MAX_SCAN_TUPLES` / `systemEnv.hnswMaxScanTuples` no longer takes effect, and its admin setting has been removed. PostgreSQL now sets the scan limit automatically from the largest Dataset vector row count involved in the current indexed search, capped at `2147483647`; existing deployments can remove the old setting.
- Added `SERVICE_AXIOS_MAX_CONTENT_LENGTH` (default: `20` MiB) to cap decompressed bodies of buffered responses from the shared server-side HTTP client; requests exceeding the limit are aborted, so custom integrations that need larger responses must raise it. Explicit caller limits take precedence, and streamed downloads remain subject to caller or business quotas.
- Added `SHOW_OUTLINK_BRAND`: without `PRO_URL`, it is always `true`; with Pro connected, it defaults to `false` and can be set to `true` to enable branding. The frontend `show_outlink_brand` value comes from the server environment and overrides the same setting in `config.json`.
- The Commercial edition adds `auth.sms.MODEL_DEPRECATION` for the model deprecation SMS template and optional `auth.sms.MODEL_DEPRECATION_EN` for English, which falls back to the Chinese template when unset. Configure the template ID in the admin console before enabling SMS reminders.
- **Plugin service deployment**: Docker Compose templates now set `fastgpt-plugin`’s `FASTGPT_BASE_URL=http://fastgpt-app:3000`, point `MONGODB_URI` to a separate `fastgpt-plugin` database, and explicitly set `DB_MAX_LINK=100` to avoid sharing collections with the main database. Custom deployments should use an address for the main service that the Plugin container can reach. If the Plugin container logs `401` during a file upload callback, check this address first, correct it, recreate the Plugin container, and run the Tool again. Before replacing an existing deployment’s template, check which database the Plugin service currently uses and keep its existing dedicated connection; if a database change is needed, back up and migrate the existing Plugin data first.
- Default deployments now use RustFS for object storage; existing deployments can keep their current storage, and switching is covered in [MinIO to RustFS migration](/en/self-host/docker_minio_to_rustfs).

- **Content moderation Plugin migration**: The legacy built-in Baidu text moderation (`censor.BAIDU_TEXT_CENSOR_CLIENTID` / `censor.BAIDU_TEXT_CENSOR_CLIENTSECRET`), custom censor URL (`censor.customCensorURL`), and per-model `censor` flag in the commercial edition are deprecated and replaced by the `moderation` Plugin system managed by `fastgpt-plugin`.
  - If you used legacy Baidu moderation, go to **Admin Console > Content Moderation > Moderation Policy** to configure and enable the official **Baidu Content Security (`baidu`)** Plugin.
  - If you used a custom moderation URL (`customCensorURL`), install the official **Legacy Custom Moderation (`legacy-custom-censor`)** Plugin to connect your existing HTTP service without code changes, or build a native `moderation` Plugin with `@fastgpt-plugin/sdk-factory`.
  - For a full comparison of legacy and new behavior, field mappings, and Plugin development steps, see the [Content moderation upgrade and migration guide](/en/self-host/migration/content-moderation).

### Upgrade scripts

**Prerequisite**: Complete the required historical migrations on 4.17.x before upgrading. Version 4.18.x removes the old task registrations and implementations, so they will no longer run; historical status and error records remain in the database.

Added **Initialize Dataset vector indexes** (`20261022_initialize_dataset_vector_indexes`), which runs automatically in the background after startup for PostgreSQL without blocking the App: it first verifies and drops the legacy global `vector_index` online, then counts vectors in active Datasets in batches and queues index maintenance jobs. A successful migration means counting and queueing are complete; index builds continue in a globally serial queue. If cleanup or scanning fails, resolve the issue and retry from the upgrade management page to resume from the saved checkpoint. A custom index with the same name but a different definition is preserved and causes an error.

PG partial indexes require `halfvec` support, a fixed vector dimension in the `1–4000` range, permission to create and drop indexes online, and sufficient memory, shared memory, and disk space. Datasets whose indexes are not ready or have failed continue to use exact search, which may increase query time. Failed builds do not automatically retry with a lower resource budget; after the issue is resolved, the next actual vector count queues another attempt. A cache hit does not trigger a retry.

Added **Backfill historical chat channels** (`20261104_backfill_chat_publish_source`), which runs independently with batched reads and writes in the background after startup without blocking the App or waiting for long-running tasks in the regular background queue. It fills `publishSource` separately for chats and statistics records without changing legacy fields, identities, messages, or counters. Historical API, MCP, and deleted channels may retain only a type without a recoverable channel ID; conflicting references or invalid data are recorded as failures. After repair, retry from the upgrade management page to resume from the checkpoint.

Added **Backfill API Key types** (`20261104_backfill_openapi_key_type`), which runs independently in background batches over a fixed range after startup. It classifies only legacy keys without a type as personal or App keys based on their `appId` binding, preserving credentials, bindings, ownership, and quotas. Invalid types or bindings are recorded as failures; after repair, retry from the upgrade management page to resume from the checkpoint and process failed records first.

### Compatibility notes

- **Legacy App keys**: Legacy keys with a valid saved `appId` binding now use App key authentication; a request’s `appId` or SDK suffix no longer overrides that binding. Integrations that used these keys to access other Apps, Datasets, or model APIs must switch to personal keys, and viewing, copying, or updating App keys requires management permission for the bound App. Upgrade every authentication instance before enabling App keys; any rollback version must also enforce key types and binding boundaries.
- **Key management scripts**: `/api/support/openapi/list` now returns only your own personal keys by default and no longer prioritizes keys by `appId`. Scripts that query legacy bound keys must explicitly select the App type. When updating App keys, submit only editable fields and remove `authProxy` and personal tag fields.
- **API Key health checks**: `GET /api/support/openapi/health` now reads credentials from the `Authorization: Bearer <apiKey>` header instead of the URL’s `apiKey` parameter. Update existing health probes to send the key in this header and remove it from the URL.
- **Creating HTTP Tools**: Creating HTTP Tools inside a tool folder now requires write permission on that folder. Integrations that previously relied on log read permission must update their folder permissions.
- **Moving root resources**: Moving Apps, Tools, Datasets, Skills, or their folders from the root level, or moving root-level Collections within a Dataset, now requires management permission for the resource being moved; when independent Collection permissions are disabled, the Dataset’s permissions apply. Integrations with only read or write access must update their permissions.
- **Dataset permission inheritance**: `inheritPermission: false` is no longer ignored when creating a regular Dataset. Existing integrations that always send this value but still need to inherit parent permissions must omit it or set it to `true`.
- **Dataset embedding models**: Collection imports and reindexing, data and index writes or updates, search tests, and publishing Apps that use Datasets now require an existing, active embedding model that the operator is authorized to use. For Datasets with missing, disabled, or unauthorized models, restore model availability and grant the operating identity the required model permissions first.
- **Team audit queries**: In the Commercial edition, `/proApi/support/user/team/audit/list` now requires `dateStart`, `dateEnd`, and a logged-in member with Team management permission. Update existing query scripts to supply both time boundaries and verify the calling identity; for full-day queries, send explicit start-of-day and end-of-day values with UTC offsets.
- **System model endpoint authentication**: If an existing system model sets `requestUrl` but relies on the default `AIPROXY_API_TOKEN` for authentication, explicitly configure that endpoint’s `requestAuth` before upgrading. Without it, direct requests through the OpenAI SDK and Pi Agent no longer fall back to default credentials.
- **Chat running status**: `chatGenerateStatus` is now derived from Redis leases and returns only `0` (generating) or `1` (idle). It is no longer persisted in Mongo and no longer returns `2` (error); integrations that read the database field directly or depend on the error enum must use API status and message errors instead. During upgrade, stop old instances from accepting new requests and let ongoing runs finish, then switch all generation and status-query instances together to avoid mixing the two concurrency controls.
- **Dynamic selection options**: User selection Nodes and single- or multi-select form fields now keep only the first `200` valid variable-bound options at runtime, with each option truncated to at most `100` UTF-16 code units. Workflows that depend on longer option values or later candidates must adjust their candidate data and review downstream matching logic.
- **Workflow memory**: Memory keys for content extraction, question classification, and Pi Agents now include the source and call path. Custom integrations that read or write `ChatItem.memories` directly must support the new keys instead of relying on `agentLoopMemory-${nodeId}` or child Workflow keys without a call path.
- **Workflow save format**: Creating or saving a regular Workflow through the API no longer accepts complete MCP/HTTP Toolkit execution definitions. Integrations that construct their own Nodes must submit Toolkit IDs with name and description summaries instead.
- **Workflow export credentials**: Exported JSON no longer includes authentication settings for MCP/HTTP Tools and Toolkits. Workflows that rely on exported files to copy or migrate credentials must reconfigure authentication after import.
- **API identity parameters**: API sessions no longer allow switching user identity; existing sessions use their saved identity. Continue with the same `customUid`; omitting, clearing, or changing a bound value, or switching from the default to a custom identity, is rejected. Integrations that reuse a session across users must allocate separate `chatId` values for different users. A nonempty `customUid` requires an API Key. It is mutually exclusive with `authProxy`, even when empty; integrations that send both must choose one identity.
- **Session ID length**: Session management, file, citation, and Sandbox APIs now limit `chatId` to `1024` characters. Integrations that use longer custom IDs must adjust their generation rules and review existing oversized session IDs and their linked records.
- **Concurrent generation responses**: Non-streaming `chat/completions` requests now return HTTP `409` when the same session already has a generation in progress. Custom clients that depend on the previous error status code must handle this conflict response.
- **Log CSV exports**: Scripts that parse Team members from the “User” column must support `ID:name` instead of the previous member name; when a member has no name, the column contains only the ID. Channel columns are now split into “Call channel” and “Channel name,” so scripts that parse column names must also be updated.
- **App log time parameters**: App log APIs now validate ISO dates or date-time strings, and the chart API no longer accepts numeric timestamps. Update scripts that use nonstandard formats; for full-day queries, send explicit start-of-day and end-of-day values with UTC offsets, since date-only and offsetless values use the server’s local time.
- **Commercial edition App chart calculations**: Statistics now group by the fixed offset in the request’s start time instead of the account’s timezone, retaining that offset across daylight saving transitions. Retention counts only later activity within the selected window and no longer expands the query; reports relying on previous calculations must supply the intended offset explicitly and review retention results.
- **Channel data**: Custom chat queries and log parsers should use `publishSource`. New runs no longer write `Chat.shareId`; integrations that query shared chat history through the legacy field must adapt, and newly created shared sessions should not be routed back to old instances during upgrade.
- **Agent history context**: Agent runs no longer read the Node's `history` setting. The standard history window is now the latest `50` rounds, while system messages and context compression checkpoints are retained. Apps that depend on zero history or custom history arrays for context isolation must review their context controls and model usage.
- **Agent text output**: `answerText` and Tool responses now combine text from the entire Agent loop, including explanations before Tool calls. Downstream Nodes that expect only the final answer must update their processing.
- **Agent interaction constraints**: Agents are now treated as interactive Nodes and cannot be placed in parallel containers. The Commercial edition also rejects new automatic evaluation tasks for Apps containing Agents. Move existing parallel Agents out of their containers and use App versions without interactive Nodes for evaluations.
- **Nested sandbox ownership**: Nested Agents and Tool calls now use the root App session’s sandbox. Workflows that rely on separate child App sandboxes or locate files by child App must adapt to root-session ownership and a workspace shared by parent and child Nodes.
- **Sandbox initialization scripts**: Workflow Agent and Tool call Nodes now track successful scripts separately by App and Node instead of reusing the legacy global marker. After upgrading an existing sandbox, each Node with a configured script runs it again on first use; make sure these scripts are safe to rerun.
- **Custom JavaScript code sandbox deployments**: Linux deployments with seccomp enabled now require `fastgpt_js_launcher`. Custom images and source deployments must rebuild and package the native components, deploying the launcher alongside the `.node` addon; JavaScript process-pool initialization fails if the launcher is missing.
- **System Tool management API**: Removed `DELETE /api/core/plugin/admin/tool/delete`. Custom admin clients that still call this legacy endpoint must stop using it.

## 🚀 New features

1. **[Tools and channels]** Added App API Keys bound to a single App, managed separately from personal keys on the App publishing page. App managers share control of these keys for that App’s chats and chat management, independently of the owning member’s App permissions; the Commercial edition transfers key ownership through resource handover, and deleting an App also removes its bound keys.
2. **[Tools and channels]** Chat and related management APIs now share support for external user IDs and Team member proxies. Use `customUid` to narrow access to a user’s history, messages, files, citations, and Sandbox resources; personal keys with proxy permission can use `authProxy` to act with the represented member’s permissions.
3. **[Tools and channels]** Added FastGPT branding to public share pages across desktop, mobile, and embedded layouts; when enabled, new links show it by default, and desktop visitors can dismiss it for the current visit. Persistent hiding requires a valid plan entitlement, configurable per plan or individual subscription in the Commercial edition; legacy links without a saved preference remain exempt, while links with a saved hiding preference show branding again if the entitlement becomes invalid and hide it again when the entitlement is restored.
4. **[Workflows and Agents]** Workflow Agent Nodes can now be added from the template panel and used as Tool Nodes by other Agents. Dataset inputs support variable bindings; standalone ChatAgent Apps can also be referenced as Workflow child Apps or Agent Tools, with file inputs and resumable interactions for composing multi-Agent Workflows.
5. **[Workflows and Agents]** Added MCP and HTTP Toolkit Nodes that you can configure directly in a Workflow without first creating a standalone Tool App. Customize child Tool descriptions and authentication, debug each Tool, and let Tool call Nodes use the latest remote Tool definitions at runtime.
6. **[Workflows and Agents]** Commercial edition Workflow Builder can build, validate, and repair Workflows directly from clear creation or modification requests, while still waiting for preview confirmation when you ask to review a proposal first. Before delivering a candidate, the same Agent checks requirement coverage in its existing context; you still apply the candidate to the canvas manually.
7. **[Workflows and Agents]** Commercial edition Workflow Builder supports switching between independent tasks within a session, saving each task’s requirements, proposals, and draft separately so work can continue from saved data after context compression or an interrupted run. Recovery still checks task status and the canvas baseline; unsaved drafts may be lost if the sandbox is lost.
8. **[Models and billing]** System models now support an “Upcoming deprecation” flag in model management and model and speech selectors; Commercial edition admins can create notification plans with multiple rounds for Teams whose currently published Apps or Datasets statically use these models, sending in-app messages with optional SMS or email. Plans support failure inspection, run recovery, retries, and termination, and stop new deliveries at the deadline; model removal remains a separate action.
9. **[Models and billing]** Commercial edition Team models can now use custom request URLs and authentication through configuration APIs or templates as a transitional option for direct chat, Agent, embedding, reranking, and speech requests, retaining endpoint settings after edits. Endpoints undergo safety checks when saved and requested, including redirect restrictions; model lists hide endpoint and authentication details.
10. **[Models and billing]** Model management now supports dragging models into a custom order and canceling before saving; the root account can reorder system models, and with team models enabled in the Commercial edition, members with the “Install model” permission can reorder their own models. “Available models” groups your own team models, shared team models, and system models in that order and applies the custom order within each group; JSON configuration updates preserve this order, which the client also uses for its final system-model fallback.
11. **[Models and billing]** Model tables with permission configuration now show creators and identify system models separately. Member display pages can load current creator details, while shared-link catalogs do not expose member information.
12. **[Datasets and files]** With Dataset enhancement enabled in the Commercial edition, the template FAQ import API now supports optional automatic index generation using both questions and answers as input. Automatic indexing tasks that exceed the processing length limit fall back to standard vector indexing, retaining each entry and its input order.
13. **[Datasets and files]** Dataset search adds a rerank candidate limit of `10–100` chunks, with a default of `100`. Candidates are sent to the rerank model in text recall order after fusion and deduplication, helping balance search quality, latency, and model load; after successful reranking, text chunks beyond the candidate limit are excluded from weighted fusion so they cannot bypass the similarity filter.
14. **[Datasets and files]** Dataset search results and citation records now include the text recall rank before reranking, making it easier to compare recall and reranking results.
15. **[Datasets and files]** The Dataset Collection list API now supports sorting by name, creation time, or update time in ascending or descending order. Name sorting ignores case and orders Chinese characters by code point.
16. **[Teams and permissions]** Resource creation APIs now let you choose inherited parent permissions or independent permissions for Datasets, Apps, HTTP/MCP Tools, Skills, and their folders, giving you control over sharing at creation.
17. **[Teams and permissions]** Commercial edition Team audit logs now combine date, member, and event filters, defaulting to the latest `7` local calendar days including today, with older dates and inactive members available. Logged-in members with Team management permission can export all matching records as localized CSV, up to `50000` records per export; narrow the filters above that limit. Log timestamps in the CSV use the query start offset, and each export request creates an audit record.
18. **[Teams and permissions]** Commercial edition user management APIs now include Team memberships, member names, and department paths. Team member lists also return login usernames to distinguish accounts from member identities.
19. **[System and operations]** Chats now record the channel used by the latest run. Logs show channel types and names separately, with channel IDs available for inspection; filters, CSV exports, and Commercial edition statistics also use the new channel classification.
20. **[System and operations]** Chat logs now include an “Authorizer” column, hidden by default, separate from “User” to distinguish your users from the authenticated Team member. API `customUid` values appear unchanged as the user, and CSV exports follow the selected columns. Log columns now size to their contents so long UIDs do not squeeze member names.

## ⚙️ Improvements

1. **[Workflows and Agents]** Unified Tool, Skill, and Dataset cards and status checks across Agent forms and Workflow Nodes. Running, publishing, and single-Node Debug use the same rules, report invalid, offline, or unconfigured resources, and preserve existing configuration during asynchronous selection and saves.
2. **[Workflows and Agents]** Commercial edition Workflow Builder previews now show a title, a short summary, and a pending-confirmation status. Restored proposals awaiting confirmation open at the top of the card and preserve the reading position during subsequent rendering; confirmation, revision, and cancellation use the shared interaction controls.
3. **[Workflows and Agents]** Raised the option limit for single- and multi-select configuration from `50` to `200`. Manual options in User selection Nodes are capped at `200`, and each option text input accepts up to `100` UTF-16 code units.
4. **[Workflows and Agents]** Standardized button and model selector sizes across App, Workflow, and Tool editors, and aligned help icons with text for a more consistent layout.
5. **[Datasets and files]** PostgreSQL now maintains FP16 partial HNSW indexes per Dataset, building them on demand above `10000` vector rows and removing them below `5000`; the existing state is retained between these thresholds. Datasets without a ready index use exact search, and candidates from all groups are ranked by FP32 distance without changing the precision of stored vectors.
6. **[Datasets and files]** Optimized MongoDB indexes and tag prefiltering for Dataset Collections, reducing database scans for folder queries, counts, and search filters. With `SYNC_INDEX` enabled, new indexes are created before registered obsolete indexes are removed, while other custom indexes and tag indexes still required by older queries are preserved.
7. **[Datasets and files]** In the Commercial edition, moved tag filtering for simple Apps, ChatAgents, and Workflow Agents to the “Search filter” tab in Dataset search settings and added a dedicated toggle. Turning it off in manual input mode preserves conditions for later editing, and the summary reflects its state; variable-bound Datasets or filters preserve their configuration so tags that cannot be resolved while editing are not removed.
8. **[Datasets and files]** Tripled the per-minute file upload rate limit for each upload identity, reducing “Too many requests” errors during repeated or batch uploads.
9. **[Models and billing]** Consistently place models in test mode last in the mobile model selector, speech playback, channel bindings, and model log and dashboard filters, preserving catalog order within each group.
10. **[Models and billing]** Aligned header and body column widths in the model management table and isolated edit dialog state by row, reducing full-table rerenders when opening a dialog in a large list.
11. **[Models and billing]** Improved truncation and hover text for long names in model and speech selectors, keeping names from stretching controls or crowding the voice column.
12. **[Chat experience]** Improved chat history sidebar refreshes with batched queries for long lists and retries while a chat is running or a request has failed. Hidden tabs pause periodic refreshes, resource switches discard late responses, and failed refreshes preserve the previous status and read flags.
13. **[Tools and channels]** API documentation now groups parameters by resource, identity, and pagination mode, highlights fields for the selected branch, and corrects required-field markers and request examples to clarify each integration option.
14. **[System and operations]** Added OpenSandbox startup troubleshooting guidance for host seccomp restrictions that can leave `/workspace` unwritable even when volume permissions are correct.
15. **[System and operations]** The upgrade management page now shows totals for Dataset and chat migrations, and displays processed counts even for stages without a total, making background progress easier to assess.
16. **[System and operations]** Added a [MongoDB 5.x to 8.x migration guide](/en/self-host/upgrading/mongodb-8) for Docker Compose deployments, covering export, restore, verification, and rollback for deployments that choose to upgrade their database.
17. **[System and operations]** The documentation site adds a top announcement banner for Chinese pages and shortcuts to contact sales, get started for free, and view pricing in the table of contents area for both Chinese and English docs.

## 🐛 Fixes

1. **[Workflows and Agents]** Fixed internal Node memory being overwritten when multiple child Apps or Workflow Tools call the same target. Content extraction, question classification, and Pi Agent state are isolated by the full call path, including cloned Apps that share descendant Tools and recursive calls back into the root App.
2. **[Workflows and Agents]** Fixed missing memory updates from Agents, Tool calls, and nested Workflows, loss of memory from branches that did not run, and concurrent child Workflows overwriting other Nodes' new state with stale state. Only each child Workflow's updates are merged, preserving other valid memory.
3. **[Workflows and Agents]** Fixed memory propagation and failure isolation in loops and parallel runs. Loops pass memory between successful iterations and preserve checkpoints when paused for interaction; failed iterations do not commit updates. Parallel runs merge only successful task results, keep failed attempts from affecting retries, and merge in input order, with later successful tasks taking precedence for the same memory key.
4. **[Workflows and Agents]** Fixed context, plans, or answers being lost when Agents resume questions as child Tools or Apps, and unfinished interaction history affecting downstream Nodes or the next loop iteration. Pause state is saved per Node, and resumes produce the complete answer.
5. **[Workflows and Agents]** Fixed root sessions being unable to browse or download files after a nested Agent successfully prepared a sandbox. Readiness now records actual sandbox use for the session; later rounds without sandbox use or errors after readiness do not clear this state, and system and Team permissions still apply.
6. **[Workflows and Agents]** Fixed parent, child, or sibling Agent and Tool call Nodes overwriting same-named files from different sources in a shared sandbox during the same run. Unique names and model-visible paths are assigned consistently; cross-Node uploads with the same name and source reuse the name allocated in that run.
7. **[Workflows and Agents]** Fixed Nodes selecting different Skills clearing one another’s deployed versions and initialization state. Published Skill versions and successful initialization state remain cached in the sandbox; redeploying a missing directory clears its old marker so initialization runs again.
8. **[Workflows and Agents]** Fixed concurrent child Apps failing immediately when competing for a shared sandbox’s initialization lock. A busy lock now triggers bounded retries; timeouts and lease errors still return an initialization error.
9. **[Workflows and Agents]** Fixed initialization clearing stop requests received during preparation for Workflows and Commercial edition auxiliary generation. Workflow runs without SSE, including MCP calls and scheduled triggers, now also respond to explicit stop signals.
10. **[Workflows and Agents]** Fixed saves failing when legacy Agents fall back to manual Dataset selection but retain old variable references. Manual Dataset selections in Agents and Dataset search Nodes now filter malformed entries while preserving the remaining selections.
11. **[Workflows and Agents]** Fixed Skill exports failing when the edit sandbox was not running: when initialization is allowed, the server starts or resumes the sandbox and waits until it is ready before packaging. Members with write permission must wait for the sandbox to be ready; read-only collaborators can access export regardless of their local edit sandbox state.
12. **[Workflows and Agents]** Fixed Agents dropping the configured time granularity and start/end limits when passing interactive form fields for a date/time or time range. The original field settings are now preserved.
13. **[Workflows and Agents]** Fixed cursor resets in multiline text fields that disrupted input method composition and candidate confirmation.
14. **[Workflows and Agents]** Fixed scrolling in Tool and form parameter configuration dialogs when their content exceeds the available space. Menus in dialogs such as Collaborator permissions and HTTP authentication settings no longer get clipped by the dialog body or expand its scroll area; long menus scroll internally so you can reach the bottom options.
15. **[Workflows and Agents]** Fixed Agent maximum output tokens and answer visibility settings not taking full effect. Hiding the answer preserves required interactions and Node results; with error capture enabled, errors go to the error branch instead of being appended to the visible answer.
16. **[Workflows and Agents]** Fixed Pi Agent requests being rejected by model providers when Tool parameter schemas contained legacy required flags or internal extension fields. Tools, Sandbox Tools, and built-in Tools now normalize schemas before model calls.
17. **[Workflows and Agents]** Fixed Workflow Debug showing Nodes as successful after they entered an error branch. These Nodes now show as failed, and you can continue debugging branches that still need to run.
18. **[Workflows and Agents]** Fixed untranslated field hints for text editing, Dataset citations, and custom feedback during assisted Workflow generation across Simplified Chinese, Traditional Chinese, English, and Korean. Text editing hints now include the complete reference syntax for upstream outputs and global variables.
19. **[Datasets and files]** Fixed website sync in the Commercial edition missing child links on directory pages without valid content and incorrectly deleting existing Collections after invalid content, write failures, or page-limit truncation; link deduplication and relative resource resolution after redirects are improved, and incomplete syncs preserve existing data. Early stops and timeouts now clean up in order with bounded waits, preventing subsequent writes and retries after cancellation while database operations already in progress finish through their normal mechanisms.
20. **[Datasets and files]** Fixed incomplete scope constraints in Collection subtree queries and permission synchronization. Traversal and updates now stay within the current Team and Dataset, preventing invalid parent-child links from affecting other Datasets.
21. **[Datasets and files]** Fixed Alibaba Cloud OSS rejecting stream uploads when a known length was supplied but chunked encoding was also added, conflicting with `Content-Length`.
22. **[Datasets and files]** Fixed filenames containing escaped quotes being truncated when parsing `Content-Disposition`. Quotes and backslashes in the filename are now restored correctly.
23. **[Chat experience]** Fixed inaccurate generation status and resume connections waiting indefinitely after long periods without output or client disconnects. Persisted chats now use independently renewed Redis leases, which expire within 60 seconds of the last renewal if the process exits; acquisition or read errors trigger fallback behavior, so mutual exclusion and accurate status cannot be guaranteed during Redis failures.
24. **[Chat experience]** Fixed concurrent sends being rejected and then waiting for a new reply instead of recovering the original round. The rejected text and attachments are restored to the input, and the existing reply is refreshed and recovered, including interactive resumes and replies that have already finished.
25. **[Chat experience]** Fixed members with read-only App access being unable to mark their own sessions as read; session access restrictions still apply.
26. **[Chat experience]** Fixed admin feedback and closing custom feedback updating the user message when it shares a `dataId` with the AI reply in the same round. These operations now update only the corresponding AI reply.
27. **[Chat experience]** Fixed images being missed when their Markdown descriptions contain paired square brackets, such as `![Image [1]](...)`; image extraction and replacement now handle these descriptions correctly.
28. **[Chat experience]** Added missing Simplified Chinese, Traditional Chinese, English, and Korean translations for sandbox connection and file errors, Skill generation status, and Tool version labels, fixing untranslated text or internal keys appearing in some screens. Also added Korean text for account deletion, password setup, related audit events, Dataset tag errors, and rate-limit messages; Question classification Nodes now use Korean default options.
29. **[Chat experience]** Fixed refreshing after sending a message being mistaken for a send failure when the browser closed the stream, causing submitted text and attachments to reappear in the draft.
30. **[Models and billing]** Fixed the OpenAI SDK and Pi Agent using AI Proxy or host environment credentials when a custom model endpoint has no configured authentication, preventing default credentials from being sent to that address.
31. **[Teams and permissions]** Fixed detail responses potentially exposing plaintext authentication settings in legacy MCP/HTTP Tool configurations. Credentials are now encrypted when saved and displayed, and linked external Toolkits return only Tool summaries.
32. **[Teams and permissions]** Fixed API Key expiration and quota errors including the plaintext key. Error messages no longer expose credentials; health checks now read keys from the `Authorization` header, reducing exposure in URLs and access logs.
33. **[Teams and permissions]** Fixed members with only read or write access being able to move root-level resources, covering Apps, Tools, Datasets, Skills, their folders, and root-level Collections within a Dataset.
34. **[Teams and permissions]** Fixed an incorrect permission check when creating HTTP Tools inside a tool folder. Collaborators with folder write permission can now create them, while members with only log read permission are rejected.
35. **[Teams and permissions]** Fixed App creation, JSON imports, copies, and conversions to new Workflow copies failing when they include unreadable or missing resources. The initial version snapshots only readable resources; any remaining unusable Node references are marked as errors in the detail view for later correction.
36. **[Teams and permissions]** Fixed audit details treating some names, URLs, or changed values containing colons as translation keys. System labels are still translated, while user content is displayed unchanged.
