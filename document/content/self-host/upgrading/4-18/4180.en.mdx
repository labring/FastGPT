## Upgrade guide

**Prerequisite**: Complete the required historical migrations on 4.17.x before upgrading. Version 4.18.x removes the old task registrations and implementations, so they will no longer run; historical status and error records remain in the database.

### Configuration changes

- **Centralized instance settings**: Manage site, authentication, security, resource limits, concurrency, file policies, parsing providers, and subservice connections through admin forms. A startup migration imports legacy database settings and ENV values from the App process, preserving existing admin values and explicit clears. After migration, changes to these legacy ENV values have no effect. See [V4.18.0 environment variables](/en/self-host/config/env4180) for deployment variables that remain supported.
- The original `config.json` and Pro default configuration file are no longer runtime sources. If your deployment relies only on file settings, back up those files and review and restore the settings through the new forms after upgrading. App's new-format `defaultConfig.json` participates only in initial setup when all business configuration domains are empty; later file edits do not override database settings.
- `FE_DOMAIN` and `FILE_DOMAIN` move to the site URL (`site.publicUrl`) and file service domain (`storage.fileDomain`) in the admin console. An empty file domain uses the site URL. Object storage download mode, public endpoint, and CDN endpoint also move to admin settings; database and object storage infrastructure connections remain ENV settings. Admin settings show the current object storage provider and the fields it supports for short-link redirects. External access endpoints are available for `minio` and `aws-s3`. CDN endpoints are available for `minio`, `aws-s3`, OSS, and COS.
- Commercial edition team mode is now controlled by Pro's `TEAM_MODE`, which defaults to `single`; the old database team mode no longer applies. Existing multi-team or external synchronization deployments must set `multi` or `sync`, respectively, and restart Pro. `sync` also requires `EXTERNAL_USER_SYSTEM_BASE_URL`; without it, the system runs in `single` mode.
- Configure `SHOW_GIT` in App only. It defaults to `false` when `PRO_URL` is set, regardless of License activation; the Community edition always shows Git information. The new `ENABLE_SAAS_ADMIN_CONFIG` defaults to `false` and controls whether admin forms show SaaS operations fields, which are hidden by default in self-hosted deployments.
- Manage Code Sandbox and MCP SSE under Admin → Subservice configuration. Both default to disabled when unconfigured. Deployments that relied on the default Code Sandbox address must enable it and enter its address and Token in the admin console; the Token must match the standalone sandbox service.
- `USE_IP_LIMIT` and `DISABLE_CACHE` no longer take effect. Registered API IP limits always apply, and system caches follow their built-in policies.
- Stream recovery retention is fixed at `300` seconds during generation and `30` seconds after completion, with a `50%` Redis memory threshold and a `5`-second memory-check cache; legacy `STREAM_RESUME_*` settings no longer apply. Tracking counters refresh every `5` seconds and WeChat channel concurrency is fixed at `1000`, replacing `TRACK_BATCH_UPDATE_TIME` and `WECHAT_CHANNEL_CONCURRENCY`. Object storage redirect signatures last at most `30` seconds. Agent Sandbox entrypoint timeout is fixed at `60` seconds, with WebSocket message/frame limits of `64` / `16` MiB. The corresponding legacy ENV settings no longer apply.
- Langfuse reads only `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, and `LANGFUSE_BASE_URL` from each App or Pro process environment, without falling back to old database values. Tracing is disabled if any value is missing; restart the affected service after changes.
- Configure LLM request tracking log retention in the admin console. Changes also apply to existing records; reducing retention makes older records eligible for automatic cleanup.
- Configure the Secure attribute for login cookies and the shared HTTP client response size limit in Admin → Security and Admin → Resource limits. Startup migration imports legacy `AUTH_COOKIE_SECURE` and `SERVICE_AXIOS_MAX_CONTENT_LENGTH` once from the App process environment only; values set in Pro are not imported. Existing form settings take precedence. Defaults remain Secure disabled and a 20 MiB response limit. The shared limit applies to decompressed buffered responses; 0 allows only empty responses. Explicit caller limits take precedence, and streamed downloads retain their business quotas. New limits apply to subsequent requests, and cookie attributes apply when cookies are reissued.
- The default for `HNSW_EF_SEARCH` / `systemEnv.hnswEfSearch` changes from `100` to `200` for PostgreSQL, Milvus, OceanBase, SeekDB, and openGauss; explicit settings still apply, with the effective search width limited to `100–1000`, and can be tuned to balance recall and query time.
- `HNSW_MAX_SCAN_TUPLES` / `systemEnv.hnswMaxScanTuples` no longer takes effect, and its admin setting has been removed. PostgreSQL now sets the scan limit automatically from the largest Dataset vector row count involved in the current indexed search, capped at `2147483647`; existing deployments can remove the old setting.
- Added `SHOW_OUTLINK_BRAND`, configured in App only: without `PRO_URL`, App ignores this variable and always enables branding (`true`). When `PRO_URL` is set, App follows the ENV value, which defaults to `false`, regardless of License activation. The frontend `show_outlink_brand` value comes from the server environment and overrides the same setting in `config.json`.
- The maximum number of data rows per evaluation task is now configured under Admin → Limits and concurrency (`resource.evaluationMaxRows`), defaulting to `1000` and excluding the header. The legacy `EVAL_LINE_LIMIT` variable is no longer read or migrated. After upgrading, the new field defaults to `1000`; use the form to set a different limit. Changes take effect without a restart.
- Legacy `EVAL_CONCURRENCY` is not migrated or read after upgrading. Configure evaluation worker concurrency under Admin → Resource limits. The default is `3`; existing instance settings are preserved.
- Agent Sandbox CPU and memory overcommit factors are now instance settings, shown only for OpenSandbox with the Kubernetes runtime. Startup migration imports `AGENT_SANDBOX_CPU_OVERCOMMIT_FACTOR` and `AGENT_SANDBOX_MEMORY_OVERCOMMIT_FACTOR` once from the App process environment only. Matching Pro values are not imported. Existing form values take precedence; missing values default to `1`. Later ENV changes have no effect. Form changes apply only to newly created or recreated sandboxes.
- The Commercial edition adds `auth.sms.MODEL_DEPRECATION` for the model deprecation SMS template. SMS reminders currently use this Chinese template regardless of the user's language; `auth.sms.MODEL_DEPRECATION_EN` has no effect on SMS delivery. Configure the Chinese template ID in the admin console before enabling SMS reminders.
- **Plugin service deployment**: Docker Compose templates now set `fastgpt-plugin`’s `FASTGPT_BASE_URL=http://fastgpt-app:3000`, point `MONGODB_URI` to a separate `fastgpt-plugin` database, and explicitly set `DB_MAX_LINK=100` to avoid sharing collections with the main database. Custom deployments should use an address for the main service that the Plugin container can reach. If the Plugin container logs `401` during a file upload callback, check this address first, correct it, recreate the Plugin container, and run the Tool again. Before replacing an existing deployment’s template, check which database the Plugin service currently uses and keep its existing dedicated connection; if a database change is needed, back up and migrate the existing Plugin data first.
- Default deployments now use RustFS for object storage; existing deployments can keep their current storage, and switching is covered in [MinIO to RustFS migration](/en/self-host/docker_minio_to_rustfs).

- **Content moderation Plugin migration**: The legacy built-in Baidu text moderation (`censor.BAIDU_TEXT_CENSOR_CLIENTID` / `censor.BAIDU_TEXT_CENSOR_CLIENTSECRET`), custom censor URL (`censor.customCensorURL`), and per-model `censor` flag in the commercial edition are deprecated and replaced by the `moderation` Plugin system managed by `fastgpt-plugin`.
  - If you used legacy Baidu moderation, go to **Admin Console > Content Moderation > Moderation Policy** to configure and enable the official **Baidu Content Security (`baidu`)** Plugin.
  - If you used a custom moderation URL (`customCensorURL`), install the official **Legacy Custom Moderation (`legacy-custom-censor`)** Plugin to connect your existing HTTP service without code changes, or build a native `moderation` Plugin with `@fastgpt-plugin/sdk-factory`.
  - See the [Content moderation upgrade and migration guide](/en/self-host/migration/content-moderation) for legacy behavior comparisons and field mappings, and the [Content moderation guide](/en/plugin/moderation) for day-to-day configuration, testing, and custom Plugin development.

- **New deployments**: The default MongoDB version in the `main` Compose templates is now `8.0.34`. Startup and health checks use `mongosh`, and dependent services wait for the replica set primary to become ready.

### Upgrade scripts

These migrations run automatically; no manual execution is required.

1. Added **Migrate system configuration** (`20261116_migrate_system_configs`), which runs automatically at startup and blocks App business startup until it succeeds. It imports legacy settings, fills missing fields, and encrypts managed secrets while preserving admin values, explicit clears, Licenses, and instance identity; original legacy configuration data is retained. The migration preserves legacy values that fail the new save rules and logs the affected fields. Admins can correct them after upgrading. External file links and cross-origin access remain restricted if the security configuration is damaged. The task reruns idempotently from the beginning. On failure, correct the issue using the logs, restart the node holding the lease, and wait for the lease to expire so the task can retry automatically.
2. Added **Initialize Dataset vector indexes** (`20261022_initialize_dataset_vector_indexes`), which runs automatically in the background after startup for PostgreSQL without blocking the App: it first verifies and drops the legacy global `vector_index` online, then counts vectors in active Datasets in batches and queues index maintenance jobs. A successful migration means counting and queueing are complete; index builds continue in a globally serial queue. If cleanup or scanning fails, resolve the issue and retry from the upgrade management page to resume from the saved checkpoint. A custom index with the same name but a different definition is preserved and causes an error.
3. PG partial indexes require `halfvec` support, a fixed vector dimension in the `1–4000` range, permission to create and drop indexes online, and sufficient memory, shared memory, and disk space. Datasets whose indexes are not ready or have failed continue to use exact search, which may increase query time. Failed builds do not automatically retry with a lower resource budget; after the issue is resolved, the next actual vector count queues another attempt. A cache hit does not trigger a retry.
4. Added **Backfill historical chat channels** (`20261104_backfill_chat_publish_source`), which runs independently with batched reads and writes in the background after startup without blocking the App or waiting for long-running tasks in the regular background queue. It fills `publishSource` separately for chats and statistics records without changing legacy fields, identities, messages, or counters. Historical API, MCP, and deleted channels may retain only a type without a recoverable channel ID; unrecognized legacy sources are classified as `unknown` without guessing their channel. Records that previously failed source enum validation can be retried directly from the upgrade management page without modifying legacy data or resetting progress; other conflicting references or invalid data remain recorded as failures and can resume from the checkpoint after repair. Final validation now scans in batches and saves checkpoints, so it can resume at the appropriate batch after an interruption or after invalid data is repaired; legacy checkpoints restart only validation and preserve completed backfills.
5. Added **Backfill API Key types** (`20261104_backfill_openapi_key_type`), which scans all keys in batches, fills missing `type` values as `personal`, and stores valid `appId` values as BSON ObjectId values. Credentials, ownership, quotas, and default target or binding semantics remain unchanged. Repair invalid records and retry from the upgrade management page. Management queries support only normalized data. Legacy-format data present during migration or written by old instances is outside query compatibility support. Legacy records written after the initial scan boundary are not automatically backfilled and require separate normalization.
6. Added **Migrate model pricing** (`20261120_migrate_model_pricing`). It runs independently in the background after the system configuration migration finishes, without blocking the App. It first backfills missing legacy STT pricing types with `duration` in batches and preserves existing rates and configured `tokens` pricing. It then multiplies system LLM tier limits (`maxInputTokens`) from M Tokens by `1000` and rounds them to whole K Tokens with a minimum of `1`, all in one transaction. It skips any model with a finite limit above `10`. Unit prices remain per M Tokens. The final stage validates both STT and system LLM pricing. If the upgrade management page reports invalid data, fix it and retry from the checkpoint.

### Compatibility notes

- **System configuration automation**: The old `/api/proApi/admin/system/updateConfig` endpoint has been removed. Admin scripts that call it must switch to the main service's `/api/admin/system/config/get` and `/api/admin/system/config/update` endpoints.
- **Admin search parameters**: In the Commercial edition, App lists replace `searchKey` with `appName` or `appId`. Team, Plan, and invoice lists no longer read `search`; update existing admin scripts to use the appropriate `username` or `teamName` field.
- **Payment record filtering**: In the Commercial edition, `username` now matches the actual payer rather than all orders from that user’s Teams. Admin scripts that depend on the previous scope must filter by Team instead.
- **Deprecated integrations**: Personal or team OpenAI accounts, fast login entries, and external provider Workflow variables are supported only when already enabled or nonempty. Once disabled or cleared, they cannot be enabled again through the admin API. Review deployments that depend on these integrations before upgrading.
- **Alipay certificates**: Certificate mode requires the application certificate, Alipay public certificate, and root certificate. Deployments with incomplete legacy settings must supply the missing certificates before making payments, querying orders, or issuing refunds.
- **Legacy API keys**: Keep your existing keys. Keys without a `type` are automatically classified as personal keys, with the stored `appId` retained as the default chat target. Their access permissions and personal management remain unchanged. New App keys are limited to their bound App and managed jointly by its administrators.
- **API Key health checks**: `GET /api/support/openapi/health` now reads credentials from the `Authorization: Bearer <apiKey>` header instead of the URL’s `apiKey` parameter. Update existing health probes to send the key in this header and remove it from the URL.
- **Commercial edition CAPTCHA integrations**: Existing integrations for ordinary verification forms must switch the image URL from `/api/proApi/support/user/account/captcha/getImgCaptcha` to `/api/support/user/account/captcha/getImgCaptcha`, complete rotation verification, and pass the returned single-use token as `captcha` to the existing endpoint; character answers are no longer accepted. Submit the token within `30` seconds and verify again after a failed send.
- **System model endpoint authentication**: If an existing system model sets `requestUrl` but relies on the default `AIPROXY_API_TOKEN` for authentication, explicitly configure that endpoint’s `requestAuth` before upgrading. Without it, direct requests through the OpenAI SDK and Pi Agent no longer fall back to default credentials.
- If your model JSON configs or admin scripts use **LLM tiered pricing**, convert finite `pricing.tiers[].maxInputTokens` values from M Tokens to positive integers in K Tokens. After upgrading, confirm that the model pricing migration has completed on the upgrade management page and review your existing tiers in model management. If the migration skipped a model whose limits were entered in M Tokens, convert those limits manually. System models with prices that fail the new runtime validation incur zero points.
- **Dynamic selection options**: User selection Nodes and single- or multi-select form fields now keep only the first `200` valid variable-bound options at runtime, with each option truncated to at most `100` UTF-16 code units. Workflows that depend on longer option values or later candidates must adjust their candidate data and review downstream matching logic.
- **API identity parameters**: API sessions no longer allow switching user identity; existing sessions use their saved identity. Continue with the same `customUid`; omitting, clearing, or changing a bound value, or switching from the default to a custom identity, is rejected. Integrations that reuse a session across users must allocate separate `chatId` values for different users. A nonempty `customUid` requires an API Key. It is mutually exclusive with `authProxy`, even when empty; integrations that send both must choose one identity.
- **Session ID length**: Session management, file, citation, and Sandbox APIs now limit `chatId` to `1024` characters. Integrations that use longer custom IDs must adjust their generation rules and review existing oversized session IDs and their linked records.
- **API error handling**. If your client depends on previous HTTP status codes, update its error handling. An invalid API Key returns `401`, insufficient Points returns `402`, denied file access (`unAuthFile`) returns `403`, a missing App or Dataset returns `404`, and a non-streaming `chat/completions` request returns `409` when the same Session already has a generation in progress. If your integration matches fixed error text or translation keys, use `code` or `statusText`. The `message` field follows the request language and defaults to English. Existing integrations that test Dataset search or Embedding model connectivity must handle the new status codes for embedding failures. For example, upstream authentication failures or insufficient quota return `502`, and transient rate limits return `429`.
- **File previews and downloads**. If your integration embeds HTML, SVG, or XML file previews, open them in a separate page. In short-link redirect mode, FastGPT serves these files through its proxy, so download clients must handle the file response directly. In short-link redirect mode, FastGPT responds to `HEAD` with file metadata. If your client reads `Location` to obtain the redirect URL, use `GET`. If your R2 deployment used `STORAGE_EXTERNAL_ENDPOINT` to override the signing endpoint, verify after upgrading that clients can reach the R2 service endpoint.
- **DingTalk workspace list**: `/api/core/dataset/apiDataset/list` returns `parentId: null` for top-level DingTalk workspaces. Integrations that rely on the previous parent ID must treat these workspaces as root folders.
- **Template import filenames**. If your script URI-encodes filenames for `/api/core/dataset/collection/create/template`, send the original UTF-8 filename in the multipart `filename` parameter.
- **Synonym file downloads**. FastGPT regenerates synonym lists in the uploaded format so you can upload them again. If your integration expects CSV only, update it to handle XLS and XLSX.
- **Point grants**. Configured grants, Plan creation and updates, and coupon creation now require point amounts to be nonnegative safe integers. Update any existing scripts or settings that use invalid amounts and reissue any affected legacy coupons you still need with valid amounts.
- **Log CSV exports**: Scripts that parse Team members from the “User” column must support `ID:name` instead of the previous member name; when a member has no name, the column contains only the ID. Channel columns are now split into “Call channel” and “Channel name,” so scripts that parse column names must also be updated.
- **Team audit log list**. Existing Commercial edition integrations must use a signed-in account with Team management permission and supply both `dateStart` and `dateEnd`. Scripts that filter or parse App activity using `UPDATE_PUBLISH_APP` must also handle `SAVE_APP` and `PUBLISH_APP` for new records. Historical records retain the old event. Scripts that filter or parse Collection activity using `CREATE_COLLECTION` or `UPDATE_COLLECTION` must also recognize `dataset.collection.create`, `dataset.collection.rename`, `dataset.collection.move`, `dataset.collection.enable`, and `dataset.collection.disable` in new records.
- **Collection deletion API**: Select exactly one request-body form: `id`, `collectionIds`, or `datasetId + apiFileIds`. Legacy `query.id` remains supported but is deprecated; new integrations should use the request body.
- **Speech recognition usage**: Existing custom speech recognition integrations must check their upstream usage responses. Duration-based billing reads `usage.seconds`; missing or invalid values count as `0`, with no fallback to client-reported recording time or estimates from transcribed text.

- **Workflow CLI scripts**: Scripts that use `@fastgpt/workflow-cli` from source must switch to `@fastgpt/cli` and replace `fastgpt-workflow` with `fastgpt workflow-build` for build commands. Add `--offline` to scripts that initialize workspaces offline. JSON parsers must support `fastgpt-cli-result/v1` and read successful results from `data`.
- **Plugin installation API**: Scripts that call the system Plugin installation API must handle HTTP `500` when all installations fail. A partially successful Team batch install returns HTTP `200` with failed items in `data.failed`. If every item fails, read the error description from `message`.

## 🚀 New features

1. **[Tools and channels]** Added App API Keys bound to a single App, managed separately from personal keys on the App publishing page. App managers share control of these keys for that App’s chats and chat management, independently of the owning member’s App permissions; the Commercial edition transfers key ownership through resource handover, and deleting an App also removes its bound keys.
2. **[Tools and channels]** Chat and related management APIs now share support for external user IDs and Team member proxies. Use `customUid` to narrow access to a user’s history, messages, files, citations, and Sandbox resources; personal keys with proxy permission can use `authProxy` to act with the represented member’s permissions.
3. **[Tools and channels]** Chat logs now include an “Authorizer” column, hidden by default, separate from “User” to distinguish your users from the authenticated Team member. API `customUid` values appear unchanged as the user, and CSV exports follow the selected columns. Log columns now size to their contents so long UIDs do not squeeze member names. App chat logs now load as you scroll. Search by title keyword or enter the full session ID for an exact match. Each App remembers your search mode, and CSV exports use the current mode and filters.
4. **[Tools and channels]** Added FastGPT branding to public share pages across desktop, mobile, and embedded layouts; when enabled, new links show it by default, and desktop visitors can dismiss it for the current visit. Persistent hiding requires a valid plan entitlement, configurable per plan or individual subscription in the Commercial edition; legacy links without a saved preference remain exempt, while links with a saved hiding preference show branding again if the entitlement becomes invalid and hide it again when the entitlement is restored.
5. **[Tools and channels]** Added Plugin-based content moderation, disabled by default. When enabled, policies can independently check user input, model context, and final output, including streamed output, with configurable actions for suspected risks and moderation service errors. Admins can configure Plugins, switch the active service, test moderation results, and view global moderation records; the first configured Plugin is selected automatically when no service is active, and chat details show the records for that chat.
6. **[Tools and channels]** Added the official beta CLI, `@fastgpt/cli`, with login, profile switching, identity and environment checks, Dataset management and joint search, and App chat and history commands. JSON output and command metadata discovery support scripts and Agents. It also supports file and link imports, Collection and chunk management, and discovery of available Apps, models, system Tools, and Code Sandbox dependencies. Edit, validate, and compile Workflows offline, or connect to FastGPT to fetch authorized templates, pull App drafts or historical versions, compare drafts, debug, run test assertions, and check for sync conflicts before saving or publishing. Output supports field selection, value extraction by path, and compact command discovery.
7. **[Workflows and Agents]** Workflow Agent Nodes can now be added from the template panel and used as Tool Nodes by other Agents. Dataset inputs support variable bindings; standalone ChatAgent Apps can also be referenced as Workflow child Apps or Agent Tools, with file inputs and resumable interactions for composing multi-Agent Workflows.
8. **[Workflows and Agents]** Added MCP and HTTP Toolkit Nodes that you can configure directly in a Workflow without first creating a standalone Tool App. Customize child Tool descriptions and authentication, debug each Tool, and let Tool call Nodes use the latest remote Tool definitions at runtime.
9. **[Workflows and Agents]** Commercial edition Workflow Builder can build, validate, and repair Workflows directly from clear creation or modification requests, while still waiting for preview confirmation when you ask to review a proposal first. Valid candidates can be delivered directly; you still apply them to the canvas manually. If a run ends naturally without delivering a candidate, the same Agent checks requirement coverage in its existing context.
10. **[Workflows and Agents]** Commercial edition Workflow Builder supports switching between independent tasks within a session, saving each task’s requirements, proposals, and draft separately so work can continue from saved data after context compression or an interrupted run. Recovery still checks task status and the canvas baseline; unsaved drafts may be lost if the sandbox is lost.
11. **[Workflows and Agents]** App templates now support experience links, with Commercial edition management for links on custom and Plugin system templates, so template integrations can offer a preview before copying.
12. **[Workflows and Agents]** Added fullscreen viewing for simple App, ChatAgent, and Workflow debug views and the complete response dialog, preserving the current content when switching sizes. The Workflow debug panel can also be resized by dragging its edge, making long answers and run details easier to inspect.
13. **[Workflows and Agents]** With vision enabled, FastAgent and Pi Agent can use images returned by MCP, HTTP, Workflow Tools, Plugins with multimodal output, and Sandbox file Tools in the next model turn. Each Tool result can pass up to `4` images. Text results remain available if an image fails to load or vision is off. Downstream Nodes can still use the Plugin’s output values.
14. **[Models and billing]** System models now support an “Upcoming deprecation” flag in model management and model and speech selectors; Commercial edition admins can create notification plans with multiple rounds for Teams whose currently published Apps or Datasets statically use these models, sending in-app messages with optional SMS or email. Plans support failure inspection, run recovery, retries, and termination, and stop new deliveries at the deadline; model removal remains a separate action.
15. **[Models and billing]** Commercial edition Team models can now use custom request URLs and authentication through configuration APIs or templates as a transitional option for direct chat, Agent, embedding, reranking, and speech requests, retaining endpoint settings after edits. Endpoints undergo safety checks when saved and requested, including redirect restrictions; model lists hide endpoint and authentication details.
16. **[Models and billing]** OpenAI and Azure Model providers now offer Auto, Responses, and Chat Completions as upstream chat protocols, with new providers defaulting to automatic selection based on the model. This affects only chat models, and the upstream must support the selected protocol.
17. **[Models and billing]** Model management now supports dragging models into a custom order and canceling before saving; the root account can reorder system models, and with team models enabled in the Commercial edition, members with the “Install model” permission can reorder their own models. “Available models” groups your own team models, shared team models, and system models in that order and applies the custom order within each group; JSON configuration updates preserve this order, which the client also uses for its final system-model fallback. Newly created or newly imported models appear at the top of their group without changing the relative order of existing models.
18. **[Models and billing]** Model tables with permission configuration now show creators and identify system models separately. Member display pages can load current creator details, while shared-link catalogs do not expose member information.
19. **[Models and billing]** Speech recognition models now support rates per `60` seconds or separate rates per million input and output tokens. Model management, the public pricing page, and usage details reflect the selected billing type; API, Lark, and WeChat Official Account entry points record usage against the model actually called.
20. **[Models and billing]** Usage in the Commercial edition now supports mutually exclusive member, department (including subdepartments), or group filters, with the same scope applied to details, charts, and CSV exports. Selections use current organization and group memberships; members with Team management permission can view usage for the selected members, while other members can view only their own usage.
21. **[Datasets and files]** Added optional MongoDB vector storage. Setting a separate search connection with `SEARCH_MONGO_URL` gives MongoDB priority over other vector stores. Use it for new vector stores, since FastGPT does not migrate existing vectors automatically. The search database requires MongoDB `8.3+` and `mongot`. It uses `1536`-dimensional unit vectors and an HNSW INT8 index, chooses exact or approximate search based on the number of vectors that match the filters, and reranks results using the original vectors.
22. **[Datasets and files]** With Dataset enhancement enabled in the Commercial edition, the template FAQ import API now supports optional automatic index generation using both questions and answers as input. Automatic indexing tasks that exceed the processing length limit fall back to standard vector indexing, retaining each entry and its input order.
23. **[Datasets and files]** Dataset search adds a rerank candidate limit of `10–100` chunks, with a default of `100`. Candidates are sent to the rerank model in text recall order after fusion and deduplication, helping balance search quality, latency, and model load; after successful reranking, text chunks beyond the candidate limit are excluded from weighted fusion so they cannot bypass the similarity filter.
24. **[Datasets and files]** Added a unified Dataset search API for joint searches across Datasets, text or image queries, and results limited by chunk count or token budget. It supports reranking, query expansion, and Commercial edition metadata filters; joint vector searches require the same Embedding model.
25. **[Datasets and files]** API file Datasets now support batch deletion by external file or directory IDs through `datasetId + apiFileIds`, including the corresponding derived folders and child documents, without first looking up internal Collection IDs. Deletion still requires ownership of each deletion root.
26. **[Datasets and files]** The object storage SDK now supports byte-range reads, allowing custom integrations to retrieve only the file segments they need.
27. **[Datasets and files]** Use the column headers in a Dataset’s Collection list to sort by name, creation time, or update time in either direction. Changing the sort returns the list to the first page and keeps the current search and tag filters.
28. **[Teams and permissions]** The root account can search and switch to any available Team to manage its resources and members, with switches recorded in audit logs. Membership created for cross-Team administration does not consume tenant seats or change the Team’s actual owner when switching.
29. **[Teams and permissions]** Commercial edition Team audit logs now have a Resource column with links to associated Apps, Tools, Datasets, Collections, and Skills. Deleted resources are marked and retain their recorded names when available. Details highlight what changed, and the list and CSV are sorted by operation time, newest first. Combine date, member, and event filters. The default range is the most recent `7` local calendar days including today, and you can select older dates and inactive members. Signed-in members with Team management permission can export all matching records as localized CSV, up to `50000` records per export. Narrow the filters if you exceed the limit. The CSV includes associated resources and uses the query start offset for timestamps. Each export request creates an audit record. Collection audit logs cover creation, renaming, moves, enable and disable actions, tag changes, restored permission inheritance, and sync attempts. They also cover signed-in users viewing source content or exporting Q&A from Collection details. Details can show the associated Dataset and relevant paths. Password sign-in logs can show the IP address and its region when available.
30. **[Teams and permissions]** Commercial edition user management APIs now include Team memberships, member names, and department paths. Team member lists also return login usernames to distinguish accounts from member identities.
31. **[System and operations]** Added an admin instance configuration center with settings for core services, security, resources, and subservices, filtered by deployment edition; shared settings are also available in the Community edition. Select parsing providers, test service connectivity, and save changes across configuration domains. The form validates settings on save, marks fields with errors, and preserves the draft if concurrent edits conflict.
