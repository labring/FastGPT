## Upgrade guide

### Configuration changes

- The default for `HNSW_EF_SEARCH` / `systemEnv.hnswEfSearch` changes from `100` to `200` for PostgreSQL, Milvus, OceanBase, SeekDB, and openGauss; explicit settings still apply and can be tuned to balance recall and query time.
- `HNSW_MAX_SCAN_TUPLES` / `systemEnv.hnswMaxScanTuples` no longer takes effect, and its admin setting has been removed. PostgreSQL now sets the scan limit automatically from the largest Dataset vector row count involved in the current indexed search, capped at `2147483647`; existing deployments can remove the old setting.
- Added `SHOW_OUTLINK_BRAND`: without `PRO_URL`, it is always `true`; with Pro connected, it defaults to `false` and can be set to `true` to enable branding. The frontend `show_outlink_brand` value comes from the server environment and overrides the same setting in `config.json`.
- **Plugin service deployment**: Docker Compose templates now set `fastgpt-plugin`’s `FASTGPT_BASE_URL=http://fastgpt-app:3000`, point `MONGODB_URI` to a separate `fastgpt-plugin` database, and explicitly set `DB_MAX_LINK=100` to avoid sharing collections with the main database. Custom deployments should use an address for the main service that the Plugin container can reach. Before replacing an existing deployment’s template, check which database the Plugin service currently uses and keep its existing dedicated connection; if a database change is needed, back up and migrate the existing Plugin data first.
- Default deployments now use RustFS for object storage; existing deployments can keep their current storage, and switching is covered in [MinIO to RustFS migration](/en/self-host/docker_minio_to_rustfs).

- **Content moderation Plugin migration**: The legacy built-in Baidu text moderation (`censor.BAIDU_TEXT_CENSOR_CLIENTID` / `censor.BAIDU_TEXT_CENSOR_CLIENTSECRET`), custom censor URL (`censor.customCensorURL`), and per-model `censor` flag in the commercial edition are deprecated and replaced by the `moderation` Plugin system managed by `fastgpt-plugin`.
  - If you used legacy Baidu moderation, go to **Admin Console > Content Moderation > Moderation Policy** to configure and enable the official **Baidu Content Security (`baidu`)** Plugin.
  - If you used a custom moderation URL (`customCensorURL`), install the official **Legacy Custom Moderation (`legacy-custom-censor`)** Plugin to connect your existing HTTP service without code changes, or build a native `moderation` Plugin with `@fastgpt-plugin/sdk-factory`.
  - For a full comparison of legacy and new behavior, field mappings, and Plugin development steps, see the [Content moderation upgrade and migration guide](/en/self-host/migration/content-moderation).

### Upgrade scripts

**Prerequisite**: Complete the required historical migrations on 4.17.x before upgrading. Version 4.18.x removes the old task registrations and implementations, so they will no longer run; historical status and error records remain in the database.

Added **Initialize Dataset vector indexes** (`20261022_initialize_dataset_vector_indexes`), which runs automatically in the background after startup for PostgreSQL without blocking the App: it first verifies and drops the legacy global `vector_index` online, then counts vectors in active Datasets in batches and queues index maintenance jobs. A successful migration means counting and queueing are complete; index builds continue in a globally serial queue. If cleanup or scanning fails, resolve the issue and retry from the upgrade management page to resume from the saved checkpoint. A custom index with the same name but a different definition is preserved and causes an error.

PG partial indexes require `halfvec` support, a fixed vector dimension in the `1–4000` range, permission to create and drop indexes online, and sufficient memory, shared memory, and disk space. Datasets whose indexes are not ready or have failed continue to use exact search, which may increase query time. Failed builds do not automatically retry with a lower resource budget; after the issue is resolved, the next actual vector count queues another attempt. A cache hit does not trigger a retry.

Added **Backfill historical chat channels** (`20261104_backfill_chat_publish_source`), which runs independently with batched reads and writes in the background after startup without blocking the App or waiting for long-running tasks in the regular background queue. It fills `publishSource` separately for chats and statistics records without changing legacy fields, identities, messages, or counters. Historical API, MCP, and deleted channels may retain only a type without a recoverable channel ID; conflicting references or invalid data are recorded as failures. After repair, retry from the upgrade management page to resume from the checkpoint.

Added **Backfill API Key types** (`20261104_backfill_openapi_key_type`), which runs independently in background batches over a fixed range after startup. It classifies only legacy keys without a type as personal or App keys based on their `appId` binding, preserving credentials, bindings, ownership, and quotas. Invalid types or bindings are recorded as failures; after repair, retry from the upgrade management page to resume from the checkpoint and process failed records first.

### Compatibility notes

- **Legacy App keys**: Legacy keys with a valid saved `appId` binding now use App key authentication; a request’s `appId` or SDK suffix no longer overrides that binding. Integrations that used these keys to access other Apps, Datasets, or model APIs must switch to personal keys, and viewing, copying, or updating App keys requires management permission for the bound App. Upgrade every authentication instance before enabling App keys; any rollback version must also enforce key types and binding boundaries.
- **Key management scripts**: `/api/support/openapi/list` now returns only your own personal keys by default and no longer prioritizes keys by `appId`. Scripts that query legacy bound keys must explicitly select the App type. When updating App keys, submit only editable fields and remove `authProxy` and personal tag fields.
- **Chat running status**: `chatGenerateStatus` is now derived from Redis leases and returns only `0` (generating) or `1` (idle). It is no longer persisted in Mongo and no longer returns `2` (error); integrations that read the database field directly or depend on the error enum must use API status and message errors instead. During upgrade, stop old instances from accepting new requests and let ongoing runs finish, then switch all generation and status-query instances together to avoid mixing the two concurrency controls.
- **Dynamic selection options**: User selection Nodes and single- or multi-select form fields now keep only the first `200` valid variable-bound options at runtime, with each option truncated to at most `100` UTF-16 code units. Workflows that depend on longer option values or later candidates must adjust their candidate data and review downstream matching logic.
- **Workflow memory**: Memory keys for content extraction, question classification, and Pi Agents now include the source and call path. Custom integrations that read or write `ChatItem.memories` directly must support the new keys instead of relying on `agentLoopMemory-${nodeId}` or child Workflow keys without a call path.
- **API identity parameters**: API sessions no longer allow switching user identity; existing sessions use their saved identity. Continue with the same `customUid`; omitting, clearing, or changing a bound value, or switching from the default to a custom identity, is rejected. Integrations that reuse a session across users must allocate separate `chatId` values for different users. A nonempty `customUid` requires an API Key. It is mutually exclusive with `authProxy`, even when empty; integrations that send both must choose one identity.
- **Session ID length**: Session management, file, citation, and Sandbox APIs now limit `chatId` to `1024` characters. Integrations that use longer custom IDs must adjust their generation rules and review existing oversized session IDs and their linked records.
- **Concurrent generation responses**: Non-streaming `chat/completions` requests now return HTTP `409` when the same session already has a generation in progress. Custom clients that depend on the previous error status code must handle this conflict response.
- **Log CSV exports**: Scripts that parse Team members from the “User” column must support `ID:name` instead of the previous member name; when a member has no name, the column contains only the ID. Channel columns are now split into “Call channel” and “Channel name,” so scripts that parse column names must also be updated.
- **Channel data**: Custom chat queries and log parsers should use `publishSource`. New runs no longer write `Chat.shareId`; integrations that query shared chat history through the legacy field must adapt, and newly created shared sessions should not be routed back to old instances during upgrade.
- **Agent history context**: Agent runs no longer read the Node's `history` setting. The standard history window is now the latest `50` rounds, while system messages and context compression checkpoints are retained. Apps that depend on zero history or custom history arrays for context isolation must review their context controls and model usage.
- **Agent text output**: `answerText` and Tool responses now combine text from the entire Agent loop, including explanations before Tool calls. Downstream Nodes that expect only the final answer must update their processing.
- **Agent interaction constraints**: Agents are now treated as interactive Nodes and cannot be placed in parallel containers. The Commercial edition also rejects new automatic evaluation tasks for Apps containing Agents. Move existing parallel Agents out of their containers and use App versions without interactive Nodes for evaluations.
- **System Tool management API**: Removed `DELETE /api/core/plugin/admin/tool/delete`. Custom admin clients that still call this legacy endpoint must stop using it.

## 🚀 New features

1. **[Tools and channels]** Added App API Keys bound to a single App, managed separately from personal keys on the App publishing page. App managers share control of these keys for that App’s chats and chat management, independently of the owning member’s App permissions; the Commercial edition transfers key ownership through resource handover, and deleting an App also removes its bound keys.
2. **[Tools and channels]** Chat and related management APIs now share support for external user IDs and Team member proxies. Use `customUid` to narrow access to a user’s history, messages, files, citations, and Sandbox resources; personal keys with proxy permission can use `authProxy` to act with the represented member’s permissions.
3. **[Tools and channels]** Added FastGPT branding to public share pages across desktop, mobile, and embedded layouts; when enabled, new links show it by default, and desktop visitors can dismiss it for the current visit. Persistent hiding requires a valid plan entitlement, configurable per plan or individual subscription in the Commercial edition; legacy links without a saved preference remain exempt, while links with a saved hiding preference show branding again if the entitlement becomes invalid and hide it again when the entitlement is restored.
4. **[Workflows and Agents]** Workflow Agent Nodes can now be added from the template panel and used as Tool Nodes by other Agents. Dataset inputs support variable bindings for composing multi-Agent Workflows.
5. **[Models and billing]** Model management now supports dragging models into a custom order and canceling before saving; the root account can reorder system models, and with team models enabled in the Commercial edition, members with the “Install model” permission can reorder their own models. “Available models” groups your own team models, shared team models, and system models in that order and applies the custom order within each group; JSON configuration updates preserve this order, which the client also uses for its final system-model fallback.
6. **[Models and billing]** Model tables with permission configuration now show creators and identify system models separately. Member display pages can load current creator details, while shared-link catalogs do not expose member information.
7. **[Datasets and files]** Dataset search results and citation records now include the text recall rank before reranking, making it easier to compare recall and reranking results.
8. **[Teams and permissions]** Commercial edition user management APIs now include Team memberships, member names, and department paths. Team member lists also return login usernames to distinguish accounts from member identities.
9. **[System and operations]** Chats now record the channel used by the latest run. Logs show channel types and names separately, with channel IDs available for inspection; filters, CSV exports, and Commercial edition statistics also use the new channel classification.
10. **[System and operations]** Chat logs now include an “Authorizer” column, hidden by default, separate from “User” to distinguish your users from the authenticated Team member. API `customUid` values appear unchanged as the user, and CSV exports follow the selected columns. Log columns now size to their contents so long UIDs do not squeeze member names.

## ⚙️ Improvements

1. **[Workflows and Agents]** Unified Tool, Skill, and Dataset cards and status checks across Agent forms and Workflow Nodes. Running, publishing, and single-Node Debug use the same rules, report invalid, offline, or unconfigured resources, and preserve existing configuration during asynchronous selection and saves.
2. **[Workflows and Agents]** Commercial edition Workflow Builder previews now show a title, a short summary, and a pending-confirmation status. Restored proposals awaiting confirmation open at the top of the card and preserve the reading position during subsequent rendering; confirmation, revision, and cancellation use the shared interaction controls.
3. **[Workflows and Agents]** Raised the option limit for single- and multi-select configuration from `50` to `200`. Manual options in User selection Nodes are capped at `200`, and each option text input accepts up to `100` UTF-16 code units.
4. **[Datasets and files]** PostgreSQL now maintains FP16 partial HNSW indexes per Dataset, building them on demand above `10000` vector rows and removing them below `5000`; the existing state is retained between these thresholds. Datasets without a ready index use exact search, and candidates from all groups are ranked by FP32 distance without changing the precision of stored vectors.
5. **[Datasets and files]** In the Commercial edition, moved tag filtering for simple Apps, ChatAgents, and Workflow Agents to the “Search filter” tab in Dataset search settings and added a dedicated toggle. Turning it off in manual input mode preserves conditions for later editing, and the summary reflects its state; variable-bound Datasets or filters preserve their configuration so tags that cannot be resolved while editing are not removed.
6. **[Datasets and files]** Tripled the per-minute file upload rate limit for each upload identity, reducing “Too many requests” errors during repeated or batch uploads.
7. **[Models and billing]** Consistently place models in test mode last in the mobile model selector, speech playback, channel bindings, and model log and dashboard filters, preserving catalog order within each group.
8. **[Models and billing]** Aligned header and body column widths in the model management table and isolated edit dialog state by row, reducing full-table rerenders when opening a dialog in a large list.
9. **[Chat experience]** Improved chat history sidebar refreshes with batched queries for long lists and retries while a chat is running or a request has failed. Hidden tabs pause periodic refreshes, resource switches discard late responses, and failed refreshes preserve the previous status and read flags.
10. **[Tools and channels]** API documentation now groups parameters by resource, identity, and pagination mode, highlights fields for the selected branch, and corrects required-field markers and request examples to clarify each integration option.
11. **[System and operations]** Added OpenSandbox startup troubleshooting guidance for host seccomp restrictions that can leave `/workspace` unwritable even when volume permissions are correct.
12. **[System and operations]** The upgrade management page now shows totals for Dataset and chat migrations, and displays processed counts even for stages without a total, making background progress easier to assess.

## 🐛 Fixes

1. **[Workflows and Agents]** Fixed internal Node memory being overwritten when multiple child Apps or Workflow Tools call the same target. Content extraction, question classification, and Pi Agent state are isolated by the full call path, including cloned Apps that share descendant Tools and recursive calls back into the root App.
2. **[Workflows and Agents]** Fixed missing memory updates from Agents, Tool calls, and nested Workflows, loss of memory from branches that did not run, and concurrent child Workflows overwriting other Nodes' new state with stale state. Only each child Workflow's updates are merged, preserving other valid memory.
3. **[Workflows and Agents]** Fixed memory propagation and failure isolation in loops and parallel runs. Loops pass memory between successful iterations and preserve checkpoints when paused for interaction; failed iterations do not commit updates. Parallel runs merge only successful task results, keep failed attempts from affecting retries, and merge in input order, with later successful tasks taking precedence for the same memory key.
4. **[Workflows and Agents]** Fixed context, plans, or answers being lost when Agents resume questions as child Tools or Apps, and unfinished interaction history affecting downstream Nodes or the next loop iteration. Pause state is saved per Node, and resumes produce the complete answer.
5. **[Workflows and Agents]** Fixed initialization clearing stop requests received during preparation for Workflows and Commercial edition auxiliary generation. Workflow runs without SSE, including MCP calls and scheduled triggers, now also respond to explicit stop signals.
6. **[Workflows and Agents]** Fixed saves failing when legacy Agents fall back to manual Dataset selection but retain old variable references. Manual Dataset selections in Agents and Dataset search Nodes now filter malformed entries while preserving the remaining selections.
7. **[Workflows and Agents]** Fixed Skill exports failing when the edit sandbox was not running: when initialization is allowed, the server starts or resumes the sandbox and waits until it is ready before packaging. Members with write permission must wait for the sandbox to be ready; read-only collaborators can access export regardless of their local edit sandbox state.
8. **[Workflows and Agents]** Fixed Agents dropping the configured time granularity and start/end limits when passing interactive form fields for a date/time or time range. The original field settings are now preserved.
9. **[Workflows and Agents]** Fixed cursor resets in multiline text fields that disrupted input method composition and candidate confirmation.
10. **[Workflows and Agents]** Fixed scrolling in Tool and form parameter configuration dialogs when their content exceeds the available space.
11. **[Workflows and Agents]** Fixed Agent maximum output tokens and answer visibility settings not taking full effect. Hiding the answer preserves required interactions and Node results; with error capture enabled, errors go to the error branch instead of being appended to the visible answer.
12. **[Workflows and Agents]** Fixed Pi Agent requests being rejected by model providers when Tool parameter schemas contained legacy required flags or internal extension fields. Tools, Sandbox Tools, and built-in Tools now normalize schemas before model calls.
13. **[Datasets and files]** Fixed Alibaba Cloud OSS rejecting stream uploads when a known length was supplied but chunked encoding was also added, conflicting with `Content-Length`.
14. **[Chat experience]** Fixed inaccurate generation status and resume connections waiting indefinitely after long periods without output or client disconnects. Persisted chats now use independently renewed Redis leases, which expire within 60 seconds of the last renewal if the process exits; acquisition or read errors trigger fallback behavior, so mutual exclusion and accurate status cannot be guaranteed during Redis failures.
15. **[Chat experience]** Fixed concurrent sends being rejected and then waiting for a new reply instead of recovering the original round. The rejected text and attachments are restored to the input, and the existing reply is refreshed and recovered, including interactive resumes and replies that have already finished.
16. **[Chat experience]** Fixed admin feedback and closing custom feedback updating the user message when it shares a `dataId` with the AI reply in the same round. These operations now update only the corresponding AI reply.
17. **[Chat experience]** Fixed images being missed when their Markdown descriptions contain paired square brackets, such as `![Image [1]](...)`; image extraction and replacement now handle these descriptions correctly.
18. **[Chat experience]** Added missing Simplified Chinese, Traditional Chinese, English, and Korean translations for sandbox connection and file errors, Skill generation status, and Tool version labels, fixing untranslated text or internal keys appearing in some screens.
19. **[Chat experience]** Fixed refreshing after sending a message being mistaken for a send failure when the browser closed the stream, causing submitted text and attachments to reappear in the draft.
20. **[Teams and permissions]** Fixed API Key expiration and quota errors including the plaintext key. Error messages no longer expose credentials.
21. **[Teams and permissions]** Fixed App creation, JSON imports, copies, and conversions to new Workflow copies failing when they include unreadable or missing resources. The initial version snapshots only readable resources; any remaining unusable Node references are marked as errors in the detail view for later correction.
22. **[Teams and permissions]** Fixed the “Cancel” button in the account deletion confirmation dialog not following the current interface language.
23. **[Teams and permissions]** Fixed share pages loading public App information through identifiers for other publishing channels. Only share channels are now accepted.
24. **[System and operations]** Fixed MongoDB 4.x failures caused by empty update fields when clearing a team's AI account or external Workflow variables, moving Dataset Collections, and updating or clearing chat feedback in some cases.
25. **[System and operations]** Fixed the Commercial edition's admin configuration page showing values that differ from the running configuration when the database has no system configuration or an older record lacks `systemEnv`. Valid `config.json` settings now initialize the running configuration, and the page fills only missing sections while preserving existing site and plan settings, preventing defaults from overwriting them on save.
26. **[System and operations]** Fixed user, feedback, and session search filters overwriting one another in chat logs; the list and CSV export now apply all selected conditions together.
27. **[System and operations]** Fixed Langfuse Node attributes leaking into parent traces and missing Agent generation records and usage. Concurrent Nodes now collect usage separately without including other Nodes' data.
28. **[Tools and channels]** Fixed audio transcription input validation errors being wrapped as generic service errors. Invalid inputs now return the standard HTTP `400` parameter error.
29. **[Tools and channels]** Fixed blank text in some Tool names, descriptions, and tags when their Traditional Chinese translation is empty. These values fall back to Simplified Chinese, then English if no usable text is available.

## 🛠️ Code improvements

1. **[System and operations]** Added skills for authoring and running integration test cases organized by business area. Workflow editor regression cases use scenario matrices with single-page browsing and filtering, plus manually triggered Node and headless Playwright scripts; AI runs uncovered cases or reviews script failures, while temporary HTML reports retain the executor, results, evidence, and retest history for each item.
2. **[System and operations]** Added a manually triggered GitHub Actions workflow for backporting merged PRs; its target branch defaults to `v4.17.x` and can be changed, and it creates a draft PR when complete. The repository's `fastgpt-backport-pr` skill supports batch backports to an explicitly specified maintenance branch, resolving mechanical conflicts automatically and requiring confirmation for semantic conflicts. After targeted checks, it pushes code directly, aligns Pro with the matching maintenance branch for `v4.17.x`, and submits Chinese and English release notes for the corresponding unreleased version in a separate PR based on `upstream/main`.
3. **[System and operations]** Updated the repository's `pr-review` skill guidelines to assess implementation plans against business constraints and consolidate security, performance, and engineering checks. Reviews include PR comments, review summaries, and inline discussions; re-reviews use previous reports and the full current diff to check earlier findings and new risks, retaining the evidence for each assessment.
4. **[System and operations]** Added per-language draft control to the documentation site, with consistent filtering across routes, navigation, search, and exports. `llms.txt` now exports published pages in the requested language, while missing translations can still fall back to published content.
5. **[System and operations]** Removed standalone evaluation workspace configuration and related Pro scripts, commands, and historical assets to simplify development tooling.
