## Upgrade guide

### Configuration

When using `HTTP_PROXY` / `HTTPS_PROXY` to access MCP services, the FastGPT container must resolve target hostnames through local DNS. The proxy must support CONNECT tunnels to the target port, including port 80 or a custom port for plain HTTP targets.

Use `NO_PROXY` for trusted hosts that require direct connections. Direct requests still pin DNS addresses and enforce SSRF checks. This update requires no new environment variables or app upgrade scripts.

## 🐛 Fixes

1. Fixed MCP connections failing when an environment proxy is configured. Proxy tunnels now connect to a validated, pinned IP address to prevent proxy-side DNS resolution from bypassing SSRF protection. Also improved connection timeouts, cancellation, and resource cleanup.
2. Fixed an issue where clearing inputs after restarting a plugin could leave stale values in some fields or fail to restore their defaults.
3. Fixed the WeCom client mistakenly redirecting to SSO when `sso.autoLogin` is disabled, and unified WeCom terminal auto-redirect behavior under `sso.autoLogin` and `WECOM_LOGIN_AUTO_REDIRECT` without requiring an SSO image update. Self-hosted WeCom SSO deployments that previously relied only on `WECOM_LOGIN_AUTO_REDIRECT=true` for auto-redirect must enable global `sso.autoLogin` after upgrading to keep auto-redirecting in WeCom (enabling it also auto-redirects regular browsers to SSO on the login page).
4. Fixed an issue where syncing selected folders in an API Dataset could incorrectly remove imported folders or files if the provider did not support folder detail lookups.
