## Upgrade guide

### Image updates

- Update the main FastGPT service (`fastgpt-app`) image tag to `v4.17.5`. For the commercial edition, also update `fastgpt-pro` to `v4.17.5`.
- The latest [Docker Compose deployment templates](/en/self-host/deploy/docker) are intended for **new deployments** (the bundled vector service `fastgpt-vector` uses `pgvector/pgvector:0.8.7-pg18`, `fastgpt-aiproxy-pg` uses standard `postgres:18.7` with both mounted at `/var/lib/postgresql`, and MongoDB uses `8.3.17`). When upgrading an existing deployment, keep the original images and `/var/lib/postgresql/data` mount paths for both PostgreSQL services so PostgreSQL 18 does not fail to start on existing PostgreSQL 15 data. If you already run MongoDB 8.0 and need compatibility with recent Ubuntu kernels, update in place to patch `8.0.38` while keeping your existing volume, and perform any cross-series MongoDB upgrade as a separate migration step. For external MongoDB instances, see the [MongoDB kernel compatibility notes](https://www.mongodb.com/docs/manual/administration/production-notes/#platform-support-notes).
- The deployment templates add the `host.docker.internal:host-gateway` mapping to OpenSandbox Server. For custom Compose deployments using this hostname, add the same mapping to `extra_hosts` on `fastgpt-opensandbox-server` so the service can reach sandbox ports published on the Docker host.

### Configuration and data

Upgrading FastGPT from v4.17.4 requires no new environment variables or application upgrade scripts. For custom Compose deployments, update the applicable image tags in your existing configuration.

If your deployment uses PostgreSQL 15 (vector database and AI Proxy database), MongoDB 5.x/8.0, or MinIO, keep your existing database images, volume mount paths, and storage configuration when upgrading FastGPT, and update only the FastGPT service images. Before switching database versions or moving from MinIO to RustFS as a separate step, follow the [data backup and migration guide](/en/self-host/migration/docker_db).

## Security fixes

1. Fixed a security isolation issue when opening an HTML preview from a chat in a new tab.
2. Fixed missing permission checks when moving apps, Datasets, Skills, and Collections from the root directory.

## 🐛 Fixes

1. Fixed an issue where replies in home chats or apps with read-only access remained marked as unread after non-root users read them.
2. Fixed incorrect permission checks when creating HTTP tools in tool folders.
3. Fixed workflow detail pages failing to load when an end node in a loop or parallel execution has an invalid reference, and aggregate output types failing to reset.
