## 1. 日志出现 ERR 等级的 “Failed to ensure external public/private bucket exists”，导致无法连接上对象存储

### 1.1 错误栈显示
- error: Error: getaddrinfo ENOTFOUND

示例
- ![1.1 错误栈显示：界面示例](/imgs/optimized/faq4.png.webp)

### 可能的错误
- 端点主机名无法解析，或客户端使用了服务端不支持的虚拟主机式桶地址

### 解决
- 从 FastGPT 容器检查 S3 端点主机名的 DNS 与网络连通性；修正端点或 DNS 配置。
- 如果端点采用路径式寻址，将 `STORAGE_S3_FORCE_PATH_STYLE` 设为 `true`，避免客户端拼接无法解析的桶子域名。

## 2. 上传对话文件 / 知识库文件报错

### 2.1 SignatureDoesNotMatch
- 签名不一致。当前文件上传由 FastGPT 后端代理到对象存储，FastGPT 入口的 Nginx 不参与 S3 签名；需要检查的是 FastGPT 与对象存储之间、位于对象存储前面的反向代理

### 可能的错误
- 对象存储前置的反向代理（如 Nginx）转发时未透传 `Host` 请求头，导致对象存储收到的 Host 与 FastGPT 签名时使用的 `STORAGE_S3_ENDPOINT` 主机不一致

### 解决
- 在对象存储前置的 Nginx 中配置 `proxy_set_header Host $http_host;`。Nginx 的 `$host` 内置变量会去掉端口，需使用 `$http_host`
