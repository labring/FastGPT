### 前端页面崩溃

1. 记录复现步骤、FastGPT 版本，以及浏览器控制台和失败请求的错误信息。
2. 检查管理员中的模型配置、服务端初始化日志和网络请求。
3. 使用当前稳定版浏览器，关闭页面翻译和相关扩展后复测；提交 Issue 时去掉密钥和个人数据。

### 能否纯本地运行

可以。需要在本地准备语言模型、Embedding 模型，以及当前部署模板要求的数据库、对象存储、AI Proxy 和插件等服务。离线环境还需提前准备镜像、模型文件和所需插件包，并验证每条调用链。

---

### 其他模型没法进行问题分类/内容提取

检查运行详情和模型响应，确认所选模型与渠道支持节点需要的工具调用或结构化输出。JSON 解析失败也可能来自返回格式、截断或提示词。先在管理员中测试模型，再使用小输入复测对应节点，按实际能力调整模型配置与提示词。参见[模型问题排查](/zh-CN/self-host/troubleshooting/model-errors)。

---

### 页面崩溃

按本页“前端页面崩溃”步骤排查。出现 `URI malformed` 时，记录发生错误的地址和操作步骤，并检查 URL 编码。配置加载失败时，先处理服务端对应错误，再刷新页面。

---

### 开启内容补全后，响应速度变慢

问题扩展会增加模型调用，并可能产生多个检索查询。查看运行详情中问题扩展、召回和重排各阶段耗时，再调整扩展模型、检索配置与并发；实际查询数量以配置和运行结果为准。

---

### 页面中可以正常回复，API 报错

比较两次调用的应用、身份、请求体和 `stream` 设置。分别测试流式与非流式请求，并记录 HTTP 状态、错误体和服务端 requestId；继续沿 FastGPT、AI Proxy、模型上游逐层定位。参见[对话接口](/zh-CN/openapi/chat)。

---

### 知识库索引没有进度/索引很慢

1. 检查集合处理状态和解析、向量训练错误。
2. 在管理员中测试该知识库绑定的 Embedding 模型与渠道。
3. 查看模型服务商的限流、余额和请求耗时，并检查解析及向量队列并发。
4. 处理错误后按页面提供的重试操作恢复。详细步骤见[知识库常见问题](/zh-CN/guide/dataset/faq)。

---

### Connection error

从 FastGPT 服务所在网络检查 AI Proxy 的地址、端口、DNS、TLS 和代理配置，再检查 AI Proxy 到模型上游的连通性。容器间通信使用共享网络内的服务名与容器端口；宿主机服务使用容器可达的宿主机地址。

---

### 修改了 vectorModels 未生效

`vectorModels` 属于旧配置方式。当前版本在管理员模型配置中管理 Embedding 模型；先确认模型测试通过，再刷新客户端。已有知识库的向量与所用模型绑定，更换模型时应按知识库页面支持的流程重新处理并验收检索结果，保留原始资料和可恢复备份。

---

### 如何修改 root 密码

修改环境变量中的 `DEFAULT_ROOT_PSW`，然后重启 FastGPT。

### FastGPT 支持 OpenAI 的 Responses API（/v1/responses）吗？

不支持（截至 4.17.0），请求会返回 404。请改用 `POST /api/v1/chat/completions` 调用应用，它兼容 OpenAI Chat Completions 格式。

### 升级后启动报 index not found（collection=modeldata_v2）怎么办？

适用版本：4.16.2 及以后，向量库为 Milvus。日志里有 `IndexNotExist ... index not found[collection=modeldata_v2]`。

原因：从 4.16.2 起，向量检索和全文检索都使用 `modeldata_v2` 这张表。启动时这张表已存在、却缺少全文检索索引，就会报错并退出。为什么会缺索引，目前还没有定论。另外要求 Milvus 不低于 2.5.16。

怎么做：升级前按 [Milvus BM25 全文检索配置与迁移](/zh-CN/self-host/milvus-bm25) 备份并升级 Milvus，再升级 FastGPT 并迁移数据。已经出现这个报错的，需要删除并重建这张表，会删除数据，请先备份并联系技术支持处理。迁移完成之前，知识库检索查不到旧数据。

### docker-compose 部署报 AGENT_SANDBOX_OPENSANDBOX_IMAGE 没配置、AGENT_SANDBOX_PREVIEW_PROXY_URL 不对怎么办？

适用版本：4.16.0 及以后。从 4.16.0 起，沙箱镜像只用 `AGENT_SANDBOX_OPENSANDBOX_IMAGE` 这一个变量，并且必须配置 `AGENT_SANDBOX_PREVIEW_PROXY_URL`。用 4.15 或更早的 compose 模板搭配新版镜像，就会报这两个错。

怎么做：按 [Docker Compose 部署](/zh-CN/self-host/deploy/docker) 使用一键脚本，或手动下载和镜像同一版本的模板（当前版本用 `main` 目录，没有 v4.16、v4.17 目录）。

注意：在已经部署过的目录里重新运行一键脚本，会重新生成数据库密码和 `AES256_SECRET_KEY`，并覆盖 `docker-compose.yml`。请先备份原文件；要保留数据，就选择不自动生成密码（或设置 `FASTGPT_AUTO_GENERATE_CREDENTIALS=false`），并把原来的密码和密钥拷过去。

### 并行执行报 parallel_task_not_reach_end，或者只跑了一个任务怎么办？

适用版本：已按 4.17.0 核实。并行执行按输入数组的元素个数开任务，一个元素对应一个任务。传入的是一整段多行文本（比如每行一个 URL）时，它会被当成只有一个元素的数组，所以只跑一个任务。`parallel_task_not_reach_end` 表示某个任务的子流程没有走到「结束」节点；子流程有更具体的报错时，会优先显示那条报错。

怎么做：在并行执行前加一个「代码运行」节点，把文本按换行拆成数组，例如返回 `text.split('\n').map(s => s.trim()).filter(Boolean)`，再让并行执行的数组输入引用这个结果。仍然报错，就打开出错任务的运行详情，检查子流程有没有走到「结束」节点。

### 用 HTTPS 访问时，上传文件报 s3 upload network error 怎么办？

适用版本：已按 4.17.0 核实。浏览器上传文件用的地址取自 `FILE_DOMAIN`，没设置时取自 `FE_DOMAIN`。页面是 HTTPS、而这个地址是 `http://` 时，浏览器会把请求当作混合内容拦截，请求到不了服务端。

怎么做：把对应配置改成可以访问的 https 地址（设置了 `FILE_DOMAIN` 就改它，否则改 `FE_DOMAIN`），然后重启。可以在浏览器控制台确认是否有 Mixed Content 报错。

### Windows 本地开发时，FastGPT 启动失败，连不上插件服务（localhost:3004）怎么办？

适用范围：本地开发环境（`deploy/dev`）。`fastgpt-plugin` 用 host 网络监听 3004 端口，FastGPT 启动时访问 `http://localhost:3004` 失败就会退出。Windows 的 Docker Desktop 默认只在它自己的虚拟机里让 host 网络生效，本机访问不到。

怎么做：在 Docker Desktop（4.34 及以上，需登录）的 Settings → Resources → Network 里勾选 Enable host networking，然后重启；或者按开发文档的建议，改在 WSL2、Linux、macOS 下开发。

### 模型报 Download multimodal file timed out，或读不到图片怎么办？

适用版本：4.15.2 及以后。`MULTIPLE_DATA_TO_BASE64` 默认值在 4.15.2 是 `true`，4.15.3 起是 `false`。为 `false` 时，FastGPT 把 `http(s)://` 开头的文件下载短链交给模型服务商去下载。短链前缀依次取 `FILE_DOWNLOAD_PUBLIC_URL_PREFIX`、`FILE_DOMAIN`、`FE_DOMAIN` 中第一个设置了的；如果是内网地址，模型服务商访问不到，就会下载超时（可能返回 `Download multimodal file timed out`）。

可选方案：其一，设置 `MULTIPLE_DATA_TO_BASE64=true`，由 FastGPT 编码为 base64 发送；其二，将 `FILE_DOMAIN` 配置为模型服务商可从公网访问的 FastGPT 服务地址，`FE_DOMAIN` 专用于用户浏览器访问。

### 导入模板时报“模板文件格式不正确，应该是首列为 q,a,indexes 的 csv 文件”怎么办？

适用版本：4.9.11～4.15.8。

原因：这些版本只接受 CSV 文件，并且文件内容（去掉首尾空白后）必须以 `q,a,indexes` 开头。表头每一列都加了引号（如 `"q","a","indexes"`）、写成了 `index`，或者第一行前面多了别的内容，都会报这个错。

怎么做：使用导入页提供的 CSV 模板填写内容，用文本编辑器打开确认第一行以 `q,a,indexes` 开头，不要另存成 `.xlsx`。也可以升级到 4.16.0 及以后：支持 `.csv` 和 `.xlsx`，表头为 `q`、`a`、`index`（可重复）、`metadata`（可选），旧版的 `q,a,indexes` 表头仍然可用，不需要改文件。新模板的写法见 [模板导入](/zh-CN/guide/dataset/template)。

### 调用对话接口时，怎么拿到模型的思考内容？

适用版本：4.15.2 及以后。思考内容放在单独的 `reasoning_content` 字段里，和正文 `content` 分开：流式返回时，有思考增量的数据块，其 `choices[0].delta` 里带 `reasoning_content`；非流式返回时，普通文本回答的 `choices[0].message` 里带 `reasoning_content`。只有模型实际输出了思考内容、并且 FastGPT 能识别时才有这个字段：上游返回 `reasoning_content` 字段，或者在模型配置里打开思考支持后，正文里用 `<think></think>` 包起来。4.17.1 起，AI Proxy 的 OpenAI 类型渠道还可以把上游的 `reasoning` 字段映射成 `reasoning_content`。
