## 1. Log shows ERR level "Failed to ensure external public/private bucket exists", resulting in inability to connect to object storage

### 1.1 Error Stack Display

- error: Error: getaddrinfo ENOTFOUND

Example

- ![1.1 Error Stack Display — interface example](/imgs/optimized/faq4.png.webp)

### Possible Errors

- The endpoint hostname cannot be resolved, or the client uses a virtual-hosted bucket address unsupported by the service

### Solution

- Check endpoint DNS resolution and network access from the FastGPT container; correct the endpoint or DNS configuration.
- For a service that uses path-style addressing, set `STORAGE_S3_FORCE_PATH_STYLE` to `true` so the client avoids an unresolvable bucket subdomain.

## 2. Upload conversation file / Dataset file error

### 2.1 SignatureDoesNotMatch

- A signature mismatch. FastGPT's backend proxies file uploads to object storage, so the Nginx in front of FastGPT does not take part in S3 signing. Check the reverse proxy that sits in front of the object storage, between FastGPT and the storage service.

### Possible Errors

- The reverse proxy in front of the object storage (such as Nginx) does not forward the `Host` header, so the host received by the object storage differs from the `STORAGE_S3_ENDPOINT` host FastGPT used for signing.

### Solution

- Set `proxy_set_header Host $http_host;` in the Nginx in front of the object storage to preserve the original host and port used to sign the request. Nginx's `$host` variable strips the port.
