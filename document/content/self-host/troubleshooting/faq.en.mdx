### Frontend Page Crash

1. The troubleshooting guidance attributes 90% of cases to model configuration. Enable at least one model in each category, then check parameters that expect arrays or objects. Use an empty array or object where an empty value is required.
2. Older browsers may lack support for JavaScript features used by FastGPT. Include the steps to reproduce the crash and browser console errors in a GitHub issue.
3. Disable the browser's automatic translation, which can interfere with the page.

### Other models cannot perform question classification/content extraction

1. Check the logs for errors such as `JSON invalid` or `not support tool`. For a model without tool or function calling support, set `toolChoice=false` and `functionCall=false` to use prompt mode. The built-in prompts have been tested with commercial model APIs; question classification generally works, while content extraction remains limited.
2. If the configuration is correct and the logs show no errors, adapt the classification prompt to the model using `customCQPrompt`.

---

### Page Crash

1. Disable automatic browser translation.
2. Check that the configuration file loaded successfully. Missing system settings can cause null-reference errors during some operations.

- The troubleshooting guidance attributes 95% of these cases to configuration errors, often reported as `xxx undefined`.
- For `URI malformed`, report the affected page and steps in a GitHub issue. This error indicates a problem decoding an encoded string.

3. Check for API compatibility issues, which are a less common cause.

---

### After enabling content completion, the response speed becomes slow

1. Query rewriting requires an additional model call.
2. It also performs 3–5 search queries, so database performance can significantly affect response time.

---

### Normal reply in the page, API error

The chat page uses `stream=true`. Test the API with the same setting using `curl`, because some model APIs have limited support for non-streaming requests.

---

### Dataset indexing has no progress/indexing is very slow

Check the error logs and identify the matching case:

1. Chat works but indexing stalls: check that an embedding model is configured in `vectorModels`.
2. Both chat and indexing fail: model API requests may be failing. Check connectivity to OneAPI or OpenAI.
3. Indexing progresses slowly: check the API key's rate limits. The historical example in this guide cites free OpenAI account limits of 3 or 60 requests per minute and 200 per day; verify the limits that apply to your current account.

---

### Connection error

Check connectivity from the FastGPT server to the model API. A server in mainland China may be unable to reach OpenAI. For OneAPI, also check that its container and FastGPT can communicate on the same network.

---

### Changes to vectorModels have no effect

1. Restart the container and confirm that the model configuration loaded. Check the logs or the model selector when creating a Dataset.
2. Refresh the browser.
3. An existing Dataset keeps the embedding model selected when it was created. Applying the new model requires deleting and recreating that Dataset. Preserve the source data before deleting it so you can import it again.

---

### How to change the root password

Modify the `DEFAULT_ROOT_PSW` environment variable, and then restart FastGPT.
