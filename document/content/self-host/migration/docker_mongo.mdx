## 作者

原社区迁移示例由 [samqin123](https://github.com/samqin123) 提供，见 [PR 1426](https://github.com/labring/FastGPT/pull/1426)。以下步骤保留逻辑备份方法，并按当前迁移边界重新整理。

## 介绍

`mongodump` 导出 MongoDB 业务数据。完整 FastGPT 迁移还需保存向量数据库、对象存储、配置与密钥，见[完整迁移清单](/zh-CN/self-host/migration/docker_db)。源端记为 A，目标端记为 B，本地备份存放位置记为 C。

迁移前核对 FastGPT、MongoDB 和 MongoDB Database Tools 版本兼容性。停止 FastGPT 及其他写入方，完成一致性备份。目标端先使用隔离实例和新的持久化卷进行恢复演练，并保留源环境与原卷用于回退。

## 1. 准备源端与备份目录

示例假设 MongoDB 容器名为 `mongo`、业务数据库为 `fastgpt`；请按实际部署替换。确认容器中安装了匹配版本的 `mongodump`，并确认备份账号具备导出权限。命令省略密码参数，由工具交互提示输入密码。

```bash
docker exec mongo mongodump --version
docker exec mongo mkdir -p /tmp/fastgpt-backup
mkdir -p ./fastgpt-backup
```

备份目录显式复制到宿主机；实际卷挂载路径通过部署配置核对。

## 2. 导出与转移

在 A 的宿主机执行：

```bash
docker exec -it mongo mongodump --db fastgpt --username BACKUP_USER --authenticationDatabase admin --archive=/tmp/fastgpt-backup/fastgpt.archive.gz --gzip
docker cp mongo:/tmp/fastgpt-backup/fastgpt.archive.gz ./fastgpt-backup/fastgpt.archive.gz
```

检查命令退出状态和导出日志，并为归档计算 SHA-256 校验值。在 Linux 使用 `sha256sum`，在 macOS 使用 `shasum -a 256`。将归档及校验值复制到 C 和 B，传输后重新计算并比较。独立日志数据库也需要单独备份。

```bash
sha256sum ./fastgpt-backup/fastgpt.archive.gz
scp ./fastgpt-backup/fastgpt.archive.gz operator@target-host:/path/to/backup/
```

## 3. 隔离恢复

B 的 MongoDB 应完成对应模板要求的账号和副本集初始化，FastGPT 业务服务保持停止。先检查 MongoDB 日志和副本集健康状态，再将归档复制到目标 MongoDB 容器：

```bash
docker cp /path/to/backup/fastgpt.archive.gz mongo:/tmp/fastgpt.archive.gz
docker exec -it mongo mongorestore --username RESTORE_USER --authenticationDatabase admin --archive=/tmp/fastgpt.archive.gz --gzip --nsInclude='fastgpt.*'
```

使用具备恢复权限的账号，检查恢复日志中的成功与失败记录数。在干净的隔离数据库执行恢复；出现重复键或命名空间冲突时，保留现场并检查目标实例和备份内容。源数据库名变化时，先核对 Database Tools 的命名空间映射参数。

## 4. 启动与验收

同步恢复配套向量数据、对象存储和原配置密钥后，启动目标 FastGPT。执行 `docker compose ps`，检查容器就绪状态和 FastGPT、MongoDB 日志；MongoDB 的 `rs.status()` 应显示预期副本集状态。

验收至少包括：账号登录、应用列表、知识库集合和数据块、文件下载、检索结果、对话历史与新对话。只有归档校验和业务验收都通过，才安排流量切换；完成后保留源备份与回退窗口。
