OpenSandbox 适合需要自托管 Agent/Skill 沙盒运行环境的场景。FastGPT 通过 OpenSandbox Server 创建沙盒，并通过 Agent Sandbox Proxy 为浏览器提供文件、终端和预览访问能力。

## Docker Compose 配置

最新版 Docker Compose 已经包含 OpenSandbox Server、Volume Manager、Agent Sandbox Proxy 和沙盒运行时镜像配置，无需再单独合并其他 YAML 文件。

[查看最新版 docker-compose.yml（PgVector，中国大陆镜像源）](/deploy/docker/main/cn/docker-compose.pg.yml)

其他向量数据库和全球镜像源版本见 [Docker Compose 部署](/zh-CN/self-host/deploy/docker)。

## 环境变量配置

Docker Compose YAML 文件中已包含默认值，下文说明各变量的含义。本文对应最新配置，旧版配置请对照对应版本的 YAML 文件。

### OpenSandbox 服务

根据实际部署环境检查 Compose 文件中的以下配置：

| 配置                          | 说明                                                                                                             |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `x-volume-manager-auth-token` | Volume Manager 的认证 Token，需要与 FastGPT 的 `AGENT_SANDBOX_OPENSANDBOX_VOLUME_MANAGER_TOKEN` 一致。           |
| `[server].api_key`            | OpenSandbox Server API Key，需要与 FastGPT 的 `AGENT_SANDBOX_OPENSANDBOX_API_KEY` 一致。                         |
| `[docker].host_ip`            | 沙盒端点对 Proxy 可访问的宿主机地址，通常使用宿主机内网 IP 或 `host.docker.internal`。                           |
| Docker socket 挂载            | Docker runtime 需要挂载宿主机 Docker socket，默认是 `/var/run/docker.sock`；OrbStack 等环境需替换为实际 socket。 |

如果服务器配置了 `HTTP_PROXY` / `HTTPS_PROXY`，建议给 OpenSandbox Server 和 Volume Manager 显式配置 `NO_PROXY` / `no_proxy`。至少包含 `localhost,127.0.0.1,127.0.0.0/8,fastgpt-app,fastgpt-opensandbox-server,fastgpt-volume-manager,fastgpt-agent-sandbox-proxy,host.docker.internal`，避免内部服务调用经过代理。

### Agent Sandbox Proxy 服务

| 变量                               | 默认值                                   | 说明                                                                                                            |
| ---------------------------------- | ---------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `PORT`                             | `1006`                                   | Proxy 容器监听端口，默认映射到宿主机 `3006`。                                                                   |
| `PREVIEW_PORT`                     | 与 `PORT` 相同                           | 自 4.16 起可单独指定 HTTP 预览监听端口；修改后需同步调整宿主机端口映射和 Agent Sandbox 管理页中的文件预览地址。 |
| `AGENT_SANDBOX_PROXY_SECRET`       | 无                                       | 与 FastGPT 主服务共用的密钥，至少 32 位。                                                                       |
| `FASTGPT_APP_URL`                  | `http://localhost:3000`                  | Proxy 回源 FastGPT 主服务的内网地址；官方 Compose 模板设置为 `http://fastgpt-app:3000`。                        |
| `FASTGPT_APP_REQUEST_TIMEOUT_SECS` | `10`                                     | Proxy 回源请求超时时间，单位秒；官方 Compose 模板设置为 `60`，沙盒冷启动较慢时可适当调大。                      |
| `RUST_LOG`                         | `info,fastgpt_agent_sandbox_proxy=debug` | Proxy 服务日志级别。                                                                                            |

自 4.16 起默认使用同一个端口提供 WebSocket 和 HTTP 预览。如果网关不支持同端口转发，可设置 `PREVIEW_PORT` 为其他容器端口（例如 `1007`），并将 Compose 端口映射改为 `3007:1007`，同时把 Agent Sandbox 管理页中的文件预览地址指向新的 3007 端口。

### fastgpt-app 服务

代理 WebSocket 地址、HTTP 预览地址和共享密钥统一在后台「子服务 → Agent Sandbox」配置。旧 Proxy ENV 仅在升级时一次性回填，此后运行读取页面配置。独立 Proxy 服务仍需设置与页面一致的 `AGENT_SANDBOX_PROXY_SECRET` ENV。

在 Compose 文件的 `x-agent-sandbox-config` 锚点中配置以下变量，使 `fastgpt-app` 和 `fastgpt-pro` 在首次初始化时迁移以下 OpenSandbox 配置：

```dotenv
# FastGPT 访问 OpenSandbox Server 的内网地址和密钥
AGENT_SANDBOX_OPENSANDBOX_BASEURL=http://fastgpt-opensandbox-server:8090
AGENT_SANDBOX_OPENSANDBOX_API_KEY=replace_with_opensandbox_api_key
AGENT_SANDBOX_OPENSANDBOX_RUNTIME=docker
AGENT_SANDBOX_OPENSANDBOX_IMAGE=registry.cn-hangzhou.aliyuncs.com/fastgpt/fastgpt-agent-sandbox:v0.5.0
AGENT_SANDBOX_OPENSANDBOX_USE_SERVER_PROXY=true

# Volume Manager 地址、Token 和持久卷名称前缀
AGENT_SANDBOX_OPENSANDBOX_VOLUME_MANAGER_URL=http://fastgpt-volume-manager:3000
AGENT_SANDBOX_OPENSANDBOX_VOLUME_MANAGER_TOKEN=replace_with_volume_manager_token
AGENT_SANDBOX_OPENSANDBOX_VOLUME_NAME_PREFIX=fastgpt-session

# 代理地址和共享密钥统一在 Agent Sandbox 管理页配置。

# 单个沙盒的资源限制
AGENT_SANDBOX_CPU_COUNT=1
AGENT_SANDBOX_MEMORY_MIB=2048
AGENT_SANDBOX_STORAGE_SIZE_GI=1
```

### 运行态镜像与 CPU 架构

`AGENT_SANDBOX_OPENSANDBOX_IMAGE` 是 OpenSandbox 创建 Agent Sandbox 时使用的完整运行态镜像地址。普通 `fastgpt-agent-sandbox` 镜像以非 root 用户运行，适合默认场景；需要修改 `/etc/apt` 或安装 apt 依赖时，必须使用 `fastgpt-agent-sandbox-root` 镜像，并同时配置 `AGENT_SANDBOX_APT_MIRROR`。

官方镜像的同一 tag 同时包含 `amd64` 和 `arm64` 架构，两个架构使用相同的环境变量配置，Docker 会根据 OpenSandbox Server 所在宿主机的架构自动选择镜像：

| 用途    | 镜像                                                                          |
| ------- | ----------------------------------------------------------------------------- |
| 非 root | `registry.cn-hangzhou.aliyuncs.com/fastgpt/fastgpt-agent-sandbox:v0.5.0`      |
| root    | `registry.cn-hangzhou.aliyuncs.com/fastgpt/fastgpt-agent-sandbox-root:v0.5.0` |

<Alert icon="⚠️" context="warning">
  自 FastGPT 4.18.0 起，沙盒持久卷统一挂载至 `/home/sandbox`（工作区
  `/home/sandbox/workspace`），运行态容器依赖内置 `fastgpt-ide-agent` 与
  `/usr/local/bin/entrypoint.sh`。升级至 4.18.0 或在系统迁移管理页执行
  `20261117_migrate_sandbox_to_opensandbox` 前，必须先将
  `AGENT_SANDBOX_OPENSANDBOX_IMAGE`（含自定义派生镜像）以及
  `fastgpt-agent-volume-manager`、`fastgpt-agent-sandbox-proxy` 升级至 `v0.5.0+`。
</Alert>

全球镜像源将 `registry.cn-hangzhou.aliyuncs.com/fastgpt` 替换为 `ghcr.io/labring`。如果使用私有镜像仓库，请确保镜像 tag 保留 `amd64` 和 `arm64` manifest；如果仓库只提供单架构镜像，请将 `AGENT_SANDBOX_OPENSANDBOX_IMAGE` 配置为与 OpenSandbox Server 宿主机架构匹配的镜像地址。

`AGENT_SANDBOX_OPENSANDBOX_API_KEY` 必须与 `[server].api_key` 一致，`AGENT_SANDBOX_OPENSANDBOX_VOLUME_MANAGER_TOKEN` 必须与 `x-volume-manager-auth-token` 一致，Agent Sandbox 管理页的共享密钥必须与独立 Proxy 服务的 `AGENT_SANDBOX_PROXY_SECRET` 一致。

请在后台「子服务 → Agent Sandbox」统一配置 WebSocket 地址（`ws://` 或 `wss://`）、文件预览地址（`http://` 或 `https://`）和共享密钥。App 与 Pro 共用该数据库配置；密钥至少 32 个字符，且须与独立 Proxy 服务的 `AGENT_SANDBOX_PROXY_SECRET` 一致。

<Alert icon="⚠️" context="warning">
  预览代理应部署在与 FastGPT 主站不同的 origin（协议、域名或端口至少一项不同）。Sandbox 中的 HTML
  可能包含用户生成的脚本；如果预览地址与主站同源，脚本可能访问主站凭证或接口。
</Alert>

预览链接是短期只读 bearer capability。获得链接的人可以在链接有效期内通过修改 URL 路径读取同一 Sandbox Workspace 中的其他文件，请勿将链接分享给无权访问该 Workspace 的用户。

从旧版 Volume Manager 升级时，请将原 `VM_VOLUME_NAME_PREFIX` 的值配置到 `AGENT_SANDBOX_OPENSANDBOX_VOLUME_NAME_PREFIX`，避免历史持久卷无法按原名称清理。

## 更多配置

### 自定义依赖源

如果沙盒内需要安装 npm、Python 或 apt 依赖，可以在 `fastgpt-app` 和 `fastgpt-pro` 中配置依赖源：

```dotenv
AGENT_SANDBOX_NPM_REGISTRY=https://registry.npmmirror.com
AGENT_SANDBOX_PYPI_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple
# 官方 Debian 13 (trixie) 镜像示例；debian-security 会自动按前缀推导为 .../debian-security
AGENT_SANDBOX_APT_MIRROR=https://mirrors.tuna.tsinghua.edu.cn/debian
```

`AGENT_SANDBOX_NPM_REGISTRY` 和 `AGENT_SANDBOX_PYPI_INDEX_URL` 适用于所有运行态镜像。`AGENT_SANDBOX_APT_MIRROR` 仅对 root 权限的 Agent 沙箱有效，并且必须配置为 apt 仓库根地址，不要填写到 `dists` 或具体版本目录。

对于官方 Debian 13（`trixie`）镜像，只需配置标准的 `/debian` 仓库根地址：FastGPT 会自动基于相同镜像前缀推导 `debian-security` 地址（当配置以 `/debian` 结尾时自动替换为 `/debian-security`）。

仅当使用自定义 Ubuntu 镜像时，才需要按运行态镜像架构手工选择对应的仓库路径（apt 镜像地址不会根据架构自动切换）：

```dotenv
# 自定义 Ubuntu 镜像（amd64 / x86_64）
AGENT_SANDBOX_APT_MIRROR=https://mirrors.tuna.tsinghua.edu.cn/ubuntu

# 自定义 Ubuntu 镜像（arm64 / aarch64）
AGENT_SANDBOX_APT_MIRROR=https://mirrors.tuna.tsinghua.edu.cn/ubuntu-ports
```

清华镜像站的 [Debian 镜像帮助](https://mirrors.tuna.tsinghua.edu.cn/help/debian/)、[Ubuntu 镜像帮助](https://mirrors.tuna.tsinghua.edu.cn/help/ubuntu/) 和 [Ubuntu Ports 镜像帮助](https://mirrors.tuna.tsinghua.edu.cn/help/ubuntu-ports/) 可用于确认对应仓库路径。使用其他镜像站时，选择该镜像站提供的 Debian 仓库或对应架构的 Ubuntu 仓库路径即可。

配置后，FastGPT 会读取沙盒的 `/etc/os-release`：Debian 镜像会生成并覆盖 `/etc/apt/sources.list.d/debian.sources`（包含主仓库、updates 和安全更新仓库 `debian-security`）；自定义 Ubuntu 镜像会生成并覆盖 `/etc/apt/sources.list.d/ubuntu.sources`（包含主仓库、updates、backports 和 security）。修改配置前，已有 sources 文件会备份为 `.copy`；删除环境变量后，有备份的文件会恢复，没有备份的文件保持不变。初始化阶段不会执行 `apt-get update`。

### 资源与生命周期

在后台开启「启用 Agent Sandbox」，并将运行时设为 Kubernetes 后，才显示「CPU 超卖倍数」与「内存超卖倍数」，默认分别为 `1` 与 `1`。配置存储在 `subservice.agentSandbox.opensandbox.cpuOvercommitFactor` 和 `memoryOvercommitFactor`。仅在 OpenSandbox Server 版本不低于 `v0.2.1` 时生效。CPU 与内存倍率必须是不小于 `1` 的有限数值；CPU requests 向下取整到毫核、最低 `1m`，内存 requests 向下取整到 MiB、最低 `1Mi`，limits 保持不变。容器本地 `ephemeral-storage` 交由 Kubernetes 集群策略（如 `LimitRange`）自行控制，FastGPT 不再下发。旧 `AGENT_SANDBOX_CPU_OVERCOMMIT_FACTOR` 和 `AGENT_SANDBOX_MEMORY_OVERCOMMIT_FACTOR` 仅在 App 升级迁移阶段读取一次，已有表单值优先；迁移完成后不再作为运行时来源。

修改倍率后，已启动的沙盒保持原资源配置；后续创建的沙盒会自动使用当前配置，包括删除或归档后重新创建的沙盒。连接或恢复已有沙盒不会重新应用这些配置。

| 配置 / 变量                                                  | 默认值 | 说明                                                                                            |
| ------------------------------------------------------------ | ------ | ----------------------------------------------------------------------------------------------- |
| `AGENT_SANDBOX_CPU_COUNT`                                    | `1`    | 单个 Agent Sandbox 的 CPU 核数上限。                                                            |
| `AGENT_SANDBOX_MEMORY_MIB`                                   | `2048` | 单个 Agent Sandbox 的内存上限，单位 MiB。                                                       |
| `AGENT_SANDBOX_STORAGE_SIZE_GI`                              | `1`    | 沙盒持久卷存储容量，单位 Gi（挂载至 `/home/sandbox`，工作区位于 `/home/sandbox/workspace`）。   |
| `subservice.agentSandbox.opensandbox.cpuOvercommitFactor`    | `1`    | Kubernetes 运行态 CPU 超卖倍数：CPU requests = limits / 该值；大于 1 时创建 Burstable QoS Pod。 |
| `subservice.agentSandbox.opensandbox.memoryOvercommitFactor` | `1`    | Kubernetes 运行态内存超卖倍数：内存 requests = limits / 该值；大于 1 时创建 Burstable QoS Pod。 |
| `AGENT_SANDBOX_SUSPEND_MINUTES`                              | `60`   | 运行中的沙盒持续未活跃多少分钟后自动暂停。                                                      |
| `AGENT_SANDBOX_ARCHIVE_INACTIVE_DAYS`                        | `7`    | 已暂停的沙盒持续未活跃多少天后自动归档。                                                        |

## 配置与连接排障

### 提示 Sandbox provider apiKey is required for opensandbox

检查 `AGENT_SANDBOX_OPENSANDBOX_API_KEY` 是否已配置，并确认它与 `opensandbox-config` 中的 `[server].api_key` 一致。

### 提示 AGENT_SANDBOX_OPENSANDBOX_VOLUME_MANAGER_URL is required

检查 `AGENT_SANDBOX_OPENSANDBOX_VOLUME_MANAGER_URL` 和 `AGENT_SANDBOX_OPENSANDBOX_VOLUME_MANAGER_TOKEN`，并确认 Volume Manager 服务正常运行。

<span id="提示-agent_sandbox_proxy_url-或-agent_sandbox_preview_proxy_url-is-required" />

### 提示 Agent Sandbox proxy configuration is missing

请在后台「子服务 → Agent Sandbox」统一配置 WebSocket 地址（`ws://` 或 `wss://`）、文件预览地址（`http://` 或 `https://`）和共享密钥。App 与 Pro 共用该数据库配置；密钥至少 32 个字符，且须与独立 Proxy 服务的 `AGENT_SANDBOX_PROXY_SECRET` 一致。

### 浏览器 WebSocket 连接失败

检查 Proxy 是否可从浏览器访问，并确认反向代理支持 WebSocket Upgrade。如果 FastGPT 使用 HTTPS，Agent Sandbox 管理页中的 WebSocket 地址也应使用 `wss://`。

### Proxy 校验失败或返回 401

确认 Agent Sandbox 管理页的共享密钥与独立 Proxy 服务的 `AGENT_SANDBOX_PROXY_SECRET` 完全一致，且至少 32 个字符。

### 沙盒创建成功，但文件树或终端连接失败

确认 Agent Sandbox 管理页中的 WebSocket 地址是浏览器可访问的 `ws://` 或 `wss://` 地址，并检查宿主机 `3006` 端口或对应域名是否已开放。

### Proxy 无法连接沙盒 endpoint

检查 `opensandbox-config` 的 `[docker].host_ip`。沙盒 endpoint 中的 `localhost` 或 `127.0.0.1` 对 Proxy 容器不可达，通常应改为宿主机内网 IP 或 `host.docker.internal`。
