This page explains current knowledge storage relationships for import and migration troubleshooting. For everyday operations, see [create and maintain a knowledge base](/en/guide/dataset/lifecycle).

## Relationship Between Files and Data

- A **knowledge base** stores model and processing configuration and contains collections.
- A **collection** stores source information, file identifiers, parent-folder relationships, and processing settings. Folder collections organize children; content collections contain chunks.
- **Data chunks** store text, Q&A content, metadata, and index associations in MongoDB's `dataset_datas`, linked through `datasetId` and `collectionId`.
- **Original files and parsed text** use object-storage services. The current file-reading path accepts S3 object keys and retains compatibility with legacy GridFS identifiers.
- **Retrieval indexes** use the vector backend selected for the deployment, with PG among the supported choices. Identifiers connect chunks to indexes; physical storage depends on the backend.

Earlier documentation describing PG `file_id` and the special `manual` and `mark` values refers to an older storage design. Investigate current deployments using the collection, chunk, and index identifiers of the installed version.

## File Import Process

1. Upload a file or connect an external source, select processing options, and preview parsing and segmentation.
2. Create the collection with its source and processing settings.
3. The backend reads, parses, and segments material according to the selected mode. Processing tasks reference the knowledge base and collection.
4. Processing creates chunks and retrieval indexes, calling language and embedding models as required by the mode.
5. Inspect processing status and failures, then use a question with a known answer to verify retrieval and original-file access.

Backups and migrations must cover MongoDB, the selected vector backend, and object storage while preserving consistency among them. See [Docker data migration](/en/self-host/migration/docker_db) and [object storage](/en/self-host/config/object-storage).
