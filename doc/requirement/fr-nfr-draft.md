# 文件级权限管理系统需求草稿（FR/NFR）

## 1. 目标、范围与统一模型

系统将 dataset、dataset 文件夹、collection 文件夹和 collection 纳入统一的资源权限模型，使协作者配置、直接访问、列表、移动、恢复继承、所有权转移及 RAG 检索使用同一份文件级权限判定。默认新建子资源 `inheritPermission=true`；显式设置为 `false` 后只使用资源自身配置和 owner 权限，不再从父级取得协作者权限。权限传播仅由继承状态和资源层级配置表达，不增加额外的范围字段或范围枚举。

权限位保持 read=4、write=2、manage=1（write=6、manage=7，按位 OR 累加），owner 为全权限。已有 tmbId/groupId/orgId/team 层级授权继续作为主体输入。dataset 的子资源为子文件夹及其所有 collection；collection 文件夹的子资源为子文件夹。范围内包括文件级授权、权限树、列表/搜索/RAG 过滤及存量升级；团队/组织/组管理和非 KB 资源行为不变。

## 2. 功能需求

### FR-01 权限数据模型与默认继承

为 dataset、dataset/collection 文件夹和 collection 保存 `inheritPermission`（布尔，默认 true）及资源级协作者配置；collection 可作为 `resource_permissions` 的独立资源类型或等价的、可被统一解析器识别的资源标识。

**验收标准**
- 新建资源缺省或传入继承值时持久化为 true；非法类型或布尔值拒绝。
- 继承态普通资源除 owner 外无独立协作者，权限解析取父级；独立态不读取父级协作者。
- 同一 dataset 的两个 collection 可解析出不同权限；tmbId/groupId/orgId 权限按既有规则叠加。
- 任何接口 schema、响应、数据库迁移和代码逻辑均不得包含废弃范围字段。

**技术约束/集成点**：兼容现有 `resource_permissions`、资源 schema、权限位和 `authDatasetByTmbId`/`getTmbPermission`；以索引、批量查询或缓存避免复制整棵权限树。

### FR-02 统一权限解析与操作门槛

提供输入 `resourceId+tmbId` 的统一解析器：继承态沿父链解析，随后叠加自身及 group/org/team 授权，owner 兜底。所有读取、操作和检索复用该解析器或其批量版本。

**验收标准**
- collection read 才能详情/列表；创建 collection 要 dataset 或父 collection write；修改要 collection write。
- move 要源、目标 folder 均 manage；删除 dataset/app 要 owner，删除 collection 要 write；changeOwner 要 owner；协作者配置/恢复继承要 manage。
- 任一门槛不足、跨团队 ID、伪造主体或路径均拒绝且不泄露资源详情。
- dataset 级门槛和 collection 级门槛叠加，不能以 dataset 权限绕过文件权限。

**技术约束/集成点**：复用现有 dataset 鉴权入口和错误码，服务端鉴权；与控制器、权限服务、缓存和审计集成。

### FR-03 文件级协作者配置

提供 collection 级协作者更新接口（建议 `/api/proApi/core/dataset/collection/collaborator/update`），支持 tmbId/groupId/orgId 主体和 read/write/manage 全量配置。

**验收标准**
- manage 用户可新增、修改、撤销单文件授权并立即影响详情、列表和检索；read 用户无权修改。
- 主体唯一、权限值合法、空配置按统一参数错误处理；重复提交幂等。
- 独立资源保存显式配置，继承资源不复制父级授权；owner 不可被普通撤权删除。
- 变更记录操作者、资源、主体、旧值、新值及时间；事务失败不产生部分写入。

**技术约束/集成点**：扩展 `updateResourceCollaborators`、权限表唯一约束、审计和缓存失效机制。

### FR-04 继承切换与显式独立子集

资源可在继承与独立间切换。独立配置只包含管理员明确指定的授权子集；父级后续变化不得放大独立资源权限。

**验收标准**
- 设为独立后 `inheritPermission=false`，保留 owner 与显式子集；父级增删授权不影响它。
- 恢复继承后清除自身除 owner 外的配置，`inheritPermission=true`，有效权限等于父级。
- 文件夹恢复时只同步仍为继承态的后代；已独立后代保持自身配置。
- 任何切换失败全量回滚；重复切换幂等。

**技术约束/集成点**：继承状态是唯一传播开关；使用事务、资源级锁/版本号、BFS+bulkWrite；批量任务具备进度、重试和审计。

### FR-05 权限冲突自动取消继承

当显式子配置比父级收窄、撤销父级主体会造成冲突时，自动设为独立并保留该配置；权限扩大不触发独立。

**验收标准**
- 父级 read、子级显式 write/更窄配置保存后为独立，且不被父级放大；父级 manage 等更大授权不触发独立。
- 主体删除、权限位变化、父级变更和迁移均执行同一冲突判定。
- 冲突不是接口错误，响应返回最终状态并有审计；文件夹仅同步其仍继承的后代。

**技术约束/集成点**：复用同一按位解析器和事务；不得由客户端推断冲突。

### FR-06 移动资源权限处理

移动时保持资源自身的继承关系不变：原继承态资源继续继承（按新父级合并权限），原独立态资源保持独立配置（仅更新 `parentId`）。update/move 接口不接收 `inheritPermission` 参数。

**验收标准**
- 原继承态移动后资源及仍继承态后代按新父级解析，旧父级独有授权无残留。
- 原独立态移动后 `inheritPermission=false` 保持不变，原 owner/显式配置不变。
- 源或目标 manage 不足、目标不存在、跨 dataset、循环或超深度均拒绝，目录和权限均不变。
- 移动后列表、平铺、直接访问和检索按新位置/权限立即收敛。

**技术约束/集成点**：目录关系和权限更新同一事务或可恢复一致性协议；集成目录树、collection 元数据、索引、缓存和审计。

### FR-07 恢复继承

提供 dataset 与 collection 恢复继承接口。恢复后清除自身除 owner 的配置并沿父链解析。

**验收标准**
- 独立文件恢复后仅留 owner，继承为 true，权限等于父级。
- 独立文件夹恢复时所有继承态后代同步恢复；独立后代不被覆盖。
- 无 manage、父级失效或资源删除时拒绝且无部分结果；缓存失效。

**技术约束/集成点**：批量任务幂等、可重试、可审计；与 `resumeInheritPermission`、权限缓存集成。

### FR-08 所有权转移

团队 owner 或资源 owner 可将 dataset/collection owner 转给同团队有效成员。

**验收标准**
- 非 owner 或跨团队目标拒绝；新 owner 获 owner 权限，旧 owner 不保留隐式 owner。
- 独立/继承资源均保持权限语义；冲突时按位取最大并去重主体记录。
- owner 字段、权限记录、关联外链/OpenAPI 记录（如适用）事务原子更新；列表、访问、检索立即一致。

**技术约束/集成点**：既有 changeOwner 服务、成员服务、resource_permissions、事务、审计、缓存。

### FR-09 按权限过滤文件列表

collection 列表必须在服务端按当前主体的 collection read 过滤。

**验收标准**
- 无 read 文件不出现在返回项、总数、游标、排序、聚合或分页占位中。
- 不泄露无权资源的 ID、名称、父路径、数量、时间或错误差异。
- 权限变更并发时采用一致快照或安全收敛，不能返回已撤权文件；空目录/无权路径为统一空或无权响应。

**技术约束/集成点**：数据库查询或批量过滤完成，禁止前端过滤；集成 collection list/listV2、分页、缓存、审计。

### FR-10 文件夹权限穿透与平铺

用户无文件夹整体权限但拥有其下具体知识库或文件权限时，允许符合规则的资源脱离隐藏路径平铺展示和访问。

**验收标准**
- 拥有知识库 read 即展示该知识库，即使祖先文件夹无权限。
- 只有子文件权限而无知识库 read 时，不展示该知识库，也不单独展示其文件。
- 无知识库权限的知识库及其文件全部隐藏；平铺项不含完整隐藏文件夹路径；直接访问仍逐资源鉴权。
- 遍历有最大深度、分页、超时及环保护，不因脏树泄露或死循环。

**技术约束/集成点**：服务端构造最小可见集合；集成目录 API、dataset 门槛、collection 列表、隐藏路径和缓存。

### FR-11 当前路径限定知识库搜索

在当前文件夹/路径搜索知识库时，只查询当前路径及允许展示的子树。

**验收标准**
- 结果不包含其他路径或全局知识库；先执行当前路径约束，再执行 dataset read 门槛和关键词匹配。
- 仅有子文件权限不能使知识库出现在结果；非法/无权路径不泄露详情。
- 空关键词、分页、排序、特殊字符、同名知识库和隐藏祖先路径遵守相同范围。

**技术约束/集成点**：查询携带规范化 parent/path 谓词，禁止全局搜索后截断；集成 dataset list/search、路径解析、权限服务、分页索引和缓存。

### FR-12 RAG/KB 检索按文件级 read 过滤

在既有 dataset read 门槛后，对向量、全文、混合召回候选按 collection read 过滤；所有 searchTest、对话召回和 OpenAPI 入口复用同一批量解析能力。

**验收标准**
- dataset 有 read 但 collection 无 read 时，该文件任何 chunk、引用、元数据、计数均不召回。
- 有权 collection 混合检索仍全部可召回；直接传 ID、folder 展开或伪造过滤参数不能绕过。
- dataset 无权不执行/不返回检索；dataset 有权但所有文件无权时结果为空。
- 撤权、授权、移动、继承切换在约定一致性窗口内生效；排序、去重、引用及流式输出正确。

**技术约束/集成点**：集成 `authDatasetData`、`defaultSearchDatasetData`、`deepRagSearch`、collectionFilter、向量/全文召回和引用构造；优先候选阶段过滤，失败默认拒绝而非放行。

### FR-13 存量权限一键升级

系统管理员可从根资源遍历，按新继承模型重新整理存量权限。

**验收标准**
- 执行前有影响范围报告和明确触发；默认继承资源为 true，独立授权仅保留必要显式子集，owner 永不丢失。
- 脏数据、旧父级残留和无法解析资源有错误清单，不静默放行。
- 任务可暂停、续跑、重试、幂等并可核对迁移前后摘要；期间读取采用安全一致策略。

**技术约束/集成点**：后台队列、批次事务、监控、审计、缓存/检索索引刷新和回滚/补偿。

## 3. 非功能需求

### NFR-01 安全与隐藏路径

所有详情、下载、列表、操作和检索必须服务端鉴权；无权请求统一错误或空结果，不返回资源存在性侧信道。日志脱敏，不记录无权内容。安全测试覆盖跨团队 ID、路径穿越、批量越权、并发撤权和直接召回。

### NFR-02 性能与容量

在单 dataset 10,000 collection、深度 20、20% 可读数据集上，列表权限过滤 P95 相对基线退化不超过 20% 且 P99≤2s；RAG 过滤额外 P95≤100ms 或基线 20%（取更严者）。禁止逐资源 N+1 查询，必须批量 `$in`/聚合、分页和缓存；过滤失败不得降级放行。

### NFR-03 递归与批处理

深树（dataset 10 层、collection 10 层）传播/恢复 P95≤5s；同层使用 bulkWrite，深度/节点数有上限，visited 去重；超时任务可回滚/补偿并告警。

### NFR-04 一致性与正确性

配置、切换、移动、恢复、转移具备原子性、幂等和并发控制；列表、直接访问、操作和 RAG 对同一主体得到一致 read 结论。测试覆盖正常、无权/非法路径、并发/父级失效、空目录、深树、同名及撤权瞬间。

### NFR-05 可用性与容错

权限服务、缓存或队列不可用时敏感读和检索默认拒绝，写操作返回可重试错误；后台任务断点续跑、重复消息不重复授权，有健康检查、告警和故障演练。

### NFR-06 兼容性与可迁移性

旧客户端缺省请求按继承 true 工作；保持现有权限位、认证入口和非 KB 资源行为。迁移可重复、可回滚/补偿，升级前后抽样权限解析一致率 100%。

### NFR-07 可观测性与审计

配置、切换、移动、恢复、转移、迁移和检索过滤记录审计；指标包含权限解析耗时、过滤命中/拒绝、缓存命中、任务进度/失败。可按 team、resourceId、主体、任务查询且日志脱敏。

## 4. 数据、接口与集成契约

1. 权限状态响应至少包含 resourceId、resourceType、parentId、ownerId、inheritPermission、当前主体有效权限和可管理标志；不包含废弃范围字段。
2. 列表/搜索请求包含团队上下文、规范化当前父资源/路径、分页游标、排序和过滤；服务端先限定路径再做权限过滤，平铺响应不得携带隐藏祖先路径。
3. 检索服务接收当前主体身份，由统一解析器生成可读 collection 集合或等价谓词，传入所有召回器；引用只能引用允许 collection。
4. 主要集成点：`packages/service/support/permission/dataset/auth.ts`、权限常量/工具、继承同步服务、dataset/collection CRUD 与 list API、`authDatasetData`、`collectionFilter.ts`、`defaultSearchDatasetData`、`deepRagSearch`、resource_permissions、缓存、事务、审计和任务队列。

## 5. 发布验收矩阵

- 单元：权限位、父链解析、继承切换、冲突、路径限定、主体叠加。
- 集成：collection 协作者、CRUD 门槛、移动、恢复、转移、列表过滤、穿透平铺、当前路径搜索、三类 RAG 入口、迁移任务。
- 安全：越权 ID/路径、隐藏路径、批量接口、并发撤权和无权召回，越权数必须为 0。
- 性能：1,000/10,000 文件，冷/热缓存，深树，高并发 RAG；满足 NFR 指标。
- 发布前须无高危越权缺陷、迁移演练与回滚/补偿记录齐全、监控告警上线、所有 FR 验收标准通过。
