额外核对：

1. 应用与工具的目录树隔离。`simple`、`chatAgent`、`advanced` 三种应用及 `plugin`、`httpToolSet`、`toolSet` 三种工具均验证正确目录创建成功、跨树创建和移动拒绝。

5. Collection 目录失去自身读权限，但独立后代仍可读时，接口返回 `folderAccessMode=navigate`；无权限正文仍不可读。这个导航能力符合现有可见性模型。

## 外部知识库深度与同步

新的无 mock 集成场景直接调用生产批量持久化服务，使用实际事务和隔离数据库，验证：

- 服务端外部目录连续创建到第 20 层成功；第 20 层下外部文件创建成功。
- 第 21 层外部目录创建失败，数据库没有残留该目录。
- 同批次混合外部文件与手动 Collection 时，手动资源仍使用 4 层策略；整批拒绝且无残留。
- 手动 HTTP create 即使携带 `apiFileId` / `maxDepth=20`，也不能取得外部同步的深度豁免。

已有的 4 项 Collection 测试补充验证：第 20 层既有外部正文同步重建成功；历史第 21 层目录下新增外部正文失败。该同步正文读取、S3 清理使用替身，因此只证明生产同步业务及持久化策略，不证明真实第三方网络和对象存储联通。

Pro 的 52 项测试覆盖 custom、飞书、语雀、钉钉适配器及共享导入 / 同步逻辑，包含 ACL 开关两态、重复导入幂等、远端列表 / 正文失败后的数据保留与重试、确认远端删除后再本地删除、201 个文件跨批导入、目录与正文队列写入失败回滚、受限源目录的移动权限、历史钉钉文档目录身份转换与跨批冲突恢复。第三方网络响应由固定 transport 夹具提供。

## 迁移事务与并发

15 项 service 测试使用真实 MongoDB 事务，覆盖：

- App / 工具独立祖先路径、非目录旧路径清除、历史超 4 层目录回填。
- 父级缺失、环、超遍历上限的失败记录处理，无部分路径写入。
- 跨树直接父级解除到根目录；更上层跨树边界截断；校验模式不写、成功后重跑幂等。
- App / 工具 / Dataset 脱离错误父级时重算继承 ACL，保留资源自有授权和独立权限分支；Dataset 关联启用权限的 Collection 同步更新。
- 迁移读取旧批次后，API 已完成移动时，事务内重新读取当前记录；已删除记录跳过。
- 与实际并发移动冲突时，整个迁移事务重试并读取新状态。
- 后续写入注入失败时，`parentId`、`ancestorIds` 和后代 ACL 一起回滚；Dataset 场景连同 Collection 权限一起回滚。

另外 3 项任务编排测试验证分阶段扫描、校验、进度与任务执行模式，不能替代上面的真实事务证据。
