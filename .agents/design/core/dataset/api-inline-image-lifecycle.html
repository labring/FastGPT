什么时候删除图片？

这里说的是新增的正文图片。

你的操作 图片的处理结果
编辑正文，移除图片引用 保留暂时没有引用，也不立即回收。
删除一个或全部分块 保留图片目录仍属于集合。
重训 / 同步重建集合 保留继承 prefix 标识。
删除集合 清理目录异步删除新图片目录；源文件图片沿用原清理机制。
删除知识库 统一清理登记整个库目录，提交后异步清理新旧文件和图片。

直接上传的独立图片数据仍按原 imageId 规则处理；本方案不把它改成正文图片。

实现细节，需要时再展开

主流程不需要逐张扫描“最后一个引用”。

扫描、替换和上传能复用哪些能力？
扫描 Markdown / HTMLmatchDocumentImages地址反转义与替换unescapeMarkdownImageUrl · item.replace()图片内容校验validateUploadFile · 现有 MIME 工具生成 key 与上传createOpaqueS3FileKey · uploadImage2S3Bucket

Base64 data URL 识别从旧函数提取成共享纯函数，三个分块写入接口共用一个转存封装。新增编排负责 prefix、同请求去重和失败清理。

不直接调用原 parseMarkdownBase64Images：它会清理 Markdown，上传失败时还会移除图片。新入口需要保留正文并报错，Base64 完整性也需要严格校验。

上传或保存失败，会不会留下无主图片？
  1. 上传之前登记临时清理记录。未被接收的图片在临时窗口到期后清理。
  2. 保存或入队成功，才取消临时清理。数据写入与图片确认放在同一 Mongo 事务；上传放在可重试事务外。
  3. 集合删除时记录目录清理任务。事务提交后再入删除队列，物理删除成功后才移除记录；失败可重试。

正常删除后立即尝试入队；异常情况由现有定时任务兜底，可能延迟到下一轮。临时图片的到期领取与成功保存互斥，避免误删刚被接收的对象。

账号注销、团队删除和免费账号清理，都能触发吗？
  • 单个、批量知识库或文件夹删除：进入 Dataset 删除队列，覆盖子库。
  • 团队删除、账号资源清理：团队删除任务调用 deleteTeamAllDatasets，统一进入 Dataset 删除队列。
  • 自助注销、管理员删除账号：删除账号拥有的团队，再走同一条路径。 非 owner 成员的共享团队资源按原规则移交给团队 owner。
  • 免费账号清理：满足原有清理条件后，也调用 deleteTeamAllDatasets。

最终都是“事务保存清理范围 → 提交后投递 S3 队列 → 物理删除成功才移除记录”。 漏投、队列故障或存储故障可由定时任务恢复；账号和团队记录先删除也不影响执行。

删除整个库登记整个库目录；清空但保留库只登记旧集合的源文件、解析图和正文图片目录， 避免延迟重试误删后来导入的对象。

目前注销完成只确认数据库资源清理。S3 物理删除仍异步执行， 未完成的清理记录会保留；账号注销尚未等待或统计这一层的最终完成。

哪些边界需要保留？
  • 只处理新 Base64。已有 S3 key、普通 HTTP 图片地址保持原样；纯文字保存不创建 prefix。
  • 文件解析不接入新目录。“手动文本创建集合”会先保存为源文件，因此也走原来的 fileId 链路。
  • 单条失败任务修改正文时复用转存。纯重试、批量重试、索引编辑和模型增强不自动上传新图片。
  • 同集合内可以共享图片。新目录图片不允许直接跨集合借用；其他集合需要独立持有自己的资产。
  • 不新增分块图片列表。正文已有引用，不再保存 relatedImgId 或 imageIds；旧 metadata.relatedImgId 保持兼容。
