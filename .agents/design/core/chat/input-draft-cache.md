# 客户端会话输入草稿

## 需求与范围

- 草稿仅存储在当前标签页的 `sessionStorage`，支持切换会话和刷新后的恢复。
- 缓存键只使用 `tmbId + appId + chatId`；任一字段未就绪时只使用当前表单。
- 保留文字和上传成功的附件引用；原始文件、上传中或失败的文件不持久化。
- 合计最多 10 份非空草稿，超限淘汰最后修改最早的一份。
- 最后一次内容修改后保留 1 小时，编辑续期，查看、切换和恢复不续期。
- 发送被正式接受后清理草稿。失败沿用现有 `clearInput && !responseText` 恢复规则。

草稿的保存、过期清理和恢复都在客户端完成，不产生附件校验、链接刷新或续期请求。
附件继续使用现有上传流程和文件生命周期。缓存保存现有 URL 和 key，不延长远端对象或预览链接的有效期；文件失效时需要重新选择上传。

## 状态与存储

`ChatBox` 切换会话时复用表单，`useForm.defaultValues` 只在首次初始化时生效。因此必须在身份变化时明确保存旧会话并恢复新会话，不能只切换保存键。

统一存储项为 `fastgpt_chat_input_drafts_v1`：

```text
version: 1
entries[]
  identity: { tmbId, appId, chatId }
  revision
  text
  files[]: { key, url, name, type }
  updatedAt
```

逻辑键为 `JSON.stringify([tmbId, appId, chatId])`，避免分隔符碰撞。
Zod 校验缓存结构，读取时剔除损坏、空内容、未来时间和已过期记录，去重后仅保留最近编辑的 10 份。
存储不可用时保留当前页面的内存副本；刷新恢复依赖浏览器允许存储。
首次操作清理由旧实现创建的 `chatInput_*` 键，不迁移无法确定身份和修改时间的旧数据。

附件只序列化上传成功的 `key、url、name、type`，排除 `rawFile`、base64 图标、进度和任务 ID。
恢复时直接使用缓存 URL：图片用它显示预览，普通文件按名称重建图标，并重新生成前端文件 ID。

## 表单与发送

- 内容变化时更新版本和实际修改时间。文字写入防抖 300ms、最大等待 1000ms，成功附件新增或移除立即保存。
- 切换前 flush 旧身份的待保存快照并取消计时器，再明确恢复新身份的文字和附件。恢复赋值不触发新编辑。
- `pagehide`、`beforeunload` 和普通卸载同步保存最后一次修改；数据更新不依赖 textarea 挂载。
- 发送点击时固定原会话、版本、文字和附件。变量校验和音频初始化的异步等待结束后重新确认所有者。
- 正式接受发送后按版本清理草稿，仅当表单仍持有该快照时清空输入；校验拒绝时保留文字与附件。
- 未收到回复的失败恢复本轮输入，不覆盖期间继续编辑的新草稿；离开当前会话时只恢复原会话缓存。
- 删除会话、清空应用历史、重置和退出登录时，使待保存任务及旧失败回调失效。删除请求使用发起时的成员和应用身份。

上传选择和结果回调也检查原成员及会话，切换或卸载时取消未完成任务，避免 FileReader 或上传结果追加到另一个输入框。

## 实现落点

| 文件 | 职责 |
| --- | --- |
| `web/core/chat/inputDraft/storage.ts` | 有界客户端缓存、校验、过期、版本清理 |
| `ChatBox/hooks/useChatInputForm.ts` | 内容监听、保存恢复、发送快照 |
| `ChatBox/hooks/useChatGenerate.ts` | 接受发送后的清理和失败恢复 |
| `ChatBox/hooks/useFileUpload.tsx` | 上传异步回调归属与取消 |
| `ChatBox/index.tsx` | 传入草稿身份和发送回调 |
| `ChatBox/Input/ChatInput.tsx` | 将提前清附件收敛到接受发送时 |
| 历史、重置、退出入口 | 清理对应的客户端缓存 |

## 验证

局部测试运行真实 React、react-hook-form、ahooks 和 JSDOM，覆盖：

- 成员、应用、会话隔离，切换和刷新恢复。
- 上传成功附件、图片 URL 回填，排除未完成文件及原始文件数据。
- 最近修改后的 1 小时边界、10 份上限、防抖 flush 和存储异常。
- 变量校验失败、接受发送后清理、未回复失败恢复和新草稿防覆盖。
- 删除与退出后的旧回调失效，上传与 FileReader 的跨会话隔离。

历史清理测试兼容 Node 不提供 Web Storage 时的纯内存成员 store。
本地测试限定为本次修改及受影响的输入、上传、发送和清理模块，不主动运行全量测试。
