# 管理员模型模板化与添加模型最终设计

本文记录系统管理员模型管理的最终设计，包括模板安装、空白创建、编辑、渠道关联、运行时目录及升级兼容。

关联设计：

- [模型引用统一为 modelId](./model-id-reference-migration.md)
- [客户端模型目录与接口收敛](./client-model-catalog.md)
- [Figma「账号」设计稿](https://www.figma.com/design/KcAmeVQkIsXRuR9CsFTa1N/%E8%B4%A6%E5%8F%B7?node-id=1252-3345)

## 1. 范围与依赖

- 本功能只管理系统模型，不引入团队安装模型、team scope 模型或成员渠道隔离。既有团队模型授权能力保持独立。
- Plugin 模型只作为创建模板，不自动成为已安装模型。全新数据库的模型列表和默认模型配置允许为空。
- 系统模型统一通过 AIProxy 网关调用，`AIPROXY_API_ENDPOINT` 和 `AIPROXY_API_TOKEN` 为必填配置。`OPENAI_BASE_URL`、`CHAT_API_KEY` 已弃用，不再作为系统调用回退配置。
- Plugin Provider 元数据是启动硬依赖；模板列表按需实时拉取。启动完成后，模板请求失败不影响已安装模型目录的加载，也不能清空或修改已安装模型。
- 模型级 `requestUrl`、`requestAuth` 保留存储、编辑和运行兼容，界面标注“即将弃用，请直接使用渠道”。用户自带 OpenAI Key 的既有调用能力保留。

## 2. 数据与身份

### 模型模板

- 模板是 Plugin 单次请求返回的创建参数，不落库，不建立 `templateId`、`templateVersion` 或模板外键。
- `{ type, model }` 仅作为一次安装请求的匹配键。
- 模板创建完成后与实例解绑；Plugin 变化不会修改实例，删除实例后不会自动重装。
- 所有已安装模型使用相同编辑、启停和删除规则，不返回或派生 `isCustom`，不提供“恢复模板默认值”。

### 模型实例

- 系统模型存储在 `ai_models`，作用域为 `system`。
- `modelId` 由 MongoDB `_id` 生成，是业务引用的稳定身份。
- `model` 是 Provider 调用及 AIProxy 渠道绑定使用的标识；system scope 内跨类型唯一，由 `{ scope, model }` 唯一索引兜底。
- 创建后 `model`、`type` 不可修改。编辑目标通过表单外部的 `modelId` 明确指定。
- 创建状态、创建表单和创建请求不得携带 `modelId`，包括可选字段或 `undefined` 占位；创建 API 拒绝注入该字段。
- 创建与编辑使用独立控制器、提交函数和请求 Schema。创建只能插入，更新目标不存在时报错，不执行 upsert 或退化创建。
- 创建初值通过字段白名单构造；复用默认模型能力参数时不复制实例身份。新建不会覆盖原默认模型或改变其默认引用。
- 新业务引用写入 `modelId`。旧 `model` 仅用于兼容读取；非空无效 `modelId` 不回退到旧名称。

### 模型与渠道

- 模型与渠道为多对多关系，AIProxy 的 `channel.models: string[]` 是关联事实源。
- 渠道按模型的 `model` 建立关系；`ai_models` 不重复保存 `channelIds`。
- 渠道数量及摘要由服务端从渠道快照反向计算，模型页和渠道页使用同一份关系。
- 零渠道允许保存和启用。启用状态与连接配置独立，保存成功不保证实际调用成功。

## 3. 创建流程

### 从模板新建

1. 每次打开入口实时拉取模板并规范化，支持 Provider、模型类型、名称筛选和多选。
2. 已安装的同名 `model` 从候选中排除，不因类型不同而允许重复。
3. 未选择模板时不能进入下一步；选择后在同一 Modal 中切换到统一渠道配置。
4. 所选渠道应用到全部待创建模型，允许零渠道，不逐个编辑模板参数；“上一步”保留选择。
5. 确认时提交 `templateKeys` 和 `channelIds`，批量范围为 1～500 个模板。
6. 服务端重新实时拉取模板。任一 `{ type, model }` 不存在则整批失败，且不开始渠道或模型写入；参数变化则采用提交时最新模板参数。
7. 渠道全部绑定成功后，在单个 MongoDB 事务中创建整批模型，统一默认为 `isActive: false`。

模板只保留在本次弹窗状态中；不使用启动预加载、定时刷新、Redis、服务端全局缓存、浏览器持久化或版本协商。

### 从空白新建

- 先选择 LLM、Embedding、TTS、STT 或 Rerank，再打开配置弹窗。
- Provider 初始为空，渠道初始为空，启用默认关闭。管理员可主动启用。
- 模型 ID 为空时，进入配置弹窗自动聚焦该输入框。
- 配置弹窗返回按钮为“上一步”，回到类型选择。
- 确认后才创建模型并提交渠道绑定；退出不保存模型草稿或普通关联草稿。

### 表单规则

| 类型 | 必填项及默认规则 |
| --- | --- |
| 通用 | 模型 ID（`model`）、模型提供商；别名可空，保存时回退到模型 ID |
| LLM | 最大上下文、最大响应 Tokens；知识库最大引用为空时取最大上下文的 80%，向下取整 |
| Embedding | 并发数（默认 1）、默认分块长度、最大上下文 |
| TTS | 音色必须是非空数组，元素遵循音色 Schema |
| Rerank | 最大 Tokens |
| STT | 遵循通用必填项 |

- Provider placeholder 为“请选择提供商”；初次进入不展示必填红色错误。
- Tokens 相关标签统一使用复数 `Tokens`，必填标签通过 `FormLabel` 显示星号。
- 同名模型使用枚举错误，客户端精确翻译为“模型 ID 已存在”。

## 4. 编辑与渠道交互

### 编辑模型

- 点击编辑立即打开 Modal，详情请求在弹窗内显示加载状态。
- 详情一次返回完整模型配置、全部脱敏渠道摘要及各渠道的 `isAssociated`；不重复请求渠道列表。
- 模型 ID 只读。参数与普通关联变化保存在本地草稿，确认后通过一次更新请求预检并提交。
- 取消编辑不提交模型参数或普通渠道关联变化。
- 新增或编辑流程前往渠道管理时，只要表单或关联集合有未保存变更，都提示确认离开；取消则保留当前草稿。

### 关联已有渠道

- 列表入口使用列表接口的渠道快照；编辑入口使用详情接口的渠道快照。
- 勾选仅改变本地状态；关闭或返回不提交。
- 从表格项直接打开时，确认调用渠道替换 API，成功提示“关联渠道成功”，然后刷新列表。
- 从模型编辑内打开时，确认只回写父弹窗草稿，不显示持久化成功提示；保存父弹窗时统一提交。
- 请求失败保留弹窗与选择，允许重试；写入期间禁止重复提交。

### 新增渠道

- 模型编辑、空白创建和模板批量创建均可新增渠道，并将创建响应中的精确渠道 ID 加入关联列表。
- 新增渠道是独立资源，子弹窗确认成功即写入 AIProxy，不随父弹窗取消而回滚。
- 已安装模型可在创建渠道时直接绑定；尚未创建的模型先建立空模型渠道，保存模型时再绑定。
- 不通过刷新前后列表差集推测新渠道 ID。
- 新建渠道拒绝同名渠道。渠道管理页支持编辑、启停、优先级及删除。
- 渠道摘要按 `created_at DESC, id DESC` 排序，启停不导致列表跳位。

### 模型测试

- 已安装模型支持按 `modelId` 测试；新增和编辑弹窗统一测试当前完整草稿，尚未落库也能测试。
- 测试只校验调用所需字段，计费字段不参与连通性测试。
- 显式渠道通过 `Aiproxy-Channel` 指定，并仅在本次请求移除模型级 `requestUrl/requestAuth`。
- 草稿模型尚未在目标渠道声明时，测试使用临时绑定并按临时绑定规则清理；不创建 MongoDB 模型。
- 测试状态按渠道 ID 隔离，并发测试互不覆盖 Loading 或结果。
- 结果提示包含模型标识、渠道名称及失败原因；模型 ID 为空时提示先填写。
- 用户 Key 优先于模型级连接配置；显式渠道测试使用指定渠道；其余保留模型级连接配置兼容，系统默认连接只使用 AIProxy。

## 5. 列表与公共组件

- 管理员页面保留模型配置、模型渠道、调用日志和监控；删除“可用模型”Tab，旧 `modelTab=model` 链接回退模型配置。
- 模型按 MongoDB `_id` 倒序展示，客户端不再按 Provider 或模型标识排序。
- 表格包含独立选择列、模型 ID/名称、Plus 计费、模型渠道、启用状态及操作。类型作为模型标签展示。
- 模型与模板列表使用固定行高虚拟滚动；固定列布局避免滚动时列宽变化，筛选变化回到顶部。
- Provider 筛选来自已安装模型实际使用的 Provider；无效筛选值保留并显示“无效值”，不回退首项。名称搜索按普通文本处理。
- 仅首次无数据请求展示整表 Loading；详情、测试和更新使用对应操作的 Loading。请求完成后才判断空状态。
- 列表 API 一次返回模型及渠道摘要；Layout 在模型配置页不重复发起管理员列表请求。
- 渠道数量 hover 展示名称、协议图标/名称和状态；离开 trigger 即关闭，点击进入关联。
- 全选覆盖当前筛选结果；进入多选状态后，非交互区域的行点击切换选择。复选框、复制、渠道、启停和操作按钮不重复触发行选择。
- 选择以稳定身份维护，复选框只打勾或反选，不产生缩放、动画或布局抖动。
- 单项和批量启停共用 `updateStatus`；批量删除同时删除模型权限记录。任一目标不存在则 MongoDB 整批失败。
- 写入成功后刷新一次列表并清空批量选择；刷新失败不反转或误报写入结果。

复用组件统一位于 `projects/app/src/pageComponents/model`：

| 组件/模块 | 职责 |
| --- | --- |
| `AddModel` | 模板选择、类型选择和创建流程 |
| `ModelEditModal` / `useModelEditWorkflow` | 编辑身份、详情、草稿、测试与离开确认 |
| `ModelConfigForm` | 通用参数展示与校验，不决定创建或更新目标 |
| `ModelLinkedChannels` / `ModelChannelModal` | 关联展示及本地选择，不重复获取渠道 |
| `ModelChannelCount` | 渠道数量与摘要展示 |
| `Channel/EditChannelModal` | 复用渠道创建与编辑表单 |
| `DefaultModelModal` / `JsonModelConfigModal` / `ModelPriceTiersTable` | 默认模型、JSON 配置及计费编辑 |

弹窗统一使用 v2 `MyModal`，按钮通过 `footer` 传入，正文内部滚动，标题和底部操作固定。模型入口的紧凑渠道新增态使用 `sm`，渠道管理完整编辑态使用 `lg`。业务名称直接显示，静态文案使用翻译 key。

## 6. 价格与 JSON 配置

- LLM 读取历史价格时兼容 `priceTiers`、`inputPrice/outputPrice`、`charsPointsPrice`。
- 打开编辑器先转换为 `priceTiers`；提交只认当前阶梯价格，清空或双零表示免费，不重新回退历史价格。
- LLM 保存时清除历史价格字段；非 LLM 继续使用 `charsPointsPrice`。不新增独立价格迁移任务。
- 输入、输出独立计费；输入价为零不跳过输出计费。
- JSON 导出保留原有价格字段及稳定 `modelId`，不转换、不回写数据库，剥离内部和未知字段。
- JSON 配置导入会事务删除文件中缺失的系统模型及其权限，保留 AIProxy 渠道和模型关联；空数组删除全部系统模型，全部缺少 modelId 的旧配置仍忽略。
- JSON 导入与编辑器共享 `normalizeModelPricingForRead`、`normalizeModelPricingForSave`；混合旧字段按历史读取规则解释，纯新格式空阶梯表示免费。
- JSON 按本地 `modelId` 命中时保留数据库中的 `model`、`type`；外部 ID 按非空 `model` 安装或匹配。
- 完整配置更新清除被省略的可清理字段，不能让旧请求配置或旧价格重新生效。
- JSON 覆盖需要二次确认，确认按钮保持 Loading 至接口完成；一次失败只显示一次错误提示。

## 7. 写入一致性与失败边界

- 模型写入编排集中在服务模块，API 路由负责管理员鉴权、请求解析和响应校验。
- 写入前完成模板、重复标识、参数、全部目标模型和渠道合法性校验。
- 涉及渠道的写入顺序为：更新全部相关渠道，再提交 MongoDB 事务。零渠道创建跳过渠道步骤。
- 删除先从全部渠道解绑，再事务删除模型和权限记录。
- MongoDB 模型、默认配置变化与 `ai_default_models.catalogRevision` 自增同事务提交，使用 majority 写确认。
- AIProxy 与 MongoDB 不做分布式事务或失败补偿。渠道部分成功时不写 MongoDB；渠道成功但 MongoDB 失败时允许保留冗余绑定，重试合并模型名时去重。
- 数据库提交成功后的运行时预热或客户端刷新失败只记录、反馈刷新问题，不把已提交操作报告为写入失败。
- AIProxy `/channels/all` 按全量协议使用。模型绑定和渠道普通编辑都必须保留完整 PUT 支持的其他可变字段，防止覆盖高级配置或凭证。
- FastGPT 渠道读改写和管理代理共用自动续租 lease，锁内读取最新快照；不自动重试已经部分成功的写入。
- AIProxy v0.6.5 不支持绑定差量更新或 CAS。对于 PUT 无法保留的非零 `balance_threshold`，拒绝修改绑定，避免静默重置。
- 外部绕过 FastGPT 的写入、旧客户端完整对象覆盖及租约过期的迟到请求仍受上游无 CAS 限制。

## 8. 运行时模型目录

- 业务统一通过异步 `getModelHandle()` 获取模型读取能力；不读取模型全局变量、私有缓存或旧 getter。
- 每个消费者可独立获取 handle，不依赖 HTTP 请求上下文。并发版本检查合并，顺序调用分别检查。
- 权威 revision 来自数据库；模型、默认配置和 revision 在同一个 snapshot 事务中加载，并一次性发布完整快照。
- 每个发布版本只构造一次 handle。快照复制并冻结，查找与默认槽位方法使用同步闭包；`findModelData` 返回可编辑副本，旧 handle 不受后续发布影响。
- handle 收敛类型 getter、展示查找、默认槽位、默认 ID、全部模型和启用模型读取；optional 通过选项表达。知识库封装只转换模型引用。
- `tryGetVlmModelData` 仅将严格 VLM getter 的 `UserError(ModelErrEnum.unExist)` 转为 `{ model: undefined, error }`，其他异常原样抛出，供图片任务显式降级。
- 版本检查与快照加载合计最多等待 5 秒；失败或超时回退到最近成功发布的本地快照，包括合法空目录。首次无快照时仍报错。
- 超时只结束等待，不取消共享加载；后台迟到成功仍可发布。失败不修改 revision、不清空快照，不另加熔断、退避或缓存系统。
- 接受故障期间旧价格、默认模型和启停状态延迟更新；5 秒是单次获取等待上限，不是缓存陈旧上限或整个 HTTP 请求累计上限。
- 鉴权、权限查询和业务写入失败不能由目录回退吞掉。
- 模型与默认配置不注册 MongoDB Change Stream；启动加载、写后主动预热及读取时 revision 检查负责更新。Provider/协议元数据通过独立入口读取，模板获取不依赖模型目录。

## 9. API 与数据暴露

下列模型管理接口统一以 `/api/admin/settings/model` 为前缀，要求系统管理员权限：

| 方法 | 路径 | 职责 |
| --- | --- | --- |
| GET | `/list` | 已安装模型、全部脱敏渠道摘要、Provider、默认模型 ID、协议元信息 |
| GET | `/detail` | 按 `modelId` 返回编辑配置和带 `isAssociated` 的渠道摘要 |
| GET | `/templates` | 实时模板候选，无版本协商或模板缓存 |
| POST | `/createFromTemplates` | 模板批量创建，统一渠道集合 |
| POST | `/create` | 空白创建，不接受 `modelId` |
| PUT | `/update` | 按 `modelId` 一次更新可编辑参数与渠道草稿 |
| PUT | `/updateStatus` | `modelIds + isActive`，单个及批量启停 |
| PUT | `/channel/replace` | 替换完整渠道集合，不接收新模型标识 |
| DELETE | `/delete` | body `modelIds` 批量删除，兼容 query 单个 `modelId` |
| GET / POST | `/test` | 已安装模型测试 / 当前草稿测试 |
| PUT | `/updateDefault` | 默认模型槽位配置 |
| GET | `/getConfigJson` | 导出配置 |
| PUT | `/updateWithJson` | JSON 配置导入 |

- 不保留模板默认恢复或独立模型绑定查询接口。
- API 请求用 `parseApiInput` 校验，业务响应用 Zod Schema 约束。
- 管理员列表模型脱敏；完整编辑配置仅由管理员详情和配置导出接口提供。
- 渠道摘要只返回 ID、名称、协议图标/名称、状态等展示字段，不暴露 API Key。
- 模型列表或详情的渠道查询失败时整体报错，不伪装成零渠道结果。
- 普通客户端模型目录、摘要、公开价格列表及知识库模型展示的接口边界见[客户端模型目录与接口收敛](./client-model-catalog.md)。
- `/api/aiproxy/**` 转发前先鉴权，只使用服务端 AIProxy 管理员 Token；客户端 Authorization、Cookie、Host、Origin、Connection 不透传，合法业务请求头按规则保留。

## 10. 升级兼容

- 已有部署保留现有模型、稳定 ID、有效默认引用及模型级请求配置；停止自动预装不等于删除历史预装模型。
- 迁移 Runner 依据注册表和 `system_migration_states` 判断是否执行，不能依据业务表是否为空。管理员清空模型后不会重新迁入旧表。
- `system_models` 按 `model` 合并到 system scope 的 `ai_models`：同名保留新表 `_id`，配置由旧表覆盖；旧表独有模型沿用旧 `_id` 新增；新表独有模型保留。
- 已有有效默认槽位优先，旧默认标记仅补齐缺失或失效槽位。
- 模型新增、覆盖与默认配置合并处于同一事务，失败全部回滚；不删除旧表。
- 旧表为空时不拉取 Plugin。历史损坏记录可用实时模板修复，但模板不能独立产生迁移或预装模型。
- 迁移需支持全量重放幂等；正式发布后的迁移 ID、顺序和既有语义保持稳定，后续修复追加任务。
- 发布迁移窗口内停止管理员及旧节点模型写入；不引入跨版本双写或写入栅栏，接受旧节点在迁移快照后写入 legacy 表的发布窗口风险。
