# PR #7663 集成与浏览器验收

## 范围与判定

- 基线：主仓库 `4ef2ed6651638f69a7e3b0472a0b7f75585ca9db`，Pro `408fbb1f9ab92448996ba175c301916649f2b5bc`。
- 依据：[需求设计](../admin-model-template-installation.md)、PR 当前描述、相对上游的实际差异。设计中较新的确认覆盖旧约定；本次合并的模型选择器行为以上游为准。
- 历史打勾和 CI 结果不计作本轮执行证据。每项必须记录执行方式、输入、实际结果及证据。
- 测试层：I = 真实 MongoDB 副本集事务与 HTTP 依赖集成；A = 本地完整 Next.js HTTP API；B = 真实浏览器交互；U = 边界/故障的定向自动化补充。U 不替代对应 B。
- 通过标准：下面所有需求的正常、失败及边界等价类具有本轮证据；发现的缺陷完成修复与回归，或明确记录未完成，不把限制标记为通过。
- AI Proxy 必需；跨 AI Proxy/MongoDB 无自动补偿属于接受边界；MongoDB 必须原子提交。允许故障期间旧快照，5 秒只约束每次获取，不能吞掉鉴权和写入失败。
- 不运行仓库全量测试，不修改部署 YAML，不修改共享开发库的业务模型或远端 AI Proxy 渠道。
