# 系统模型状态探测

## 目标

在管理员的「系统模型」下增加状态页，定时调用现有模型测试能力，展示启用模型最近 48 小时的状态、稳定性和汇总数量，并在模型从正常变为异常或从异常恢复时通过 webhook 逐模型告警。

## 关键决策

- 探测对象是运行时模型目录中的 `isActive=true` 模型。停用模型不继续产生记录，也不计入汇总。
- 每个模型首次调用失败后最多重试 3 次（最多 4 次实际尝试）。任意一次成功即结束重试；最终失败才记为红色。
 - 单次成功请求耗时 `> 30s`（30000ms）记为黄色，否则记为绿色。30 秒是高延迟判定阈值，代码集中定义，后续可以在不改变记录结构的情况下调整。
- 记录保存每次探测的最终结果，而不是每次重试的中间结果。记录包含实际尝试次数，便于判断边界问题。
- webhook 只发送状态边沿：红色进入发送错误，红色转为绿色或黄色发送恢复；同一模型持续红色不重复发送。每个模型使用独立请求，单个 webhook 失败不影响其他模型和记录落库。
- 配置存放在 `systemConfigs` 的 `modelStatusProbe` 类型中。token 只允许写入，查询只返回是否已配置；通过显式清空参数删除旧 token。
- 探测记录存放在独立集合，`testedAt` 建立 30 天 TTL 索引，同时建立模型和时间复合索引支持状态页读取。
- 定时任务每分钟触发一次，根据配置的 5-60 分钟间隔判断是否到点；timer lock 在任务结束后主动释放，异常退出时保留兜底 TTL，多实例不会在同一轮重复启动。管理员可通过「立即探测」复用同一业务服务做本地验证和故障排查，同一进程内的定时/手动并发会复用正在执行的一轮。

## 数据与接口

- `GET /api/admin/system/model/status`：返回脱敏配置、汇总状态、启用模型状态和最近 48 小时记录。
- `PUT /api/admin/system/model/status/config`：更新启用开关、5-60 分钟间隔、webhook 地址和 token。
- `POST /api/admin/system/model/status/probe`：管理员立即执行一轮探测并返回本轮记录。
- 前端状态图按 48 小时窗口显示记录；为了避免 1 分钟间隔在宽屏上挤压，实际记录使用横向滚动的细刻度展示，服务端只返回窗口内数据。

## 验证策略

- 服务层单测覆盖：初次失败后的 3 次重试、成功延迟阈值、最终失败状态、TTL/索引声明。
- 既有管理员模型 API 单测回归通过；新增配置、状态页和立即探测接口通过本地浏览器实际验证。
- 浏览器验证启用配置、1 分钟间隔、绿/黄/红状态展示及时间线刷新；本地实际产生 125 个启用模型、250 条 48 小时内记录，超过 5 条记录目标。
