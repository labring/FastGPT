# 模型计价统一为百万单位

## 计价结构

仅系统模型计费，团队模型始终免费。价格迁入独立的 `pricing` 对象：

```typescript
pricing: {
  // 仅 LLM 使用；每档下限由上一档上限推导，省略上限表示无限。
  tiers?: { maxInputTokens?: number; inputPrice: number; outputPrice: number }[];
  // Embedding、Rerank、TTS、STT 使用，值为积分金额。
  unitPrice?: number;
}
```

LLM、Embedding、Rerank 固定为百万 Tokens，TTS 固定为百万字符；这些类型不存单位切换标记。STT 的旧单价表示每 60 秒，新计价类型及固定单位见本文末尾的 STT 扩展设计。单价保存及显示最多两位小数，不补零；单次费用与监控累计保留精度。STT 迁移复制历史单价，不因单位迁移改变其金额。

计价 Schema 使用普通 `z.object`，按默认行为剥离未知字段，不使用 `.strict()`；已声明字段仍校验数值、范围和必填约束。旧价格声明只保留在迁移专用 Schema，并通过 `.meta({ deprecated: true })` 标记弃用。

业务 Schema、API、配置读写、运行期、表单、公开目录和监控仅使用 `pricing`。`0` 表示免费；单价缺失表示未配置；整个 `pricing` 缺失表示尚未迁移，按免费处理。新版保存清空价格时写入 `pricing: {}`，表示管理员已编辑，后台迁移不能恢复旧价格。LLM 可显式保存空阶梯。

旧根级计价字段已从业务与 Mongoose Schema 删除；数据库原值保持不变，仅由迁移专属 Schema 经原生集合读取，后续版本再清理旧 BSON 数据。新版 API 不再暴露，也不再新增原价备份标记。缓存单价、用量、供应商 SDK、依赖和部署配置不在本需求范围；Pro 测试与跑分中的残留另行提交，主 PR 不更新 Pro gitlink。

## 自动迁移

4.17.3 任务 `20261025_token_prices_per_million` 位于注册表末尾，声明 `independent: true`，不阻塞业务，也不等待后台普通队列中的其他回填。一次读取所有系统模型，先校验并计算所有变更，再调用一次 `bulkWrite`。团队模型不读取、不写入；STT 也迁入新对象，但单价不乘千。

计价依赖系统模型目录已经迁入 `ai_models`。该前提由框架的全局启动屏障保证：`20260903_migrate_legacy_system_models` 是启动阻塞任务，成功后各节点先重载模型缓存、完成业务初始化，才启用独立后台任务。独立模式与非空 `dependsOn` 互斥，因此不重复声明这一启动前提；若未来模型迁移退出启动链，必须重新评估计价任务的模式与显式依赖。独立任务复用集群共享的 3 个并发名额，获得名额后才竞争本任务 Mongo lease。

- 已有合法 `pricing` 直接跳过，包含空对象、空阶梯和零价；已有非法对象则报错，不覆盖。
- 缺少 `pricing` 时从历史根字段构建新对象。LLM 优先非空旧阶梯，再读取输入/输出价，最后回退综合价；仅在迁移中保留此规则。
- Token/TTS 单价十进制指数加 3，再四舍五入至两位，避免中点浮点误差：`0.000035 → 0.04`、`0.000065 → 0.07`。LLM 上限指数减 3，保留有效位：`4.1 → 0.0041`，不按单价精度截断。不保存旧下限。
- 每条更新只 `$set: { pricing }`，过滤条件再次要求 `pricing` 不存在，保护重试和管理员并发保存。
- 一次批量写入与系统目录修订号在同一事务中提交，失败整体回滚。没有分批游标、checkpoint、原价备份、失败模型队列或全量回读；修复数据后在管理页重试整次任务。
- 旧版系统模型初始化迁移在自身目录冻结根级价格 Schema，避免当前业务 Schema 剥离后续任务仍需读取的原价。

## 升级行为

旧节点继续读取原根字段，迁移不改变其既有价格。新版保存的价格不会同步写回旧字段，升级期间旧节点仍按旧价计算，新节点按新价计算。新建或删除模型、旧节点主动编辑与新版配置的同步不属于本轮保证。

用户接受升级及后台迁移期间的计费偏差；未迁移的新节点暂按免费处理。不要求停机、排空、旧节点检测、运行期每千单位兼容、双写或窗口补偿。这是对[系统迁移规范](../../../skills/system/system-migration-development/SKILL.md)默认滚动兼容建议的明确例外。价格任务不阻塞 App 与业务消费者；其他任务规则不变。

## STT 后续扩展

STT 新增按每百万 Tokens 或每 60 秒计价，通过后续启动迁移为本设计形成的旧 `pricing.unitPrice` 补齐 duration 类型。具体规则见 [STT 用量与计费](./stt-usage-billing.md)。其他模型的百万单位及历史迁移规则不变。

## LLM 阶梯输入上限回退为 K Tokens

LLM 使用 `pricing.tiers[].maxInputTokensK` 配置阶梯上限，值为正整数 K Tokens。新版按 `inputTokens / 1000 <= maxInputTokensK` 选档。省略上限表示无限档，尚未回填的旧阶梯因此直接使用首档。单价按每百万 Tokens 结算。

4.18.0 的独立后台任务 `20261120_migrate_model_pricing` 先分批回填 STT 计价类型，再用单事务回填系统 LLM 的 `maxInputTokensK`，最后联合校验。模型任一旧上限小于 1 时，按 M Tokens 将有限旧上限乘以 1000、四舍五入并最小取 1。其余旧上限按 K Tokens 复制。已有新上限及开放档跳过，原 `maxInputTokens` 保留供回退读取。新版保存只写 `maxInputTokensK`，经新版编辑的配置按新版格式使用。

公开 API、SDK 和新版导出的模型配置只提供 `maxInputTokensK`。当系统模型仍有待回填的旧上限时，暂缓导出 JSON，避免在同一新版实例保存配置时将首档变为无限档并覆盖后续档位。4.17.5 导出的配置可导入新版，能精确换算为正整数 K Tokens 的上限由导入入口转换。

## 缓存计费扩展

百万单位及 `pricing` 结构已合入；缓存计费在 `pricing.tiers` 中增加可选的 `cacheReadPrice`、`cacheCreationPrice`，均为每百万 Tokens 的单价。未配置沿用该档输入价，显式 0 免费。只影响 LLM，不新增单位标记，不读取旧根字段，也不修改既有价格迁移或新增迁移任务。

总输入包含两类缓存。已标记 K 单位的配置按总输入选档，缺少标记时用首档。费用为 `(普通输入 × 输入价 + 缓存读取 × 读取价 + 缓存创建 × 创建价 + 输出 × 输出价) / 1000000`。负数或非有限用量按 0 处理，缓存读取最多为总输入，缓存创建最多为剩余输入；团队模型仍免费。单次费用不舍入。

OpenAI 兼容响应在请求聚合入口归一化供应商缓存字段并累计连续输出；Pi 的普通输入不含缓存，适配时补回缓存以形成总输入。锁定 SDK 的 pnpm 补丁补齐其 OpenAI 缓存解析，输出与普通请求统一采用 `completion_tokens` 总量，不再次累加其中的 `reasoning_tokens` 分项，避免推理模型重复计费。镜像安装上下文同步包含补丁。普通请求、两种 Agent、压缩、知识库检索、训练、辅助生成与评估逐层转发两类缓存数量。Pro 创建/追加/合并用量后按已有积分总额扣费，不再重新计价。

新账单仅写入实际发生的 `cacheReadTokens`、`cacheCreationTokens`。使用详情中历史零值按空值展示，每列仅在至少一个模块存在该项用量时显示。监控使用当前单价和渠道聚合用量估算积分，钱包以实际扣费为准。模型列表保留输入、输出两行，模型选择弹窗直接展示四类单价。悬停或聚焦价格摘要可查看同一张阶梯明细表，表头标明输入区间使用 K Tokens，单价使用积分 / M Tokens。缺省或舍入为 0 的价格显示 `-`，只有一个档位且两类缓存都无有效价格时隐藏提示。
