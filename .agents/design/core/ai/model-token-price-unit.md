# 模型计价统一为百万单位

## 计价结构

仅系统模型计费，团队模型始终免费。价格迁入独立的 `pricing` 对象：

```typescript
pricing: {
  // 仅 LLM 使用；每档下限由上一档上限推导，省略上限表示无限。
  tiers?: { maxInputTokens?: number; inputPrice: number; outputPrice: number }[];
  // Embedding、Rerank、TTS、STT 使用，值为积分金额。
  unitPrice?: number;
}
```

类型决定固定分母：LLM、Embedding、Rerank 为百万 Tokens，TTS 为百万字符，STT 为 60 秒；不存单位字段或切换标记。单价保存及显示最多两位小数，不补零；单次费用与监控累计保留精度。STT 迁移复制历史单价，不因单位迁移改变其金额。

业务 Schema、API、配置读写、运行期、表单、公开目录和监控仅使用 `pricing`。`0` 表示免费；单价缺失表示未配置；整个 `pricing` 缺失表示尚未迁移，按免费处理。新版保存清空价格时写入 `pricing: {}`，表示管理员已编辑，后台迁移不能恢复旧价格。LLM 可显式保存空阶梯。

根级 `priceTiers`、`inputPrice`、`outputPrice`、`charsPointsPrice` 仅在 Mongo Schema 中标记弃用并保留原值，由迁移读取；不向新 API 暴露，后续版本另行清理。不新增 `legacyTokenPricing`，不处理缓存单价或用量、供应商 SDK、依赖、部署配置及 Pro gitlink。

## 自动迁移

未发布的 4.17.4 任务 `20261025_token_prices_per_million` 位于注册表末尾，非阻塞自动后台执行。一次读取所有系统模型，先校验并计算所有变更，再调用一次 `bulkWrite`。团队模型不读取、不写入；STT 也迁入新对象，但单价不乘千。

- 已有合法 `pricing` 直接跳过，包含空对象、空阶梯和零价；已有非法对象则报错，不覆盖。
- 缺少 `pricing` 时从历史根字段构建新对象。LLM 优先非空旧阶梯，再读取输入/输出价，最后回退综合价；仅在迁移中保留此规则。
- Token/TTS 单价十进制指数加 3，再四舍五入至两位，避免中点浮点误差：`0.000035 → 0.04`、`0.000065 → 0.07`。LLM 上限指数减 3，保留有效位：`4.1 → 0.0041`，不按单价精度截断。不保存旧下限。
- 每条更新只 `$set: { pricing }`，过滤条件再次要求 `pricing` 不存在，保护重试和管理员并发保存。
- 一次批量写入与系统目录修订号在同一事务中提交，失败整体回滚。没有分批游标、checkpoint、原价备份、失败模型队列或全量回读；修复数据后在管理页重试整次任务。
- 旧版系统模型初始化迁移在自身目录冻结根级价格 Schema，避免当前业务 Schema 剥离后续任务仍需读取的原价。

## 升级行为

旧节点继续读取原根字段，迁移不改变其既有价格。新版保存的价格不会同步写回旧字段，升级期间旧节点仍按旧价计算，新节点按新价计算。新建或删除模型、旧节点主动编辑与新版配置的同步不属于本轮保证。

用户接受升级及后台迁移期间的计费偏差；未迁移的新节点暂按免费处理。不要求停机、排空、旧节点检测、运行期每千单位兼容、双写或窗口补偿。这是对[系统迁移规范](../../../skills/system/system-migration-development/SKILL.md)默认滚动兼容建议的明确例外。价格任务不阻塞 App 与业务消费者；其他任务规则不变。
