# SQL 向量库全文检索与存量回填

> 更新：2026-11-19。范围：PG、OceanBase、SeekDB、OpenGauss；Milvus/Zilliz 保留现有路径。
> 全文统一按 `index.text` 构建。临时兼容开关控制读写，迁移负责校验结构、分词版本和实际全文召回。

## 1. 目标与边界

在既有 `modeldata` 向量行中维护外置分词词串，复用向量 ID、归属及删除生命周期。Mongo `dataset_datas` 仍是正文和有效索引引用的权威来源；健康向量不重新 embedding，仅为确认物理缺失的有效引用生成新向量和全文，并替换对应 Mongo 引用，正文保持不变。

```text
Mongo dataset_datas._id             = 业务块 ID
Mongo dataset_datas.indexes[].dataId = modeldata.id
index.text → 对应历史同义词处理 → 统一分析器 → modeldata.fulltext_tokens
```

`fulltext_tokens IS NULL` 表示未回填；图片向量的全文词串为空串。检索库不额外保存业务原文。

新写入通过向量通道将向量和词串同行提交，随后在 Mongo 事务中写主数据及兼容全文；两个数据库之间没有分布式事务。SQL 查询结果须按 Mongo 当前有效引用核对，孤儿及已替换的旧向量不能成为有效业务命中。

## 2. 临时兼容开关

| 环境变量 | 迁移验收前 | 迁移验收后 |
| --- | --- | --- |
| `TMP_MIGRATE_FULL_TEXT=true` | 读 Mongo，全量写删 SQL 和旧 Mongo 全文 | 继续读 Mongo、双写，等待管理员移除变量 |
| 未设置 | SQL 同行写删，纯全文提示等待迁移，混合检索保留向量结果 | 仅读原生 SQL 全文，继续 SQL 同行写删 |

为保持升级期间的全文服务，先在所有新版 App/Pro 和训练写入方统一配置 `TMP_MIGRATE_FULL_TEXT=true`。管理员确认迁移成功后，在统一切换窗口移除变量并重启相关进程。切换窗口可暂停写入并排空在途请求，避免只写 SQL 的节点和仍读 Mongo 的节点同时提供服务。Milvus/Zilliz 始终沿用原生路径。

选择在迁移期间停用全文服务的部署可以省略变量，期间只写 SQL 词串。旧镜像或暂不满足原生全文能力的部署可持续开启兼容。每个进程在向量存储启动时检查一次，在未就绪期间每隔五秒后台复查，成功后停止。运行态只读本地缓存。迁移成功、验收记录与当前 SQL 目标完全匹配时才允许原生全文。未就绪时纯全文提示等待迁移，混合检索只合并已可用的向量候选，纯向量查询沿用已有路径。停双写后旧 Mongo 全文会落后，恢复 Mongo 查询前需补齐并验证增删改。

## 3. 分词规则与物理目标

原生读取绑定三个目标字段。

| 字段 | 作用 |
| --- | --- |
| `targetId` | SQL 目标库持久化 UUID，用于绑定 checkpoint 和 ready；换库不能沿用旧游标。 |
| `schemaVersion` | 全文物理结构版本，当前为 1。 |
| `analyzerVersion` | 所有 SQL provider 共用 `fastgpt-jieba-search-v1`，只表示词典、切词、清洗、停用词及归一化规则。 |

数据库引擎和索引配置由各适配器核验。provider 单独保存在 checkpoint 和 Mongo 验收记录中。

SQL 的 `fastgpt_fulltext_metadata` 保存目标和版本。Mongo `dataset_sql_fulltext_targets` 记录已验收的目标，Runner 成功提交也带入同一结果。后台就绪检查必须同时看到成功终态和匹配的两端信息。

分析器采用 jieba 搜索模式，共用词典、URL/Markdown 清洗与停用词，统一小写。写入、回填、验收和查询使用同一实现；查询词去重，清洗后没有词时不查询 SQL。原文上限 1 MiB，词串上限 16 MiB，拒绝 NUL，不静默截断。OpenGauss 仍会用内置分词处理词串，统一外置规则不表示四库查询语义完全相同。

分词规则变更仍须新迁移代次或明确的重建流程；当前任务仅补 NULL，不能覆盖旧规则生成的非空词串。已存在的预览库元数据会幂等补上结构版本列，保留目标 ID 和分词签名。

历史 `synonymVersion` 保留：词串必须还原索引生成时的同义词版本，不能使用最新词表猜测；历史快照无法确认时记录业务 ID 并阻断 ready。图片索引及明确版本 0 不额外依赖同义词快照。

## 4. 数据库适配与建索引

共享业务回填流程，逐库实现版本/能力核验、DDL、条件回填和原生查询。SeekDB 复用 OceanBase 适配，但保留独立 provider 与产品版本检查。

| Provider | 当前代码门槛 | 全文实现及检查 |
| --- | --- | --- |
| PG | 已安装并预加载与 PostgreSQL 兼容的 `pg_search` | 0.25.0 前使用 `bm25`，此后使用 `paradedb`；0.26.0 前显式指定 `key_field=id`。词串用 `pdb.whitespace`，归属字段用 `pdb.literal`。 |
| OceanBase | 至少 4.3.5.1，MySQL 模式 | FULLTEXT SPACE，`min_token_size=1`；核对索引列、可见性、解析器与属性。 |
| SeekDB | 至少 1.0.1 | 与 OceanBase 共用 FULLTEXT 适配，独立解析产品版本。 |
| OpenGauss | 7.0.x，至少 RC2，并具备 DataVec BM25 | 普通 astore 表、nullable TEXT、BM25 索引及对应执行计划。 |

这些版本是当前适配范围，不表示厂商首次支持全文的版本，也不承诺所有更高版本均已验证。必要的产品/扩展约束保留，兼容开关不参与能力检查。

启动先准备基础表、词串列及必要的向量侧索引。PG 只在管理员运行手动任务后构建全文索引，已存在的词串列通过目录查询确认，只有缺列才短暂获取表排他锁。列 DDL 提交后，`pg_search` 0.26.0 及以上使用 `CREATE INDEX CONCURRENTLY`。旧版扩展在构建期间使用普通 `CREATE INDEX`，由 PG 表锁阻塞写入，读取继续。索引建完后，回填与验收阶段都允许写入。建索引遇到长事务等待超时后可重试，仅对同表、同名、定义匹配的无效索引重建。扩展原地升级后会复用仍受支持的历史有效索引，并继续校验索引列、分词及固定查询结果。

其他已适配的 SQL 向量库继续异步准备全文索引，应用启动可以继续。共享的 prepare Promise 合并本进程内对同一 provider 的并发准备。切读还需 Runner 提交成功并核验目标。

仓库现有公开 PG 镜像未预装 pg_search，openGauss 示例仍为 RC1。使用这些组合时，升级前设置兼容变量可保留 Mongo 全文。切换 SQL 原生全文前需先准备上述数据库版本及扩展。

## 5. 三阶段手动迁移

任务：`projects/app/src/migration/tasks/4180/20261110_migrate_sql_fulltext/`，首次版本 4.18.0，`manual: true`，恢复策略保持分批断点续跑。

前置：所有旧版 App/Pro/训练写入方已经升级排空。初始状态 waiting，管理员确认后入队；不阻塞 App 启动。手动确认不自动证明集群已排空。

```text
prepare：清除旧 ready → 等待/执行物理准备与能力核验
scan：   校验源记录 → 条件补 NULL / 补建缺失向量 → 写后核对 → 保存错误快照 → 推进游标
validation：完整重验当前有效引用 → 核对能力和目标版本 → 固定查询验收 → 登记验收结果
```

### 5.1 合并预检与回填

不再先做独立的全量只读预检。每条回填入口在任何写入前校验完整源记录，包括所有向量 ID、文本和历史同义词。SQL 更新仅命中 ID 与团队/知识库/集合一致的已有行，且只补 NULL。

已有非空冲突值和错误归属不会被覆盖。发现坏记录时允许其他健康记录完成派生词串回填，但最终失败且不登记 ready。

对仍被 Mongo 引用的无效 SQL 行，再按全局 ID 查询确认物理缺失，不能把错误归属当作缺失。PostgreSQL、OceanBase、SeekDB 和 openGauss 均只补建物理缺失项，复用 `DatasetDataIndexOperation.insertVectors`，使用知识库配置的 embedding 模型与记录的历史同义词输入，在新 SQL 行中一并写入向量和全文，分配新 ID；不会使用空向量或复用旧 ID。

提交前检查执行权，并在 Mongo 事务中核对模型引用、数据归属、原始 BSON indexes、updateTime、indexStatus 和 synonymVersion，只更新缺失项的 dataId。并发编辑、删除或模型重建使快照失效时不提交，清理未被引用的新向量；提交响应不确定时先查主库引用，主库不可读则保留派生行供孤儿清理。修复提交后重新读取并只读验收全部当前引用。原文、历史同义词版本及 Mongo 兼容全文不变；图片补建失败不能静默删除索引。

已提交的修复重试不会再次生成向量。迁移补建免 FastGPT 团队积分检查和向量用量扣费，Embedding 服务仍可能按其自身规则收费。迁移任务不创建计费记录。模型调用与 SQL/Mongo 之间没有跨系统事务，中断在提交前可能重做请求。补建不能恢复原向量的逐位数值，也不能从缺失的 Mongo 索引、历史词表或失效图片猜测输入。模型不可用、待训练/重建的数据保留失败，基础设施异常由 Runner 处理。

这减少了一轮全库扫描与分词；所有有效记录仍需最终完整验收。不能只凭“没有异常抛出”“词串不为 NULL”或计数相同认定成功。

### 5.2 断点、错误与恢复

- checkpoint 绑定 provider、targetId、schemaVersion、analyzerVersion，记录 scan 游标、固定上界、阶段与计数；换目标或分词规则不允许续跑。
- scan 按 Mongo 主库 `_id` 稳定分页，每批有界；恢复 scan 时刷新上界以覆盖中断期间新增记录。
- 重试先处理该阶段已保存的失败项，再继续游标后的记录；错误原因只保留有界消息和必要 ID。
- 每个业务批次前确认 lease；批次处理后先报告完整未解决错误快照，再保存 checkpoint。提交后断点前退出可以幂等重放。
- 数据完整性错误记入 failedRecords；连接、超时、驱动等意外错误直接上抛，Runner 保留已提交的错误快照与断点。
- 进入 validation 时始终从头扫描当前完整范围；不沿用旧验收游标跳过前半段。
- 验收本身只读。发现数据错误时进入回填入口补 NULL 或补建缺失向量，再重新只读验收。非空冲突始终失败。
- 回填与验收都会再次读主库确认当前引用，并发删除或替换后的旧向量不要求复活。新增数据依靠升级后的业务写入通道直接写齐词串，不依赖历史扫描追赶。
- 删除跨 Mongo/SQL 不具备分布式原子性：SQL 行已删除、Mongo 删除尚未提交时可能触发补建；引用提交的 CAS 与删除发生竞争，删除先提交则修复失败并清理新行，修复先提交后删除仍以 Mongo 当前引用为准，遗留 SQL 行由孤儿清理回收。绕过正常入口在同一向量 ID 下直接修改文本会作为冲突阻断 ready，不静默覆盖。
- 所有未解决错误清零后，验证索引能力、目标版本以及固定探测数据的中英文匹配、集合允许和排除。探测使用隔离的临时 SQL 行和固定向量，无需调用模型。探测结束清理，Runner 成功提交后才可能读原生全文。

返回值保留 applicable、provider、targetId、schemaVersion、analyzerVersion、scanned、validated，不再返回 prechecked。Milvus 按相同三阶段报告不适用，不执行 SQL。

## 6. 检索与兼容期

SQL 先按团队、知识库、集合允许/禁止范围过滤，再做相关性排名与 limit。返回向量 ID，经 Mongo 主库当前索引引用映射为业务块，去重后进入既有 RRF/rerank。

候选逐步扩展且最多 500 条；本轮按用户要求保留现有预算与去重行为，不额外实现分组 Top-K 或分页。

开启兼容时，迁移成功后仍保持读 Mongo 和双写。管理员移除变量并重启后，进程核验目标并启用原生读写。

本轮不删除旧 Mongo 集合、活动索引、正文、既有向量或文件；补建失败只回收本次新生成且未被引用的行。停双写由管理员移除变量完成。旧 Mongo 全文的退役留给后续独立任务。

一个 Mongo 业务库内每 provider 仅绑定一个目标。多目标范围隔离、跨时间点备份恢复、分析器变更的非空词串重建均需独立设计，不能沿用旧成功状态。

## 7. 验证范围

局部测试应覆盖：

- 三阶段注册、Milvus 不适用边界、手动 waiting 入队和真实 Runner 完成/失败。
- 坏数据与健康数据混合时健康行可回填，错误完整保存且 ready 不激活；修复后优先重试游标前错误。
- 源记录无效时不写该记录，已有词串冲突不覆盖，向量、正文及旧 Mongo 全文保持原样。
- 各 SQL 向量库只补建物理缺失项，向量和全文同写，保留旧 BSON 形状并只替换 ID，重试不重复生成。覆盖历史同义词、并发编辑/删除/换模型、lease 丢失、图片生成失败及不确定提交后的保守清理。
- checkpoint 提交前退出、取消、lease 失效、意外数据库错误、恢复验收重扫及条件补 NULL。
- 目标/规则不匹配拒绝恢复，目标 ready 记录在 Mongo 事务中的提交和回滚。
- 迁移暂停期间读 Mongo 与双写、固定查询失败阻断、成功提交前拒绝原生、成功后仍保持兼容、移除变量后只读写 SQL。
- PG 在线建索引期间仍可读写，取消后恢复无效索引，节点启动不触发建索引。
- 每库真实版本、DDL、索引属性、过滤和分词语义。缺少隔离实例时跳过，不能记作通过。

真实 SQL 集成入口保留 database.integration.test.ts；PG 恢复演练为 service.integration.test.ts，公开语料为 quality.integration.test.ts。测试使用 Ubuntu 测试机上的独立容器与数据库/schema，通过 SSH 本地端口转发访问。
