# 历史邀请成员清理

## 已确认需求

- 4.17.0 追加 `20260908_cleanup_legacy_invited_members`，非阻塞，失败继续后续任务。
- 只处理历史 `waiting` / `reject`，不把未知状态、缺失状态当成可删除对象。
- 删除成员的权限、成员组、部门关系，再删除成员；不删用户和业务资源，不生成备份。
- 用户确认数据较少，使用全量重跑，无 checkpoint。

## 开发设计

- 任务独立放在 4170 目录，注册表尾部追加，不改变既有任务语义。
- 一个事务读取完整候选及所有者保护条件，串行删除和校验。每次重试重新读取源数据。
- ObjectId 和字符串形式的 tmbId 均匹配；以候选成员 ID 限定范围，不清扫其他孤立关系。
- 团队所有者、ACL 所有者、成员组所有者及旧 apps/datasets/agent_skills 作者保留。
- 坏数据只记录 ID 和原因；可清理记录仍提交，保护记录导致任务失败，管理员修复后全量重试。
- 候选最多 10000 条，超过则写入前失败，避免意外大集合耗尽内存。事务失败整体回滚。
- 事务前、写入前、提交前及提交后检查 lease。提交后再次检查历史状态残留。
- 状态自 4.9.1 弃用；当前版本滚动升级不再产生这些状态。若仍运行更老的邀请写入代码，不保证并发新增关联可被捕获；最终残留检查发现新邀请时失败。
- 非阻塞意味着清理完成前已有 reject 数据的成员页仍可能报错，但不应因此阻止整站启动。
- 不依赖前置非阻塞 owner ACL 回填成功；自主检查保护条件。
- 历史版本作者引用保留，不为清理成员而扫描或删除版本内容。
- 成功统计是本次执行的删除数量；提交后进程退出再重跑可能显示 0，状态仍可正确完成。
