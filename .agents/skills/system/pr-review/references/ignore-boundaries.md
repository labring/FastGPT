# PR 审查忽略边界

## 短时数据回填期间取得的管理配置

新版启动后，管理员可能在后台回填完成前打开编辑表单或导出配置，之后继续保存该表单或导入该文件。即使在回填完成后才提交，配置快照仍来自回填窗口。

以下条件全部成立时，将意见记录为非阻塞的 `已确认取舍`。

1. **正常升级的窗口有依据地短。** 按代表性数据量和部署方式核对。从新版能够读到待回填数据开始，直到相关管理入口能够读到回填结果为止。核对任务调度、数据量、实测耗时和缓存可见性，确认完整窗口足够短。单次数据库写入耗时只能证明执行阶段的速度。
2. **触发依赖管理员在窗口内主动操作。** 风险来自人工在这段时间内打开、导出或保存受影响配置。正常配置操作在回填后使用完整数据。持续运行的客户端、定时任务和自动化写入按其实际调用方式单独审查。
3. **维护者明确接受具体后果。** PR 说明或审查讨论记录过渡期的行为、排除的操作、可能影响以及回填后的保证。

迁移时长、实际可见窗口或接受范围缺少依据时，列 `讨论项` 说明缺口。正常升级可能长时间排队、跨较长的滚动发布，或回填成功后从正常入口重新读取仍会丢失数据时，按常规风险定级。安全、权限、已发布契约和迁移失败恢复继续按对应规范审查。

### 模型阶梯上限回填示例

[FastGPT #8486](https://github.com/labring/FastGPT/pull/8486) 从旧上限回填 `maxInputTokensK`，以 350 条 Dev 系统模型记录在隔离环境验证回填。维护者确认这次回填窗口短，接受窗口内取得的表单或 JSON 后续提交可能覆盖已回填阶梯。这个复现说明了已接受的后果。回填后重新打开编辑页或导出 JSON 仍须保留完整阶梯，过渡期首档计费也仍须按约定验证。

复审以已记录的范围为准。只有新证据推翻窗口短、仅人工触发、回填后正常读取完整这三项事实中的任意一项，或发现影响超出维护者接受的范围，才重新定级。
