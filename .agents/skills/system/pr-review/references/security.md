# 安全与权限

用于涉及外部输入、鉴权、命令执行、文件路径或敏感数据的改动。检查真实数据流与可达路径，不能仅因出现某个 API 或鉴权函数就认定安全或有漏洞。API 校验与契约归属见 [工程与类型](engineering.md#接口与类型契约)。

## 输入与注入

- 从请求或工具输入追到数据库条件、更新字段及命令参数，确认运行时校验确实限制类型和允许操作。TypeScript 声明不能代替外部数据校验。
- MongoDB 查询不能直接透传不受信任的 filter 或操作符；动态查询需限制字段、类型及允许的操作。结合实际 schema 和查询 API 判断 ID 校验、转换是否有效，不要求所有查询机械新增 ObjectId 转换，也不禁止合法的服务端结构化条件。
- SQL 查询使用参数绑定；执行外部程序时优先使用程序名与参数数组，避免把用户输入拼进 shell 命令，同时核对程序自身的参数语义。

## 路径与文件边界

- 规范化路径后，用相对路径或等价的目录边界校验阻止 `..` 和绝对路径逃逸；仅用字符串 `startsWith` 会误放行 `/uploads-backup` 一类相邻目录。
- 允许符号链接时，继续确认解析后的实际落点，不能只检查拼接后的路径。

## 权限与租户隔离

- 追踪用户、API key、teamId 与资源权限的可信来源，确认下游没有用客户端传入的归属字段绕过鉴权。
- 对批量资源、子资源、文件及间接引用分别核实所属团队和操作权限；入口授权不能自动覆盖后续取得的所有资源。
- 无权限路径不得泄露数据，也不得在拒绝前产生写入、扣费或队列任务等副作用。权限行为变化需验证正常及越权路径。

## 敏感信息

- 密钥、token、密码不得硬编码或意外进入响应、日志、遥测；持久化敏感字段需按业务要求保护，`select: false` 不能代替存储保护。
- 输出遵循字段白名单或明确脱敏规则，避免泄露完整对话和用户输入。截断文本不等于脱敏；关闭 OTEL 导出也不能防止本地日志泄露。
- 日志结构、分类和导出控制见 [错误与日志](errors-logging.md#日志与链路上下文)。
