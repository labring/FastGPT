# 数据与性能

用于模型、索引、查询、批量处理、循环及同步计算的改动。结合数据规模、调用频率和查询/执行路径判断成本；需要测量才能确认的风险应写明证据缺口。

## 模型与索引

- 模型定义与实际写入、读取、序列化契约一致；新增虚拟字段或实例方法时核对其消费者，不为满足形式要求引入无业务用途的定义。目录与数据访问分层见 [工程与类型](engineering.md#模块与依赖)。
- 当前及废弃索引统一用 `defineIndex(schema, { key, options, deprecated })` 声明，禁止直接使用 `schema.index()` 或字段级 `index: true` / `unique: true`。
- 字段、唯一约束、TTL、partialFilterExpression、collation 或索引配置变化时，检查 FastGPT 明确创建过的历史索引。明确废弃的索引紧邻当前定义登记 `deprecated: true`，同步检查 `packages/service/test/common/mongo/indexManager.test.ts` 的清理覆盖；不能删除客户索引或来源不明的索引。
- 历史索引删除的 name/key 精确匹配、text 索引兼容及其他细则以 [仓库索引约定](../../../../../AGENTS.md) 为准。
- 高频查询结合过滤、排序、数据分布和已有复合索引前缀核对覆盖，必要时检查查询计划；不能仅因某字段没有独立索引就断言全表扫描。

## 查询与批量操作

- 检查循环内查询是否形成 N+1；能批量取得的数据按实际成本评估批量查询与内存关联，不把所有循环内查询一律判错。
- 面向页面的大结果集应分页或有业务上限；需要完整遍历的后台任务可使用游标和分批处理，避免先把全部数据载入内存。
- 查询只返回消费者所需字段，特别检查 content、vectorData、fileContent 等大字段的传输和内存成本。
- 批量读写限制单批规模及并发量；需要写入全部数据时分批完成，不能用截断数据掩盖资源问题。
- 注入与查询信任边界见 [安全与权限](security.md#输入与注入)；重复键、连接异常等失败处理见 [错误与日志](errors-logging.md#错误传播与兜底)。

## 增长、循环与执行资源

- 日志数组、历史记录或累计数据需有符合业务语义的容量/保留策略，检查无限 `$push`、无上限批量写入等增长路径；不能随意截断仍需保留的业务数据。
- 递归和队列遍历需核实终止条件、环形引用及重新入队路径，按业务选择访问集合、深度或工作量限制，并明确触发限制后的处理结果。
- 检查请求热路径上的同步 I/O、大 JSON 解析和密集计算是否阻塞事件循环；按实际成本选择分片、流式处理或 worker，不能只凭代码含 `reduce`、同步调用或固定毫秒数判错。
- 验证有代表性的输入规模及边界，报告耗时、内存或查询次数等可观察依据；推理估计与实测分开表述。
