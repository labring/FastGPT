# 工程设计原则与质量把控

[代码规范](./syntax.md)约束可逐行判定的写法；本文约束方案取舍：同一需求有多种可行实现时，按以下原则选择更收敛、更不易出错的一种。修复与迭代过程另见[根因修复与代码收敛规范](./root-cause-fix.md)。

## 适用与判定

- **适用范围**：新增或修改的方案与实现。复用旧组件的可接受边界不在此列，也不借此重构存量代码。
- **开发自检**：中大型、跨层或涉及数据模型的改动，编码前先写清权威数据源、核心不变量和更简方案，再逐条对照下列原则。
- **审查定级**：
  - 违反原则并导致确定缺陷（数据错写或丢失、状态失真、越权、计费错误），或在本 PR 增量中新增了确定的重复维护、残骸代码、不生效的契约 → `必须修复`（类别：方案 / 收敛）。
  - 依赖产品取舍或证据不足 → `讨论项`；收益有限 → `非阻塞建议`。
  - 写法流派、抽象审美等纯偏好不阻断。

## 1. 单一事实源

同一业务规则、状态转换、格式解析或权限口径，只在归属层定义一次，其余各端和各层直接消费。

- 跨端（主仓 / `pro` / SDK / CLI / 前端）共享的判定、校验与文案，收敛到共享模块或共享资源；不在各端各维护一份等价实现。
- 同一状态转换只保留一个业务写入口，由它统一定义目标集合、权限口径和事务边界，调用方在同一事务内提交；不为不同页面或入口各写一套写入逻辑。
- 只能从已有数据推导出的值不另行存储或维护，避免派生状态与源数据失步。

> 反例：SDK 与 service 各维护一套远端终止判定；导入页与设置页各有一份整库开关写入，导入路径部分提交；路由与 SDK 各写一套签名链接格式规则；接口降级文案与 i18n 资源各维护一份。

## 2. 依据权威信号决策

分支判断和状态更新依据实际发生的事实，不依据推测。

- 以真实出站内容、结构化错误码和 `cause`、带提交版本的响应、按 ID 读取的权威记录作为判断依据；不从外层错误文案、配置开关、旧快照或前端列表推断状态。
- 增量写入只携带本次被修改的字段；审计、通知等派生信息由服务端按 ID 读取权威数据，不由客户端回传。
- 外部标识与输入按字面身份处理；不当作正则或文案模式匹配，也不靠截断、子串猜测归属。

> 反例：按节点开关推断媒体已内联，而实际所选引擎会丢弃音视频；只看外层 `Failed to create sandbox` 判断远端终止；接受滞后副本返回的旧配置快照；快捷操作带上旧列表里的名称，把已改名的模板改回旧名。

## 3. 复用优先，自研限定在差异点

- 优先使用仓库已锁定的依赖、公共模块和已有实现；只有现有能力确实无法满足时才自研，并在代码旁说明原因，自研范围限定在差异点。
- 不为假想的扩展需求提前增加抽象层、配置开关或透传层；出现第二个真实调用方时再抽象。

> 反例：为响应取消手写 SOCKS5 认证、协议解析与缓冲管理，而锁定的 `socks` 已支持在调用方提供的 socket 上协商。

## 4. 最小作用面

新能力、兼容容错与特殊处理只落在需要它的边界内，不扩散到主流程和通用契约。

- 兼容与修复逻辑放在明确的边界（历史回放、读取归一化、特定入口或版本）；不改变实时主流程的校验与执行契约。
- 局部需求不拖慢无关热路径：通用接口不同步等待只有部分场景才需要的数据，社区版不执行商业版专属的准备工作，高频更新不触发无关组件重建。
- 不修改共享组件、共享常量或模块级可变对象去迁就单一调用方；差异由调用方传入，或返回新对象。

> 反例：为修复历史数据的 JSON 修复提前到实时工具校验之前，使原本应报错的参数通过校验；通用初始化接口逐请求同步等待登录专用元数据；流式输出更新导致输入表单全部重挂载；所有零入参工具共享同一个模块级参数对象。

## 5. 只保留当前方案所需的代码

每次变更（包括改方案、裁剪范围）后，代码库只保留当前方案实际使用的路径。

- 删除失去调用方的函数、回调链、索引、兼容壳与对应测试；不保留只被自身测试调用的旧实现。
- 公开契约（配置开关、API 字段、SDK 参数）必须真实生效；不能落地的契约要么实现完整，要么从契约中移除。

> 反例：新连接模块从不读取 `onError`，回调链仍从 Editor 透传到 Skill；运行时只读结构化注册表，仍构建并返回无人消费的旧索引；公开的 `syncAllFiles` 开关写入成功却不影响同步。

## 6. 保护用户数据，结果可预期

- 用户可编辑的数据（手工配置、本地文件、自定义输出）只在用户明确操作时改写；输入没有变化时不触发重算和覆盖。
- 破坏性操作限定在系统受管的范围内，执行前能识别用户的本地修改，必要时提供预览或确认。
- 列表、分页与批处理结果确定：排序附带唯一副键（如 `_id`），重复执行结果一致。

> 反例：重复保存相同语言仍触发端口同步，删除了手工声明的输出；技能更新强制覆盖本地编辑，卸载递归删除用户添加的文件；按时间排序分页未加 `_id` 副键，跨页重复或漏数据。

## 常用机制的首选方案

以下机制仓库已有成熟实现。新需求优先复用，不另造同类机制；确需扩展时在原实现上扩展，并遵守对应约束。

### 互斥执行：租约（lease）

- **复用**：短时互斥与并发名额用 Redis token 租约（[`LeaseCache`](../../packages/dal/redis/caches/lease.ts)）；需要持久状态、可接管的长任务用 Mongo 租约 + `runId` fencing（见[系统升级管理器设计](../design/common/system-upgrade-manager.md)）。
- **约束**：
  - 获取租约用单次原子操作（`SET NX PX`、条件更新），不用“先查是否占用、再写入”两步判断；持有者 token 随机生成，过期时间以 Redis / Mongo 服务端时间为准。
  - 续租、释放以及租约保护下的每次业务写入，都校验 token 或 `runId` 仍匹配且未过期；心跳间隔小于 TTL 的 1/3；失租后立即停止后续写入。
  - 锁 TTL 只控制执行权；远端操作结果未知时，隔离或重试等待时间单独设定，不依赖锁过期。

### 异步任务：BullMQ 队列

- **复用**：统一使用 [`packages/dal/redis/bullmq`](../../packages/dal/redis/bullmq/) 提供的队列运行时、`QueueNames`、默认重试与清理配置（`options.ts`）及 `addOrRequeueFailedJob`；不自建内存队列或数据库轮询队列。
- **约束**：
  - 队列语义是至少一次投递：处理器必须幂等，用业务主键作为 `jobId` 去重。
  - 任务结果与其副作用（用量、状态推进）按同一工作项提交，失败后可恢复，不出现结果已提交而用量漏记、或重放重复入账。
  - 依赖数据库写入的入队挂在 `tx.afterCommit(...)`，避免消费者读不到未提交数据。

### 变更通知：Redis Pub/Sub 唤醒 + 定时兜底

- **复用**：用 [`SignalPubSubChannel`](../../packages/dal/redis/caches/pubSubSync.ts) 定义信号通道，在事务提交后发布（如[知识库训练唤醒](../../packages/service/core/dataset/training/wakeup.ts)），见[多库仓储架构](../design/common/dal/multi-db-repository-architecture.md)；不新增 Mongo Change Streams。
- **约束**：信号只表示“有变化，去查一下”，不携带权威状态，消费者始终从数据库读取最新数据；消息可能丢失，必须配周期任务对账兜底。

### 缓存与配置版本

- **复用**：运行期配置与目录使用修订号（如系统实例配置的 `revision`、模型目录修订号），与权威数据在同一事务内递增，各节点按修订号重载。
- **约束**：
  - 读取方（包括前端缓存）按版本号拒绝滞后结果，保存后的刷新要能确认拿到的是本次提交之后的版本。
  - 缓存失效挂在 `tx.afterCommit(...)`；缓存只用于加速，未命中时回源权威数据，不把缓存缺失当作数据不存在。

### 数据迁移与回填

- **复用**：自动升级任务接入系统迁移框架，按[系统迁移规范](../skills/system/system-migration-development/SKILL.md)实现。
- **约束**：按稳定游标分批处理并保存 checkpoint，写入用 compare-and-set 保证重放安全；完整任务及最小可重放单元都必须幂等。
