## 验证基线与结果

- 关联 PR：[FastGPT #8107](https://github.com/labring/FastGPT/pull/8107)。
- 验证日期：2026-10-23；代码基线：`c427e784a531d0f45fd23dbe679766ea6e06ce76`。
- 浏览器：本地开发环境中的真实 Chrome，通过产品界面导入流程、拖线、排序、删除、保存和刷新。
- 浏览器结果：19 组功能流程样例，237 条断言通过，其中目标 Handle 可连接性断言 163 条、操作结果断言 74 条。

这里记录实际完成的场景、复测方法和验证边界。237 条是断言数量，不等同于 237 个独立业务场景；第 00～18 组是功能样例，另有一个用于展示的流程，不计入功能样例数。

## 统一测试方法

在独立的本地测试应用中操作，避免修改用户正在编辑的流程。每组从初始拓扑重新开始；同组中需要保留前一步结果的操作会单独说明。

- `A → B`：普通执行连线；`Caller ⇢ Tool`：菱形工具挂载连线。
- `Branch[continue] → C`：从指定分支出口连接；`B[catch] → Error`：从报错捕获出口连接。
- 除特别说明外，普通节点使用文本编辑节点，必填文本已填写，节点位于同一主流程。
- `Free` 表示没有入线、尚未归属工具流程或容器的独立节点。
- 节点与展开区域应留足间距，避免重叠影响鼠标命中。

每次拖线同时检查两项：目标 Handle 是否可见，以及是否具有可连接状态。允许的代表路径还会实际松开鼠标创建连线；禁止的代表路径会向目标节点位置松开鼠标，确认没有创建连线。

拒绝连接、排序、折叠等不应改变连线的操作，比较操作前后**完整的连线 ID 集合**。显式删除操作比较具体删除的连线 ID，不能只看总数，防止误删其他连线后仍得到相同数量。

以下各组所列操作与预期均已通过；未完成的项目集中列在文末。

## 浏览器功能用例

### 00：主流程、多个工具流程与工具入口归属

初始拓扑：11 个节点、9 条边。

```text
Start → CallerA → Outer
Start → CallerB
CallerA ⇢ ToolA → A-Mid → A-Tail
CallerA ⇢ ToolB → B-Tail
CallerB ⇢ ToolC
Free（独立）
```

| 操作                                               | 预期结果                                                                                                      |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 从 ToolA 普通出口拖线                              | Outer、CallerA、CallerB、ToolB、B-Tail、ToolC 的入口隐藏；自身和重复目标 A-Mid 隐藏；A-Tail、Free 可连接      |
| 从 Outer 普通出口拖线                              | 工具入口及内部节点隐藏；上游 CallerA 和自身隐藏；同一主流程的 CallerB、Free 可连接                            |
| 实际尝试跨主流程、工具流程连接                     | 拒绝连接，原有全部连线 ID 不变                                                                                |
| 从 CallerA 菱形出口拖线                            | 自身、重复挂载 ToolA/ToolB、属于 CallerB 的 ToolC、已有普通入线的 A-Mid/Outer/CallerB 均不可挂载；Free 可挂载 |
| 将 Free 挂载到 CallerA，再从 CallerB 尝试挂载 Free | 第一步增加一条边；第二步隐藏 Free 的工具入口，不替换原归属                                                    |
| 从 CallerB 尝试挂载 ToolA/ToolB/ToolC              | 其他调用的入口和已存在的挂载均不可重复连接                                                                    |

更换归属需要重新加载初始拓扑：手动删除 `CallerB ⇢ ToolC`，精确确认仅删除该边，剩余 8 条边。此时 CallerA 可以挂载 ToolC，实际连接后恢复为 9 条边；原有 ToolA、ToolB 的重复挂载入口仍隐藏。

### 01：纯串行回环、同出口多目标与删除上游节点

初始拓扑：`Start → A → B → C`，另有独立 Free，共 5 个节点、3 条边。

| 操作                     | 预期结果                                                   |
| ------------------------ | ---------------------------------------------------------- |
| 从 C 拖线到 A、B 或自身  | 目标入口隐藏；实际尝试 C → A 不创建边，原 3 条边完整保留   |
| 从 C 拖线到 Free         | Free 可连接                                                |
| 从 A 拖线                | 自身、重复目标 B 隐藏；C、Free 可连接                      |
| 实际创建 A → C           | 同一普通出口可以连接第二个不同目标，总数变为 4             |
| 重新加载初始拓扑，删除 B | 仅删除 A → B、B → C，保留 Start → A；剩余 4 个节点、1 条边 |
| 删除 B 后从 C 连接 A     | 原串行路径已经断开，A 重新可连接；实际连接后共 2 条边      |

本样例还用于几何测量、取消拖线和缩放测试，见后文。

### 02：无环分支汇合

初始拓扑：`Start → A`、`A → B → D`、`A → C`，共 5 个节点、4 条边。

从 D 拖线：A、B 因会形成串行回环而隐藏，自身隐藏；C 可连接。实际创建 `D → C` 后共 5 条边，证明同一上游分出的两路可以汇合。

### 03：判断器稳定分支 ID 的回流

初始拓扑：`Start → A → Branch`、`Branch[continue] → C`、`Branch[ELSE] → Exit`，共 5 个节点、4 条边。Branch 为判断器，配置有效条件和稳定 `branchId=continue`。

从 C 拖线时，A、Branch、Exit 可连接，自身不可连接；实际创建 `C → A` 成功。重新加载后，从 `Branch[continue]` 直接连接 A 也成功；该出口到 C 的重复连线和节点自身连接仍被禁止。

### 04：旧版判断器 IF/ELSE 格式

拓扑与第 03 组相同，但导入数据中的判断分支没有 `branchId`，连线使用旧版 `IF`、`ELSE` Handle。

导入后兼容转换为稳定分支，原有 4 条边保留。展开、折叠后 IF 出口仍可使用；`C → A` 和判断器 IF 出口直接回到 A 都能实际连接，自身和重复连接仍被禁止。

### 05：问题分类分支回流与删除

拓扑与第 03 组相同，Branch 改为问题分类，配置 `continue`、`exit` 两个分类。

- 从 C 回到 A，以及从 `Branch[continue]` 直接回到 A，均可实际连接。
- 自身连接、同出口到 C 的重复连接不可连接。
- 重新加载初始拓扑，使用分类项的删除按钮删除 `continue`：只删除 `Branch[continue] → C`，其余 3 条边保留。

### 06：用户选择的手动选项回流、排序与删除

拓扑与第 03 组相同，Branch 改为用户选择，手动配置 `continue`、`exit` 两个选项。

- `C → A`、`Branch[continue] → A` 均可实际连接；自身和重复连线不可连接。
- 重新加载初始拓扑，拖起选项时，真实 source Handle 只有一个，拖动副本不重复注册端口，全部 4 条边 ID 保留。
- 将选项拖到列表外松开，取消排序：原选项顺序和全部连线 ID 保留。
- 实际将顺序从 `continue, exit` 改为 `exit, continue`：顺序确实变化，全部连线 ID 保留。
- 删除 `continue` 选项：仅删除该选项对应的 `Branch → C`，其余 3 条边保留。

### 07：用户选择的动态选项出口

初始拓扑：`Start → A → Branch[ref_default] → C`，另有独立 Exit，共 5 个节点、3 条边。选项输入使用变量引用，动态选项共用 `ref_default` 出口。

`C → A`、`C → Branch` 和 `Branch[ref_default] → A` 可连接；自身、重复目标不可连接。实际创建反馈边成功，总数变为 4。

本组验证客户端动态选项出口；没有在浏览器中执行后端的动态选项求值。求值及路由由后面的服务端自动测试覆盖。

### 08：条件分支不能掩盖另一条纯串行回路

在第 03 组初始拓扑上增加 `A → Plain → C`，共 6 个节点、6 条边。

从 C 拖线时，A 和 Plain 隐藏；Branch、Exit 可连接。实际尝试 `C → A` 被拒绝，6 条边完整保留。原因是即使 `A → Branch → C` 经过条件出口，`A → Plain → C → A` 仍是纯串行回路。

### 09：报错捕获的成功出口、失败出口与开关

初始拓扑：`Start → A → B`、`B[普通成功出口] → Success`、`B[catch] → Error`。B 是开启报错捕获的代码节点，共 5 个节点、4 条边。

| 顺序 | 操作与预期                                                                                  |
| ---- | ------------------------------------------------------------------------------------------- |
| 1    | Success、Error 均可回到 A、B；各自不能连接自身。实际反馈连线可创建                          |
| 2    | 重新加载，依次创建 `B[成功] → A`、`B[catch] → A`；不同出口可连接同一目标，总数变为 6        |
| 3    | 关闭 B 的报错捕获：只删除两条 catch 出口边，保留成功出口边，总数变为 4                      |
| 4    | 保留的 `B[成功] → A` 此时形成纯串行回环，提示问题但不自动删除；Success → A/B 的目标入口隐藏 |
| 5    | 再次开启报错捕获：原 4 条边全部保留；Success → A/B 恢复可连接，实际创建 Success → A 成功    |

此组同时验证关闭捕获导致规则变化时，系统只删除明确消失的 catch 端口关联边，不清理其他“新变得不合法”的边。

### 10：自定义 source 输出仍受串行回环限制

初始拓扑：`Start → A → B[custom] → C`，另有独立 Free，共 5 个节点、3 条边。B 是关闭报错捕获的代码节点，额外配置有效的 `source` 类型输出 `custom`。

从 C 连接 A/B 的入口隐藏，Free 可连接。实际尝试反馈被拒绝，原边保留。自定义出口不会自动取得条件分支的回环许可。

### 11：报错捕获涵盖有效的自定义成功出口

使用第 10 组拓扑，将 B 的报错捕获开启。

从 C 连接 A/B 的入口可见且可连接；实际创建 `C → A` 后共 4 条边。证明成功出口的条件语义包括有效 `source` 输出，而非仅节点默认普通出口。

### 12：旧版左右方向 Handle 兼容

初始拓扑与第 01 组相同，其中 `A → B` 存储为旧版 `A-source-left`、`B-target-right`。

导入时兼容方向格式，3 条历史边完整保留。从 C 连接 A/B 仍被禁止，Free 可连接；实际拒绝反馈后，全部历史连线 ID 保留。旧 Handle 格式不能绕过新规则。

### 13：循环与并行容器边界

初始拓扑共 12 个节点、4 条边：外层 `Start → Loop → Parallel`，另有独立 Outer；Loop 内包含 `L1 → L2`、独立 L3、循环终止 L-Break；Parallel 内包含 `P1 → P2`、独立 P3、用户选择 P-Select。内部节点配置对应 `parentNodeId`。

| 操作                                                         | 预期结果                                                   |
| ------------------------------------------------------------ | ---------------------------------------------------------- |
| Outer 向内部 L1/L3/P3 拖线                                   | 内部入口隐藏；容器节点 Loop、Parallel 自身的外部入口可连接 |
| L1 向 L3、L-Break 拖线                                       | 同循环内部可连接；实际连接 L-Break 后共 5 条边             |
| L1 向 Outer、Loop 或另一个容器的 P3 拖线                     | 入口隐藏；自身和重复目标 L2 也隐藏                         |
| P1 向 P3 拖线                                                | 同并行容器内部可连接；实际连接后共 6 条边                  |
| P1 向 P-Select、循环内部、外层、容器父节点或循环终止节点拖线 | 不可连接；并行容器内交互节点受限，且不能跨容器连接         |

### 14：工具参数、工具终止与循环终止节点

初始拓扑：`Start → Caller → Outer`、`Caller ⇢ ToolRoot → ToolTail`，另有独立 Params（工具参数配置）、Stop（工具调用终止）、Break（循环终止），共 8 个节点、4 条边。

- Outer 普通出口不能连接 Params、Stop、Break 或工具内部的 ToolTail。
- ToolTail 普通出口可以连接 Stop，实际连接后共 5 条边；不能连接 Params、Break、Outer、Caller。
- Caller 菱形出口可以挂载 Params，实际连接后共 6 条边；不能挂载 Stop、Break、已有普通入线的 Outer 或重复入口 ToolRoot。
- 被拒绝的操作不改变已有图。

### 15：嵌套工具隔离与祖先挂载限制

初始拓扑：`Start → Caller → Outer`、`Caller ⇢ ToolRoot → ToolTail → NestedCaller`、`NestedCaller ⇢ InnerRoot → InnerTail`，另有 Free，共 9 个节点、7 条边。

- InnerTail 普通出口不能连接 ToolRoot、ToolTail、NestedCaller、Caller、Outer，也不能回到已挂载的工具入口 InnerRoot；Free 可连接。
- 实际尝试向祖先流程连接被拒绝，原 7 条边保留。
- NestedCaller 的菱形出口可以挂载 Free；不能向 Caller、ToolRoot 建立递归挂载。实际挂载 Free 后共 8 条边。

### 16：历史非法回环的运行、发布、草稿与刷新

初始拓扑为第 01 组再加 `C → A`，故意导入当前规则不允许的串行回环，共 5 个节点、4 条边。

| 操作                   | 预期结果                                       |
| ---------------------- | ---------------------------------------------- |
| 点击编辑页“运行”       | 提示纯串行回环，全部 4 条历史连线 ID 保留      |
| 点击“保存并发布”       | 同样提示回环，不进入发布确认；全部历史连线保留 |
| 点击“仅保存”           | 草稿保存成功，显示已保存                       |
| 刷新浏览器重新加载草稿 | 全部 4 条历史连线保留                          |

对照组使用第 03 组再加 `C → A`：运行前检查通过并打开预览，保存并发布前检查通过并进入确认弹窗。测试取消了发布确认，没有实际发布，也没有发送消息执行后端工作流。

预览关闭使用实际视口位置确认，不能只依赖 DOM 的可见状态：侧栏关闭后可能仍挂在 DOM 中，只是移出了视口。

### 17：判断器多分支排序、删除与折叠

初始拓扑沿用第 03 组，增加稳定分支 `second`，连接 `Branch[second] → Exit`；保留 ELSE → Exit，共 5 个节点、5 条边。

- 拖起分支时，真实 source Handle 只有一个，全部 5 条边 ID 保留。
- 实际排序 `continue, second` 为 `second, continue`：顺序变化，全部连线 ID 保留。
- 删除 `continue`：只删除 `Branch[continue] → C`，其余 4 条边保留。
- 折叠后，剩余 `second`、`ELSE` 出口仍存在，全部 4 条边保留。

### 18：自定义及历史 source 输出的展示与连接

使用第 10 组的自定义 `custom` 输出和历史导入配置。

`B[custom] → Free` 可连接并实际创建，边数从 3 变为 4；连接 A、自身或重复目标 C 不允许。已有自定义输出及关联连线在导入、渲染过程中保留。

本组没有完成“通过界面删除输出字段”的验证。尝试输入的旧 `deprecated` 标记会被前端模板适配覆盖，代码节点的该自定义 source 输出也未提供对应可编辑删除入口，因此不能把这个场景记作输出删除通过。
